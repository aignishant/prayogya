# ADR-0008 — The day document is the deliverable; the learner builds the project

- **Date:** 2026-09-10
- **Day:** between the v4.0.0 rewrite and P01 day 0
- **Phase:** repository-wide
- **Status:** accepted
- **Amends:** v4.0.0 → v4.1.0. Adds §0 rule 5. Adds a sixth constraint to §5.1. Rewrites §1's
  opening and §2's preamble, and changes `python p.py codemap` from a write to a print.
- **Related:** ADR-0006 (why every project teaches everything it uses), ADR-0007 (the restart)

## Context

Immediately after v4.0.0 landed, work started on P01 day 0. The procedure in
`.claude/skills/day-prayoga/SKILL.md` said *"build the code before writing the day, where you
can"* — a rule adopted because every time this curriculum wrote first and ran second, the day
shipped a claim the code contradicted. Following it, the assistant built a working
`projects/01-claims-intake-desk/`: `.gitignore`, `.python-version`, `.env.example`,
`pyproject.toml`, `uv.lock`, and a 102-line `check.py` that went green on the pinned interpreter
and red on four distinct faults.

Every one of those files was correct. Producing them was still the wrong thing to do, and the
learner said so before the day was written:

> **"i want to do complete implementation manually … you just create days for me and mention all
> code and details there, i will run cmd manually with help of doc … reason is i want to learn and
> implement all file and code in project."**

The plan had left this ambiguous rather than decided. §1 said the project tree is *"take this
folder anywhere; it runs"*, which reads as something the curriculum hands over. §2.4 said
`CODEMAP.md` is *"generated by `python p.py codemap NN`"* — a command that wrote a file into
`projects/`. Nothing anywhere said **who types the code**, and when a plan does not say, the
default that wins is whatever is most convenient in the moment. Here that default silently removed
the exercise: a learner handed a finished `check.py` has read a file, and a learner who typed it
has built one. The distinction is the entire value of the curriculum.

It compounds per day, not per project. Every day written under the ambiguity produces a slice of
tree the learner did not build, and by the end of a twenty-day project the tree is complete and the
learner has typed none of it.

## Decision

**Rule 5 of §0: The Document Is The Deliverable.** Nothing is ever written into `projects/` by
whoever writes the curriculum. A day document must carry everything needed to build that day's
slice of the system:

- every file **in full, at its real path** — the path is where the learner puts it;
- every command **in the order it is run**;
- **what each command actually printed**.

A day that assumes a file whose contents the learner was never given has failed. So has one that
says "create the usual scaffolding". So has one that hands over a finished tree instead of the
instructions for building it. **`projects/<NN-name>/` is the learner's own work, and it is the only
thing in this repository that is.**

**The load-bearing half is how this squares with "never invent a transcript."** The author still
runs every command — **in a throwaway directory outside this repository, deleted when the day is
written**. That is the only way an output block can be real, and Principle 7 is not negotiable. So
the rule is precisely: *run everything, ship the transcripts, ship no tree.* A day whose commands
were not run carries `TODO(me): run <exact command>` where each output would go, and says so.

**Consequential changes, all mechanical:**

- **§5.1 gains a sixth constraint** — *Typed, not received*: the block is the whole file, the path
  above it is where it goes, and the command that creates the directory it sits in is in the hub
  §3. Nothing arrives pre-built.
- **§2 names the day that prints each project document**, because under rule 5 they are files the
  learner types like any other: `PROJECT.md` and `SETUP.md` on day 0, `README.md` and `CODEMAP.md`
  on the ship day.
- **`python p.py codemap NN` prints instead of writing.** `--write` saves it, and `--write` is a
  command the *learner* runs against the tree they built. Same for `python p.py verify NN`, which
  only ever reads.
- The reference tree built while this decision was being made — `projects/01-claims-intake-desk/`
  and the P01 day-0 scaffold — was deleted rather than kept. Keeping it would have made the first
  project the one exception to the rule that governs the other thirty-nine.

## Options considered

| Option | Why not |
| --- | --- |
| **Leave it ambiguous** | The status quo, and it had already produced the wrong outcome once, silently, on the very first day written under v4. An unstated default is not a decision; it is whoever is typing choosing for everyone. |
| **Ship the reference tree *and* the days, and let the learner choose** | It sounds generous and it is not. A finished, working, green `check.py` sitting in the tree is the answer key next to the exercise. Nobody types 102 lines they can already run, and the learner asked for exactly the opposite. |
| **Stop running the code, so nothing can be handed over** | This buys the rule at the cost of Principle 7, which outranks it. Unrun days would mean invented transcripts or a document that is `TODO(me)` from top to bottom — and the ledger notes on days 8 and 10 of the archived v3 work record five real defects that only appeared *because* the code was built first. The build has to happen; only its output ships. |
| **Ship the tree for the first project as a worked example, then stop** | Then P01 is the one project written to a different contract, which is the shape ADR-0007 has just finished paying to remove. Forty projects, one rule. |

## Consequences

**Better.** The learner types every line, which is the thing they asked for and the thing that
teaches. The day document becomes genuinely self-sufficient — it now has to be, because it is all
there is — and that pressure improves it: a day that would have leaned on "the file is in the repo"
must instead print the file, name its path, and show what running it prints. `python p.py check`
staying green with an empty `projects/` is now a correct signal rather than a gap.

**Worse.** Day documents get longer, and the author does strictly more work for the same output:
build it, verify it, transcribe it, then throw the build away. There is also no mechanical check
for this rule — `check` can see a cross-project reference, but it cannot see a day that quietly
omitted a file's contents. The defence is the checklist box and the reader: **the first person to
follow a day and find they do not know what to type has found the bug**, and that report is worth
more than a linter.

**The new failure mode is the plausible-looking gap.** A day that prints nine of the ten files it
needs looks complete until someone builds it. What catches it: the ship day's cold clone, which
follows the project's own documents from nothing, and `CODEMAP.md`, which lists every file in the
finished tree against the day that printed it — a file with no day is exactly this bug, and it
fails the gate.

**One thing this decision does not settle, and should be watched.** `uv.lock` is written by a tool,
not by a person, and cannot sensibly be "printed in full" — it is thousands of lines. §2.4 requires
every file in the finished project to map to a day. A generated lockfile satisfies the spirit by
having the day print the *command* that writes it, but the plan does not yet say so. If a second
generated file appears with the same problem, §2.4 needs an explicit clause and this ADR needs a
successor.

**What would have to be true to revisit this.** If the curriculum is ever used by someone who wants
a reference implementation to read rather than an exercise to do — a reviewer, or the author six
months on — the answer is a separate, clearly-labelled tree built *from* the days by following
them, never a tree the days were written from. That is a different artifact with a different name,
and it does not require touching rule 5.
