## One-line answer

Set this project's agent beside P01's and every line is the same except one — `tools=[...]` — and
that single line is the difference between an agent whose capabilities were decided by the file it
lives in and an agent whose capabilities are decided by a process it has to reach.

## The idea

The card by the phone has the extension on it. It does not have the stock list on it, and it never
will, and that is the point of the card.

Think about what actually changed for the person at your desk when the aisles turned into a phone
number. Their job description did not. They still take a question, work out what they need to know,
find it out and answer. They still have standing orders — *read the count before you change it,
never change a count nobody asked you to change, and if we do not stock the part, say so*. Those
orders are word for word what they always were. What changed is one line of their instructions: it
used to say *the shelves are in the far aisle*, and now it says *the desk is on 214*.

Everything else on the brief is unchanged, and it is worth naming the four things that stayed,
because "one line changed" is only an interesting sentence if the other lines really did not move.
Who they are, so that anything they file can be found under it. Which brain they use, written down
rather than left to whoever the agency has spare. What they may spend on a single question, which is
your number and not the agency's. And where the conversation is kept, so the second question about
the same job does not start from nothing.

Two of those four are worth staring at for a moment longer, because both are cases of a default that
is not wrong, exactly, but is somebody else's answer to a question you were supposed to answer. The
agency has a person who is always free — the one who has been on the books longest, four generations
behind the one you would have picked, and nothing about handing them the job feels like a mistake at
the time. And the agency has a spending limit, which exists to stop somebody making calls all night
and has nothing to do with what *one* question ought to cost. Leave either blank and work still comes
back. That is exactly why they are worth writing down.

And there is a fifth thing, which is not on the brief at all and belongs to nobody on the agency's
side: the key to the building. This project keeps its own keys in its own drawer and reads them
itself. The framework has never heard of that drawer. Somebody has to carry the key from the drawer
to the place the framework looks, and that somebody is a named function in this file, four lines
long, whose absence produces a message that is true and unhelpful in the same breath.

## The mechanism

`projects/02-parts-counter/parts_counter/agent.py`, whole file — new today:

```python
# parts_counter/agent.py
"""The counter, as an ADK agent, with its tools on the far side of a boundary.

The only line here that differs in shape from P01's agent is `tools=[...]`. P01 passed plain Python
functions and ADK wrapped each one; this passes a **toolset**, and the tools are discovered by
asking the server when the agent runs.

The model is pinned explicitly, as it is in every project (the plan section 9): ADK 2.8.0's
built-in default is `gemini-3.5-flash`, which the provider lists as Stable and calls its legacy
Flash model, so an agent that omits `model=` is quietly four generations old.

Verified against google-adk 2.8.0 and mcp 1.30.0 on 2026-09-10.
"""

from __future__ import annotations

import os

from google.adk.agents import Agent
from google.adk.agents.run_config import RunConfig
from google.adk.runners import Runner
from google.adk.sessions import BaseSessionService, InMemorySessionService
from google.adk.tools.mcp_tool import McpToolset
from google.genai import types

from parts_counter.util import keys, mcp, models
from parts_counter.util.budget import Budget

APP_NAME = "parts_counter"

INSTRUCTION = (
    "You are a workshop parts counter. Answer only from the tools you are given. "
    "Read a stock level before changing it, and never change a count unless the person has "
    "clearly asked you to. If a part is not in the inventory, say so and do not guess a number."
)


def export_key() -> None:
    """Copy this project's key into the process environment, because the framework reads it there.

    `google-genai` builds its client from `os.environ` and has never heard of this project's
    `.env`. Without this, a project that reads its own file gets `ValueError: No API key was
    provided.` while the key sits on disk. The environment wins if it already has one.
    """
    if os.environ.get("GOOGLE_API_KEY") is None:
        value = keys.get("GOOGLE_API_KEY")
        if value is not None:
            os.environ["GOOGLE_API_KEY"] = value


def build_counter(toolset: McpToolset | None = None) -> Agent:
    """The agent. Its tools live in another process and are fetched when it runs."""
    return Agent(
        name="parts_counter",
        model=models.require_pinned(models.ANSWERING),
        description="A workshop parts counter that answers from an inventory behind a boundary.",
        instruction=INSTRUCTION,
        tools=[toolset if toolset is not None else mcp.over_stdio()],
    )


def run_config(budget: Budget | None = None) -> RunConfig:
    """Run settings, with ADK's bound set from this project's own budget rather than its default.

    `max_llm_calls` defaults to 500 in ADK 2.8.0 — a ceiling sized to stop an infinite loop, not to
    budget one question. `Budget.max_per_turn` is the number this project chose for that job.
    """
    return RunConfig(max_llm_calls=(budget or Budget()).max_per_turn)


def build_runner(session_service: BaseSessionService | None = None,
                 agent: Agent | None = None) -> Runner:
    """A runner for the counter. `session_service` is ADK's one required keyword argument."""
    return Runner(
        app_name=APP_NAME,
        agent=agent or build_counter(),
        session_service=session_service or InMemorySessionService(),
    )


async def ask(question: str, *, user_id: str = "local", session_id: str = "s-1") -> str:
    """Ask the counter one question and return its final answer. Needs a working key."""
    keys.require("GOOGLE_API_KEY")
    export_key()

    sessions = InMemorySessionService()
    await sessions.create_session(app_name=APP_NAME, user_id=user_id, session_id=session_id)
    runner = build_runner(sessions)

    message = types.Content(role="user", parts=[types.Part(text=question)])
    answer = ""
    async for event in runner.run_async(
        user_id=user_id, session_id=session_id, new_message=message,
        run_config=run_config(),
    ):
        if event.is_final_response() and event.content and event.content.parts:
            answer = "".join(part.text for part in event.content.parts if part.text)
    return answer
```

**Line by line:**

- `from google.adk.tools.mcp_tool import McpToolset` — **the one import in this file that P01's agent
  does not have**, and it is here only for the type annotation on `build_counter`. That is worth a
  sentence: the agent module does not construct a toolset directly, it asks
  `parts_counter/util/mcp.py` for one, so the connection details live in exactly one file. This
  import is the type, not the knowledge.
- `from parts_counter.util import keys, mcp, models` — `mcp` here is **this project's**
  `parts_counter/util/mcp.py`, printed in part 1.1, and not the third-party `mcp` package. Inside a
  package, `from parts_counter.util import mcp` is unambiguous; at the top of a script it would not
  be, which is why part 1.2's `run.py` imports it `as client`.
- `APP_NAME = "parts_counter"` — a module constant because the same string has to reach two calls
  written apart from each other: `Runner(app_name=...)` and `create_session(app_name=...)`. Nothing
  reconciles them, so two literals is two places for a typo that surfaces as a missing session.
- `INSTRUCTION` as a module constant rather than a literal inside `build_counter` — so that day 18's
  eval can import the exact string the agent is run with, instead of a copy that will drift.
- **Read the instruction as policy, not as prose.** Three sentences, and each is doing a job that
  part 1.2 showed the protocol will not do for you. *"Answer only from the tools you are given"* is
  the grounding rule, and it is the one part 2.2 breaks. *"Read a stock level before changing it"*
  and *"never change a count unless the person has clearly asked you to"* exist because a write comes
  back through the identical envelope as a read — the boundary does not distinguish them, so the
  instruction has to. *"If a part is not in the inventory, say so and do not guess a number"* is
  aimed at the failure mode a language model has and a lookup table does not.
- `def export_key() -> None:` — the bridge, and the reason it exists is that **the framework does not
  use your key reader.** `google-genai` builds its client from `os.environ` directly. A project that
  reads its own `.env` and never exports the value gets `ValueError: No API key was provided.` from
  inside a library that is looking somewhere you never filled in, while the key sits on disk three
  feet away. The guard is `if os.environ.get(...) is None`, so **the process environment wins and
  the file is the fallback** — reverse that test and a container with a real injected secret gets it
  overwritten by whatever stale value a `.env` happened to carry.

  > **Recap — the key, and who reads it.** Nothing loads a `.env` for you: not Python, not `uv run`,
  > not the shell. A running program has an environment, `os.environ`, built by whatever launched it,
  > and the file is inert until code opens it. This project's code opens it; the framework's code
  > does not, so the value has to be copied across by hand, once, in a named function.
  > Self-contained version: `PRIMER.md` §3.
  > Deep version, if you have the full plan:
  > `days/01-ask-desk/day-09-sessions-errors-surface/parts/02-when-it-goes-wrong/2.1-the-error-that-reached-the-caller.md`
- `def build_counter(toolset: McpToolset | None = None) -> Agent:` — **a factory, and no
  module-level agent.** P01 had both: a `desk = Agent(...)` at module scope and a `build_desk`
  beside it. This project has only the factory, and that is day 6's own production note being taken
  rather than repeated. The consequence is concrete and lands in part 2.2: a module-level agent is
  validated by the *import*, so a bad model ID or a bad name fails the moment anything touches the
  module; a factory moves that to the call. Nothing here is validated until somebody asks for an
  agent.
- The `toolset` parameter with a `None` default — the seam. Passing one in is how a test, an eval or
  part 2.2 substitutes a different boundary; leaving it out is how the CLI gets the ordinary one.
  Note that the default is **evaluated on every call**, because it is `mcp.over_stdio()` inside the
  body rather than a default argument value — which is correct (a mutable default evaluated once at
  import would share one launched server across every agent ever built) and expensive (part 1.1
  measured what each construction costs).
- `name="parts_counter"` — a valid Python identifier. A space raises a pydantic `ValidationError`
  before the object exists, and the message calls it a *node* name, which is a hint about how the
  framework addresses agents once there is more than one.
- `model=models.require_pinned(models.ANSWERING)` — **the constant does not go straight through.** It
  is passed via this project's registry, so the exact ID the agent will name is checked against a
  written-down list at the place the value is used, not only in `run.py check`. The framework's own
  default, if this line were deleted, is `gemini-3.5-flash` — which the provider's models page lists
  as **Stable** and describes as its legacy Flash model. So an unpinned agent here is not broken and
  not experimental. It is old, which is the quietest of the three.

  > **Recap — a floor is not a pin, and an alias is a floor.** A name that stands for *whichever
  > model currently holds a role* — anything ending `-latest`, and a framework default that moves
  > between releases — hands the choice to whichever machine resolves it, on whichever day. An
  > application pins; a library takes ranges. `models.require_pinned` refuses an alias by name.
  > Self-contained version: `PRIMER.md` §1.
  > Deep version, if you have the full plan:
  > `days/01-ask-desk/day-06-first-adk-agent/parts/01-the-brief/1.2-the-model-nobody-chose.md`
- `tools=[toolset if toolset is not None else mcp.over_stdio()]` — **the one line that differs in
  shape from P01, and the reason this day exists.** P01 wrote `tools=[tools.search_notes,
  tools.fetch_note, tools.check_service_status]`: three plain functions, three declarations derived
  from three docstrings, one list, decided when the file was saved. This is a list of **one** object,
  and that object is not a tool. It is a thing that will be *asked* for tools, once, when the runner
  first needs them. A reader who wants to know what this agent can do cannot find out by reading this
  file — and that is not a defect in the file, it is the shape of the system.
- `def run_config(budget: Budget | None = None) -> RunConfig:` — **two bounds exist and they answer
  different questions.** ADK's `RunConfig.max_llm_calls` defaults to `500`: a runaway ceiling, sized
  so no legitimate run ever trips it. "What may one question cost?" is a different question, and this
  project answers it in `parts_counter/util/budget.py` — day 11's file — with `max_per_turn = 6`.
  This line is where the second answer overrides the first, and setting both from one constant means
  there is one place to change and no chance of the two disagreeing.

  > **Recap — the framework's bound is not your bound.** ADK does bound the loop, at 500, overridable
  > from outside the repository by the `ADK_MAX_LLM_CALLS` environment variable, and enforced by
  > raising `LlmCallsLimitExceededError`. A value of zero or less disables it, which reads like the
  > opposite of what it does. 500 stops a runaway; it does not budget a question.
  > Self-contained version: `PRIMER.md` §5.
  > Deep version, if you have the full plan:
  > `days/01-ask-desk/day-07-functiontool-what-adk-does/parts/02-what-it-reads-that-you-did-not-mean-to-write/2.2-what-it-did-and-what-it-did-not.md`
- `(budget or Budget()).max_per_turn` — the number is read off the budget object rather than
  hard-coded, so a test can hand in a `Budget(max_per_turn=1)` and get an agent that is allowed
  exactly one model call. `or` rather than `is None` is safe here only because a `Budget` instance is
  always truthy; on an `int` parameter it would turn `0` into the default, which is the bug this
  idiom is famous for.
- `session_service` on `Runner` — **ADK's one required keyword argument.** Everything else, `agent`
  included, defaults to `None`, so a misspelt keyword is a missing argument and not a `TypeError`.
  That asymmetry is deliberate on ADK's part: an agent with nowhere to keep a conversation forgets
  between turns.
- `async def ask(...)` — `keys.require("GOOGLE_API_KEY")` **before** `export_key()`, and both before
  anything is built. The order is the point: `require` is this project's own three-state check and
  produces this project's own sentence about a key that is absent or empty; `export_key` then hands
  the value to a library that would otherwise produce a confusing one. Check first, bridge second.
- `run_config=run_config()` passed into `run_async` — **the bound is not inherited, it is handed
  over per run.** Omit this keyword and the run silently uses ADK's 500, which is the same class of
  mistake as omitting `model=`: nothing fails, and a number nobody in this project chose is now in
  charge.
- `event.is_final_response() and event.content and event.content.parts` — a filter, not a summary.
  Everything else in the stream is the middle of the work, and today it is thrown away on purpose;
  `days/01-ask-desk/day-08-events-streaming/` is where events are read rather than skipped.

Here is the whole file's observable state, with no key and nothing contacted:

```console
$ uv run --frozen python -c "
import warnings; warnings.filterwarnings('ignore')
from parts_counter.agent import build_counter, run_config
a = build_counter()
print('agent    :', a.name, '| model:', a.model)
print('tools    :', [type(t).__name__ for t in a.tools])
print('bound    :', run_config().max_llm_calls)
"
agent    : parts_counter | model: gemini-3.8-flash
tools    : ['McpToolset']
bound    : 6
```

*(Run on this machine on 2026-09-10.)* Three lines, and each one is a claim that could have been
wrong. The model is the pinned ID and not `gemini-3.5-flash`, so the registry really is on the path.
`a.tools` holds **one** object and its class is `McpToolset` — not four `FunctionTool`s, which is what
the same probe printed in P01 — so the substitution really happened. And the bound is `6`, this
project's number, not `500`.

**And notice what did not happen.** `build_counter()` returned. Nothing was launched, nothing was
dialled, no tool list was fetched, and the four names that part 1.2 printed are nowhere in this
output. The agent is holding a promise. Part 2.2 is what happens when the promise is not kept.

### The same agent, twice, one line apart

| The brief | P01 `ask_desk/agent.py` | P02 `parts_counter/agent.py` | Same? |
| --- | --- | --- | --- |
| `name=` | `"ask_desk"` | `"parts_counter"` | same shape — an identifier, validated by pydantic |
| `model=` | `models.require_pinned(models.ANSWERING)` | identical | **same line** |
| `description=` | one sentence, for a future second agent | one sentence | same shape |
| `instruction=` | `loop.SYSTEM_INSTRUCTION`, a module constant | `INSTRUCTION`, a module constant | same shape |
| `tools=` | three plain functions | **one `McpToolset`** | **the difference** |
| the bound | `RunConfig(max_llm_calls=...)` from a project constant | from `Budget.max_per_turn` | same shape |
| the key bridge | `export_key()` | identical, shorter docstring | **same line** |
| `session_service` | required keyword on `Runner` | identical | **same line** |
| where the agent is built | module scope **and** a factory | factory only | P02 dropped the module-level one |
| when a bad config is caught | at **import** | at the **first `build_counter()`** | moved, on purpose |

The last two rows are the ones that will matter tomorrow, when this agent goes in a container and the
question "did it start correctly?" has to be answered by a process that is not you.

## When it breaks

Delete `run_config=run_config()` from the `run_async` call — or, much more commonly, never write it,
because a first draft of `ask` almost never passes a `RunConfig` at all. Nothing raises. The agent
answers. The bound in force is ADK's, and it is not the number in `budget.py`:

```console
$ uv run --frozen python -W ignore -c "
from google.adk.agents.run_config import RunConfig
from parts_counter.agent import run_config
print('ADK default      :', RunConfig().max_llm_calls)
print('this project sets:', run_config().max_llm_calls)
"
ADK default      : 500
this project sets: 6
```

*(Run on this machine on 2026-09-10.)* Somebody shipped that on a Friday. What they saw was nothing
at all, for weeks, until one badly-phrased question sent the model round a tool loop and the run cost
eighty-odd calls before it settled — every one of them a real request against a quota nobody can see.
The smallest fix is one keyword argument. The lesson underneath it is that **a default is a decision
somebody else made**, and the only defaults worth inheriting are the ones you have read.

## In production

**What a senior writes instead.** They do not let `build_counter()` construct its own toolset. The
parameter loses its default and the caller becomes responsible for the boundary — one toolset,
created once at process start, shared by every agent and closed on shutdown — because a factory that
quietly launches a subprocess is a factory nobody can call in a loop. They also give the agent a
`tool_filter`, so the counter's read-only path cannot reach `adjust_stock` at all, rather than
relying on the third sentence of `INSTRUCTION` to hold that line.

**What degrades at scale.** Two numbers, both from this project. `max_llm_calls=6` bounds a single
turn, and the cast here is **one** agent, so a question that needs one lookup costs at least two
provider calls and the ceiling allows six. Multiply that by the toolset: with `build_counter()`
constructing its own `over_stdio` toolset, a hundred questions is a hundred launched interpreters at
roughly **1.1 seconds each** — about two minutes of `subprocess` before any of them has spoken to a
model. The framework's own default would have allowed **500** calls for one of those questions.

**The review comment.** "`build_counter`'s default toolset has to go. Every call forks a server and
nothing reaps it, and `build_runner` calls `build_counter()` with no argument, so we fork one there
too. Make it a required parameter and wire it once in `run.py`. Separately, please pass `run_config`
in `ask` — it is there, and the day it is missing we inherit 500."

**The interview question.** "An agent's `tools` list has one object in it and that object is a
toolset. Your monitoring says the agent is up and healthy. Name two states the system can be in that
this health signal cannot distinguish, and say what you would add to tell them apart."
