## One-line answer

This project carries its own copy of the code that reads a secret — not an import of the one P00
already wrote — because the rule that lets any one of forty folders be picked up and built alone is
that no line it needs lives outside it, and a duplicated file is a cheaper price for that than the
dependency it removes.

## The idea

Picture a room of forty writing desks, each belonging to a different correspondence. Somebody wheels
one of them out to a bare room and shuts the door behind you. Whatever is in its drawers is what you
have. If the paper is in this desk, you can write. If the stamps are in this desk, you can post. If
one drawer holds a note reading *stamps are in desk 3*, then this desk does not write letters — it
writes a request for stamps, and there is nobody in the room to hand it to.

That is the shape of the whole curriculum, and it is why this part exists at all. Forty projects,
each one a folder somebody can take away on its own. This project needs to read a secret out of a
`.env` file, and the code that does it was already written, carefully and well, two days ago, in a
different folder. The obvious move — import it — is the move that turns thirty-nine of these
projects into requests for stamps.

Say it as the rule the plan states, because it is short. **Every line of code a project needs
appears in full, at its real path, inside that project's own documents.** No import from another
project. No "copy this from P00". A day document that says `from foundry.keys import require` is not
printing code; it is printing a pointer to a file the reader does not have, and the reader finds
that out at the moment they run it, which is after they have believed the document.

Now the honest part, because this rule has a price and pretending otherwise is how rules get
quietly dropped. The price is duplication. `ask_desk/util/keys.py` and the file P00 wrote are the
same idea, and improving one will not improve the other. They have separate lives from here on. That
is real, it is paid deliberately, and there are two things that make it the right side of the trade.

The first is that the alternative is not "one file instead of forty". The alternative is one file
plus a shared package, plus that package's version, plus the question of which projects are on which
version of it, plus an install step in every project's setup, plus the day a change made for project
twenty-two breaks project four. Shared code is not free; it is a dependency, and a dependency is a
relationship you have to maintain. Forty copies of eighty lines have no relationship at all.

The second is that this is a *teaching* repository, and the thing being taught is the system, not
the library. A reader who takes one folder to a new machine and builds it from its own documents has
learned something a reader who ran `pip install our_kit` has not. The duplication buys that, and it
is the only thing that buys it.

What this part does **not** re-teach is the file itself. The process environment against the file,
the three states a key can be in, and the one no local check can settle were taught in full on day
3, and the pointer at the end of the walkthrough is where that lives. Read the table below for what
each line prevents; read the pointer if you want the argument behind it.

## The mechanism

`projects/01-ask-desk/ask_desk/util/keys.py`, whole file. It is this project's own, it imports
nothing that is not in the standard library, and nothing above this folder is on its import path:

```python
# ask_desk/util/keys.py
"""Read this project's secrets, and refuse — by name — when one of them is not wired.

Nothing loads a `.env` file for you. This project carries its own reader, as every project in this
curriculum does, because a project that borrowed one from a sibling would not run alone.

Recap depth. The deep version of this idea — the process environment against the file, the three
states of a key, and the one no local check can settle — is P00 Foundry day 3. `PRIMER.md` §1 has
the self-contained version, and you do not need to have read either to use this file.
"""

from __future__ import annotations

import os
from pathlib import Path

# Anchored to this file, not to the working directory, so the answer does not depend on where the
# shell was standing. ask_desk/util/keys.py -> ask_desk/util -> ask_desk -> the project root.
PROJECT_ROOT = Path(__file__).resolve().parent.parent.parent
ENV_FILE = PROJECT_ROOT / ".env"
EXAMPLE_FILE = PROJECT_ROOT / ".env.example"


class MissingKey(RuntimeError):
    """Raised with the name of the key, where it was looked for, and what to do about it."""


def read_env_file(path: Path | None = None) -> dict[str, str]:
    """Parse `KEY=value` lines into a dict. Nothing is exported; the caller decides."""
    path = ENV_FILE if path is None else path
    values: dict[str, str] = {}
    if not path.exists():
        return values
    for line in path.read_text(encoding="utf-8").splitlines():
        line = line.strip()
        if not line or line.startswith("#") or "=" not in line:
            continue
        name, _, value = line.partition("=")
        values[name.strip()] = value.strip().strip('"').strip("'")
    return values


def names_this_project_reads(path: Path | None = None) -> list[str]:
    """Every key name `.env.example` declares. The committed file is the list of names."""
    return sorted(read_env_file(EXAMPLE_FILE if path is None else path))


def get(name: str) -> str | None:
    """The process environment wins; the file is the fallback. Absent is `None`, never `''`."""
    from_process = os.environ.get(name)
    if from_process is not None:
        return from_process
    return read_env_file().get(name)


def require(name: str) -> str:
    """Return the value, or raise `MissingKey` naming the key and the file it belongs in."""
    value = get(name)
    if value is None:
        raise MissingKey(
            f"{name} is not set. Add a line `{name}=...` to {ENV_FILE}, or export it in this "
            f"shell. `.env.example` lists every name this project reads."
        )
    if not value.strip():
        raise MissingKey(
            f"{name} is present in {ENV_FILE.name} with an empty value. An empty string is a "
            f"value, so a check written as `if not os.environ.get(...)` cannot tell this apart "
            f"from the key being absent, and will tell you it is not set."
        )
    return value
```

**Line by line:**

Recap depth — this code is taught in full on day 3, and the table gives one row per line that
carries a decision, each naming the failure that line exists to prevent.

| Line | What it does, and the failure it prevents |
| --- | --- |
| `PROJECT_ROOT = Path(__file__).resolve().parent.parent.parent` | Anchors every path to **this file** rather than to the working directory. Without it the same program finds `.env` when run from inside the project and silently finds nothing when run from a directory above it — and "silently finds nothing" reads exactly like "the key is not set". |
| `.resolve()` before walking up | Turns a relative or symlinked path into a real absolute one before counting parents. Without it, a project invoked through a symlink counts parents in the wrong tree and lands on a `.env` belonging to something else. |
| `ENV_FILE` and `EXAMPLE_FILE` as module constants | One name for each file, so the reader and the error messages cannot disagree about which file was consulted. An error naming the wrong file sends somebody to edit a file that was never read. |
| `class MissingKey(RuntimeError)` | A type a caller can catch on its own. `run.py` catches exactly this to print a wiring problem as a wiring problem, instead of letting it arrive as a traceback that looks like a code bug. |
| `path: Path \| None = None`, resolved in the body | A default argument is evaluated once, at `def` time. Written the obvious way as `path: Path = ENV_FILE`, the module-level value is frozen into the function object and reassigning `keys.ENV_FILE` afterwards changes nothing — which makes the file untestable and produced a real wrong transcript on day 3. |
| `if not path.exists(): return values` | An absent `.env` is an empty dict, not an exception. Deployment targets inject secrets as environment variables and never write this file; raising here would make every container fail on a file it correctly does not have. |
| `line.startswith("#") or "=" not in line` | Comments and blank lines are skipped rather than parsed into garbage keys. Without it a commented-out line becomes a key named `# GOOGLE_API_KEY`, which nothing will ever look up and nothing will ever report. |
| `name, _, value = line.partition("=")` | Splits on the **first** `=` only and always returns three parts. `split("=")` breaks on any value containing `=` — which base64 padding produces constantly — either by raising or by silently truncating the secret to its first segment. |
| `.strip('"').strip("'")` | Removes wrapping quotes that shells tolerate and this parser would otherwise keep. Without it the key travels with its quotation marks attached and the provider rejects a credential that looks correct in the file. |
| `names_this_project_reads` reading `.env.example` | The committed example file is the **list of names**, so the check knows what to look for without a second list to keep in step. Two lists drift; one cannot. |
| `get`: process environment first, file second | Every deployment target injects secrets as environment variables. If the file won, your machine would behave unlike every place the code actually runs, and the difference would show up first in production. |
| `if from_process is not None` rather than `if from_process` | Distinguishes an exported-but-empty variable from an unset one. The truthiness test collapses them, and then a deliberately emptied variable silently falls through to the file — using a value somebody thought they had removed. |
| `require`: `value is None` and `not value.strip()` as **two** branches | Absent and present-but-empty are two situations needing two different sentences. One condition covering both forces a message vague enough to tell somebody a key is not set while they are looking at the line that sets it. |
| Both messages naming `ENV_FILE` and pointing at `.env.example` | The error carries the fix. A reader gets the file to edit and the list of names without having to open the source of the check that refused them. |
| `require` **returns the value** | The check and the use are one expression, so no call site can validate and then read from somewhere else. A validator you must remember to call separately is one that gets skipped on the path added in a hurry. |

> **Recap — reading a key, and the three ways one can be wrong.** Nothing loads a `.env` for you;
> the process environment wins and the file is the fallback, because that is the way round every
> deployment target actually works. A key can be **absent** (`None`), **present and empty** (`''`,
> and usually a CI secret that was never populated), or **present, non-empty and not accepted** —
> and nothing running on your machine can decide the third, because a credential is valid only
> because a server holding the other half says so. Self-contained version: `PRIMER.md` §1.
> Deep version, if you have the full plan:
> `days/00-foundry/day-03-keys-pinning-refusing-check/parts/01-the-key/1.2-three-states-and-the-one-you-cannot-check.md`

The claim this part is actually making is about *location*, so here is the evidence for it. Every
path this module computes lands inside this project folder and nowhere above it:

**Line by line:**

- `PROJECT_ROOT` stops at `projects/01-ask-desk`. Three `.parent` calls from
  `ask_desk/util/keys.py` and not one more, so the module cannot reach a `.env` belonging to a
  sibling project or to the repository above it. Move this folder anywhere and the printed path
  moves with it.
- `ENV_FILE` is that root plus `.env` — the file `SETUP.md` step 3 tells a stranger to create, and
  the file every `MissingKey` message will name. One value, printed here, used in the error, so the
  document and the error cannot drift.
- `names_this_project_reads()` returns `['GOOGLE_API_KEY']` and it read that from the committed
  `.env.example`, not from a list in the source. One name today; the day this project needs a second
  secret, adding it to `.env.example` is the whole change and the check picks it up.
- Nothing in this transcript needed a key, a network or a framework. That is the point of anchoring
  by path rather than by process state: it is answerable offline.

*Observed on this machine on 2026-09-09, uv 0.12.3, CPython 3.12.12.*

## When it breaks

The failure this rule exists to prevent has one error message, and here it is. P00 keeps its key
reader as a top-level `keys.py` beside its driver, so `import keys` is how its day documents spell
it. Type that inside this project — as somebody copying a snippet from two days ago would — and:

```console
$ cd projects/01-ask-desk
$ uv run --frozen python -c "import keys"
Traceback (most recent call last):
  File "<string>", line 1, in <module>
ModuleNotFoundError: No module named 'keys'
```

Somebody shipped a day document with that line in it, and the reader who had only this folder got
exactly this at the first command they typed — not a wrong answer, not a bad key, just a file that
is not there and never was. The smallest fix is the one this project already makes: the reader lives
at `ask_desk/util/keys.py`, inside the package, and is imported as `from ask_desk.util import keys`.
The general fix is the rule — if a project needs a line, that project's documents print it.

## In production

**What a senior writes instead.** For a real service they usually do the opposite of this: one
internal library, versioned, released, imported by everything — because the cost being optimised
there is *maintenance across a fleet*, not portability of a single folder. What they do share with
this file is the shape at the boundary: configuration is read in one place, validated once at
process start, and the process refuses to serve if it is not wired — a `Settings` object built with
`pydantic-settings` or one `load_config()` called from `main`. What nobody senior does is scatter
`os.environ["GOOGLE_API_KEY"]` through the call sites, because then the failure surfaces wherever
the request happened to reach first.

**What degrades at scale.** The number is **thirty-nine**. Forty projects each carry their own copy
of this idea, so a bug found here is fixed in one of them and left standing in thirty-nine — and
nothing in any of those thirty-nine will mention that a fix exists. That is the real, measurable
cost of independence, and it is why the curriculum pays it only for small, finished, rarely-changing
files. The moment a duplicated file starts changing every week, the trade has flipped and the honest
move is to say so rather than to keep copying.

**The review comment.** "This module imports `keys` from the repository root. That works on your
machine because you run from the root, and it will not work for anyone who takes this folder on its
own — which is the one thing this project promises. Please move the reader into
`ask_desk/util/keys.py` and import it as a package module, and add a check that the project's
imports all resolve inside the project."

**The interview question.** "You have a shared internal library used by thirty services. A security
fix lands in it. Walk me through what has to happen before every one of those thirty is actually
running the fixed version, and then tell me what would have to happen instead if each service had
vendored its own copy — and which of the two you would rather be responsible for."
