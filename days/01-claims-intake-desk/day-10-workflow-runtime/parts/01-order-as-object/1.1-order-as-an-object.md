## One-line answer

A workflow agent is the order of the work turned into a value — nodes and the edges between them,
some of them models and some of them ordinary code — and the thing you get for it is that the order
can be printed, tested and changed without reading the function that used to contain it.

## The idea

Ask a supervisor how a notification is handled and you get a procedure: it is read, the policy is
checked, the rules are applied, and if it cannot be fast-tracked a letter goes out. They can say
that without opening anyone's drawer, and they can hand it to a new starter on one sheet of paper.

Ask the same question of day 9's desk and the honest answer is *read `run_queue`*.

The steps were all there and they were all correct. What was missing is that **nothing but a person
could see them**. No log line could say which stage a claim was in. No test could assert that the
reading happens before the rules. Nothing could ask how many stages there are, because there was no
"there" — the order lived in the order of statements in a function, which is the one form of
knowledge a program cannot inspect about itself.

A **workflow agent** fixes that by making the order a value. It is an agent whose job is not to
answer anything but to **run other agents in a stated arrangement**: one after another, all at once,
or repeatedly until something says stop. The three arrangements are `SequentialAgent`,
`ParallelAgent` and `LoopAgent`, and this project ends today using all three.

The stage that matters most is the one that surprises people: **a node does not have to be a
model.** A workflow's children are agents, and an agent is anything that can be run and yield
events, so a piece of ordinary Python that reads state, decides something and writes state back is a
first-class node. In this desk the node that reaches the verdict is exactly that — the only node in
the triage workflow that decides anything is the one with no model behind it.

## The mechanism

The whole file, at `claims_desk/workflow.py`:

```python
"""The order this desk works in, written down as an object instead of as a `for` loop.

Day 9 called two agents in a fixed order in ordinary Python. That is readable and it cannot be
inspected: nothing can ask that code what the stages are, how many there are, or which of them
could run at the same time. This file makes the order a value.

Three workflows. Two of them the desk uses and one it measured:

- **`triage()`** is a `SequentialAgent`: the classifier reads, then a node that is code applies day
  2's rules to what it said. Two stages, and only the first of them costs anything.
- **`correspondence()`** is a `LoopAgent`: a draft is written, the house style is checked, and a
  draft that fails is written again with the objection attached. It is bounded by
  `max_iterations`, because a repair loop with no bound is a bill with no bound.
- **`morning()`** is a `ParallelAgent` built from the queue: every notification triaged at once, in
  one invocation, into one shared state. It runs. Whether this desk should use it is a question of
  cost rather than of taste, and day 10 part 3.1 has the numbers.

**A workflow agent has no conditional edge.** It runs its children; it has no `if`. Whether a claim
needs a letter at all is decided in `claims_desk/desk.py`, in Python, where it can be read — and the
materials for that letter are fetched there too, so a claim the boundary refuses costs no draft.
"""

from __future__ import annotations

import json
import re
from collections.abc import AsyncGenerator
from typing import Any

from google.adk.agents import Agent, BaseAgent, LoopAgent, ParallelAgent, SequentialAgent
from google.adk.agents.invocation_context import InvocationContext
from google.adk.events import Event, EventActions

from claims_desk import models, sessions
from claims_desk.agents import classifier, letter_writer
from claims_desk.domain import Cover, Notification, assess
from claims_desk.scripted import ScriptedLetterWriter
from claims_desk.util.budget import Budget
from claims_desk.util.logging import log

#: The extra paragraph the loop's writer carries and day 9's writer did not. `{feedback?}` is the
#: framework's own substitution: the key is read out of session state, and the `?` means an absent
#: key leaves an empty string rather than raising. It is how the checker talks to the writer.
FEEDBACK_CLAUSE = "\n{feedback?}\n"

#: What the house style refuses. A digit in an outgoing letter is a figure this desk never gave the
#: writer and cannot stand behind. The check is for digits rather than for currency symbols, so
#: "2500" and "GBP 2,500" are both caught and "two thousand" is not — say what a check misses.
FORBIDDEN_IN_A_LETTER = re.compile(r"\d")

#: What the checker writes into state when it refuses a draft. It is an instruction to the writer
#: rather than a description of the fault, because the writer is being asked to act on it.
OBJECTION = "The previous draft named an amount. Write it again with no figure of any kind in it."


def body_of(draft: str, claim: str) -> str:
    """The draft with the claim reference removed — the one number a letter is required to carry."""
    return draft.replace(claim, "") if claim else draft


class Rules(BaseAgent):
    """A node that is code. It spends no model call and it is the only node that decides anything.

    It reads what the classifier said and what the boundary returned, parses the one and applies
    day 2's rules to both, and writes the verdict back into state. The parsing lives here because
    this is the node that has to cope with a model that answered badly.
    """

    notification: Notification
    cover: Cover | None = None
    reading_key: str = "reading"
    verdict_key: str = "outcome"

    async def _run_async_impl(self, ctx: InvocationContext) -> AsyncGenerator[Event, None]:
        state = ctx.session.state
        read, error = parse_reading(str(state.get(self.reading_key, "")))
        cover = self.cover
        if error:
            log("workflow.rules_blocked", claim=self.notification.id, detail=error)
            yield Event(
                author=self.name,
                invocation_id=ctx.invocation_id,
                actions=EventActions(
                    state_delta={self.verdict_key: "", "reason": "", "error": error}
                ),
            )
            return
        outcome, reason = assess(
            self.notification, cover, read["loss_type"], bool(read["injury_reported"])
        )
        log(
            "workflow.rules",
            claim=self.notification.id,
            loss_type=read["loss_type"],
            outcome=outcome.value,
            reason=reason.value if reason else None,
        )
        yield Event(
            author=self.name,
            invocation_id=ctx.invocation_id,
            actions=EventActions(
                state_delta={
                    self.verdict_key: outcome.value,
                    "reason": reason.value if reason else "",
                    "error": "",
                }
            ),
        )


def parse_reading(text: str) -> tuple[dict[str, Any], str]:
    """The classifier's answer as an object, or an empty object and the reason it is not one.

    Moved here from day 7's `classify` when the orchestration became a workflow: the node that
    needs the fields is the node that has to survive not getting them. **It never guesses on the
    model's behalf** — an unparseable answer is reported, not repaired.
    """
    try:
        parsed = json.loads(text)
    except json.JSONDecodeError:
        return {}, "the classifier did not answer with an object"
    if "loss_type" not in parsed or "injury_reported" not in parsed:
        return {}, "the classifier's object is missing a field"
    return parsed, ""


def triage(notification: Notification, cover: Cover | None) -> SequentialAgent:
    """Read the description, then apply the rules to what was read. Two stages, one of them code.

    The policy has already been fetched by the caller, because day 7's ordering is worth keeping:
    everything decidable from fields is decided before anything is asked of a model. A workflow
    cannot express that ordering — it has no conditional edge — so the cheap half stays in Python
    and the workflow is what runs once the desk has decided a reading is needed.
    """
    return SequentialAgent(
        name="triage",
        description="Reaches a verdict on one notification.",
        sub_agents=[
            classifier.build(output_key="reading"),
            Rules(
                name="rules",
                description="Applies the desk's rules to what was read.",
                notification=notification,
                cover=cover,
            ),
        ],
    )


def morning(notifications: list[Notification]) -> ParallelAgent:
    """Every notification in the queue, triaged at the same time, in one invocation.

    Built dynamically from the queue rather than declared, because the queue is not known until it
    is read. **Every node writes into one shared state**, so every key is named after the claim it
    belongs to; part 3.1 is what happens when they are not.
    """
    return ParallelAgent(
        name="morning",
        description="The whole queue at once.",
        sub_agents=[
            SequentialAgent(
                name=f"triage_{slug(note.id)}",
                description=f"Triage for {note.id}.",
                sub_agents=[
                    classifier.build(output_key=f"reading_{slug(note.id)}"),
                    Rules(
                        name=f"rules_{slug(note.id)}",
                        description=f"Rules for {note.id}.",
                        notification=note,
                        reading_key=f"reading_{slug(note.id)}",
                        verdict_key=f"outcome_{slug(note.id)}",
                    ),
                ],
            )
            for note in notifications
        ],
    )


def slug(claim_id: str) -> str:
    """A claim reference as a name a framework will accept: identifiers, not references."""
    return claim_id.replace("-", "_")


class HouseStyle(BaseAgent):
    """A node that is code, inside a loop. It ends the loop or it writes the objection.

    `escalate` is how a node inside a `LoopAgent` says *stop*. Without it the loop runs to
    `max_iterations` every time, including when the first draft was already correct.
    """

    async def _run_async_impl(self, ctx: InvocationContext) -> AsyncGenerator[Event, None]:
        state = ctx.session.state
        draft = str(state.get("letter", ""))
        claim = str(state.get("claim", ""))
        offending = FORBIDDEN_IN_A_LETTER.search(body_of(draft, claim))
        accepted = draft.strip() != "" and offending is None
        log(
            "workflow.house_style",
            claim=claim,
            accepted=accepted,
            found=offending.group(0) if offending else None,
            chars=len(draft),
        )
        yield Event(
            author=self.name,
            invocation_id=ctx.invocation_id,
            actions=EventActions(
                escalate=accepted,
                state_delta={"feedback": "" if accepted else OBJECTION},
            ),
        )


def correspondence() -> LoopAgent:
    """Draft, check, and draft again if the house style refuses — at most three times.

    The bound is the point. A repair loop whose writer cannot use the objection produces the same
    draft every time; `max_iterations` is what turns that from an unbounded bill into a bounded one.
    """
    writer = Agent(
        name="letter_writer",
        model=models.pinned(ScriptedLetterWriter()),
        description="Writes a deficiency letter from a claim reference and one reason.",
        instruction=letter_writer.INSTRUCTION + FEEDBACK_CLAUSE,
        output_key="letter",
    )
    return LoopAgent(
        name="correspondence",
        description="Writes a letter and rewrites it until it passes the house style.",
        sub_agents=[
            writer,
            HouseStyle(name="house_style", description="Refuses a draft that names a figure."),
        ],
        max_iterations=3,
    )


def stages(agent: BaseAgent) -> list[dict[str, Any]]:
    """The workflow as data: every node, its kind and how deep it sits.

    This is the thing a `for` loop cannot give you. It exists so that a person, a log line and a
    test can all ask the same question — *what runs, in what order* — of the object rather than of
    the source code.
    """
    out: list[dict[str, Any]] = []

    def walk(node: BaseAgent, depth: int) -> None:
        out.append({"name": node.name, "kind": type(node).__name__, "depth": depth})
        for child in node.sub_agents:
            walk(child, depth + 1)

    walk(agent, 0)
    return out


def model_nodes(agent: BaseAgent) -> set[str]:
    """The names of the nodes in a workflow that actually call a model."""
    return {stage["name"] for stage in stages(agent) if stage["kind"] == "LlmAgent"}


def charge(budget: Budget, agent: BaseAgent, events: list) -> int:
    """Charge the budget for the model calls a workflow made, counted from its events.

    Counted **afterwards, by author**, which is the honest shape of it: a workflow does not tell
    its caller how many calls it intends to make, and the framework does not hand the number over.
    It counts events rather than calls, so a streaming provider would count many where this
    stand-in counts one — day 11 replaces this with a callback that counts the call itself.
    """
    names = model_nodes(agent)
    spent = 0
    for event in events:
        if event.author in names and event.partial is not True:
            budget.spend(event.author)
            spent += 1
    return spent


async def run_triage(
    notification: Notification, cover: Cover | None, budget: Budget
) -> dict[str, Any]:
    """Run the triage workflow for one notification and return what it decided.

    `max_calls` is the framework's own hard bound and it is what actually stops a runaway. The
    budget is this desk's record of what happened, and it is written after the fact.
    """
    agent = triage(notification, cover)
    _answer, events = await sessions.turn(
        agent,
        notification.id,
        notification.description,
        state={"claim": notification.id},
        thread="triage",
        max_calls=budget.remaining,
    )
    spent = charge(budget, agent, events)
    stored = await sessions.stored(notification.id, "triage")
    state = stored.state if stored else {}
    log(
        "workflow.triage",
        claim=notification.id,
        events=len(events),
        calls=spent,
        outcome=state.get("outcome"),
        error=state.get("error") or None,
    )
    return {
        "outcome": state.get("outcome", ""),
        "reason": state.get("reason", "") or None,
        "error": state.get("error", ""),
    }


async def run_correspondence(claim_id: str, reason: str, needed: str, budget: Budget) -> str:
    """Run the letter loop for one claim and return the accepted draft, or an empty string."""
    agent = correspondence()
    question = (
        f"Claim: {claim_id}\n"
        f"Reason: {reason}\n"
        f"The policyholder must send or confirm: {needed}"
    )
    _answer, events = await sessions.turn(
        agent,
        claim_id,
        question,
        state={"claim": claim_id},
        thread="correspondence",
        max_calls=budget.remaining,
    )
    drafts = charge(budget, agent, events)
    stored = await sessions.stored(claim_id, "correspondence")
    draft = str((stored.state if stored else {}).get("letter", ""))
    clean = FORBIDDEN_IN_A_LETTER.search(body_of(draft, claim_id)) is None
    accepted = draft.strip() != "" and clean
    log(
        "workflow.correspondence",
        claim=claim_id,
        reason=reason,
        drafts=drafts,
        accepted=accepted,
        chars=len(draft),
    )
    return draft.strip() if accepted else ""
```

**Line by line:**

- **The module docstring names all three workflows and says which the desk uses**, including the one
  it does not. A file that ships an unused arrangement without saying why is a file that gets a
  well-meaning cleanup commit.
- **"A workflow agent has no conditional edge"** — the sentence that will save the most time. The
  framework offers sequence, parallelism and repetition, and it offers no `if`. Everything
  conditional in this desk stays in Python, and the docstring says where.
- `from google.adk.agents import Agent, BaseAgent, LoopAgent, ParallelAgent, SequentialAgent` —
  **five names and only one of them is what day 7 meant by "agent"**. The other four are structure.
- `FEEDBACK_CLAUSE = "\n{feedback?}\n"` — **the framework substitutes `{key}` in an instruction from
  session state**, and `?` makes the key optional. Without the `?`, the first pass through the loop
  fails outright because no checker has written `feedback` yet.
- `FORBIDDEN_IN_A_LETTER = re.compile(r"\d")` — **one digit is enough.** The comment names what the
  rule misses, which is "two thousand", because a check that does not say what it misses gets
  trusted for what it does not do.
- `OBJECTION = "The previous draft named an amount. Write it again with no figure of any kind in
  it."` — **an instruction, not a diagnosis.** "Contains a figure" describes the fault; this tells
  the writer what to do about it, and the writer is the audience.
- `def body_of(draft, claim)` — **the claim reference is the one number a letter must contain**, so
  it is removed before the digit scan. Written as a function rather than inline because two places
  need exactly the same definition of "the body", and two spellings of that is a bug that only shows
  up on letters.
- `class Rules(BaseAgent)` — **the node that is code.** It subclasses `BaseAgent` rather than
  `Agent`, has no model and no instruction, and the workflow cannot tell the difference.
- `notification: Notification` and `cover: Cover | None = None` — **fields, not constructor
  arguments.** `BaseAgent` is a pydantic model, so a node's dependencies are declared as typed
  fields and passed by keyword when the node is built.
- `reading_key: str = "reading"` and `verdict_key: str = "outcome"` — **the state keys this node
  reads and writes, as parameters.** One claim at a time does not need them; `morning()` does,
  because twelve nodes sharing one state cannot all write `outcome`.
- `async def _run_async_impl(self, ctx: InvocationContext) -> AsyncGenerator[Event, None]` — **the
  one method a custom node implements.** Underscore-prefixed because the framework calls it, not
  you; you call `run_async`, which wraps it.
- `state = ctx.session.state` — **the invocation context carries the session**, so a node reads what
  earlier nodes wrote without anything being passed to it. That is the edge between two nodes: not
  an argument, a shared dictionary.
- `yield Event(author=self.name, invocation_id=ctx.invocation_id, actions=EventActions(...))` —
  **a node communicates by yielding events**, exactly as a model-backed agent does. `author` is what
  every log and every test will match on, and `invocation_id` is what ties this event to the run.
- `state_delta={self.verdict_key: outcome.value, ...}` — **state is changed by declaring a delta on
  an event, not by assigning to the dictionary.** Assigning would change the object in memory and
  leave nothing in the session's record; the delta is what the service persists.
- `"error": ""` in the success branch — **the key is always written.** A state that carries `error`
  only when there is one makes every reader write `state.get("error")` and one of them will forget.
- `return` after the error event — **an early exit inside an async generator.** The node has yielded
  its one event and has nothing further to say; the sequence continues to the next node regardless,
  because a `SequentialAgent` has no way to be told to stop.
- `def parse_reading(text) -> tuple[dict, str]` — **the answer and the complaint**, in that order,
  and never both filled in. Day 7's version returned `{"error": ...}` inside the same dictionary as
  the fields, which meant every caller had to check for a key that is not a field.
- `except json.JSONDecodeError:` — **the only exception caught**, and the message says what the
  desk actually needs to know: it did not answer with an object. Not the parser's message; the
  desk's.
- `def triage(notification, cover) -> SequentialAgent:` — **a function that returns a workflow**,
  not a module-level constant, because two of its nodes need this claim's notification and cover.
- `classifier.build(output_key="reading")` — **day 7's agent, unchanged except for where its answer
  goes.** That is the whole adaptation an existing agent needs to become a workflow node.
- **The docstring on `triage` argues for what is *not* in the workflow**: day 7's ordering, where
  everything decidable from fields is decided before a model is asked. A workflow cannot express it,
  so it stays in Python, and the reason is written down at the boundary between the two.
- `def morning(notifications) -> ParallelAgent:` — **a workflow built from data.** The queue is not
  known until it is read, so the arrangement is constructed rather than declared. This is what makes
  a workflow a value rather than a shape.
- `name=f"triage_{slug(note.id)}"` — **every node in one workflow needs a distinct name**, so the
  claim reference goes into it. `slug` turns `FNOL-4471` into `FNOL_4471` because names are
  identifiers.
- `reading_key=f"reading_{slug(note.id)}"` — **the state keys are namespaced by claim**, which is
  the whole reason those fields exist. Part 3.1 runs the version where they are not.
- `class HouseStyle(BaseAgent)` — the second code node, and the one with a job the framework
  understands: `escalate`.
- `escalate=accepted` — **the loop ends when a node says so.** Not by returning a value, not by
  raising: by setting a flag on an event that the `LoopAgent` reads as each event goes past.
- `state_delta={"feedback": "" if accepted else OBJECTION}` — **written on the same event as the
  escalate flag.** One event carries both the decision and its consequence, so a reader of the
  session sees why the loop went round again.
- `instruction=letter_writer.INSTRUCTION + FEEDBACK_CLAUSE` — **day 9's instruction, plus one
  line.** The five rules a letter must obey are not restated here; the file that owns them still
  owns them.
- `max_iterations=3` — **the bound**, and part 2.2 is entirely about it.
- `def stages(agent)` — **the workflow as data.** Eleven lines that turn an object into a list of
  dictionaries, and the reason the rest of this day can assert anything at all.
- `for child in node.sub_agents: walk(child, depth + 1)` — **`sub_agents` is the tree**, the same
  attribute day 9's delegation used. One field means two different things depending on the agent
  that carries it, which is worth knowing before reading somebody else's workflow.
- `def charge(budget, agent, events)` — **the budget is charged afterwards.** Day 7 spent before the
  call because the caller made exactly one; a workflow makes an unknown number, so the count comes
  out of the events.
- `if event.author in names and event.partial is not True:` — **only model nodes, and only whole
  events.** `is not True` rather than `== False`, for day 8's reason: the field has three states.
- `max_calls=budget.remaining` — **the framework's own ceiling, set from the desk's own budget.**
  Two bounds that could disagree, made to agree by deriving one from the other.
- `state={"claim": notification.id}` on both runs — the claim reference in state, because
  `HouseStyle` reads it and because day 8's rule permits a reference and forbids contents.
- `thread="triage"` and `thread="correspondence"` — **day 9's threads**, so the reading and the
  writing are separate conversations under one claim reference.

**Line by line:**

- **Six lines that day 9 could not produce.** The same work, the same order, and now it is output
  rather than source.
- `triage · SequentialAgent` with two children — **the arrangement is the parent's type.** Nothing
  in a child says what comes next; the parent says it.
- `classifier · LlmAgent` — day 7's agent, reported by its class rather than by its name, which is
  how `model_nodes` knows which nodes cost money.
- `rules · Rules` — **the node whose kind is its own class name.** A code node has no framework kind
  to report, and that turns out to be an advantage: the log says exactly which piece of this
  project's code ran.
- `house_style · HouseStyle` — the same, inside a loop, and the only node in this desk that can end
  one.
- **Neither listing mentions the claim.** The arrangement is the same for every notification; only
  the fields on the nodes differ, which is why `triage()` is a function.

## When it breaks

Write the node without the `yield` — compute the verdict, write it, return:

```
AttributeError: 'coroutine' object has no attribute 'aclose'
sys:1: RuntimeWarning: coroutine 'NoYield._run_async_impl' was never awaited
```

Verbatim, from this project, and the cause is one keyword. `_run_async_impl` is declared as
returning an `AsyncGenerator`, and a Python function is an async generator **only if it contains a
`yield`**. A node that returns instead is an ordinary coroutine, and the framework — which expects
something it can iterate and close — asks it for `aclose` and gets an attribute error.

The two lines are worth reading together. The first names a method nobody wrote and nobody called;
the second is the one that says what actually happened, and it arrives as a warning after the fact.
Neither mentions `yield`, and neither points at the node.

The smallest fix is to yield an event even when the node has nothing to report — which is the right
shape anyway, because **a stage that ran and said nothing is invisible in the session**, and the
next person debugging a claim will want to know the rules node ran at all.

## In production

**What a senior writes instead.** The same nodes, with the arrangement built by a factory that
reads configuration rather than by three functions — so the order of stages can change without a
deploy. What they would insist on first, though, is exactly what `stages()` does: **something that
prints the workflow**, wired into the startup log, so that the arrangement a running process
actually has is in the record next to the claims it decided.

**What degrades at scale.** Two stages per claim over a morning's several hundred notifications is
several hundred workflow objects built and thrown away, which is free. What is not free is the
tree: at eight stages and three levels, `stages()` output stops fitting on a screen and nobody reads
it, and the arrangement becomes as opaque as the `for` loop it replaced. The threshold is not the
number of nodes, it is whether one screen can hold the whole thing.

**The review comment.** *"This node reads `state['outcome']` and the node before it writes
`state['result']`. Neither name is wrong and the workflow cannot tell you they disagree — put both
keys in the node's fields so the mismatch is visible where the workflow is built."*

**The interview question.** *"You replaced a function that called three things in order with a
workflow object that calls the same three things in the same order. What can you do now that you
could not do before, and what did it cost?"*
