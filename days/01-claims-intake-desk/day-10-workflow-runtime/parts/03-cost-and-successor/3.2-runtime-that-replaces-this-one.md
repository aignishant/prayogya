## One-line answer

The three arrangements this day is built on are deprecated in the very version it pins, in favour of
a graph — nodes and edges, with a plain Python function as a node — and that successor runs here,
today, in six lines.

## The idea

The first time you see it, it is one line of stderr in the middle of a passing test run.

> *SequentialAgent is deprecated in favor of Workflow and will be removed in a future version.
> Workflow cannot yet be used as an LlmAgent sub-agent.*

There is a specific professional skill in what happens next, and it is not "upgrade". It is
reading the notice properly, finding out what the successor is, running it once, and then deciding —
with the second sentence of that notice very much in mind, because it says the replacement is not
finished.

That is the ordinary condition of working with a fast-moving runtime. The interesting question is
never *is the new thing better*. It is **what does this project pay if it moves now, what does it
pay if it waits, and what does it have to write down either way** — and the answer here is one this
project can defend, in a file, next to the code the notice is about.

A word about the shape of the successor, because it is a genuinely different idea. The three
arrangements are **compositions**: a sequential thing containing a parallel thing containing agents.
The successor is a **graph**: a list of edges between nodes, starting at `START`. A composition can
express *this, then that*; a graph can express *this, then that, and back again if the checker
says so* — the cycle and the branch as first-class things rather than as a `LoopAgent` and an
argument about conditionals.

## The mechanism

The notice, in full, from the installed package:

```bash
uv run python -c "
import asyncio
from google.adk.agents import SequentialAgent, BaseAgent

class Nothing(BaseAgent):
    async def _run_async_impl(self, ctx):
        return
        yield

SequentialAgent(name='t', description='x', sub_agents=[Nothing(name='n', description='y')])
"
```

```
<string>:10: DeprecationWarning: SequentialAgent is deprecated in favor of Workflow and will be removed in a future version. Workflow cannot yet be used as an LlmAgent sub-agent.
```

**Line by line:**

- **A `DeprecationWarning`, not an error.** Python hides these by default in many contexts, and
  `pytest -p no:warnings` — which this project uses to keep test output readable — hides them
  entirely. It is worth knowing where your own tooling is quiet.
- **"in favor of Workflow"** — a class, and the notice does not say where it lives. It is
  `google.adk.workflow.Workflow`, not `google.adk.agents`, which is the first thing to find out and
  the first thing a search will not tell you.
- **"Workflow cannot yet be used as an LlmAgent sub-agent"** — **the sentence that decides this
  project's answer.** The successor is not yet a drop-in: an `LlmAgent` can hold a `SequentialAgent`
  as a sub-agent and cannot yet hold a `Workflow`. This desk does not do that today; day 9's
  delegation part is the arrangement that would, and it is exactly the direction this project might
  grow.
- `return` followed by an unreachable `yield` — how you write a node that yields nothing at all, and
  the reason part 1.1's failure exists.

The successor, driven for real. Six lines of wiring around the agent day 7 built:

```python
import asyncio

from google.adk.workflow import START, Workflow

from claims_desk import sessions, workflow
from claims_desk.agents import classifier
from claims_desk.store import Store

note = {n.id: n for n in Store().notifications()}["FNOL-4477"]


def rules(reading: str) -> str:
    """A plain function as a node. Its parameter is bound from session state by name."""
    parsed, error = workflow.parse_reading(reading)
    return error or parsed["loss_type"]


reader = classifier.build(output_key="reading")

graph = Workflow(
    name="triage",
    description="Read, then apply the rules.",
    edges=[(START, reader), (reader, rules)],
)


async def main():
    answer, events = await sessions.turn(graph, note.id, note.description, thread="graph")
    for event in events:
        text = ""
        if event.content and event.content.parts:
            text = "".join(part.text or "" for part in event.content.parts)
        print("  author=%-14s %s" % (event.author, text[:60].replace("\n", " / ")))
    print("answer:", answer[:80])


asyncio.run(main())
```

**Line by line:**

- `from google.adk.workflow import START, Workflow` — **a different package from every other agent
  import in this project.** `google.adk.agents` holds the deprecated three; the successor lives
  beside them, not among them.
- `def rules(reading: str) -> str:` — **a plain function is a node.** No `BaseAgent`, no
  `_run_async_impl`, no `Event`, no `EventActions`. Compare `class Rules(BaseAgent)` in part 1.1:
  forty-eight lines become four, and almost everything that went is framework ceremony.
- `reading: str` — **the parameter name is the state key.** The runtime binds a node function's
  arguments from state by name, which is the same edge part 1.2 described with the plumbing removed.
- `return error or parsed["loss_type"]` — a return value, not a `state_delta`. The node says what it
  concluded and the runtime does the recording.
- `edges=[(START, reader), (reader, rules)]` — **the whole arrangement, as a list of pairs.**
  `START` is where the run enters. There is no sequential container: the order is the edges, which
  is what the plan means by *nodes and edges*.
- `sessions.turn(graph, ...)` — **this project's own session code takes it unchanged**, because part
  1.2 widened the type to `BaseAgent` and a `Workflow` is one. The change that was made for
  `SequentialAgent` paid for the successor too.

What it prints:

```
  author=classifier     {"scripted": true, "loss_type": "fire", "injury_reported": f
  author=triage
answer: {"scripted": true, "loss_type": "fire", "injury_reported": false}
```

**Line by line:**

- **Two events, and the second is authored by the graph itself.** In part 1.1's `SequentialAgent` the
  rules node authored its own event, because it was an agent. Here `triage` speaks for the function
  it ran, so **a plain function node has no identity in the event stream** — a real loss, and the
  price of the four-line node.
- **The graph ran the classifier and then the function**, in edge order, with the reading passed by
  name. The mechanism works.
- `answer:` **is the classifier's text, not the function's return.** What a graph considers its final
  answer is not obvious from the outside, and this project has not established it — which is exactly
  the kind of thing that has to be pinned down before a migration, not during one.

## When it breaks

The obvious next step is the loop, as a graph: an edge from the checker back to the writer when the
draft fails, and on to the end when it passes. The successor accepts a mapping for that —
`(house_style, {True: send, False: writer})` — so it looks like four lines.

It is not four lines:

```
Node 'house_style' has conditional/DEFAULT edges but none were matched by the emitted route(s): None. The branch will end.
```

Verbatim, from this project. The checker function returned `True`, and the runtime reports the
emitted route as `None`: **a node's return value is not its route.** Routes are emitted some other
way, and this project has not established how.

Two things follow, and the second is the point.

The first is a `TODO(me)` with the exact command, because an unfinished investigation is a
`TODO(me)` and never a guess: *build the correspondence loop as a `Workflow` graph and find out how a
node emits a route; start from `uv run python -c "import inspect, google.adk.workflow as w;
print(inspect.getsource(w.Edge)); print([n for n in dir(w) if not n.startswith('_')])"`.*

The second is the decision. **This project stays on `SequentialAgent`, `ParallelAgent` and
`LoopAgent` for now**, and the reasons are written down rather than assumed:

- the deprecated three run this desk end to end today, with 110 tests green;
- the successor's notice says it *cannot yet* be an `LlmAgent` sub-agent, so migrating would close
  the door day 9's delegation part deliberately left open;
- the loop — the arrangement this desk depends on most — is the one this project could not yet build
  on the successor, and a migration that leaves the hardest part unmigrated is not a migration;
- and none of that is an argument the three are better. They are deprecated, and this project has
  said so, in this part and in `docs/adr/ADR-0010-p01-stays-on-the-composition-workflow-agents.md`.

**A deprecation you have read, run and written down is a decision. A deprecation you have not
noticed is a surprise with a date on it.**

## In production

**What a senior writes instead.** The same decision, recorded the same way, plus a pin: the version
that deprecated the API is in `PACKAGES.md`, so the next person can tell whether the notice they are
reading is the one this file is about. What they would add is a test — one that imports the
successor and builds a two-node graph — so that **the day the successor becomes usable, something
green tells you** rather than nobody remembering.

**What degrades at scale.** One deprecated class in one project is a note. The spine this curriculum
teaches puts a workflow in every project, so a deprecation here is a decision that repeats across
forty of them, and the cost of getting it wrong is forty migrations rather than one. That is the real
argument for writing the reasoning down rather than the conclusion: a future reader needs to know
whether the second sentence of the notice still applies before deciding again.

**The review comment.** *"This adds a `SequentialAgent` and the library says it is deprecated. I am
not asking you to migrate — I am asking where the decision not to migrate is written, because right
now the only record is that nobody mentioned it."*

**The interview question.** *"A library you depend on deprecates the class your architecture is built
on. Walk me through the first hour, and tell me what you would have to produce before you were
willing to say 'not yet'."*
