## One-line answer

A plugin is registered once on the runner and runs around **every** model call and every tool call
in the process, whichever agent makes them — so it is the one place a desk can charge for a call
before it happens, refuse it, and write a log line that names the agent that asked.

## The idea

Every claims department has a post room, and the post room is not part of anybody's job description.

Letters go out through it. Nobody writes *"take it to the post room"* at the bottom of a procedure;
it is simply where outgoing things pass. And because everything passes through it, it is the only
place in the building where you can put a rule that applies to everything: a franking machine that
records what left, a scale that refuses a package over the limit, a stamp that says which office
sent it.

Put that rule inside each department instead and you have five copies of it, four of which are
correct.

A **plugin** is the post room. It is an object registered on the runner, and the framework calls its
hooks around every model call and every tool call that happens inside that runner — for agents it
has never heard of, in workflows that did not exist when it was written.

The distinction that matters, and it is the whole of this section: a plugin is **cross-cutting** and
an agent callback is **local**. A rule that is true of the whole desk goes in the plugin. A rule that
is true of one agent goes on that agent, where somebody reading the agent will find it. Getting this
backwards produces a plugin full of `if agent_name == ...`, which is five copies of the rule again
with extra steps.

There are two hooks worth understanding before any code, because they are the ones with teeth.

**`before_model_callback` runs before the request goes out, and what it returns replaces the call.**
Return `None` and the model is asked. Return an `LlmResponse` and **the provider is never
contacted** and the framework treats what you returned as the answer. That is how a budget can
refuse, and it is also how somebody can quietly make an agent stop working.

**`after_model_callback` runs on the answer, and what it returns replaces the answer.** This project
uses it only to log, and the restraint is deliberate: a hook that edits what a model said, without
saying so, is a thing nobody will find.

## The mechanism

The whole file, at `claims_desk/hooks.py`:

```python
"""What runs around every model call and every tool call, and what it is allowed to do.

Day 10 counted the budget by looking at events after the run finished. That worked and it counted
the wrong thing: an event is what a model *said*, and a call is what the desk *pays for*. This file
counts the call, at the moment it is about to be made, in the one place every agent's request passes
through — and because it is in that place, it can also refuse.

Two levels, and the difference between them is the whole of this file:

- **A plugin** is registered on the runner and sees **every agent** in the process. `DeskPlugin`
  charges the budget, refuses a call the budget cannot pay for, and writes one structured line per
  call and per tool. It knows nothing about claims.
- **An agent callback** is a field on one agent and sees only that agent. `refuse_the_description`
  is on the letter writer alone, because the thing it refuses — a policyholder's own words reaching
  the agent that writes to them — is a rule about that agent and not about the desk.

**What a callback must never do:** take a long time, call a model, raise for an ordinary condition,
or change an answer without saying so. It runs inside every request, on every agent, and a callback
that is slow makes everything slow in a way that looks like the provider.
"""

from __future__ import annotations

from contextvars import ContextVar
from typing import Any

from google.adk.agents.callback_context import CallbackContext
from google.adk.models.llm_request import LlmRequest
from google.adk.models.llm_response import LlmResponse
from google.adk.plugins.base_plugin import BasePlugin
from google.adk.tools.base_tool import BaseTool
from google.adk.tools.tool_context import ToolContext
from google.genai import types

from claims_desk.util.budget import Budget, BudgetExceeded
from claims_desk.util.logging import log

#: The budget for the unit of work currently being done, or `None` outside one.
#:
#: A plugin is constructed once and sees every run, so it cannot hold the budget as a field. A
#: context variable is the narrowest thing that works: it is per-task, so two claims decided
#: concurrently do not see each other's allowance, which a module-level global would not survive.
current_budget: ContextVar[Budget | None] = ContextVar("current_budget", default=None)

#: What must never appear in the request sent to an agent that writes to a policyholder. It is the
#: description — the words a caller said on the telephone — and day 9 part 3.1 is the run where it
#: arrived there by accident. That was fixed by giving each agent its own thread; this refuses it.
FORBIDDEN_IN_A_WRITERS_REQUEST = "forbidden_phrase"


#: The agents this plugin refused a call to, for the unit of work currently being done.
#:
#: A callback **must not raise for an ordinary condition**: the framework catches whatever comes
#: out of a plugin and re-raises it as its own `RuntimeError`, so the exception a caller was written
#: to catch never arrives. Being over budget is ordinary. So the refusal is returned as an answer
#: and recorded here, and the caller reads this list after the run.
#:
#: The default is `None` rather than `[]`: a mutable default on a context variable is shared by
#: every context that never set one, so one run's refusals leak into the next. Ruff refuses it, by
#: rule B039, which is the second time this project has been saved by a lint rule it did not choose.
refusals: ContextVar[list[str] | None] = ContextVar("refusals", default=None)

#: The answer a refused call comes back with. Empty on purpose: an empty draft fails the house style
#: and an empty reading fails the parser, so a refusal cannot be mistaken for work.
REFUSED = ""


class DeskPlugin(BasePlugin):
    """Charges, refuses and records every model call in this process, whichever agent makes it.

    Registered once on the runner. It has no idea what a claim is: it counts calls, it writes log
    lines, and the only decision it makes is whether there is anything left to spend.
    """

    def __init__(self) -> None:
        super().__init__(name="claims-desk")

    async def before_model_callback(
        self, *, callback_context: CallbackContext, llm_request: LlmRequest
    ) -> LlmResponse | None:
        """Charge the budget for the call that is about to be made, or refuse it.

        Returning an `LlmResponse` here **replaces the call**: the provider is never contacted and
        the framework treats what is returned as the model's answer. That is the whole power of this
        hook and the whole reason to be careful with it.
        """
        budget = current_budget.get()
        if budget is None:
            return None
        try:
            budget.spend(callback_context.agent_name)
        except BudgetExceeded as refused:
            log(
                "hooks.refused",
                agent=callback_context.agent_name,
                invocation=callback_context.invocation_id,
                detail=str(refused),
            )
            seen = refusals.get()
            if seen is not None:
                seen.append(callback_context.agent_name)
            return LlmResponse(
                content=types.Content(role="model", parts=[types.Part(text=REFUSED)]),
                turn_complete=True,
            )
        return None

    async def after_model_callback(
        self, *, callback_context: CallbackContext, llm_response: LlmResponse
    ) -> LlmResponse | None:
        """One structured line per model call, however deep the agent is in a workflow.

        It records **how much** was said and never **what** was said. A log is retained, and the
        thing a model produced on a claim is the policyholder's business.
        """
        parts = (llm_response.content.parts if llm_response.content else None) or []
        log(
            "hooks.model",
            agent=callback_context.agent_name,
            invocation=callback_context.invocation_id,
            parts=len(parts),
            chars=sum(len(part.text or "") for part in parts),
            partial=llm_response.partial,
        )
        return None

    async def on_model_error_callback(
        self, *, callback_context: CallbackContext, llm_request: LlmRequest, error: Exception
    ) -> LlmResponse | None:
        """Record the failure and let it through. Returning a response here would hide an outage."""
        log(
            "hooks.model_error",
            agent=callback_context.agent_name,
            invocation=callback_context.invocation_id,
            kind=type(error).__name__,
            detail=str(error)[:200],
        )
        return None

    async def before_tool_callback(
        self, *, tool: BaseTool, tool_args: dict[str, Any], tool_context: ToolContext
    ) -> dict[str, Any] | None:
        """One line per tool call, with the argument **names** and not their values."""
        log(
            "hooks.tool",
            tool=tool.name,
            agent=tool_context.agent_name,
            args=sorted(tool_args),
        )
        return None

    async def after_tool_callback(
        self,
        *,
        tool: BaseTool,
        tool_args: dict[str, Any],
        tool_context: ToolContext,
        result: dict[str, Any],
    ) -> dict[str, Any] | None:
        """One line per tool answer, with the keys it came back with and not their values."""
        log("hooks.tool_result", tool=tool.name, keys=sorted(result) if result else [])
        return None


def refuse_the_description(
    callback_context: CallbackContext, llm_request: LlmRequest
) -> LlmResponse | None:
    """An agent callback: refuse to send a request that carries a phrase this agent must not see.

    On the letter writer alone. Day 9 gave each agent its own conversation so the description could
    not reach this one; this is the second lock, on the request itself, because a thread name is a
    convention and a convention is a thing somebody changes.

    It **replaces** the call with a refusal rather than raising, so the run continues and the empty
    answer reaches the house style, which refuses an empty draft anyway.

    That is not free, and the number was measured rather than assumed: a refused request still
    costs the budget, because the plugin charges before this runs, and the loop then goes round its
    full bound refusing three empty drafts. **A guaranteed refusal is the one case a repair loop
    cannot help with, and it pays anyway.** Day 11 part 2.1 has the transcript.
    """
    forbidden = str(callback_context.state.get(FORBIDDEN_IN_A_WRITERS_REQUEST, "")).strip()
    if not forbidden:
        return None
    sent = "\n".join(
        part.text or ""
        for content in (llm_request.contents or [])
        for part in (content.parts or [])
    )
    if forbidden.lower() not in sent.lower():
        return None
    log(
        "hooks.refused_leak",
        agent=callback_context.agent_name,
        invocation=callback_context.invocation_id,
        chars=len(forbidden),
    )
    return LlmResponse(
        content=types.Content(role="model", parts=[types.Part(text="")]),
        turn_complete=True,
    )
```

**Line by line:**

- **The module docstring opens by naming what day 10 got wrong**, which is the reason this file
  exists: *an event is what a model said, and a call is what the desk pays for*. Those are the same
  number for a stand-in that never streams and different numbers for a provider that does.
- **"What a callback must never do" is in the docstring, not in a comment somewhere.** Four rules,
  and the third one — *raise for an ordinary condition* — is the day's deliberate failure, in part
  3.1.
- `from google.adk.plugins.base_plugin import BasePlugin` — **plugins live in their own package.**
  Not `google.adk.agents`, which is where every other import in this project's agent code comes
  from.
- `current_budget: ContextVar[Budget | None]` — **a plugin is built once and sees every run**, so it
  cannot hold per-claim state as a field. A context variable is per-task: two claims decided
  concurrently see their own allowance, which a module-level global would not survive.
- `refusals: ContextVar[list[str] | None] = ContextVar("refusals", default=None)` — **`None`, not
  `[]`.** A mutable default on a context variable is one object shared by every context that never
  set one, so one run's refusals would appear in the next. `ruff` refuses it by rule `B039`.
- **The comment says which lint rule caught it.** A future reader who tries to "simplify" this to
  `default=[]` will meet the same rule, and the comment tells them the rule is right.
- `REFUSED = ""` — **the answer a refused call comes back with, and it is empty on purpose.** An
  empty draft fails the house style and an empty reading fails the parser, so a refusal cannot be
  mistaken for work anywhere downstream.
- `def __init__(self) -> None: super().__init__(name="claims-desk")` — **a plugin has a name**, and
  it is not decoration: the framework uses it when something inside a plugin goes wrong, which part
  3.1 is entirely about.
- `async def before_model_callback(self, *, callback_context, llm_request)` — **keyword-only, both
  arguments.** The framework calls it by keyword; a positional signature fails at call time with a
  message about arguments rather than about your hook.
- `budget = current_budget.get()` / `if budget is None: return None` — **the plugin works with no
  budget registered.** Anything that runs an agent outside a unit of work — a test, a one-off
  command, day 19's container starting up — should not need to know this file exists.
- `budget.spend(callback_context.agent_name)` — **the agent's own name, straight from the context.**
  Day 10 got this by counting events by author; here it is handed over. Same string, one fewer step
  to be wrong.
- `except BudgetExceeded as refused:` **and no re-raise.** Day 7's budget raises, which is right when
  a caller calls it directly; inside a plugin it is wrong, and part 3.1 is the transcript of why.
- `seen = refusals.get()` / `if seen is not None:` — **the caller decides whether refusals are being
  collected.** Outside a unit of work nobody is listening and the plugin does not force a list into
  existence.
- `return LlmResponse(content=..., turn_complete=True)` — **the call is replaced.** No provider is
  contacted, no money is spent beyond the budget line already written, and the run continues with an
  empty answer.
- `parts = (llm_response.content.parts if llm_response.content else None) or []` — **two guards on
  one line**, because day 8 established that a failed response has `content` of `None`, and a
  content object can carry no parts.
- `chars=sum(len(part.text or "") for part in parts)` — **how much, never what.** The log is
  retained; the sentence a model wrote about somebody's claim is not this project's to keep.
- `partial=llm_response.partial` — **recorded rather than filtered.** Against this stand-in it is
  always `null`; against a streaming provider it is how you would tell one call from forty fragments,
  and the honest thing is to record it now and find out later.
- `async def on_model_error_callback(...) -> LlmResponse | None:` with `return None` — **this hook
  can turn an outage into an answer, and this project refuses to.** Returning a response here is how
  a system quietly answers claims during a provider failure.
- `detail=str(error)[:200]` — **truncated**, because a provider's error text can carry a request
  body, and a log line is the last place for one.
- `before_tool_callback` logging `args=sorted(tool_args)` — **the names of the arguments, never their
  values.** A tool argument on this desk is a policy number or a claim reference; the log needs to
  say a tool was called with a policy number, not which one.
- `after_tool_callback` logging `keys=sorted(result)` — the same rule on the way back.
- `def refuse_the_description(callback_context, llm_request)` — **not on the plugin.** It is an agent
  callback, it is a rule about one agent, and part 2.1 is why that matters.
- `callback_context.state.get(FORBIDDEN_IN_A_WRITERS_REQUEST, "")` — **the phrase comes from session
  state**, so the callback is a fixed function and the thing it refuses is per-claim.
- `if not forbidden: return None` — **no phrase, no opinion.** A guard that fires when it has nothing
  to compare against would refuse every call the first time somebody forgot to set the key.
- `forbidden.lower() not in sent.lower()` — **a substring, case-insensitively.** Crude, and part 2.1
  says exactly what it misses.
- **The docstring records a measured number and not an assumption.** It first said a refused leak
  costs nothing; the run in part 2.1 says three drafts, and the file says three drafts.

## When it breaks

Register nothing and the budget is never charged. Day 10's counting is gone, so nothing else counts:

```
{"event": "hooks.model", "agent": "classifier", "invocation": "e-40966bae-934c-4fb4-b2ba-f2811f03e33c", "parts": 1, "chars": 76, "partial": null}
{"event": "session.turn", "claim": "FNOL-4471", "session": "claim-FNOL-4471", "yielded": 1, "chars": 76}
spent: 1 {'classifier': 1}
```

That is the working version, and it is here first because the broken one looks almost the same. Take
`plugins=[DeskPlugin()]` off the runner and the `hooks.model` line disappears, `spent` stays at `0`
for every claim, and **every test that asserts on a letter or a verdict still passes** — because the
budget is the only thing that changed and no letter depends on it.

What you would see in production is a bill with no ceiling and a `budget.by` that is empty on every
claim. What you would see in the test suite is nothing at all, unless somebody wrote the assertion
in part 4.1's `test_the_plugin_charges_the_call_rather_than_counting_the_events`.

The smallest fix is one keyword argument on the `Runner`. The lesson is the one this project keeps
meeting: **a cross-cutting rule is registered in exactly one place, and the failure mode of one
place is that it is easy to leave out.** Part 1.2 puts it where every turn goes through it.

## In production

**What a senior writes instead.** The same plugin, with the counting behind a metrics client rather
than a log line, and the refusal behind a feature flag so it can be turned off during an incident
without a deploy. What they would insist on is the thing this file already does: **the plugin knows
nothing about claims.** The moment a plugin contains a claim reference, it has stopped being
cross-cutting and become one agent's rule in the wrong file.

**What degrades at scale.** Two hooks per model call and two per tool call is nothing — until one of
them does input or output. This plugin writes a log line, which is a synchronous write to stderr on
this desk. A morning's several hundred notifications at seventeen model calls per twelve claims is
roughly 250 log lines a morning, which is free; the same hook doing a network write to a metrics
service is 250 round trips inside the request path, and every one of them makes the desk look slower
in a way that will be blamed on the provider.

**The review comment.** *"This plugin returns a response from `on_model_error_callback` so that a
provider outage produces a default classification. That is not resilience, it is a system that
decides claims during an outage and does not say so. Log it and re-raise."*

**The interview question.** *"You have a hook that runs before every model call and can replace the
call entirely. Name three legitimate uses and one that would get through code review and should
not."*
