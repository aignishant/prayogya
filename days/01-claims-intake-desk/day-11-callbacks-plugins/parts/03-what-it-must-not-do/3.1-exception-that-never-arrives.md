## One-line answer

A plugin that raises does not raise your exception: the framework catches it and re-raises its own
`RuntimeError` naming the plugin — so `except BudgetExceeded` stopped catching anything, the desk's
over-budget path went dead, and every test that mattered still passed.

## The idea

This is the day's deliberate failure, and it was not planned. It happened while the budget was being
moved into the plugin, it took two green test runs to notice, and the shape of it is worth more than
the fix.

Day 7 made a decision on purpose: `BudgetExceeded` **raises**. The reasoning is in that day's file
and it is good — a caller that has run out of allowance should stop, not continue with a default
answer, and an exception is the only thing in Python that cannot be quietly ignored. Every part of
this project since has relied on it. `desk.decide` catches it and returns a pending verdict; a test
asserts that it does.

So when the charge moved into `before_model_callback`, the obvious code was the code that kept that
decision: catch the framework's hook, call `budget.spend`, and let `BudgetExceeded` fly the way it
always has.

It flies. It just does not arrive.

The general principle, which is worth carrying to every framework you meet: **an extension point is
a boundary, and exceptions do not cross boundaries unchanged.** A framework that calls your code in
a loop over other people's plugins cannot let one of them abort the run with an arbitrary exception
and no attribution — so it wraps. What comes out the other side is the framework's exception, with
your message inside it as text.

## The mechanism

The version that looks right. One line, in `DeskPlugin.before_model_callback`:

```python
        try:
            budget.spend(callback_context.agent_name)
        except BudgetExceeded as refused:
            log("hooks.refused", agent=callback_context.agent_name, detail=str(refused))
            raise refused
```

**Line by line:**

- `raise refused` — **re-raising the exception day 7 designed.** Not a new one, not a wrapped one: the
  same object, so the message and the type both survive. Everything about this line is correct in
  isolation.
- **It keeps day 7's contract exactly.** `BudgetExceeded` goes out of the thing that spends, the
  caller catches it, the claim goes pending. Three days of this project's design is preserved.
- **The log line is written first**, so even if something eats the exception the refusal is in the
  record. That instinct is right and it is what makes the failure survivable.

Now ask for a call with nothing to spend, and catch the exception the project was built around:

```bash
uv run python -c "
import asyncio
from claims_desk import hooks, sessions
from claims_desk.agents import classifier
from claims_desk.util.budget import Budget, BudgetExceeded

hooks.current_budget.set(Budget(limit=0, label='FNOL-4471'))
hooks.refusals.set([])
try:
    asyncio.run(sessions.turn(classifier.build(), 'FNOL-4471', 'the flexible hose let go overnight'))
except BudgetExceeded as refused:
    print('caught BudgetExceeded:', refused)
except Exception as other:
    print(type(other).__name__ + ': ' + str(other))
"
```

```
RuntimeError: Error in plugin 'claims-desk' during 'before_model_callback' callback: classifier asked for call 1 of 0 for FNOL-4471; already spent: {}
```

**Line by line:**

- **`except BudgetExceeded` did not fire.** The second clause did. The exception the whole project
  was written to catch never reached the caller.
- `RuntimeError` — **the framework's own type**, and about as generic as a type can be. Nothing
  downstream can distinguish it from any other runtime failure without reading its text.
- `Error in plugin 'claims-desk' during 'before_model_callback' callback:` — **the framework naming
  the plugin and the hook**, which is genuinely helpful and is the reason it wraps: with a dozen
  plugins registered, an unattributed exception from inside one of them is unsolvable.
- **Day 7's message survives, as text**: *classifier asked for call 1 of 0 for FNOL-4471; already
  spent: {}*. Everything needed to understand what happened is there, and none of it is available to
  a program.
- `name="claims-desk"` — **the string passed to `super().__init__` in part 1.1**, appearing where it
  earns its keep. A plugin with a default name would produce this message about something anonymous.

## When it breaks

The failure is not the message. It is what happened in `claims_desk/desk.py` while nobody was
looking:

```python
    try:
        read = await workflow.run_triage(notification, cover, budget)
    except BudgetExceeded as refused:
        log("desk.over_budget", claim=notification.id, detail=str(refused))
        return Verdict(notification.id, PENDING, waiting_for="over_budget")
```

That `except` clause is now **dead code**. `BudgetExceeded` cannot reach it — a `RuntimeError` can —
so an over-budget claim no longer goes pending. It propagates out of `decide`, out of `run_queue`,
and stops the morning's queue with a runtime error on the first claim that runs out.

Here is the part that makes it a good failure rather than merely a bug. Run the suite:

```
2 failed, 108 passed in 6.12s
```

Two failures out of a hundred and ten, and **neither of them is about the desk.** Both are tests that
happened to assert on the exception directly. `desk.decide`'s over-budget path has no test that
drives it to the limit, so the thing that actually broke — a queue that now dies instead of skipping
a claim — is not in the count. The suite was, in the way that matters, still green.

The fix is not to catch `RuntimeError`. Catching the framework's generic exception and matching on
its text would work and would be the wrong shape: it makes this desk depend on the wording of a
message.

The fix is to stop raising, because **being over budget is an ordinary condition** and a callback
must not raise for one. The refusal becomes a returned `LlmResponse` and a name appended to a list,
part 1.2's `OVER_BUDGET` becomes a returned value the desk checks, and part 4.1 adds the test that
was missing all along — `test_a_refused_claim_goes_pending_and_names_the_reason` — which drives a
real claim to a zero budget and asserts on the verdict.

The rule, which is the fourth line of `hooks.py`'s docstring and was written after this happened:
**a callback must not raise for an ordinary condition.** Reserve exceptions inside a hook for things
that genuinely mean *stop the run* — and then expect them to arrive wrapped, and design for that.

## In production

**What a senior writes instead.** The same refusal as a returned response, with the reason attached
to something structured rather than a bare list of agent names — a small object carrying which agent,
which limit and what had been spent, so the caller does not have to re-derive the story. What they
would ask for first, though, is not code: **a test for the path that just went dead.** The bug here
was not the exception; it was that a whole branch of `decide` had no test driving it.

**What degrades at scale.** One claim reaching its limit is an exception nobody catches, on a queue
that stops. Twelve claims, and the eleven after the failure are never looked at. A morning's several
hundred notifications with a ceiling somebody has tightened, and the entire batch dies on whichever
claim runs out first — with a log that says `hooks.refused` once and then nothing, which reads like
the run simply ended. **The blast radius of an exception in a cross-cutting hook is every unit of
work after it**, and that is the argument for the hook returning rather than raising, independent of
what any framework does with it.

**The review comment.** *"This plugin raises `BudgetExceeded` and the desk catches it. Try it —
the framework wraps whatever comes out of a plugin, so your `except` clause is dead. Either return a
refusal or write the test that would have told you."*

**The interview question.** *"You put a limit in a framework hook and the exception you raise is not
the one your caller sees. Describe what you would check before choosing between catching the
framework's exception and not raising at all."*
