## One-line answer

Thirteen tests hold the schema to what it accepts and what it refuses, the peril enum to being the
only list of perils in the project, and the JSON schema to carrying the prose that actually crosses
to a provider — and none of them touches a framework, a runner or an event loop.

## The idea

The best thing about moving the shape into a schema is what it does to the tests.

Yesterday, finding out whether the desk would accept a particular answer meant building an agent,
building a runner, opening a session, running a turn against a stand-in, and reading state. Six
pieces of machinery to answer a question about one dictionary.

Today it is `Reading.model_validate({...})` and an assertion, and the whole file runs in about a
second. That is not a small convenience: **a check that is cheap gets written, and a check that
needs a runner gets skipped.** This file has thirteen tests where the equivalent through the
framework would have had four.

There is a second thing worth pointing at, and it is the group of tests that assert *agreement*
rather than behaviour. The peril enum matches the policy data. The instruction lists exactly the
enum. The JSON schema names every peril. None of those tests exercise a code path — they check that
three files that must say the same thing still do, which is the failure part 1.1 was written to
prevent and the only kind of failure a single source of truth can still have.

## The mechanism

The whole file, at `tests/test_schemas.py`:

```python
"""Schemas: what the desk accepts, what it refuses, and what happens when one gains a field.

Every test here runs pydantic against this project's own models. No framework, no runner, no event
loop — which is the point of declaring the shape in `claims_desk/schemas.py` rather than inside an
agent: it can be argued with in milliseconds.
"""

from __future__ import annotations

import json

import pytest
from pydantic import BaseModel, ConfigDict, Field, ValidationError

from claims_desk.agents import classifier
from claims_desk.domain import PHOTO_REQUIRED_FOR, Peril
from claims_desk.schemas import Reading
from claims_desk.store import Store

GOOD = {"loss_type": "escape-of-water", "injury_reported": False}


def test_a_well_formed_reading_is_accepted() -> None:
    reading = Reading.model_validate(GOOD)
    assert reading.loss_type == "escape-of-water"
    assert reading.injury_reported is False
    assert reading.scripted is False


def test_the_peril_comes_back_as_a_string_the_rules_can_use() -> None:
    """`use_enum_values` — so `assess` compares against `cover.perils`, which holds strings."""
    reading = Reading.model_validate(GOOD)
    assert isinstance(reading.loss_type, str)
    assert reading.model_dump()["loss_type"] == "escape-of-water"


def test_a_peril_this_desk_does_not_recognise_is_refused() -> None:
    """The confident guess. Valid JSON, both fields present, and not a thing any policy covers."""
    with pytest.raises(ValidationError) as refused:
        Reading.model_validate({"loss_type": "water damage", "injury_reported": False})
    error = refused.value.errors()[0]
    assert error["loc"] == ("loss_type",)
    assert error["type"] == "enum"


def test_an_invented_field_is_refused_rather_than_dropped() -> None:
    """`extra="forbid"`. A model that returns a confidence score is telling you something."""
    with pytest.raises(ValidationError) as refused:
        Reading.model_validate({**GOOD, "confidence": 0.91})
    assert refused.value.errors()[0]["type"] == "extra_forbidden"


def test_a_missing_field_is_refused() -> None:
    with pytest.raises(ValidationError) as refused:
        Reading.model_validate({"loss_type": "fire"})
    assert refused.value.errors()[0]["loc"] == ("injury_reported",)


def test_a_string_where_a_boolean_belongs_is_coerced_and_that_is_worth_knowing() -> None:
    """Pydantic coerces `"true"` to `True`. Not a bug, and not obviously what you want either."""
    assert Reading.model_validate({**GOOD, "injury_reported": "true"}).injury_reported is True
    with pytest.raises(ValidationError):
        Reading.model_validate({**GOOD, "injury_reported": "probably"})


def test_the_enum_is_the_only_list_of_perils() -> None:
    """Every peril in every policy is one of these, and every one of these is used."""
    perils = {peril for policy in Store().policies() for peril in policy.perils}
    assert perils == {peril.value for peril in Peril}


def test_the_photo_rule_names_perils_from_the_enum() -> None:
    assert set(Peril) >= PHOTO_REQUIRED_FOR
    assert Peril.THEFT not in PHOTO_REQUIRED_FOR
    assert Peril.WINDSCREEN not in PHOTO_REQUIRED_FOR


def test_the_instruction_lists_exactly_the_enum() -> None:
    """The model is told the same list the schema will hold it to. One source, two readers."""
    listed = classifier.INSTRUCTION.split("The peril slugs are: ")[1].split(".")[0]
    assert [slug.strip() for slug in listed.split(",")] == [peril.value for peril in Peril]


def test_the_schema_the_model_is_given_names_every_peril() -> None:
    """What actually crosses to a provider is the JSON schema, so that is what is asserted."""
    schema = json.dumps(Reading.model_json_schema())
    for peril in Peril:
        assert peril.value in schema
    assert "True only if the description says a person was hurt." in schema


# --- schema evolution: the field that appeared last Tuesday ------------------------------------


class ReadingWithOptional(BaseModel):
    """Tuesday's version, adding a field the old answers do not have."""

    model_config = ConfigDict(extra="forbid", use_enum_values=True)

    loss_type: Peril
    injury_reported: bool
    scripted: bool = False
    police_reference: str | None = Field(default=None, description="Theft claims only.")


class ReadingWithRequired(BaseModel):
    """The same field, required. One word different and every stored answer is now invalid."""

    model_config = ConfigDict(extra="forbid", use_enum_values=True)

    loss_type: Peril
    injury_reported: bool
    scripted: bool = False
    police_reference: str


def test_an_optional_new_field_accepts_every_answer_written_before_it_existed() -> None:
    reading = ReadingWithOptional.model_validate(GOOD)
    assert reading.police_reference is None


def test_the_same_field_made_required_refuses_all_of_them() -> None:
    """The only change is the default. Every claim decided before Tuesday now fails to load."""
    with pytest.raises(ValidationError) as refused:
        ReadingWithRequired.model_validate(GOOD)
    assert refused.value.errors()[0]["loc"] == ("police_reference",)


def test_an_old_reader_refuses_a_new_answer_because_extra_is_forbidden() -> None:
    """The direction people forget. `extra="forbid"` cuts both ways: today's reader, tomorrow's
    answer, and the field that was added to help."""
    tomorrow = {**GOOD, "police_reference": "CR/2026/118"}
    with pytest.raises(ValidationError) as refused:
        Reading.model_validate(tomorrow)
    assert refused.value.errors()[0]["type"] == "extra_forbidden"
    assert ReadingWithOptional.model_validate(tomorrow).police_reference == "CR/2026/118"
```

**Line by line:**

- **The docstring's last clause is the argument for the whole day**: a shape declared outside an
  agent *can be argued with in milliseconds*. Everything below follows from that.
- `GOOD = {...}` **as a module constant** — one canonical valid answer, reused by seven tests. When
  the required fields change, one line changes and every test follows.
- `assert reading.scripted is False` — **the default, asserted.** It is the one field with a default,
  and a default that silently changes is a field that starts meaning something else.
- `test_the_peril_comes_back_as_a_string_the_rules_can_use` — **`isinstance(..., str)` and a
  `model_dump()` check.** Both, because `use_enum_values` affects the attribute and the dump
  separately, and day 2's `assess` reads one while the session's state holds the other.
- `assert error["type"] == "enum"` — **the error type, not its message.** Pydantic's prose changes
  between versions; `"enum"` is the machine-readable fact and is what part 1.2's log line records.
- `test_an_invented_field_is_refused_rather_than_dropped` — **`"confidence": 0.91` specifically**,
  because that is the field a model actually starts adding, and its docstring says why refusing it
  is information rather than pedantry.
- `test_a_string_where_a_boolean_belongs_is_coerced_and_that_is_worth_knowing` — **the test that
  documents a surprise.** `"true"` becomes `True`; `"probably"` does not. Neither is wrong, and a
  reader who assumed a schema means "exactly this type" needs to know which of the two happened.
- `test_the_enum_is_the_only_list_of_perils` — **equality between the enum and the policy data, in
  both directions.** Not a subset: a peril in the enum that no policy covers is as much of a problem
  as the reverse, because it is an answer the classifier may give that the rules will always refuse.
- `assert set(Peril) >= PHOTO_REQUIRED_FOR` — **the subset relation, asserted rather than assumed.**
  Part 1.1 rewrote `PHOTO_REQUIRED_FOR` in terms of the enum; this is what would notice if somebody
  put a raw string back.
- `assert Peril.THEFT not in PHOTO_REQUIRED_FOR` — **two named exclusions**, and they are the two the
  handbook's HB-02 gives reasons for: the repairer inspects a windscreen, and a police reference
  stands in for a photograph on theft.
- `test_the_instruction_lists_exactly_the_enum` — **splits the prompt on its own sentence and
  compares ordered lists.** Brittle on purpose, in the way day 7 established: a prompt is edited far
  more casually than code, and this list must not drift from the schema.
- `test_the_schema_the_model_is_given_names_every_peril` — **asserts on the generated JSON schema**,
  because that is the artefact that crosses to a provider. The Python model could be right and the
  serialisation wrong.
- `assert "True only if the description says a person was hurt." in schema` — **a field description,
  asserted present in the JSON.** It is the sentence that corrects day 2's keyword scan, it only does
  its job if it reaches the model, and this is the only test in the project that checks that it does.
- **The section comment before the evolution models** — a `# ---` divider with the part's title in
  it. Three classes and three tests that are about a hypothetical future belong visibly apart from
  the ones about today.
- **The two future models keep `extra="forbid"`** so the variable under test is the field and nothing
  else, and both are declared here rather than in `schemas.py` because neither is a shape this desk
  uses.

Run the file:

```bash
uv run pytest tests/test_schemas.py -q -p no:warnings
```

```

13 passed in 1.13s
```

**Line by line:**

- **Thirteen tests, 1.13 seconds, no event loop.** The comparable file for day 10's workflow takes
  twice as long for fewer tests, and every one of those seconds is a runner.
- **No fixture in the file at all.** Nothing to set up: pydantic models are values and the store is
  read-only.

## When it breaks

Add a peril to the policy data and forget the enum — the exact failure part 1.1 said a single list
prevents, arriving now as a red test rather than as a wrong letter:

```
E       AssertionError: assert {'accidental-... 'theft', ...} == {'accidental-... 'windscreen'}
E         Extra items in the left set:
E         'subsidence'
E         Use -v to get more diff
FAILED tests/test_schemas.py::test_the_enum_is_the_only_list_of_perils - Asse...
1 failed, 12 deselected in 1.12s
```

Verbatim, from this project — and note that pytest truncates both sets, so the useful line is
`Extra items in the left set`. That is the peril that exists in the data and not in the code.

One test. Compare that with what happened before there was an enum: the classifier could not name subsidence, so it would have chosen
the closest slug it was given, and the rules would have refused the claim as `peril_not_covered` —
a letter to a policyholder saying their loss is not covered, when it is.

**That is the whole value of the assertion, and it is worth being precise about what it is not.** It
is not a test of the retrieval, the rules, the letter or the model. It is a test that two files
agree, and it catches a class of failure where every individual file is correct.

The smallest fix is one enum member. The habit worth keeping: **when a fact lives in data and in
code, write the test that compares them before you write anything that depends on either.**

## In production

**What a senior writes instead.** The same thirteen, plus one that round-trips: build a `Reading`,
dump it, validate the dump, and assert the two are equal. Cheap, and it catches the serialisation
asymmetries that `use_enum_values` and aliases introduce — the class of bug where the object is right
and the stored JSON is not.

**What degrades at scale.** Thirteen tests over one model is proportionate. Ten models with four
fields each, all with the same four assertions, is forty near-identical tests and nobody reads them.
The shape that survives is a **parametrised sweep over the schema registry** — every model refuses an
extra field, every enum matches its data source, every field has a description — with per-model tests
only for what is genuinely specific, which here is the peril list and the coercion surprise.

**The review comment.** *"`test_the_instruction_lists_exactly_the_enum` splits the prompt on the
string `'The peril slugs are: '`. That sentence is now load-bearing and nothing in the prompt says
so. Put a comment above it in `classifier.py`, or generate the whole sentence and assert on the
generated form."*

**The interview question.** *"You have a list of valid values in a config file and in a Python enum.
Write me the test that keeps them honest, and tell me what it cannot catch."*
