## One-line answer

A container that exits is a container something restarts, so the desk gains a process that stays
up: two routes on one port, `GET /healthz` that answers only after asking the boundary a question it
cannot get wrong, and `POST /queue` that runs the same `run_queue` day 6 wrote — with nothing kept
between requests, which is what makes part 1.1's word *stateless* true.

## The idea

A branch counter is not a person who arrives, decides the morning's post, and goes home. It is a
counter that is open — and the first thing head office asks a new branch, every morning, is not
"how many claims did you decide" but "are you open, and can you reach the policy department".

That second question is the one this part is about, and it is harder than it sounds. A branch that
answers "yes, open" by looking at its own sign is a branch that will say yes with the phone line
down. The honest answer requires making a call — picking up the phone to the policy department and
asking something trivial, so that "we're open" means "we can decide a claim right now, not merely
that the lights are on". And the trivial question has to be *genuinely* trivial: not "is policy
SYN-POL-1001 in force", which reads a real record every thirty seconds and leaves a real line in a
log, but a policy number that exists in no book, so that the only thing the answer proves is that the
department picked up.

That is `/healthz`. It asks the boundary for a policy that does not exist and treats `found: false`
as the pass. If the boundary is reachable the desk is healthy; if it is not, the desk says so with a
status that a machine reads as *not now* and a body that names what went wrong — not `ExceptionGroup`,
which is what the client library actually raises and which tells nobody anything, but the leaf
inside it: `ConnectError`, the refused connection.

The second route is the counter itself. `POST /queue` runs `run_queue` — the same function, with
the same trace, spans and claim files — and returns the counts. It is not a new desk; it is the old
desk reachable by a request instead of a command, which is what a container needs.

What this part does *not* do is bring in a web framework, and the reason is worth a sentence. Two
routes, one JSON body each and an exit status need nothing the standard library does not have. The
framework this desk is built on ships `adk api_server`, which serves a root agent over HTTP with a
generated interface — and this desk has no root agent, for the reason day 18 part 3.2 gave: the
thing worth reaching is the queue through the whole desk, not one agent's turn. So the server is
sixty lines, single-threaded, and honest about both.

The failure this part carries is the one every service meets on its first day: the port is taken.
On this machine, by a process that was not this project's — which is the ordinary case, and the
reason the port is a variable.

## The mechanism

The whole file, at `claims_desk/serve.py`:

```python
"""The desk as a service: one port, two routes, and nothing kept between requests.

Every day until now has run the desk as a command that reads the queue, decides it, and exits. A
container runs the same code, and a container that exits is a container something restarts — so
the desk needs a way to stay up and answer *is it alive* without deciding anything. That is
`/healthz`. The second route, `/queue`, is the same `run_queue` day 6 wrote, reached by a request
instead of a command line.

What this deliberately is not: a framework. The standard library's `http.server` is enough for two
routes, a JSON body and an exit status, and it adds nothing to `uv.lock`. It is single-threaded and
it serves one request at a time, which is the right shape for a desk that decides a queue in order —
day 10 measured what parallel claims cost and chose not to pay it.

**The container is stateless because this file is.** Nothing here outlives a request: no cache, no
session, no counter. Every fact the desk needs comes from the boundary on every call, so a second
copy of this container answers exactly as the first would, and killing either loses nothing.
"""

from __future__ import annotations

import asyncio
import json
import os
import sys
from http.server import BaseHTTPRequestHandler, HTTPServer
from typing import Any

from claims_desk import boundary
from claims_desk.desk import run_queue
from claims_desk.util.logging import log

#: Where the desk listens. `0.0.0.0` inside a container, where the network is the container's
#: own and the port is published by whoever runs it; loopback everywhere else, for the same reason
#: day 4's boundary binds loopback — nothing here authenticates anybody.
HOST = os.environ.get("CLAIMS_DESK_HOST", "127.0.0.1")
PORT = int(os.environ.get("CLAIMS_DESK_PORT", "8080"))

#: A policy number that exists in no book. The health check asks the boundary for it and expects
#: `found: false` — a round trip that proves the boundary answers and reads nothing real.
NOBODY = "SYN-POL-0000"


def innermost(failure: BaseException) -> BaseException:
    """The exception that actually happened, dug out of however many groups wrapped it.

    The client runs its connection inside task groups, and a refused connection arrives here as an
    `ExceptionGroup` holding an `ExceptionGroup` holding the refusal. A health check that reports
    the wrapper reports nothing; this walks down to the first leaf and reports that.
    """
    while isinstance(failure, BaseExceptionGroup) and failure.exceptions:
        failure = failure.exceptions[0]
    return failure


def health() -> tuple[bool, dict[str, Any]]:
    """Is the desk able to decide a claim right now? Ask the one thing it depends on.

    A health check that returns `ok` without asking anything is the failure day 17 warned about
    from the other side: a page that fires on nothing. This one makes a real boundary call, so a
    desk whose boundary is gone says so — and says which transport it tried.
    """
    transport = "http" if os.environ.get(boundary.ENDPOINT, "").strip() else "stdio"
    try:
        answer = asyncio.run(boundary.fetch_policy(NOBODY))
    except Exception as failure:  # noqa: BLE001 - reported, never hidden
        kind = type(innermost(failure)).__name__
        log("serve.unhealthy", transport=transport, kind=kind)
        return False, {"ok": False, "boundary": transport, "error": kind}
    reachable = answer.get("found") is False
    return reachable, {"ok": reachable, "boundary": transport, "asked": NOBODY}


class Desk(BaseHTTPRequestHandler):
    """Two routes. Anything else is 404, and every answer is JSON with a status that means it."""

    def _send(self, status: int, body: dict[str, Any]) -> None:
        payload = json.dumps(body, sort_keys=True).encode("utf-8")
        self.send_response(status)
        self.send_header("Content-Type", "application/json")
        self.send_header("Content-Length", str(len(payload)))
        self.end_headers()
        self.wfile.write(payload)

    def do_GET(self) -> None:  # noqa: N802 - the base class names it
        if self.path != "/healthz":
            self._send(404, {"error": "no such route", "path": self.path})
            return
        ok, body = health()
        self._send(200 if ok else 503, body)

    def do_POST(self) -> None:  # noqa: N802 - the base class names it
        if self.path != "/queue":
            self._send(404, {"error": "no such route", "path": self.path})
            return
        counts = asyncio.run(run_queue())
        self._send(200, counts)

    def log_message(self, format: str, *args: Any) -> None:  # noqa: A002 - the base class names it
        """One structured line per request, on the desk's own logger, instead of the default."""
        log("serve.request", line=format % args)


def main() -> int:
    """Serve until stopped. The exit status is for whoever ran it: 0 on a clean stop."""
    server = HTTPServer((HOST, PORT), Desk)
    log("serve.listening", host=HOST, port=PORT)
    try:
        server.serve_forever()
    except KeyboardInterrupt:
        pass
    finally:
        server.server_close()
        log("serve.stopped")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

**Line by line:**

- `from http.server import BaseHTTPRequestHandler, HTTPServer` — **the standard library, on
  purpose.** Nothing is added to `uv.lock` for two routes. `HTTPServer` handles one request at a
  time, which for a desk that decides claims in order is a feature: two `POST /queue` requests at
  once would be two runs writing the same claim files, and day 10 decided the queue is sequential.
- `HOST = os.environ.get("CLAIMS_DESK_HOST", "127.0.0.1")` and `PORT = int(...)` — **both
  variables, both with the laptop's defaults.** Loopback for day 4's reason; `8080` because the plan
  says so and because it is the port everybody guesses. The container sets the host to every
  interface; the failure below is what sets the port.
- `NOBODY = "SYN-POL-0000"` — **a number no policy has.** The health check reads nothing real and
  leaves a `boundary.fetch_policy` line with `found: false` every time it runs, which is a line a
  reader learns to skip and the audit never sees.
- `innermost` — **the leaf, not the wrapper.** The client library runs its connection in task
  groups, so a refused connection arrives as an `ExceptionGroup` inside an `ExceptionGroup`. The
  first version of this file reported `ExceptionGroup` in the 503 body; the transcript below is what
  it says now.
- `health()` and `except Exception as failure:  # noqa: BLE001` — **catch everything, report
  everything.** A health check is the one place a broad catch is right, because its whole job is to
  turn any failure into a status; the `noqa` says the catch is deliberate, and the `log` line means
  nothing is swallowed.
- `reachable = answer.get("found") is False` — **`found: false` is the pass.** Not `not
  answer.get("found")`, which would pass an empty answer; the boundary must have said, in so many
  words, that it looked and found nothing.
- `self._send(200 if ok else 503, body)` — **503 and not 500.** *Service unavailable* is the status
  that means *not now, try later*, and it is what a load balancer or a compose health check reads
  as *do not send traffic here*. A 500 means the check itself broke.
- `do_POST` and `asyncio.run(run_queue())` — **the old desk, unchanged.** One event loop per
  request, which is what `run_queue` expects; the counts come back as the body.
- `log_message` — **the default request log goes to the desk's logger** as a `serve.request`
  event, so a request is one JSON line beside the desk's other lines rather than a bare text line in
  a different format on the same stream.
- `main()` and `KeyboardInterrupt` — **a clean stop is exit 0**, and the `finally` closes the socket
  either way, so the port is free for the next start.


**Line by line:**

- `PLANNED` **is empty**, and stays as a dictionary rather than being deleted: day 1's `usage()`
  reads it, and an empty map of what is not built yet is the sentence the driver was designed to be
  able to say.
- `"up": [["docker", "compose", "up", "--build"]]` — **the first command in this driver that is not
  `uv run`**, and the `except FileNotFoundError` is its consequence. On this machine `docker` does
  not exist, and the day-18 driver answered `./run up` with a traceback that names `subprocess.py`
  and `_winapi.CreateProcess`; the day-19 driver answers with one line and exit status 127, the
  shell's own code for *command not found*. Both are below.
- `./run eval` **in the docstring** — day 18 added the command and not the line that documents it.
  The map is only a map if it is complete.

## When it breaks

Take the question out of the health check — the version everybody writes first, because it is
faster and it is always green:

```diff

-    transport = "http" if os.environ.get(boundary.ENDPOINT, "").strip() else "stdio"
-    try:
-        answer = asyncio.run(boundary.fetch_policy(NOBODY))
-    except Exception as failure:  # noqa: BLE001 - reported, never hidden
-        kind = type(innermost(failure)).__name__
-        log("serve.unhealthy", transport=transport, kind=kind)
-        return False, {"ok": False, "boundary": transport, "error": kind}
-    reachable = answer.get("found") is False
-    return reachable, {"ok": reachable, "boundary": transport, "asked": NOBODY}
+    return True, {"ok": True}
```

With the boundary pointed at a port nobody listens on, the same request:

```
HTTP/1.0 200 OK
Server: BaseHTTP/0.6 Python/3.12.12
Content-Type: application/json
Content-Length: 12

{"ok": true}
```

There is no error, and that is the failure. A container reporting healthy with its boundary gone is
a container an orchestrator keeps sending work to, and every `POST /queue` it receives escalates
twelve claims as `provider_unavailable` — day 15's honest escalation, twelve times, on a desk that
said it was fine. Part 5.1's second test is the one that catches this: it points the boundary at a
dead port and asserts `503`. The smallest fix is the question, and the rule is day 17's from the
other side: **a check that cannot fail is not a check.** It is a sign that says *open* and nobody to
turn it round.

## In production

**What a senior writes instead.** Two routes where this has one: `/healthz`, which proves the
process is up and costs nothing, and `/readyz`, which asks the boundary and costs a connection —
because an orchestrator treats the two differently. Unhealthy means restart me; not ready means do
not send me traffic yet. Folding both into one route, as this desk does, means a boundary outage
restarts every desk container in the fleet, which fixes nothing and loses the queue each was
deciding. And a real request log — method, path, status, duration, the trace id from day 17 — so a
slow `/queue` can be found by the same `grep` as a slow claim.

**What degrades at scale.** `HTTPServer` serves one request at a time. A `POST /queue` holds the
only thread for the sixty-four seconds the transcript shows, and every `/healthz` that arrives in
that window waits behind it — so the health check times out at five seconds, the container is
marked unhealthy *because it is busy*, and an orchestrator restarts it mid-queue. At one desk per
region with a morning's post of three hundred notifications, that is a restart every morning, in
every region, at the moment the queue is longest. The answer is not threads; it is that `/queue`
should accept the work and return a reference, and the run should happen somewhere that answering
`/healthz` does not wait for.

**The review comment.** *"`/queue` is a `POST` that anyone who can reach the port can call, and it
runs the whole queue with the desk's key. Loopback on a laptop is fine; in compose the port is
published to the host. Either put a shared secret on the request or do not publish the port — and
say which in the README under *not built*."*

**The interview question.** *"What is the difference between a health check and a readiness check,
and what goes wrong if a service only has the first?"*
