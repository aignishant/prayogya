## One-line answer

Twelve tests, and seven of them read files as text — because an image nobody can build here is
still a `Dockerfile` somebody can misread, and the properties that matter about it are lines a test
can find: the interpreter matches the pin, no key is baked in, the user is not root, the lock is
honoured, and the boundary's port is never published.

## The idea

The inspector cannot open the sealed drive. What they can do is read the card on the box — and the
card says the version, the contents, and what was left out. If the card is wrong, the branch is
wrong, and the card is the thing that can be checked from head office without a courier.

This file is that reading. The image was not built today and the pipeline never ran, so a test
that builds an image or triggers a job is a test that cannot run on this machine — and a test that
cannot run is worse than none, because it goes grey in the report and the grey becomes normal. What
*can* be tested is the text of the files those tools would read: a `Dockerfile` is a list of
instructions, `compose.yaml` and the workflow are YAML, and every property the day argued for is a
line in one of them. The interpreter in `FROM` is the one in `.python-version`. There is no
`GOOGLE_API_KEY` anywhere in the `Dockerfile` or the compose file. `USER desk` exists. `--locked`
and `--no-dev` are on the install. `.env` is in `.dockerignore` and `!.env.example` sits below the
pattern it excepts. `compose.yaml` has exactly one `ports:` key. `./run check` comes before `./run
eval` in the workflow.

Those are string assertions, and they are honest about being weak: a test that greps for `USER
desk` cannot tell whether the line is above or below the `COPY` it should follow. They are also
exactly the assertions that catch what actually happens to these files — somebody "simplifies"
`3.12.12` to `3.12`, somebody adds `ports:` to the boundary to `curl` it once, somebody drops
`--locked` because the pipeline was red for a good reason. Each of those is a one-line change that
looks harmless in review, and each is a red test here.

The other five tests run the one thing in this day that runs: the service. A server on a port the
operating system chooses, a request to `/healthz` with the in-process boundary from day 17's tests,
a request with the boundary pointed at a port nobody listens on, and the leaf-not-wrapper rule for
the error it reports. The `503` test is the one that holds the day's health-check argument: point
the boundary at a dead port and the desk must say so, or a container reporting healthy with its
boundary gone is a container an orchestrator keeps sending work to.

## The mechanism

The whole file, at `tests/test_ship.py`:

```python
"""The desk as a service, and the three files that decide whether a stranger's clone runs.

The image cannot be built by these tests — there is no build tool inside a test — so what is held
here is what a test *can* hold: that the health route answers honestly, that the files an image is
built from say what the day says they say, and that the driver knows the commands the container and
the pipeline will call.
"""

from __future__ import annotations

import json
import pathlib
import threading
import urllib.error
import urllib.request
from contextlib import asynccontextmanager
from http.server import HTTPServer

import pytest
from mcp import Client

from claims_desk import boundary, serve
from claims_mcp import tools
from claims_mcp.server import server

PROJECT = pathlib.Path(__file__).resolve().parent.parent


@pytest.fixture()
def in_process(tmp_path, monkeypatch):
    monkeypatch.setattr(tools.store, "claims", tmp_path / "claims")

    @asynccontextmanager
    async def connected():
        async with Client(server) as client:
            yield client

    monkeypatch.setattr(boundary, "connected", connected)


@pytest.fixture()
def listening():
    """The desk's server on a port the operating system chooses, stopped when the test ends."""
    httpd = HTTPServer(("127.0.0.1", 0), serve.Desk)
    thread = threading.Thread(target=httpd.serve_forever, daemon=True)
    thread.start()
    yield f"http://127.0.0.1:{httpd.server_address[1]}"
    httpd.shutdown()
    httpd.server_close()


def get(url: str) -> tuple[int, dict]:
    try:
        with urllib.request.urlopen(url, timeout=10) as answer:
            return answer.status, json.loads(answer.read())
    except urllib.error.HTTPError as refused:
        return refused.code, json.loads(refused.read())


# --- the health route -----------------------------------------------------------------------------


def test_healthz_is_200_when_the_boundary_answers(in_process, listening) -> None:
    status, body = get(f"{listening}/healthz")
    assert status == 200
    assert body == {"ok": True, "boundary": "stdio", "asked": serve.NOBODY}


def test_healthz_is_503_when_the_boundary_is_gone(listening, monkeypatch) -> None:
    """A health check that cannot fail is not a check. This one asks, and reports the refusal."""
    monkeypatch.setenv(boundary.ENDPOINT, "http://127.0.0.1:9/mcp")
    status, body = get(f"{listening}/healthz")
    assert status == 503
    assert body["ok"] is False
    assert body["boundary"] == "http"
    assert body["error"]


def test_the_health_check_names_the_failure_and_not_the_wrapper() -> None:
    """A refusal arrives as a group inside a group, and `ExceptionGroup` tells nobody anything."""
    leaf = ConnectionRefusedError("refused")
    wrapped = ExceptionGroup("outer", [ExceptionGroup("inner", [leaf])])
    assert serve.innermost(wrapped) is leaf
    assert serve.innermost(leaf) is leaf


def test_healthz_asks_for_a_policy_that_exists_in_no_book(in_process) -> None:
    """The probe reads nothing real: a number no policy has, and `found: false` is the pass."""
    ok, body = serve.health()
    assert ok is True
    assert body["asked"] == "SYN-POL-0000"


def test_any_other_route_is_404_and_says_so(in_process, listening) -> None:
    status, body = get(f"{listening}/decide")
    assert status == 404
    assert body["path"] == "/decide"


def test_the_listener_defaults_to_loopback_and_the_container_overrides_it() -> None:
    """Loopback by default, for day 4's reason; the Dockerfile sets the variable the other way."""
    assert serve.HOST == "127.0.0.1"
    assert serve.PORT == 8080
    dockerfile = (PROJECT / "Dockerfile").read_text(encoding="utf-8")
    assert "ENV CLAIMS_DESK_HOST=0.0.0.0" in dockerfile


# --- the files an image is built from ------------------------------------------------------------


def test_the_image_pins_the_interpreter_this_desk_pinned() -> None:
    dockerfile = (PROJECT / "Dockerfile").read_text(encoding="utf-8")
    pinned = (PROJECT / ".python-version").read_text(encoding="utf-8").strip()
    assert f"FROM python:{pinned}-slim" in dockerfile
    assert "uv:0.12.3" in dockerfile
    assert ":latest" not in dockerfile


def test_the_image_bakes_no_key_and_runs_as_nobody_in_particular() -> None:
    dockerfile = (PROJECT / "Dockerfile").read_text(encoding="utf-8")
    assert "GOOGLE_API_KEY" not in dockerfile
    assert "USER desk" in dockerfile
    assert "--no-dev" in dockerfile
    assert "--locked" in dockerfile


def test_the_image_never_receives_the_env_file() -> None:
    """Day 0's rule for the same file, at the same moment: before it exists."""
    ignored = (PROJECT / ".dockerignore").read_text(encoding="utf-8").splitlines()
    assert ".env" in ignored
    assert "!.env.example" in ignored
    assert ignored.index("!.env.example") > ignored.index(".env.*")
    assert ".git/" in ignored
    assert "data/claims/" in ignored


def test_compose_injects_the_key_and_publishes_only_the_desk() -> None:
    compose = (PROJECT / "compose.yaml").read_text(encoding="utf-8")
    assert "env_file: .env" in compose
    assert "GOOGLE_API_KEY" not in compose
    assert "CLAIMS_BOUNDARY: http://boundary:8931/mcp" in compose
    assert compose.count("ports:") == 1
    assert '"127.0.0.1:8080:8080"' in compose
    assert "condition: service_healthy" in compose


def test_the_workflow_runs_both_gates_in_order_on_a_pinned_uv() -> None:
    workflow = (PROJECT / ".github" / "workflows" / "check.yml").read_text(encoding="utf-8")
    assert 'version: "0.12.3"' in workflow
    assert "uv sync --locked" in workflow
    assert workflow.index("./run check") < workflow.index("./run eval")
    assert "contents: read" in workflow


# --- the driver -----------------------------------------------------------------------------------


def test_the_driver_has_every_command_the_container_and_the_pipeline_call() -> None:
    driver = (PROJECT / "run").read_text(encoding="utf-8")
    for command in ('"serve"', '"up"', '"eval"', '"check"'):
        assert command in driver.split("PLANNED")[0]
    assert "not built yet" in driver
    assert 'PLANNED: dict[str, str] = {\n}' in driver
```

**Line by line:**

- `in_process` — **day 17's boundary fixture, without the session service and the trace reset**,
  because nothing here runs an agent: the health route calls `fetch_policy` and nothing else. Not
  `autouse`, because the `503` test needs the *real* `connected` — the one that reads
  `CLAIMS_BOUNDARY` and tries the dead port — and a fixture that replaced it everywhere would make
  that test pass for the wrong reason.
- `HTTPServer(("127.0.0.1", 0), serve.Desk)` — **port zero: the operating system picks a free
  one.** The first `./run serve` on this machine met a port that was already held; a test that
  hard-coded 8080 would meet the same process and fail for a reason that has nothing to do with the
  desk. The fixture reads the port it was given from `server_address`.
- `threading.Thread(..., daemon=True)` and `httpd.shutdown()` — **the server runs beside the test
  and is stopped by it.** `shutdown` blocks until `serve_forever` returns, and `server_close`
  releases the port; without both, the next test's server would be a second listener on a port the
  first still held.
- `get` and `except urllib.error.HTTPError as refused` — **a 404 or a 503 is an exception to
  `urlopen`**, with the body still readable. The helper returns the status and the parsed body
  either way, so a test asserts on both without caring which side of 400 the status fell.
- `assert body == {"ok": True, "boundary": "stdio", "asked": serve.NOBODY}` — **the whole body,
  equal.** A test that asserted only `ok` would pass a health route that stopped saying which
  boundary it asked or what it asked for — and the transcript in part 1.2 is what the body should
  read, exactly.
- `monkeypatch.setenv(boundary.ENDPOINT, "http://127.0.0.1:9/mcp")` — **port 9, the discard
  port**, which nothing listens on by convention. The connection is refused at once rather than
  timing out, so the test is fast and the failure is a refusal rather than a wait.
- `assert status == 503` — **the assertion the day is about.** With the health check that asks
  nothing, this reads `200`, and the failure transcript below is what that looks like.
- `test_the_health_check_names_the_failure_and_not_the_wrapper` — **a group inside a group, and
  the leaf comes back.** Built by hand, because provoking the client library into raising its real
  nested group is what the `503` test does; this one holds the unwrapping rule on its own, so a
  change to `innermost` that stopped at the first group fails here and not only in a body's text.
- `test_the_image_pins_the_interpreter_this_desk_pinned` — **`.python-version` read, `Dockerfile`
  grepped.** The pin file is the source and the image line is derived; a test that hard-coded
  `3.12.12` twice would pass when both drifted together. `":latest" not in dockerfile` — with the
  colon, because the word appears in a comment explaining why it must not.
- `test_the_image_never_receives_the_env_file` and `ignored.index("!.env.example") >
  ignored.index(".env.*")` — **the order, asserted**, for the reason day 0 gave: a negation above
  the pattern it excepts does nothing, and the file would silently stop shipping the example.
- `compose.count("ports:") == 1` — **one published port in the whole file.** The boundary gaining
  a `ports:` key is the failure part 2.1 ends on; this line is the invariant the other way round,
  and it does not care which service gained it.
- `workflow.index("./run check") < workflow.index("./run eval")` — **the fast gate first.** A
  string position comparison is a crude way to assert step order and exactly as strong as the
  claim: the two commands appear once each, and one comes before the other.
- `assert 'PLANNED: dict[str, str] = {\n}' in driver` — **the map is empty, and still a map.** Day
  1's `usage()` reads it; this asserts both that nothing is left unbuilt and that the structure
  survived to say so.

the same change seen from the reader's side. Somebody who shipped the short version on a Friday
would have a fleet of green containers on Saturday and twelve `provider_unavailable` escalations per
queue from each of them, and the health dashboard would be the last place they looked. The smallest
fix is the nine lines back; the test is what makes the nine lines stay.

## In production

**What a senior writes instead.** The text assertions replaced by tools that understand the files:
a `Dockerfile` linter in the pipeline that knows `USER` should follow `COPY --chown` and that a
`HEALTHCHECK` needs a start period; `docker compose config` to render the compose file and fail on
a key the schema does not know; the workflow file checked by the service's own validator on every
push. And an image test that *does* build — in the pipeline, where Docker exists — and asserts
`id -u` is `1000`, `cat .env` fails, and `python -c "import sys; print(sys.version)"` begins
`3.12.12`. Those are the three build commands part 1.1 leaves as `TODO(me)`, made into a job.

**What degrades at scale.** A string assertion is a snapshot of one wording. `compose.count("ports:")
== 1` is right until a second legitimate service arrives — the audit as a one-shot container, say —
and the fix is to raise the number, at which point the test asserts the count and not the rule. At
a desk per region with a compose file per region, twelve copies of this test drift twelve ways. The
rule survives as a parsed assertion — *no service named `boundary` has a `ports` key* — which is
what the YAML parser this environment happens to have would let a test say, and what the production
note above means by tools that understand the files.

**The review comment.** *"`test_the_image_pins_the_interpreter_this_desk_pinned` asserts the tag
matches `.python-version`. It does not assert the tag *exists*. A typo in the patch version passes
this test and fails the build on a registry lookup twenty minutes later. Either accept that the
build is the test for that, and say so in the docstring, or resolve the tag in the test and mark it
as needing the network."*

**The interview question.** *"You cannot run Docker in your unit tests. What can you still test
about a Dockerfile, what can you not, and where does the rest go?"*
