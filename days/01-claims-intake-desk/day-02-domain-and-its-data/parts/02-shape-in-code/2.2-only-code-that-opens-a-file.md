## One-line answer

One class holds every path this desk knows, hands back domain records rather than JSON, and
replaces a claim file in a single indivisible step — which is what makes the whole thing movable
behind a process boundary tomorrow.

## The idea

The claim file at a branch office is a physical folder, and there is a rule about it that sounds
bureaucratic until you have seen it broken: **the folder does not leave the file room.** You ask
the clerk, the clerk fetches, you read at the desk, the clerk puts it back. Nobody carries a claim
folder to their own desk "just for the afternoon".

The rule is not about tidiness. It is about there being one place that knows where everything is,
one person who can say whether a file is out, and one point at which a policy about who may see
what can be applied at all. The moment three people can walk into the file room, none of those
sentences is true any more.

This desk is about to have several agents in it — an intake, a classifier, a policy checker, an
adjuster, a letter writer — and every one of them will want data. If each of them opens
`data/policies.json` for itself, the desk has five file rooms and no clerk. So this part builds the
clerk: **the only code in this project that opens a file.**

Two contracts, stated before the code, because they are what day 3 will carry across a process
boundary unchanged:

- **The read contract.** Ask by key. Get a domain record, or `None` when there is no such thing.
  Never a half-loaded object and never raw JSON.
- **The write contract.** A claim file is replaced in one indivisible step, or not at all. A reader
  arriving at any moment sees the old contents or the new ones, and never the gap between them.

That second one has a name — **atomic replace**: write the new contents to a temporary file in the
same directory, force them to disk, then move that file over the target. And it is worth the four
extra lines for a reason this part demonstrates rather than asserts.

## The mechanism

The whole file, at `claims_desk/store.py`:

```python
"""The only code in this desk that opens a file.

Two reads and one write, and the write is atomic. Everything above this module asks it for records
and never touches a path — which is what makes it possible, on day 3, to move this whole file
behind a process boundary without a single caller changing.

The read contract: ask by key, get a record or `None`, never a partially-loaded object.
The write contract: a claim file is replaced in one indivisible step, or not at all.
"""

from __future__ import annotations

import json
import os
import tempfile
from collections.abc import Iterator
from pathlib import Path

from claims_desk.domain import Notification, Policy

ROOT = Path(__file__).resolve().parents[1]
DATA = ROOT / "data"
CLAIMS = DATA / "claims"


class Store:
    """The policy store, the notification queue and the claim file, behind one object."""

    def __init__(self, data: Path = DATA) -> None:
        self.data = data
        self.claims = data / "claims"

    def _read_json(self, name: str) -> dict:
        """Read one JSON document whole. A half-read file is never returned to a caller."""
        return json.loads((self.data / name).read_text(encoding="utf-8"))

    def policies(self) -> Iterator[Policy]:
        """Every policy in the store, in file order."""
        for record in self._read_json("policies.json")["policies"]:
            yield Policy.from_record(record)

    def policy(self, number: str) -> Policy | None:
        """One policy by number, or `None` when the store has never heard of it.

        `None` rather than an exception: a notification quoting a policy number that does not
        exist is an ordinary Tuesday at an intake desk, and it has a letter of its own.
        """
        for policy in self.policies():
            if policy.number == number:
                return policy
        return None

    def notifications(self) -> Iterator[Notification]:
        """Every notification in the queue, in file order."""
        for record in self._read_json("notifications.json")["notifications"]:
            yield Notification.from_record(record)

    def expectations(self) -> dict[str, dict]:
        """The declared correct outcome for each notification, by id.

        Read by tests and, from day 18, by the evalset. **Nothing the desk itself runs may call
        this.** It is the answer key, and it lives beside the questions only because keeping them
        in one file is how they stay in step.
        """
        return {
            record["id"]: record["expected"]
            for record in self._read_json("notifications.json")["notifications"]
        }

    def write_claim(self, claim_id: str, record: dict) -> Path:
        """Write one claim file so that a reader sees the old contents or the new, never neither.

        Writing straight to the target truncates it first, so a reader arriving in that instant
        gets an empty file. This writes a temporary file **in the same directory**, forces it to
        disk, and moves it over the target in one step.
        """
        self.claims.mkdir(parents=True, exist_ok=True)
        target = self.claims / f"{claim_id}.json"
        text = json.dumps(record, indent=2, sort_keys=True) + "\n"
        handle, temporary = tempfile.mkstemp(dir=self.claims, prefix=f".{claim_id}.", suffix=".tmp")
        try:
            with os.fdopen(handle, "w", encoding="utf-8", newline="\n") as writer:
                writer.write(text)
                writer.flush()
                os.fsync(writer.fileno())
            os.replace(temporary, target)
        except BaseException:
            Path(temporary).unlink(missing_ok=True)
            raise
        return target

    def claim(self, claim_id: str) -> dict | None:
        """One claim file by id, or `None` if the desk has not written it yet."""
        path = self.claims / f"{claim_id}.json"
        if not path.exists():
            return None
        return json.loads(path.read_text(encoding="utf-8"))
```

**Line by line:**

- **The module docstring states both contracts before any code.** They are the interface, and on
  day 3 they become the interface of a *process* rather than an object — which is only possible
  because they were written as promises about behaviour rather than as a list of methods.
- `ROOT = Path(__file__).resolve().parents[1]` — one level up from `claims_desk/`, so `DATA` is the
  project's own `data/` directory however the desk was started. Same reasoning as day 1's kit: a
  path computed from the working directory is a path that breaks under a scheduler.
- `DATA` and `CLAIMS` as module constants — the two directories this project knows about, named
  once. `grep -r "data/" claims_desk/` finding only this file is the property that makes the
  boundary possible.
- `class Store:` with `__init__(self, data: Path = DATA)` — **the data directory is a parameter
  with a default.** The default is what the desk uses; the parameter is what lets a test point it
  at a temporary directory and write real files without touching the project's own. A class that
  hard-codes its paths can only be tested by a test that is careful, and careful is not a property
  code has.
- `def _read_json(self, name)` — the leading underscore says "not part of the contract". Every read
  goes through it, so the day this becomes a network call there is one place to change.
- `json.loads((self.data / name).read_text(encoding="utf-8"))` — **read the whole file, then
  parse.** Not a streaming parse: the read contract says a caller never gets a partially-loaded
  object, and the simplest way to keep that promise is to have the whole document in memory before
  anything is built from it. `encoding="utf-8"` explicitly, because the default depends on the
  machine and a policyholder's address may not be ASCII.
- `def policies(self) -> Iterator[Policy]` — **it yields `Policy` objects, not dictionaries.** The
  parsing from part 2.1 happens here, at the edge, so nothing above this line ever sees
  `record["inception"]`.
- `def policy(self, number)` — the keyed read, and it is a **linear scan**. Eight policies, twelve
  notifications: the scan is right for this size and it is honestly slow, re-reading and re-parsing
  the whole store on every call. Making it fast is not this file's job; day 3 moves it behind a
  process that can hold an index, and doing it before then would be optimising a file that is about
  to move.
- `return None` at the end of `policy` — **the absent case is a value, not an exception.** A
  notification quoting a policy number nobody has heard of is an ordinary intake event with a
  letter of its own, and part 2.1's `assess` takes `Policy | None` for exactly this reason.
- `def expectations(self)` — the answer key, by id, and its docstring is the loudest thing in the
  file: **nothing the desk runs may call this.** It is on the `Store` because it is in the same
  file as the notifications and because the tests need it; a reviewer's job is to make sure it
  never appears in `claims_desk/agents/`.
- `def write_claim(self, claim_id, record) -> Path` — the one write in the project, and every line
  of it is about the same promise.
- `self.claims.mkdir(parents=True, exist_ok=True)` — make the directory on demand rather than at
  import. Importing a module should not create directories; a program that has not written anything
  should leave no trace.
- `json.dumps(record, indent=2, sort_keys=True)` — indented and **sorted**, so that two claim files
  for the same claim differ only where the claim differs. An unsorted dump makes every rewrite look
  like a change, which matters the moment these files are compared or committed.
- `tempfile.mkstemp(dir=self.claims, ...)` — **`dir=` is the load-bearing argument.** The temporary
  file must be on the same filesystem as the target, or the move at the end is a copy and stops
  being atomic. Putting it in the same directory is the only reliable way to be sure.
- `prefix=f".{claim_id}."` — the temporary file is named after the claim and starts with a dot, so
  a half-written `FNOL-4471` is recognisable if it is ever left behind, and hidden from an ordinary
  listing while it exists.
- `os.fdopen(handle, "w", ...)` — `mkstemp` returns an open file **descriptor**, not a path opened
  for you. Wrapping it rather than opening the path again is what closes the window in which
  another process could have replaced the file between the two operations.
- `writer.flush()` then `os.fsync(writer.fileno())` — **two different flushes.** `flush` empties
  Python's buffer into the operating system; `fsync` tells the operating system to put it on the
  disk. Without the second one, a power failure can leave the rename done and the contents not,
  which is the one outcome the whole dance exists to prevent.
- `os.replace(temporary, target)` — the atomic step. `os.replace` overwrites an existing file and,
  unlike `os.rename`, behaves the same way on Windows as on POSIX — which is why it is this call
  and not the other one.
- `except BaseException:` with `unlink(missing_ok=True)` and a bare `raise` — **`BaseException`,
  not `Exception`**, so that a `KeyboardInterrupt` also cleans up the temporary file. The bare
  `raise` re-raises the original with its traceback: this handler tidies, it does not decide.
- `return target` — the path that was written, so a caller can log it or read it back without
  reconstructing the name.
- `def claim(self, claim_id)` — the read side of the write, returning `None` for a claim the desk
  has not decided yet, in the same shape as `policy`.

Write the same claim twice and read it back:

```bash
uv run python -c "
from claims_desk.store import Store
s = Store()
s.write_claim('FNOL-4471', {'outcome': 'fast-track', 'version': 1})
print(s.write_claim('FNOL-4471', {'outcome': 'fast-track', 'version': 2}))
print(s.claim('FNOL-4471'))
"
```

```
.../claims-intake-desk/data/claims/FNOL-4471.json
{'outcome': 'fast-track', 'version': 2}
```

**Line by line:**

- The path is returned by the write, with the leading directories shortened here. The file is at
  `data/claims/`, named for the claim, and nothing else in the project knows that.
- The second write replaced the first. **No temporary file is left behind** — part 3.1 asserts that
  with a glob, because a cleanup that happens on the happy path and not on the failing one is the
  usual way this goes wrong.
- `data/claims/` is not in the repository until the desk writes something, which is why it is not
  in `.gitignore` and why nothing today prints it.

## When it breaks

This is what the four extra lines buy. A write straight to the target, interrupted between the
truncate and the write:

```bash
uv run python -c "
import json, pathlib
f = pathlib.Path('data/claims/FNOL-4471.json')
print('before:', f.read_text(encoding='utf-8').strip().replace(chr(10), ' '))
try:
    with open(f, 'w', encoding='utf-8') as writer:
        raise RuntimeError('the process was killed between the truncate and the write')
except RuntimeError as stop:
    print('interrupted:', stop)
print('after:', repr(f.read_text(encoding='utf-8')))
try:
    json.loads(f.read_text(encoding='utf-8'))
except json.JSONDecodeError as broken:
    print('reading it back:', type(broken).__name__ + ':', broken)
"
```

```
before: {   "outcome": "fast-track",   "version": 1 }
interrupted: the process was killed between the truncate and the write
after: ''
reading it back: JSONDecodeError: Expecting value: line 1 column 1 (char 0)
```

Opening a file for writing truncates it **immediately**, before a single byte of the new content
exists. The claim file is now empty, the old decision is gone, the new one was never written, and
the next thing to read it gets `Expecting value: line 1 column 1`. Somebody deployed during a
batch run and found a handful of claim files empty the next morning, with no error in any log,
because the process that emptied them was the one that was killed. The smallest fix is
`write_claim` as printed: a temporary file, an `fsync`, and `os.replace`.

## In production

**What a senior writes instead.** A database, and the whole of `write_claim` becomes a transaction.
The reason this project writes files is that a file is a thing you can look at, and day 3's
boundary is much easier to believe in when you can see what is behind it. What a senior would take
from this file into the database version is not the code, it is the pair of contracts at the top:
**ask by key, get a record or nothing** and **a change is visible all at once or not at all.** Both
survive the change of storage; neither survives being left unstated.

**What degrades at scale.** `policy()` re-reads and re-parses the entire store on every call, so
deciding twelve notifications reads `policies.json` twelve times. At eight policies that is
invisible. At a book of two hundred thousand it is a file read per lookup and a claims desk that
falls over on a Monday morning batch — and the answer is not a cache in this file, it is the
boundary on day 3, which owns the data and can hold an index because it is the only thing that
touches it.

**The review comment.** *"This agent opens `data/policies.json` directly because it only needs one
field. Route it through `Store` — the moment two things open that file, nothing can move it, and
day 3 is about moving it."*

**The interview question.** *"Walk me through what happens on disk when your program writes a file
it is replacing, and tell me at which instant a concurrent reader is in trouble."*
