## One-line answer

Nine tests hold the four promises the rest of this desk will be built on, and the way you learn
whether they hold anything is to break the code on purpose and watch `./run check` go red.

## The idea

The kit bag gets checked before it leaves the office. Camera charged, meter reading zero on a dry
block, forms in date. It takes a moment and it almost always finds nothing — and the one morning
it finds a meter reading 4% on a dry block is the morning it paid for every other morning.

The check has to be able to fail, and somebody has to have seen it fail, or it is not a check. A
meter that reads zero because it is broken passes a test that only looks for zero.

This desk now has four pieces of kit and a registry, and every one of them makes a promise: the key
is never printed, a log line carries no secret, a retry waits what it was told to wait and then
escalates, a budget refuses rather than overspending, and a model name is an exact ID. Those
sentences are worth nothing on their own. This part turns each into a test that can go red, wires
all of them into the door the project is operated through, and then breaks something to prove the
wiring is real.

A term, used from here to day 19: a **gate** is a check whose exit status decides whether work
proceeds. `./run check` is this project's gate. Today it guards a commit; on day 19 the same
command guards a deployment, and the only thing that changes is who is reading the exit status.

## The mechanism

The whole file, at `tests/test_kit.py`:

```python
"""The kit, tested before anything uses it.

Every test here can go red. Between them they hold the four promises the rest of this desk will
be built on: the key is never printed, a log line carries no secret, a retry waits what it was
told to wait and then escalates, and a budget refuses instead of overspending.
"""

from __future__ import annotations

import pytest

from claims_desk import models
from claims_desk.util import keys
from claims_desk.util import logging as desk_logging
from claims_desk.util.backoff import Transient, delays, retry
from claims_desk.util.budget import Budget, BudgetExceeded


def test_require_names_the_variable_and_quotes_no_value(monkeypatch: pytest.MonkeyPatch) -> None:
    monkeypatch.setenv("GOOGLE_API_KEY", "")
    with pytest.raises(keys.MissingKey) as raised:
        keys.require("GOOGLE_API_KEY")
    assert "GOOGLE_API_KEY" in str(raised.value)


def test_load_env_leaves_the_platform_alone(tmp_path, monkeypatch: pytest.MonkeyPatch) -> None:
    env_file = tmp_path / ".env"
    env_file.write_text("GOOGLE_API_KEY=from-the-file\n", encoding="utf-8")
    monkeypatch.setenv("GOOGLE_API_KEY", "from-the-platform")
    assert keys.load_env(env_file) == []
    assert keys.require("GOOGLE_API_KEY") == "from-the-platform"


def test_fingerprint_is_stable_and_is_not_the_secret() -> None:
    tag = keys.fingerprint("AIzaSy-not-a-real-key")
    assert tag == keys.fingerprint("AIzaSy-not-a-real-key")
    assert len(tag) == 12
    assert tag not in "AIzaSy-not-a-real-key"


def test_log_redacts_by_field_name_at_any_depth() -> None:
    record = desk_logging.log(
        "policy.fetched",
        policy="SYN-4471",
        api_key="AIzaSy-not-a-real-key",
        provider={"name": "test-double", "auth_token": "also-not-real"},
    )
    assert record["policy"] == "SYN-4471"
    assert record["api_key"] == desk_logging.REDACTED
    assert record["provider"]["auth_token"] == desk_logging.REDACTED
    assert record["provider"]["name"] == "test-double"


def test_delays_double_and_stop_one_short_of_the_attempts() -> None:
    assert list(delays(attempts=4, base=1.0)) == [1.0, 2.0, 4.0]
    assert list(delays(attempts=1)) == []


def test_retry_prefers_the_interval_the_provider_asked_for() -> None:
    waited: list[float] = []
    attempts = {"n": 0}

    def flaky() -> str:
        attempts["n"] += 1
        if attempts["n"] < 3:
            raise Transient("429 from the policy service", retry_after=7.5)
        return "in force"

    assert retry(flaky, attempts=4, sleep=waited.append) == "in force"
    assert waited == [7.5, 7.5]


def test_retry_escalates_rather_than_inventing_an_answer() -> None:
    def always_busy() -> str:
        raise Transient("429 from the policy service")

    with pytest.raises(Transient):
        retry(always_busy, attempts=3, sleep=lambda _: None)


def test_budget_refuses_and_says_who_spent_what() -> None:
    budget = Budget(limit=5, label="notification SYN-4471")
    for who in ("intake", "classifier", "policy_checker", "adjuster", "letter_writer"):
        budget.spend(who)
    assert budget.remaining == 0
    with pytest.raises(BudgetExceeded) as raised:
        budget.spend("critic")
    assert "critic" in str(raised.value)
    assert "notification SYN-4471" in str(raised.value)


def test_registry_refuses_an_alias_and_the_legacy_default() -> None:
    assert models.pinned(models.PRIMARY) == "gemini-3.8-flash"
    with pytest.raises(models.UnpinnedModel):
        models.pinned("gemini-flash-latest")
    with pytest.raises(models.UnpinnedModel):
        models.pinned(models.LEGACY)
```

**Line by line:**

- **The test names are sentences.** `test_retry_escalates_rather_than_inventing_an_answer` is the
  promise, spelled out, and it is what pytest prints when it fails. A file of
  `test_retry_1`, `test_retry_2` gives a failing CI job nothing to say.
- `import pytest` sits alone above the project imports, and the `claims_desk` imports are grouped
  below it. That grouping is not taste: ruff's `I` rules sort imports into standard library,
  third-party and first-party blocks, and this file failed the lint until they were split.
- `from claims_desk.util import logging as desk_logging` — aliased, because `logging` is a standard
  library name and a file that imports both would be confusing to read even where it is legal.
- `monkeypatch: pytest.MonkeyPatch` — pytest's fixture for changing the environment for the
  duration of one test and putting it back afterwards. **The alternative is a test that sets
  `os.environ` and leaks into every test after it**, which produces the worst kind of failure: one
  that depends on the order tests ran in.
- `monkeypatch.setenv("GOOGLE_API_KEY", "")` — set to **empty**, not deleted. That is the state a
  reader lands in when they copy `.env.example` and stop, and it is the case a naive `if name in
  os.environ` would call success.
- `with pytest.raises(keys.MissingKey) as raised:` — the failure is the assertion. `as raised`
  keeps the exception so the next line can check its message.
- `assert "GOOGLE_API_KEY" in str(raised.value)` — the message names the variable. There is
  deliberately no assertion that it does *not* contain the value, because the value here is the
  empty string; the promise about never printing values is held by the code review of `keys.py` and
  by the redaction test below.
- `def test_load_env_leaves_the_platform_alone(tmp_path, ...)` — `tmp_path` is pytest's per-test
  temporary directory, so the test writes a real `.env` file and reads it, rather than mocking the
  filesystem. **A test that mocks the thing it is testing tests the mock.**
- `assert keys.load_env(env_file) == []` — the empty list is the assertion: `load_env` set nothing,
  because the variable was already in the environment. The line after it proves *which* value won.
- `assert tag not in "AIzaSy-not-a-real-key"` — the fingerprint is not a slice of the secret. This
  catches the tempting wrong implementation, `secret[:12]`, which would pass a stability test
  perfectly.
- `record = desk_logging.log(...)` and asserting on the returned dictionary — this is why `log`
  returns the record. Capturing standard error and parsing JSON back out would test the same thing
  with three times the code and a new failure mode of its own.
- `assert record["provider"]["auth_token"] == desk_logging.REDACTED` — **the nested case, which is
  the one that matters.** A top-level `api_key` is caught by any implementation; a token two levels
  down is caught only if `redact` recurses.
- `assert record["provider"]["name"] == "test-double"` — and the sibling field survives. Without
  this line, a `redact` that replaced everything inside a dictionary would pass.
- `assert list(delays(attempts=4, base=1.0)) == [1.0, 2.0, 4.0]` — the schedule as data. Three
  waits for four attempts, doubling, asserted in one line because `delays` was written as its own
  function.
- `assert list(delays(attempts=1)) == []` — the edge that a `range(attempts - 1)` without the
  `max(..., 0)` would get wrong.
- `attempts = {"n": 0}` and `attempts["n"] += 1` — a dictionary as the counter, because a plain
  integer would need `nonlocal`. It is a small ugliness kept in preference to a fixture, so the
  test reads top to bottom.
- `raise Transient("429 from the policy service", retry_after=7.5)` — the provider's instruction,
  and `7.5` is chosen precisely because it is **not** on the doubling schedule. If the code ignored
  `retry_after`, the assertion below would see `[1.0, 2.0]` and say so.
- `assert waited == [7.5, 7.5]` — both waits honoured the instruction. This is the test that would
  catch the most plausible bug in `backoff.py`: computing the doubling first and using it always.
- `retry(always_busy, attempts=3, sleep=lambda _: None)` — a sleep that does nothing, so the
  escalation test costs no time at all. `pytest.raises(Transient)` **is** the promise: the failure
  reaches the caller rather than being converted into a plausible answer.
- `for who in ("intake", "classifier", "policy_checker", "adjuster", "letter_writer")` — the actual
  cast from this project's brief, spending one call each. The test is a rehearsal of day 9.
- `assert "critic" in str(raised.value)` and `assert "notification SYN-4471" in ...` — the refusal
  names who was refused and which claim. Asserting on a message looks fussy until the day somebody
  simplifies the message and takes the diagnosis with it.
- `assert models.pinned(models.PRIMARY) == "gemini-3.8-flash"` — the literal string, not
  `models.PRIMARY` again. Comparing the constant to itself would pass no matter what it held; the
  literal is what makes this a test of the registry's *contents*.

**Line by line:**

- **Three steps, in one command, in the order that fails fastest first.** Lint before tests because
  a typo should not wait for a test suite; tests before the machine check because a broken kit
  matters more than a missing key.
- `All checks passed!` — ruff, on the whole project, with the six rule families from
  `pyproject.toml`.
- `9 passed in 0.03s` — nine tests, and the number is worth reading rather than skipping: a test
  file that stops being collected reports `0 passed` and still exits zero, which is the quietest
  possible way for a gate to stop guarding anything.
- **Day 0's check is the third step, unchanged.** It was written before the package existed and it
  is still the last word on whether the machine is set up.
- `OK check` and exit status 0 — the driver's verdict. On day 19 a CI job reads this number.

## When it breaks

Break the registry on purpose — short-circuit the first guard in `pinned` so that any name is
returned — and run the gate:

```
--- uv run ruff check .
All checks passed!
--- uv run pytest -q
........F                                                                [100%]
================================== FAILURES ===================================
____________ test_registry_refuses_an_alias_and_the_legacy_default ____________

    def test_registry_refuses_an_alias_and_the_legacy_default() -> None:
        assert models.pinned(models.PRIMARY) == "gemini-3.8-flash"
>       with pytest.raises(models.UnpinnedModel):
             ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
E       Failed: DID NOT RAISE UnpinnedModel

tests\test_kit.py:94: Failed
=========================== short test summary info ===========================
FAILED tests/test_kit.py::test_registry_refuses_an_alias_and_the_legacy_default
1 failed, 8 passed in 0.07s

FAIL check: `uv run pytest -q` exited 1
```

Verbatim, from this project. Three things to notice. The lint still passed, because the broken code
was still valid Python — **a linter is not a gate.** The test named the promise that stopped being
true rather than a line number. And the driver stopped there and reported which step failed with
its exit status, so day 0's machine check never ran: there is no point asking whether the key is
present when the kit is broken. Put the guard back and the gate goes green again.

## In production

**What a senior writes instead.** The same three steps, plus type checking, plus coverage with a
floor, plus the eval suite once it exists — and all of it behind the same one command, run
identically by a person and by CI. What they would push back on here is the temptation to add a
step that cannot fail: a "smoke test" that prints a version and exits zero looks like coverage on a
dashboard and guards nothing.

**What degrades at scale.** Nine fast tests are run constantly; a suite that takes long enough to
be annoying gets run on the pull request instead of on the change, and then on the branch instead
of on the pull request. This desk's kit is deliberately testable without waiting — the retry takes
a `sleep` parameter for exactly this reason — because the difference between a gate that runs in
well under a second and one that takes minutes is the difference between a gate people run and a
gate people route around.

**The review comment.** *"This adds `util/rates.py` with no test. What promise does it make, and
what would I have to break for something to go red? If the answer is nothing, it is not part of the
kit yet."*

**The interview question.** *"How do you know your test suite is actually testing anything? Give me
a method that does not involve reading all the tests."*
