## One-line answer

Every model this desk may use is named in one file as an exact ID, and a function refuses anything
else — an alias, the provider's legacy default, or a name nobody registered — so the pin is
enforced by code rather than promised by a comment.

## The idea

The firm's schedule of rates lists the exact make and model of moisture meter an adjuster may use.
Not "a moisture meter". A named instrument, because two instruments give two readings and a claim
declined on a reading has to be defensible a year later, in front of somebody whose job is to ask
which instrument it was.

Now suppose the schedule said "the current standard meter" instead. Every word of that is
reasonable. It is also a name that means a different object each time the supplier revises the
range, and the claim file from March would say the same thing as the claim file from November while
meaning something different.

That is what a model alias is. The provider's own documentation says of a `-latest` name: *"This
alias will get hot-swapped with every new release of a specific model variation."* It is a **model
alias**: a name that stands in for whichever model currently holds a role rather than for a model.
For most software that is a convenience. For a desk that decides whether to fast-track claims, it
means the answer to "what decided this claim" is unanswerable from the repository.

There is a second way to end up unpinned, and it is quieter, because it involves writing nothing at
all. A framework that lets you leave the model unspecified has a default, and defaults are chosen
for compatibility rather than for you. Observed at
`https://ai.google.dev/gemini-api/docs/models` on 2026-09-10, `gemini-3.5-flash` is described by
the provider as *"Our legacy Flash model, providing baseline speed and foundational performance
for routine, high-throughput workloads"*, with `gemini-3.6-flash`, `gemini-3.7-flash` and
`gemini-3.8-flash` all newer. An unspecified model is not experimental. It is old, silently, and
three agents means three of them.

So this desk keeps a **registry**: one file naming every model it may use, as an exact ID, with a
function that refuses everything else.

## The mechanism

The whole file, at `claims_desk/models.py` — note the path: this is the desk, not the kit, because
which model decides a claim is a fact about the business and not about infrastructure.

```python
"""Every model this desk may name, pinned to an exact ID, with nothing resolved at run time.

Observed at https://ai.google.dev/gemini-api/docs/models on 2026-09-10:

    gemini-3.8-flash       New Stable  "Our most intelligent Flash model, engineered for
                                        long-horizon software engineering, autonomous agents,
                                        and complex enterprise workflows."
    gemini-3.7-flash       Stable      "Our previous-generation Flash model for complex coding,
                                        agentic workflows, and reliable multi-step execution."
    gemini-3.5-flash       Stable      "Our legacy Flash model, providing baseline speed and
                                        foundational performance for routine, high-throughput
                                        workloads."

The same page says of a `-latest` alias: "This alias will get hot-swapped with every new release
of a specific model variation." A claims desk that changes which model decides a claim, without
a commit, cannot explain a decision it made last month.
"""

from __future__ import annotations

PRIMARY = "gemini-3.8-flash"
FALLBACK = "gemini-3.7-flash"

#: The legacy Flash ID. Named here so the registry can refuse it by name rather than by silence:
#: it is what an unpinned agent can end up on, and this desk never chooses it deliberately.
LEGACY = "gemini-3.5-flash"

ALLOWED = frozenset({PRIMARY, FALLBACK})


class UnpinnedModel(ValueError):
    """A model name this project will not use: an alias, or an ID not in the registry."""


def pinned(name: str) -> str:
    """Return `name` if it is an exact allowed ID, or raise `UnpinnedModel` saying why.

    Called wherever an agent is configured, so the pin is enforced by code rather than promised
    by a comment.
    """
    if name.endswith("-latest"):
        raise UnpinnedModel(
            f"{name!r} is an alias, not a pin: it is hot-swapped on every release, "
            f"so it names whichever model currently holds the role rather than a model"
        )
    if name == LEGACY:
        raise UnpinnedModel(
            f"{name!r} is the provider's legacy Flash model and this desk does not choose it; "
            f"pin {PRIMARY!r} or {FALLBACK!r}"
        )
    if name not in ALLOWED:
        raise UnpinnedModel(f"{name!r} is not in this project's registry: {sorted(ALLOWED)}")
    return name
```

**Line by line:**

- **The docstring carries the observation, with its source and its date.** Three IDs, the
  provider's own words for each, and the sentence about aliases, quoted. When somebody asks in six
  months why this desk is on 3.8, the answer is in the file that made the choice — not in a chat
  message and not in somebody's memory.
- `PRIMARY = "gemini-3.8-flash"` — the model that answers claims. A module-level constant, so every
  agent from day 7 onward names `models.PRIMARY` and there is exactly one line to change when the
  registry is revised.
- `FALLBACK = "gemini-3.7-flash"` — the previous generation, stable, and the second half of the
  fallback chain day 15 builds. It is registered on day 1 so that reliability day has something to
  fall back *to* that this project already vouched for, rather than reaching for whatever is
  available in the middle of an incident.
- `LEGACY = "gemini-3.5-flash"` — **named in order to be refused.** This is the ID an unspecified
  model can land on, and the refusal below is by name rather than by omission, so the message can
  explain what happened instead of saying "not in the registry".
- `ALLOWED = frozenset({PRIMARY, FALLBACK})` — the membership test, and `frozenset` rather than a
  list or a set: it cannot be appended to at run time. A registry that code can add to during a run
  is not a registry.
- `class UnpinnedModel(ValueError)` — a `ValueError`, because that is what it is: a bad value for
  an argument. Subclassing it gives callers something specific to catch and gives this project's
  tests something specific to assert.
- `def pinned(name: str) -> str` — **it returns the name it was given.** That is the whole design:
  it can be wrapped around a value at the point of use — `Agent(model=models.pinned(models.PRIMARY))`
  — so the check happens where the model is chosen, without a separate validation step anybody can
  skip.
- `if name.endswith("-latest")` — the alias check comes **first**, so an alias gets the message
  about aliases rather than the generic "not in the registry". Order in a validation chain is how
  error messages stay useful.
- The alias message says *why*: "it is hot-swapped on every release, so it names whichever model
  currently holds the role rather than a model". A refusal that only says no gets worked around; a
  refusal that explains gets understood.
- `if name == LEGACY` — the second special case, with a message that names both acceptable
  alternatives. Somebody hits this because they copied an example from documentation, and the fix
  is right there in the message.
- `if name not in ALLOWED` — the general case, listing `sorted(ALLOWED)` so the message shows what
  *is* acceptable. `sorted` because a `frozenset` prints in an arbitrary order and an error message
  that changes between runs is one people stop trusting.
- `return name` — the identity return, again, because that is what makes it usable inline.
- **What is deliberately absent: any network call.** This function does not ask the provider
  whether a model exists. It asks whether *this project* has decided to use it, which is a question
  with a different answer and no latency.

Ask it to accept the pin, and to refuse the three ways of not being one:

```bash
uv run python -c "
from claims_desk import models
for name in ('gemini-flash-latest', 'gemini-3.5-flash', 'gemini-4-flash'):
    try:
        models.pinned(name)
    except models.UnpinnedModel as refusal:
        print(f'{name}: {refusal}')
print('pinned:', models.pinned(models.PRIMARY))
"
```

```
gemini-flash-latest: 'gemini-flash-latest' is an alias, not a pin: it is hot-swapped on every release, so it names whichever model currently holds the role rather than a model
gemini-3.5-flash: 'gemini-3.5-flash' is the provider's legacy Flash model and this desk does not choose it; pin 'gemini-3.8-flash' or 'gemini-3.7-flash'
gemini-4-flash: 'gemini-4-flash' is not in this project's registry: ['gemini-3.7-flash', 'gemini-3.8-flash']
pinned: gemini-3.8-flash
```

**Line by line:**

- **Three refusals, three different messages.** Each one names the specific thing that is wrong,
  which is the difference between a guard people route around and a guard people read.
- `gemini-4-flash` is a name that does not exist at all, and the registry does not know that — it
  only knows the name is not registered. **That is the right amount of knowledge**: this file's job
  is to enforce a decision, not to mirror a provider's catalogue.
- `pinned: gemini-3.8-flash` — the accepted case returns the string, unchanged, ready to be handed
  straight to an agent.

## When it breaks

Remove the guard and nothing complains — until the gate does. With the first check in `pinned`
short-circuited so that any name is returned:

```

```

`DID NOT RAISE` is the whole story: the desk would have accepted `gemini-flash-latest` and nothing
at run time would have said so. Somebody weakened the check to unblock an experiment on a Friday,
and without a test the only evidence would have been a claim decided in November by a model that
was not the model in October. The smallest fix is to restore the guard — and the reason the failure
was visible at all is the next part.

## In production

**What a senior writes instead.** The same registry, plus the ID recorded in the decision record
for every claim, so the audit answer is per-decision rather than per-deployment. Day 14 builds that
record. They also review the registry deliberately — a dated entry in `PACKAGES.md` when a model
is added or retired — rather than editing the constant during unrelated work.

**What degrades at scale.** This desk's cast is five agents. If each is configured with a bare
string, moving to a newer model is five edits and the one you miss is the one that keeps answering
in the old model's voice — and no test will notice, because the output is still a plausible claim
decision. With a registry it is one line. On a claims platform with several services sharing a
provider, the same argument applies one level up, and the failure looks like two services
disagreeing about the same policy on the same afternoon.

**The review comment.** *"`Agent(model="gemini-3.8-flash")` — use `models.pinned(models.PRIMARY)`.
Same string today; the difference is that in three months the constant moved and this line did
not."*

**The interview question.** *"Your framework has a default model and your code does not set one.
Argue for why that is a bug rather than a convenience, and say how you would prove it is happening
in a running system."*
