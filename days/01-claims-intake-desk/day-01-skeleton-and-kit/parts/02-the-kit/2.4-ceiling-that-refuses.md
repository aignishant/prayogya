## One-line answer

One object counts model calls for one notification across every agent that touches it, and raises
when the count would exceed its limit — because a ceiling written in a document is not a ceiling.

## The idea

The branch has a spend limit on emergency accommodation. When a house is uninhabitable the
adjuster can authorise a hotel, and the limit is a number, and above that number somebody senior
has to say yes. The limit is not there because hotels are wrong. It is there because a decision
that can be made repeatedly, quickly, under pressure, by a person who is trying to help, needs a
place where it stops and asks.

Notice what makes it work: it is enforced at the moment of authorisation, not reviewed afterwards.
A limit that is checked in next month's report is not a limit, it is a way of finding out.

This desk is about to acquire the same problem. Its cast is `intake` → `classifier` ‖
`policy_checker` → `adjuster` → `letter_writer`, and every one of those is a model call. Five
agents is five calls for one notification before anything goes wrong, and two of them talking to
each other — a drafter and a critic passing a letter back and forth — is unbounded until something
bounds it. Day 9 builds the cast and day 10 builds the loop; this file is what they will be handed.

A **request budget** is a written-down ceiling on how many model calls a unit of work may make,
enforced by code that refuses rather than by a paragraph in a document, and counted **across the
whole cast** rather than per agent. The last clause is the one that gets lost. Five agents with a
limit of three calls each is a limit of fifteen, and nobody ever wrote fifteen down.

The unit here is one notification, because that is the unit an insurer thinks in: this claim cost
this much to process.

## The mechanism

The whole file, at `claims_desk/util/budget.py`:

```python
"""The ceiling on model calls, counted across the whole cast and enforced by refusing.

This desk ends up with five agents working one notification. Five agents is at least five model
calls, and a pair of them talking to each other is unbounded until something bounds it. That
something is this file.
"""

from __future__ import annotations

from dataclasses import dataclass, field


class BudgetExceeded(RuntimeError):
    """The work asked for more model calls than it was allowed.

    Raised rather than returned, and never swallowed into a default answer: the caller is meant
    to stop, not to continue with a claim it could not finish.
    """


@dataclass
class Budget:
    """A ceiling for one unit of work, and a record of who spent what.

    `limit` is calls, not tokens and not money — a count is the only unit every provider agrees
    on, and it is the one a person can hold in their head while reading a trace.
    """

    limit: int
    label: str = "one notification"
    spent: int = 0
    by: dict[str, int] = field(default_factory=dict)

    def spend(self, who: str, calls: int = 1) -> int:
        """Record `calls` against `who`, or refuse. Returns what is left."""
        if self.spent + calls > self.limit:
            raise BudgetExceeded(
                f"{who} asked for call {self.spent + calls} of {self.limit} for {self.label}; "
                f"already spent: {self.by}"
            )
        self.spent += calls
        self.by[who] = self.by.get(who, 0) + calls
        return self.remaining

    @property
    def remaining(self) -> int:
        return self.limit - self.spent
```

**Line by line:**

- `class BudgetExceeded(RuntimeError)` — its own exception type, so a caller can catch exactly this.
  The docstring carries the rule that matters more than the code: **raised, never swallowed into a
  default answer.** A desk that hits its ceiling and writes a fast-track letter anyway has used the
  budget as a suggestion.
- `@dataclass` — the generated `__init__`, `__repr__` and `__eq__` are all wanted here, and the
  class is data plus two small behaviours. Writing the constructor by hand would add six lines
  that say nothing.
- `limit: int` — **calls, not tokens and not money.** Tokens differ per provider and per model;
  money needs a price table that goes stale. A count is the unit every provider agrees on and the
  one a person can hold in their head while reading a trace at speed.
- `label: str = "one notification"` — what this budget is *for*, carried so the refusal message can
  say it. A message that reads "budget exceeded" tells you nothing; one that reads "for
  notification SYN-4471" tells you which claim to look at.
- `spent: int = 0` and `by: dict[str, int]` — the running total and the breakdown. The total
  enforces; the breakdown explains. When the ceiling is hit, the first question is always "which
  agent is looping", and `by` is the answer without a trace.
- `field(default_factory=dict)` — **a dataclass rule with teeth.** A bare `{}` as a default would
  be created once, at class definition, and shared by every `Budget` ever made — so two
  notifications would spend from one dictionary. `default_factory` makes a new one per instance.
- `def spend(self, who: str, calls: int = 1) -> int` — `who` is required and positional, because
  an unattributed spend is exactly the one you cannot debug. `calls` defaults to 1 for the ordinary
  case and exists so a caller that knows it is about to make three can say so.
- `if self.spent + calls > self.limit:` — **the check is before the increment.** The budget is
  never in a state where more has been spent than was allowed; a refusal changes nothing.
- The message: `f"{who} asked for call {self.spent + calls} of {self.limit} for {self.label}; already spent: {self.by}"`
  — who, which call number, out of what, for what, and the full breakdown. Everything a person
  needs to decide whether this is a loop or a genuinely expensive claim, in one line, with no
  further lookups.
- `self.by[who] = self.by.get(who, 0) + calls` — accumulate per agent. `.get(who, 0)` because the
  first spend by an agent has no entry yet.
- `return self.remaining` — the caller learns what is left without asking a second question. A
  caller with a decision to make ("do I run the critic once more?") has the number in hand.
- `@property def remaining` — derived, never stored, so it cannot disagree with `spent`. Two fields
  that must sum to a third are two fields that will eventually not.
- **What is deliberately absent: a reset, and a global instance.** A `Budget` is made per
  notification and thrown away. A module-level budget shared by the whole process would be the
  same bug as the mutable default, one scope up, and it would make two claims processed at once
  compete for one ceiling.

- `adjuster asked for call 3 of 2` — the agent that was refused, the call number it wanted, and the

## When it breaks

Share the breakdown dictionary between instances — the bug `field(default_factory=dict)` exists to
prevent — and the second claim of the day starts life having already spent the first claim's calls:

```
second claim, before it has done anything: {'intake': 1, 'classifier': 1}
same object? True
```

Real output, from a copy of `Budget` with that one line changed. Nothing raised, nothing logged,
and the numbers are entirely plausible — a claim that "used" two calls before it began. What
happens next is worse than an error: the fifth or sixth notification of the batch hits the ceiling
and is refused, having done nothing wrong, while the message names an agent that is behaving
correctly. Somebody spends an afternoon looking for a loop in the `adjuster`. The smallest fix is
the line as printed above: `by: dict[str, int] = field(default_factory=dict)`, so every `Budget`
gets its own.

## In production

**What a senior writes instead.** The same object, plus a second ceiling in wall-clock or token
terms, and the count exported as a metric so the average calls-per-notification is visible before
anybody hits a limit. The instinct worth copying is not the class, it is where the enforcement
sits: **at the point of spending, inside the thing that spends.** A budget checked by the caller is
a budget every new caller has to remember.

**What degrades at scale.** Five agents on one notification is five calls; a critic loop that
averages three rounds is eight. On a Monday batch of five hundred notifications that is four
thousand calls against a free-tier key whose actual ceiling is not published as a number — AI
Studio shows the limits for your own account, and day 15 is where this desk meets one for real.
The failure without a budget is not an error message; it is a bill, or a queue that stops moving
while one claim loops.

**The review comment.** *"Each agent gets its own `Budget(limit=3)`. That is not a budget, it is
five budgets — pass one instance through the whole cast, or the number in the design document is
off by a factor of five."*

**The interview question.** *"How would you stop a two-agent writer-and-critic loop from running
forever, and where exactly would you put the check — in the loop, in the agent, or in the thing
that calls the model?"*
