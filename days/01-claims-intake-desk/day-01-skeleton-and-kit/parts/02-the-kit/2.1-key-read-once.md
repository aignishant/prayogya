## One-line answer

One module turns `.env` into a value in memory, refuses loudly when the value is missing, and
offers a fingerprint so a log can say *which* key was used without saying what it is.

## The idea

There is one key to the evidence cupboard at the branch office, and it hangs in a cabinet by the
back door. Adjusters sign it out and sign it back in. Nobody has a copy in a drawer, nobody has one
on their own keyring, and if the key is not in the cabinet at half past eight, somebody says so
immediately — because the whole arrangement depends on there being exactly one place it lives.

The failure mode is not theft. It is the third copy: somebody has a spare cut "just for the week
the cabinet was being moved", and it stays in a coat pocket for a year. Nothing goes wrong, until
the day something does and there is no way to say who had access.

Day 0 put the key in `.env` and made git incapable of holding it. That solved the *storage*
problem and left the *access* problem untouched: any file in this desk could open `.env`, and any
one of them could print what it found. This part closes that by making one module the only reader.

Three terms, defined here because the rest of this desk leans on all three:

- The **process environment** is the set of name-to-string pairs the operating system handed a
  program when it started, which Python exposes as `os.environ`. It is built by whatever launched
  the program and has never heard of any file.
- To **load** a `.env` file is to copy its lines into that environment yourself. Nothing does this
  automatically; there is no platform on which a file called `.env` is consulted by anybody.
- A **fingerprint** is a short, one-way tag derived from a secret, safe to write in a log, useless
  to anybody who reads it, and stable enough to answer one question: is this the same key as
  before?

The cabinet by the back door is `keys.py`. Everything else in this desk asks it.

## The mechanism

The whole file, at `claims_desk/util/keys.py`:

```python
"""The one place this desk turns a file on disk into a secret in memory.

Nothing else in this project opens `.env`, and nothing anywhere prints what it finds. A key
reaches the rest of the desk through `require`, and reaches a log only as a `fingerprint`.
"""

from __future__ import annotations

import hashlib
import os
from pathlib import Path

ROOT = Path(__file__).resolve().parents[2]
ENV_FILE = ROOT / ".env"


class MissingKey(RuntimeError):
    """A required variable is absent or empty. Carries the name and never the value."""


def load_env(path: Path = ENV_FILE) -> list[str]:
    """Copy `name=value` lines from a .env-shaped file into the process environment.

    Returns the names it set, in file order. A name already present in the environment is left
    alone: whatever started this process — a shell, a container runtime, a CI runner — outranks a
    file on one developer's disk.
    """
    if not path.exists():
        return []
    loaded = []
    for line in path.read_text(encoding="utf-8").splitlines():
        line = line.strip()
        if not line or line.startswith("#") or "=" not in line:
            continue
        name, value = line.split("=", 1)
        name, value = name.strip(), value.strip()
        if name and name not in os.environ:
            os.environ[name] = value
            loaded.append(name)
    return loaded


def require(name: str) -> str:
    """The value of `name` from the process environment, or `MissingKey` naming the variable.

    The message quotes the variable and never the value, because an exception message ends up in
    a log, a terminal, a ticket and a screenshot.
    """
    value = os.environ.get(name, "").strip()
    if not value:
        raise MissingKey(f"{name} is not set: copy .env.example to .env and fill the value in")
    return value


def fingerprint(secret: str) -> str:
    """Twelve hex characters of the SHA-256 of a secret: safe to log, useless to an attacker.

    It answers one question and only one — "is this the same key as before?" — which is the
    question that actually comes up when two machines disagree.
    """
    return hashlib.sha256(secret.encode("utf-8")).hexdigest()[:12]
```

**Line by line:**

- **The module docstring states the monopoly**: nothing else opens `.env`. A rule like that is only
  worth writing where it can be checked, and it can be checked here — one `grep` for `.env` across
  the project should find this file and `check.py`, and nothing else.
- `import hashlib` — for the fingerprint, from the standard library. No dependency is added to read
  a file of `name=value` lines; a library that loads `.env` files exists and is perfectly good, and
  writing the twenty lines first is what lets you judge it later.
- `ROOT = Path(__file__).resolve().parents[2]` — **two levels up**, because this file is at
  `claims_desk/util/keys.py` and the `.env` it wants is at the project root. `parents[0]` is
  `util`, `parents[1]` is `claims_desk`, `parents[2]` is the project. Computing it from the file's
  own location rather than from the working directory means the desk finds its key when started by
  a scheduler, a container or a test runner, none of which stand where you stand.
- `class MissingKey(RuntimeError)` — a named exception rather than `KeyError` or a bare
  `RuntimeError`, so a caller can catch exactly this and nothing else. The docstring records the
  rule that governs its message: **the name, never the value.**
- `def load_env(path: Path = ENV_FILE) -> list[str]` — the default is the project's own `.env`, and
  the parameter exists so a test can point it at a temporary file. A function that can only read
  one hard-coded path is a function no test can exercise honestly.
- `if not path.exists(): return []` — **a missing `.env` is not an error here.** In a container
  there is no `.env` at all and the values arrive in the environment already; this function's job
  is to add what is missing, not to insist on a file. The error, when there is one, belongs in
  `require`, at the moment a specific value is actually needed.
- `if not line or line.startswith("#") or "=" not in line: continue` — blanks, comments and
  anything shapeless are skipped. This is the same tiny parser day 0's `check.py` used, and the
  same restraint applies: it does not handle quoting or `export` prefixes, because it only ever
  reads a file this project prints.
- `name, value = line.split("=", 1)` — **split once.** An API key can contain `=`, and splitting on
  every occurrence would turn one value into three fields and set the key to a truncated string
  that still looks plausible.
- `if name and name not in os.environ:` — **the platform wins.** If the variable is already set,
  this function does not touch it. That single condition is what makes the same code correct on a
  laptop with a `.env` and in a container where the platform injected the value: no branch, no
  environment flag, no "if production".
- `loaded.append(name)` and `return loaded` — the *names* it set, never the values. A caller that
  wants to log what happened at startup has something honest to log.
- `def require(name: str) -> str` — the accessor everything else uses. It reads the process
  environment, not the file: by the time anything calls this, loading has either happened or was
  never needed.
- `os.environ.get(name, "").strip()` and `if not value:` — **absent and empty are the same
  failure.** A variable set to the empty string is the exact state day 0's fourth check catches,
  and it is what you get when somebody copies `.env.example` and forgets to fill it in.
- The message `f"{name} is not set: copy .env.example to .env and fill the value in"` — names the
  variable, names the fix, and quotes no value. Exception messages travel: they land in logs,
  tickets, chat messages and screenshots, and every one of those is a place a secret does not
  belong.
- `def fingerprint(secret: str) -> str` — `hashlib.sha256(...).hexdigest()[:12]`. Twelve hex
  characters is enough to distinguish keys you might be holding and far too little to attack; the
  full digest would be equally safe and harder to read at a glance in a log.
- **Why a fingerprint exists at all**: the question that actually comes up is never "what is the
  key", it is "are these two machines using the same one". A fingerprint answers that exactly, and
  answers nothing else.

## When it breaks

Run anything that needs the key with an empty `.env`, and the desk stops with the variable's name
and no value anywhere in sight:

```
Traceback (most recent call last):
  File "<string>", line 3, in <module>
  File "...\claims_desk\util\keys.py", line 51, in require
    raise MissingKey(f"{name} is not set: copy .env.example to .env and fill the value in")
claims_desk.util.keys.MissingKey: GOOGLE_API_KEY is not set: copy .env.example to .env and fill the value in
```

The path is shortened; the rest is verbatim. This is the good version of a bad morning: the desk
refused at the first thing that needed a key, said which variable, and said what to do about it.
The version to be afraid of is the one where a missing key becomes an empty string, travels into a
request, and comes back as an authentication error from a provider three layers away — at which
point the message on the screen is about a service you did not write.

## In production

**What a senior writes instead.** The same shape, with the values coming from a secret manager
rather than a file, and `load_env` reduced to nothing in that environment because everything is
already set. The two habits that survive the change of source are the ones in this file: **one
reader** and **a fingerprint instead of a value**. Both are cheap now and impossible to retrofit
once forty call sites have learned to read `os.environ` for themselves.

**What degrades at scale.** A claims desk answers with a provider key, and provider keys get
rotated — after an exposure, on a schedule, when somebody leaves. Rotation across a service, a
boundary process and a CI job is a coordinated change while a queue keeps arriving, and the only
question that makes it survivable is "which of these is still on the old key?" A fingerprint in
the startup log answers it in seconds. Without one you are comparing prefixes by eye, in a chat
window, with the key on screen.

**The review comment.** *"This logs `key[:8]` to prove the right key loaded. Use
`keys.fingerprint(key)` — a prefix is still part of the secret, and it is the part an attacker uses
to confirm they have found the right one in a dump."*

**The interview question.** *"Your service reads a `.env` file locally and gets its configuration
injected in production. Show me the branch in your code that handles the difference — and if there
isn't one, explain why not."*

## Check yourself

- **Run:** `uv run python -c "from claims_desk.util import keys; print(keys.fingerprint('a'), keys.fingerprint('a'), keys.fingerprint('b'))"`
  — expect the first two to be identical and the third to differ.
- **Say out loud:** `load_env` refuses to overwrite a variable that is already set. Describe the
