## One-line answer

Eleven tests run the real client, the real result envelope and the real refusals against an
in-process boundary — swapping only the transport, at the one function whose job is choosing one —
so the suite exercises everything except the pipe and finishes in seconds rather than in a minute
and a half.

## The idea

The department tests a new procedure by running it, not by reading it. But it does not run it on the
morning's real post: it runs it on a folder of made-up claims, at a desk, with the outgoing tray
swapped for a bin. Everything about the procedure is real — the forms, the rules, the sign-off —
and the one thing that is not is where the letters go.

That substitution has to be made at exactly one point, and it has to be the right one. Swap the
rules and you have tested nothing. Swap the tray and you have tested the procedure.

The desk's version of the tray is `boundary.connected`. Day 4 wrote it as its own context manager
whose entire job is to decide which transport to open, and that was a design choice with no obvious
payoff at the time. This is the payoff: **swapping it gives the tests an in-process boundary while
everything else stays real.** `boundary.call` still runs, so the result envelope, the `is_error`
handling and the structured-content unwrapping are all exercised. The tools still run, against a
real `Store` pointed at a temporary directory. Only the pipe is gone.

The cost of not doing this is measurable, and part 1.1 measured it: ninety-one seconds for one pass
over the queue. A test suite that takes a minute and a half is a test suite people run on the
branch instead of on the change.

## The mechanism

The whole file, at `tests/test_desk.py`:

```python
"""The desk deciding what it can, and refusing to decide the rest.

Every test here runs the real `boundary.call` — the real result envelope, the real `is_error`
handling — against an in-process server. Only the transport is swapped, and it is swapped at
`boundary.connected`, which is the one function whose job is choosing one.

Running these over a subprocess would be honest and would take about a minute and a half, which is
the number part 2.1 quotes and the reason day 9 exists.
"""

from __future__ import annotations

import asyncio
from contextlib import asynccontextmanager

import pytest
from mcp import Client

from claims_desk import boundary, desk
from claims_desk.domain import Notification, Outcome, Reason
from claims_desk.store import Store
from claims_mcp import tools
from claims_mcp.server import server


@pytest.fixture(autouse=True)
def _in_process_boundary(tmp_path, monkeypatch):
    """Swap the transport for an in-process one, and give the boundary a scratch claims dir."""
    monkeypatch.setattr(tools.store, "claims", tmp_path / "claims")

    @asynccontextmanager
    async def connected():
        async with Client(server) as client:
            yield client

    monkeypatch.setattr(boundary, "connected", connected)
    return tmp_path


def test_the_four_rules_run_in_the_order_day_two_fixed() -> None:
    """A notification missing several things is reported on the first rule that fails."""
    broken = Notification(
        id="FNOL-9001",
        policy_number="SYN-POL-9999",
        description="nothing much",
        estimate=100,
        date_of_loss=None,
        contact_ref=None,
    )
    assert desk.rules_that_need_no_reading(broken, False, None) is Reason.MISSING_DATE_OF_LOSS


def test_a_notification_the_rules_can_settle_is_settled() -> None:
    queue = {n.id: n for n in Store().notifications()}
    verdict = asyncio.run(desk.decide(queue["FNOL-4473"]))
    assert verdict.outcome == Outcome.DEFICIENCY
    assert verdict.reason == Reason.MISSING_DATE_OF_LOSS.value
    assert verdict.waiting_for is None
    assert verdict.decided is True


def test_a_notification_the_rules_cannot_settle_is_pending_with_a_reason_why() -> None:
    """Pending is an answer. It says what the desk is waiting for, not that something went wrong."""
    queue = {n.id: n for n in Store().notifications()}
    verdict = asyncio.run(desk.decide(queue["FNOL-4471"]))
    assert verdict.outcome == desk.PENDING
    assert verdict.reason is None
    assert verdict.waiting_for == desk.NEEDS_CLASSIFICATION
    assert verdict.decided is False


def test_the_lapsed_policy_is_settled_by_the_boundary_not_by_the_desk() -> None:
    queue = {n.id: n for n in Store().notifications()}
    verdict = asyncio.run(desk.decide(queue["FNOL-4474"]))
    assert verdict.reason == Reason.POLICY_NOT_IN_FORCE.value


def test_the_whole_queue_splits_four_and_eight() -> None:
    counts = asyncio.run(desk.run_queue())
    assert counts == {"fast-track": 0, "deficiency": 4, "pending": 8}


def test_only_decided_claims_reach_the_claim_file(_in_process_boundary) -> None:
    asyncio.run(desk.run_queue())
    written = sorted(path.stem for path in (_in_process_boundary / "claims").glob("*.json"))
    assert written == ["FNOL-4473", "FNOL-4474", "FNOL-4476", "FNOL-4482"]


def test_a_pending_claim_has_nothing_written_about_it() -> None:
    asyncio.run(desk.run_queue())
    answer = asyncio.run(boundary.read_decision("FNOL-4471"))
    assert answer == {"found": False, "claim_id": "FNOL-4471"}


def test_a_refused_write_stops_the_batch_rather_than_being_counted(monkeypatch) -> None:
    """The boundary refuses as data. A caller that does not read the answer counts a lie.

    Before this was caught, `run_queue` reported four deficiencies while the boundary had refused
    every one of them and written nothing at all.
    """
    real = boundary.record_decision

    async def send_a_reason_the_boundary_will_not_accept(claim_id, outcome, reason=None):
        return await real(claim_id, outcome, "no_date")

    monkeypatch.setattr(boundary, "record_decision", send_a_reason_the_boundary_will_not_accept)
    with pytest.raises(RuntimeError) as raised:
        asyncio.run(desk.run_queue())
    assert "refused to record" in str(raised.value)
    assert "unknown reason" in str(raised.value)


def test_the_letter_tool_refuses_to_write_the_letter() -> None:
    materials = asyncio.run(
        boundary.call(
            "draft_letter", {"claim_id": "FNOL-4477", "reason": "missing_photo_reference"}
        )
    )
    assert materials["drafted"] is False
    assert materials["needed"] == "a photograph of the damage"
    assert "no model" in materials["why"]


def test_the_letter_tool_refuses_a_reason_it_does_not_recognise() -> None:
    materials = asyncio.run(
        boundary.call("draft_letter", {"claim_id": "FNOL-4477", "reason": "no_photo"})
    )
    assert materials["drafted"] is False
    assert "unknown reason" in materials["refused"]


def test_every_reason_this_desk_can_name_has_something_to_ask_for() -> None:
    """A reason code with no `needed` line is a letter that says nothing actionable."""
    for reason in Reason:
        assert reason in tools.WHAT_IS_NEEDED
        assert tools.WHAT_IS_NEEDED[reason].strip()
```

**Line by line:**

- **The module docstring names the trade** — in-process, and what that costs — with the number.
  A reader who wants to know whether these tests are real gets the answer before the imports.
- `from claims_desk import boundary, desk` **and** `from claims_mcp.server import server` — both
  sides, which a test may do and production code may not. The fixture below is the only place they
  meet.
- `@pytest.fixture(autouse=True)` — every test gets it, unrequested. Two tests would write into the
  project without it, and the one that forgot would be the one that did the damage.
- `monkeypatch.setattr(tools.store, "claims", tmp_path / "claims")` — the boundary's real `Store`,
  pointed at a temporary directory. **The atomic write from day 2 really runs**, into real files
  that pytest deletes.
- `@asynccontextmanager async def connected(): async with Client(server) as client: yield client` —
  **five lines, and this is the substitution.** Identical shape to the real `connected()` minus the
  transport choice and the log line.
- `monkeypatch.setattr(boundary, "connected", connected)` — patched **on the module**, so
  `boundary.call` picks it up by attribute lookup at call time. That works because `call` says
  `async with connected()` rather than importing the function into its own namespace, which is a
  small thing to have got right and the reason this is one line.
- **What is deliberately not patched: `boundary.call`.** The `is_error` check, the `RuntimeError` it
  raises, the `dict(result.structured_content or {})` unwrapping — all real, all exercised.
- `return tmp_path` — the fixture hands back the directory, so a test that wants to look at what was
  written can take `_in_process_boundary` as an argument. Only one test does.
- `test_the_four_rules_run_in_the_order_day_two_fixed` — **the only test in the file with no
  boundary at all.** A hand-built `Notification` missing three things at once, asserting the *first*
  rule wins. `is Reason.MISSING_DATE_OF_LOSS` uses identity, which enumeration members allow.
- `queue = {n.id: n for n in Store().notifications()}` — the real fixture set, indexed by id, so each
  test names the notification it is about. `FNOL-4473`, `FNOL-4471` and `FNOL-4474` are chosen
  because each exercises a different branch.
- `assert verdict.waiting_for is None` in the decided case, and `assert verdict.reason is None` in
  the pending one — **each test asserts the field that should be empty as well as the one that
  should be full.** A `Verdict` carrying both would pass a test that only looked at one.
- `test_the_whole_queue_splits_four_and_eight` — the summary, compared as a whole dictionary. This
  is the assertion that will change on day 7, deliberately and visibly, when the classification
  arrives and eight pending become fast-tracks and deficiencies.
- `test_only_decided_claims_reach_the_claim_file` — **the filesystem, checked directly**, by
  globbing the temporary directory. Four names, sorted, compared exactly. This is the test that
  would have caught the failure in part 3.2, and it did not exist until that failure was found.
- `test_a_pending_claim_has_nothing_written_about_it` — the same fact from the other side, through
  `read_decision`, which is how a caller would ask. `{"found": False, ...}` — day 5's honest empty
  answer, arriving at the end of a real run.
- `test_a_refused_write_stops_the_batch_rather_than_being_counted` — **the regression test for a bug
  that shipped in this project's own code for about an hour.** Its docstring says what happened
  rather than what it checks, because the what-happened is the reason anybody would keep it.
- `real = boundary.record_decision` **before** the patch — capturing the genuine function, so the
  substitute calls through to the real boundary with a bad argument rather than faking the refusal.
  **The refusal in this test is produced by the boundary**, not by the test.
- `with pytest.raises(RuntimeError) as raised:` and two `assert ... in str(raised.value)` — the
  escalation, and that the message names both the failure and its cause.
- `test_every_reason_this_desk_can_name_has_something_to_ask_for` — **iterates `Reason`, not
  `WHAT_IS_NEEDED`.** That direction is the whole point: a reason code with no entry is the failure,
  and iterating the dictionary could never find it.
- `assert tools.WHAT_IS_NEEDED[reason].strip()` — non-empty after stripping, so an entry of `""` or
  `" "` fails. Cheap, and it is exactly the value somebody adds as a placeholder.

Run the file:

```bash
uv run pytest tests/test_desk.py -q
```

**Line by line:**

- **Eleven tests in about five seconds**, covering a queue pass that takes ninety-one seconds over a
  real process line. The whole difference is the fixture.
- Two of those tests run `run_queue` end to end — twelve notifications, twenty-eight boundary calls
  each time — and it costs nothing, because in-process a boundary call is a function call with a
  protocol envelope around it.

And two assertions from earlier days had to move, because the docket grew. A **marked diff against
`tests/test_boundary.py` from day 3 part 3.1 and `tests/test_tools.py` from day 5 part 3.1**:

**Line by line:**

- **The third time in four days that a version assertion has gone red on purpose.** Day 4 added a
  resource and a prompt, day 5 added three tools, day 6 adds one — and each time a test stopped the
  work until somebody acknowledged the change.
- The test's **name** changed with it, from `four_tools` to `five_tools`. A test named for a number
  it no longer checks is the kind of small lie that survives for years.
- `draft_letter` at the **end** of the list, because `DECLARED` puts it there, and the docket's order
  is the tuple's order.

## When it breaks

Take the transport substitution out — delete the `monkeypatch.setattr(boundary, "connected", ...)`
line — and every test still passes. That is the uncomfortable part: they pass over real subprocesses
too, because the fixture was never hiding a failure. What changes is only this:

```
11 passed in 96.31s
```

The suite is now slower than everything else in this project put together. Nothing is red, nothing
warns, and the only symptom is that people stop running `./run check` before committing — which is a
failure that arrives weeks later as a broken main branch nobody can attribute to anything.

Somebody would introduce this by "making the tests more realistic", which is a good instinct pointed
at the wrong seam. The smallest fix is to put the line back. The judgement to keep: **substitute the
narrowest thing that removes the cost**, and know exactly what you gave up. Here that is the pipe,
and this project pays for it once, in the one subprocess test day 3 wrote.

## In production

**What a senior writes instead.** The same split, made explicit — a marker or a separate directory
for the tests that use a real transport, so that `pytest -m "not slow"` is the default and the slow
ones run in CI. What they would insist on is that the slow set is **not empty**: an entirely
in-process suite proves the protocol works and never proves the thing you ship starts.

**What degrades at scale.** Two tests here run the whole queue, and each one costs twelve
notifications' worth of work. Add ten more such tests and the in-process suite is slow too — at
which point the answer is not another substitution but a smaller queue: a fixture of two
notifications for the tests that are about the loop, and the full twelve for the one test that is
about the numbers.

**The review comment.** *"This patches `boundary.call` to return a canned dictionary. Patch
`connected` instead — otherwise the `is_error` check, the refusal handling and the structured
content unwrapping are all untested, and those are the parts that have actually broken."*

**The interview question.** *"You have a test suite that talks to a service over a process boundary
and takes too long. Where do you substitute, and how do you decide that you have substituted the
right thing?"*
