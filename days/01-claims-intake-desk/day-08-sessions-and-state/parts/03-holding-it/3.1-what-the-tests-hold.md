## One-line answer

Twelve tests hold the addressing, the accumulation, the isolation between claims, the refusal of
what must not be retained, and both halves of how a failure arrives — and the fixture that makes
them possible is the one that gives each test a session service of its own.

## The idea

A supervisor checking the running-sheet procedure does not check that sheets can be written. They
check the properties the procedure exists for: that a sheet is filed under the claim, that two calls
about one claim end up on one sheet, that a sheet for one claim contains nothing about another, and
that the things which must not be written down are not on it.

Every one of those is a property of the *arrangement* rather than of any particular call, and the
way you test a property is by trying to violate it.

There is one thing about this file worth more attention than the tests themselves. The session
service is a module-level dictionary that nothing evicts — which is the property day 8 spent two
parts on — and that makes it **shared between tests**. A test that ran second would see the
conversations of the test that ran first, and the suite's result would depend on the order pytest
happened to collect it in.

So the first thing in the file is a fixture that replaces the service for every test. It is worth
noticing what that means: **the test suite has to defend itself against the very property under
test.** That is not a smell; it is what testing global state looks like, and the alternative — a
service passed as an argument everywhere — is a real design and a real cost, and the build brief
asks you to weigh it.

## The mechanism

The whole file, at `tests/test_sessions.py`:

```python
"""Sessions: what one holds, how it is addressed, what it refuses, and how a failure arrives.

Every test here runs the real `Runner` against this project's stand-in, and inspects the stored
conversation afterwards through the same service the desk uses.
"""

from __future__ import annotations

import asyncio
import contextlib
from collections.abc import AsyncGenerator

import pytest
from google.adk.models.base_llm import BaseLlm
from google.adk.models.llm_request import LlmRequest
from google.adk.models.llm_response import LlmResponse

from claims_desk import sessions
from claims_desk.agents import classifier
from claims_desk.util.budget import Budget


@pytest.fixture(autouse=True)
def _fresh_sessions(monkeypatch):
    """A new session service per test.

    The module-level service is a dictionary that nothing evicts, so without this every test would
    see the conversations of the ones before it — which is the property under test here, and
    therefore the last thing the tests themselves should rely on.
    """
    from google.adk.sessions import InMemorySessionService

    monkeypatch.setattr(sessions, "service", InMemorySessionService())


class BrokenDouble(BaseLlm):
    """A stand-in that fails. Announced like every other double in this project."""

    model: str = "scripted/broken"

    async def generate_content_async(
        self, llm_request: LlmRequest, stream: bool = False
    ) -> AsyncGenerator[LlmResponse, None]:
        raise RuntimeError("the provider was unreachable")
        yield  # pragma: no cover - unreachable, and required to make this a generator


def test_a_session_is_addressed_by_the_claim_reference() -> None:
    assert sessions.address("FNOL-4471") == "claim-FNOL-4471"


def test_nothing_is_stored_about_a_claim_nobody_has_asked_about() -> None:
    assert asyncio.run(sessions.stored("FNOL-4471")) is None


def test_a_session_accumulates_the_turns_asked_of_it() -> None:
    """One question makes two events: the question and the answer."""

    async def two_questions() -> tuple[int, int]:
        budget = Budget(limit=4)
        await classifier.classify("FNOL-4471", "the flexible hose let go overnight", budget)
        after_one = await sessions.stored("FNOL-4471")
        await classifier.classify("FNOL-4471", "the ridge tiles came off", budget)
        after_two = await sessions.stored("FNOL-4471")
        return len(after_one.events), len(after_two.events)

    one, two = asyncio.run(two_questions())
    assert (one, two) == (2, 4)


def test_one_claims_conversation_is_not_in_another_claims_session() -> None:
    async def ask_about_one() -> object:
        await classifier.classify(
            "FNOL-4471", "the flexible hose let go overnight", Budget(limit=2)
        )
        return await sessions.stored("FNOL-4472")

    assert asyncio.run(ask_about_one()) is None


def test_the_claim_reference_survives_in_state() -> None:
    async def ask() -> dict:
        await classifier.classify(
            "FNOL-4471", "the flexible hose let go overnight", Budget(limit=2)
        )
        stored = await sessions.stored("FNOL-4471")
        return dict(stored.state)

    assert asyncio.run(ask()) == {"claim": "FNOL-4471"}


def test_state_accepts_a_claim_reference() -> None:
    assert sessions.check_state({"claim": "FNOL-4471"}) == {"claim": "FNOL-4471"}


@pytest.mark.parametrize(
    ("state", "smell"),
    [
        ({"contact_ref": "C-3301"}, "contact"),
        ({"api_key": "AIza-not-real"}, "key"),
        ({"holder_phone": "0000"}, "phone"),
        ({"risk_address": "12 Kiln Row"}, "address"),
    ],
)
def test_state_refuses_what_must_not_be_retained(state: dict, smell: str) -> None:
    """Refused by the name of the key, and the refusal says which smell matched."""
    with pytest.raises(sessions.ForbiddenState) as raised:
        sessions.check_state(state)
    assert smell in str(raised.value)


def test_a_failure_arrives_as_an_exception() -> None:
    agent = classifier.build(BrokenDouble())
    with pytest.raises(RuntimeError, match="the provider was unreachable"):
        asyncio.run(sessions.turn(agent, "FNOL-9999", "anything at all"))


def test_a_failure_also_arrives_as_an_event_in_the_conversation() -> None:
    """The run's own record carries the failure. The exception is not the only trace."""

    async def fail_then_look() -> list:
        agent = classifier.build(BrokenDouble())
        with contextlib.suppress(RuntimeError):
            await sessions.turn(agent, "FNOL-9999", "anything at all")
        stored = await sessions.stored("FNOL-9999")
        return list(stored.events)

    events = asyncio.run(fail_then_look())
    assert len(events) == 2
    failure = events[-1]
    assert failure.author == "classifier"
    assert failure.error_code == "RuntimeError"
    assert failure.error_message == "the provider was unreachable"
    assert failure.content is None
    assert failure.is_final_response() is True
```

**Line by line:**

- `@pytest.fixture(autouse=True) def _fresh_sessions(monkeypatch)` — **the defence described above**,
  and its docstring says the awkward thing out loud: the tests must not rely on the property they
  exist to check.
- `from google.adk.sessions import InMemorySessionService` **inside the fixture** — a local import
  for one use, keeping the framework out of this file's import block, which is otherwise this
  project's own modules and pytest.
- `monkeypatch.setattr(sessions, "service", InMemorySessionService())` — patched **on the module**,
  so `sessions.turn` and `sessions.stored` both pick it up by attribute lookup. That works because
  those functions say `service.get_session(...)` rather than importing the object into their own
  namespace — the same small thing day 6's fixture relied on with `connected`.
- `class BrokenDouble(BaseLlm)` — **a second stand-in, announced like the first.** `model:
  str = "scripted/broken"`, so it passes day 7's registry for the same reason and appears in any log
  line as a double.
- `raise RuntimeError(...)` followed by `yield` — **the `yield` is unreachable and required.** A
  function containing `yield` is a generator; without it this would be an ordinary coroutine and the
  framework would fail on the wrong thing, in the wrong place, with a message about the signature
  rather than about the provider. `# pragma: no cover` says the line is deliberately never executed.
- `test_a_session_is_addressed_by_the_claim_reference` — one line, asserting the addressing policy
  as a string. Trivial, and it is the test that fails loudly if somebody makes the id a timestamp.
- `test_nothing_is_stored_about_a_claim_nobody_has_asked_about` — `is None`, not an empty session.
  **Absence, not emptiness**, which is the same distinction day 5's `read_decision` draws.
- `test_a_session_accumulates_the_turns_asked_of_it` — **two questions, two measurements, one
  assertion.** `(one, two) == (2, 4)` as a tuple rather than two separate asserts, so a failure
  reports both numbers and you can see whether the first turn or the second went wrong.
- `budget = Budget(limit=4)` — one budget across both questions, deliberately, because this test is
  about the session rather than about cost. A limit of 4 leaves headroom that the test never uses.
- `test_one_claims_conversation_is_not_in_another_claims_session` — **asks about a claim it never
  asked about**, after asking about one it did. This is the isolation property, and it is the one an
  implementation that used a single shared session id would fail.
- `test_the_claim_reference_survives_in_state` — `dict(stored.state)` compared whole. Comparing the
  whole dictionary means anything *else* appearing in state fails this test, which is a cheap second
  line of defence behind `check_state`.
- `@pytest.mark.parametrize(("state", "smell"), [...])` — **four refusals, four cases**, each naming
  the substring it expects in the message. Asserting on the smell rather than the whole message
  means the wording can improve without breaking four tests, and it still proves the message says
  *which rule* caught you.
- The four cases are chosen to cover both halves of the list: `api_key` is a secret, `contact_ref`
  and `holder_phone` and `risk_address` are personal data. **A test set that only used secrets would
  pass against a version that dropped the four retention words.**
- `test_a_failure_arrives_as_an_exception` — `pytest.raises(RuntimeError, match=...)`. The `match`
  is a regular expression against the message, so this asserts the *provider's* error surfaced
  rather than some other `RuntimeError` from inside the framework.
- `test_a_failure_also_arrives_as_an_event_in_the_conversation` — **the other half, and the reason
  there are two tests rather than one.** A failure that only raised would pass the first test and
  fail this one; a failure that was only recorded would do the opposite. Both are true, and each
  needs saying.
- `with contextlib.suppress(RuntimeError):` — the exception is expected and ignored, because this
  test is about what happened afterwards. Written as `suppress` rather than `try`/`except`/`pass`
  because the linter asked, and the linter was right: it reads as a deliberate discard.
- `assert failure.error_code == "RuntimeError"` — **the exception's class name, as a string, on the
  event.** Not the exception object: an event is a record and a record holds text.
- `assert failure.content is None` and `assert failure.is_final_response() is True` — **the two
  together are the shape of an error event**, and they are the reason part 1.1's read loop is
  guarded by `event.content`. An event can conclude a turn and carry nothing.

Run the file:

```bash
uv run pytest tests/test_sessions.py -q
```

```

12 passed in 1.42s
```

**Line by line:**

- **Twelve tests from eight functions**, the four extras coming from the parametrised refusals.
- `1.42s` — no subprocess, no boundary, no network. These tests exercise the framework's runner and
  session store and this project's own policy, and nothing else.

And five tests from day 7 changed, because `classify` gained an argument. A **marked diff against
`tests/test_agent.py` as printed on day 7 part 3.1**:

```diff
-        classifier.classify("the flexible hose let go overnight", Budget(limit=2))
+        classifier.classify("FNOL-4471", "the flexible hose let go overnight", Budget(limit=2))
```

**Line by line:**

- **Five call sites, one new first argument.** The claim reference is not optional and was not given
  a default, which is why every caller had to be touched — and that is the right cost for a change
  that makes every conversation findable by claim.
- **A default would have been cheaper and worse.** `claim_id: str = "unknown"` would have left five
  tests untouched and quietly filed every conversation in test suites under one address, which is
  the exact failure day 8 exists to prevent.

## When it breaks

Disable the fixture — leave it in place but stop it replacing the service — and run the file:

```
FAILED tests/test_sessions.py::test_a_failure_also_arrives_as_an_event_in_the_conversation
1 failed, 11 passed, 1 warning in 1.51s
```

```
E       AssertionError: assert 4 == 2
E        +  where 4 = len([Event(model_version=None, content=Content(\n  parts=[\n    Part(\n      text='anything at all'\n    ),\n  ],\n  role='user'...
```

Verbatim, from this project. Now run that same test on its own:

```bash
uv run pytest tests/test_sessions.py -q -k "event_in_the_conversation"
```

```
1 passed, 11 deselected, 1 warning in 1.74s
```

**It passes alone and fails with its neighbours**, which is the worst diagnostic a test can offer.

Read what actually happened. `test_a_failure_arrives_as_an_exception` runs first and asks about
`FNOL-9999`, creating a session with two events. `test_a_failure_also_arrives_as_an_event_in_the_conversation`
then asks about the same claim, and finds four. The failing test is **correct**; the test that broke
it is also correct; and neither of them mentions the other.

The message is an arithmetic mismatch — `assert 4 == 2` — followed by a dump of two events, one of
which is a `user` message the reader is not expecting. There is nothing in that output pointing at
the real cause, which is that a module-level dictionary survived from one test into the next.

Somebody meets this as a test that fails in CI and passes locally, or that starts failing when a
colleague adds a test above it. The smallest fix is the fixture. The lesson is the one its docstring
already states: **shared mutable state does not become safe because the tests happen to avoid each
other**, and here they did not even manage that.

## In production

**What a senior writes instead.** The session service passed in rather than reached for — as an
argument to `turn`, or held on an object the desk constructs once — so that "which store does this
use" is answered by reading the call site rather than by knowing what a module-level name currently
points at. This project uses a module global because it keeps `sessions.py` readable in one screen
and the whole desk is one process; that is a real trade, and the build brief asks you to make the
other version and decide.

**What degrades at scale.** Twelve fast tests around a global are fine. The failure arrives when the
suite is parallelised — `pytest -n auto` — and two workers in the same process would share the
dictionary. This project's fixture happens to protect against that too, which is luck rather than
design: the fixture exists for isolation between tests and would need thinking about again for
isolation between workers.

**The review comment.** *"This test asserts `len(session.events) > 0`. Assert the number — two, for
one question — otherwise a change that stops recording the user's message passes, and we lose half
the record without a test noticing."*

**The interview question.** *"A module in your system holds mutable state at import time. What does
that do to your test suite, and what are the two ways out?"*

- **Say out loud:** Two tests assert on the same failure, one for the exception and one for the
