## One-line answer

A session is one stored conversation, held by a service and addressed by a name you choose — and
this desk chooses the claim reference, so everything ever asked about FNOL-4471 is findable by
asking for FNOL-4471 and nothing about another claim is in it.

## The idea

A handler taking a call writes on a running sheet. It is not a transcript and it is not a summary:
it is the sequence of the conversation as it happened, and it is attached to the claim file when
the call ends. Two calls about the same claim produce two blocks on the same sheet. A call about a
different claim goes on a different sheet, in a different file, and the two are never near each
other.

The filing is the point. The sheet is not organised by handler, or by date, or by shift. It is
organised by **the thing it is about**, because that is how anybody will ever look for it — and
because a sheet with two claims on it is a sheet that cannot be sent anywhere without sending both.

Day 7 built an agent and gave it a session with an id that was a placeholder — `"one-notification"`
— and a brand-new session service on every single call. Both of those were fine for a day whose
subject was the agent, and both are wrong now.

A **session** is one stored conversation, identified by an app name, a user and a session id, held
by a **session service** rather than by your code. Your code stops holding the conversation and
holds only the address; the service decides which conversation that names.

So this part chooses the address deliberately, and it chooses one service for the process rather
than one per call. The consequences are immediate: two questions about a claim accumulate on one
sheet, a question about a different claim finds nothing, and the desk's whole exchange about a
notification can be pulled up by its reference.

## The mechanism

The whole file, at `claims_desk/sessions.py`:

```python
"""Where a conversation lives, how it is addressed, and what must never be written into it.

A session is one stored conversation, held by a service rather than by your code. This desk keeps
one session **per notification**, addressed by the claim reference, so that a run's whole exchange
about FNOL-4471 can be found by asking for FNOL-4471 and nothing about claim 4472 is in it.

The half of this file that matters in a claims system is the refusal. A session's `state` is a
dictionary that travels with the conversation, is written into the store, and outlives the turn
that put it there — which makes it exactly the wrong place for a policyholder's telephone number
and exactly the right place for a claim reference.
"""

from __future__ import annotations

from typing import Any

from google.adk.agents import Agent
from google.adk.runners import Runner
from google.adk.sessions import InMemorySessionService, Session

from claims_desk.util.logging import log

#: The app name every session on this desk is filed under. One desk, one app.
APP = "claims-intake-desk"

#: The user a batch run acts as. A real desk would carry the handler's identity here; this one runs
#: unattended, and saying so in a constant is better than a bare string in four call sites.
BATCH_USER = "desk-batch"

#: Substrings that must never appear in a state key. A session's state is written down and kept, so
#: this list is about retention rather than about secrecy alone: a key is a secret, a contact
#: reference is personal data, and neither belongs in a conversation record.
FORBIDDEN_IN_STATE = ("key", "token", "secret", "password", "contact", "phone", "address", "email")

#: The single session service for this process. In-memory: a dictionary that nothing evicts and no
#: restart survives, which is correct for a batch that decides a queue and stops. Day 19's
#: container gets the same behaviour and the same limitation.
service = InMemorySessionService()


class ForbiddenState(ValueError):
    """An attempt to write something into session state that must not be retained there."""


def check_state(state: dict[str, Any]) -> dict[str, Any]:
    """Return `state` if every key is safe to keep, or refuse and name the key that is not.

    Checked by name rather than by value, for the same reason day 1's logger redacts by name: the
    call site knows what it is passing and the value tells you nothing reliable.
    """
    for key in state:
        lowered = key.lower()
        for smell in FORBIDDEN_IN_STATE:
            if smell in lowered:
                raise ForbiddenState(
                    f"{key!r} must not be written into session state: a session is retained, "
                    f"and {smell!r} names something that should not be"
                )
    return state


def address(claim_id: str) -> str:
    """The session id for one notification. One claim, one conversation, findable by reference."""
    return f"claim-{claim_id}"


async def turn(
    agent: Agent, claim_id: str, question: str, state: dict[str, Any] | None = None
) -> tuple[str, list]:
    """Run one turn for `agent` about `claim_id`, and return the final text and the events.

    Returns the events as well as the answer because the events are the run: they say which agent
    spoke, whether anything failed, and how many steps it took. A caller that only wants the text
    can ignore the second value; a caller debugging a run cannot.
    """
    from google.genai import types

    session_id = address(claim_id)
    existing = await service.get_session(app_name=APP, user_id=BATCH_USER, session_id=session_id)
    if existing is None:
        await service.create_session(
            app_name=APP,
            user_id=BATCH_USER,
            session_id=session_id,
            state=check_state(state or {}),
        )

    runner = Runner(app_name=APP, agent=agent, session_service=service)
    message = types.Content(role="user", parts=[types.Part(text=question)])

    events = []
    answer = ""
    async for event in runner.run_async(
        user_id=BATCH_USER, session_id=session_id, new_message=message
    ):
        events.append(event)
        if event.error_code or event.error_message:
            # An error arrives as an event *and* as a raised exception. Logging it here means the
            # failure is in the run's own record, not only in whatever caught the exception.
            log(
                "session.error_event",
                claim=claim_id,
                author=event.author,
                code=event.error_code,
                message=event.error_message,
            )
        if event.is_final_response() and event.content and event.content.parts:
            answer = "".join(part.text or "" for part in event.content.parts)

    log("session.turn", claim=claim_id, session=session_id, yielded=len(events), chars=len(answer))
    return answer, events


async def stored(claim_id: str) -> Session | None:
    """The stored conversation for one claim, or `None` if nothing has been asked about it."""
    return await service.get_session(
        app_name=APP, user_id=BATCH_USER, session_id=address(claim_id)
    )
```

**Line by line:**

- **The docstring says where a conversation lives and what must not go in it**, in that order,
  because the second is the part somebody will be tempted to skip.
- `APP = "claims-intake-desk"` — a session is addressed by **three** things: an app name, a user
  and a session id. The app name separates this desk's conversations from anything else filing into
  the same store, which matters the moment there is more than one application.
- `BATCH_USER = "desk-batch"` — the second part of the address, and the comment is honest about what
  it stands in for. A real desk carries the handler's identity here and this one runs unattended;
  naming that as a constant makes it a decision rather than a stray string.
- `FORBIDDEN_IN_STATE = ("key", "token", ..., "contact", "phone", "address", "email")` — **eight
  substrings, and the first four are day 1's secret list while the last four are new.** The comment
  says why they are together: *"this list is about retention rather than about secrecy alone."* A
  key is a secret; a contact reference is personal data; a conversation record keeps both far longer
  than either should live.
- `service = InMemorySessionService()` — **one, at module level, for the process.** Day 7 built a
  new one on every call, which meant every conversation was thrown away the instant it ended. The
  comment is honest about what in-memory costs: nothing evicts it and no restart survives it, and
  day 19's container inherits both.
- `class ForbiddenState(ValueError)` — its own type, so a caller can catch exactly this. The name
  says what happened rather than what failed.
- `def check_state(state)` — **checked by key name, not by value**, and the docstring gives the same
  reason day 1's redaction gives: the call site knows what it is passing and a value tells you
  nothing reliable. A telephone number and a claim reference are both short strings of digits and
  letters.
- `for key in state: ... for smell in FORBIDDEN_IN_STATE:` — a nested loop over eight substrings, on
  a dictionary with one or two keys. It runs once per session and it is not worth being clever
  about.
- The refusal message names **both the key and the smell that matched**: `'contact_ref' must not be
  written into session state: ... 'contact' names something that should not be`. A caller who
  disagrees can see exactly which rule caught them and argue with the right thing.
- `return state` on success — **the identity return again**, the same shape as day 1's
  `models.pinned`, so it can be wrapped around a value at the point of use rather than called as a
  separate validation step.
- `def address(claim_id) -> str: return f"claim-{claim_id}"` — **the whole addressing policy, in one
  line.** The prefix is there so a session id is recognisable as one when it appears in a log next
  to a claim reference that is not one.
- `async def turn(agent, claim_id, question, state=None)` — the desk's one way to run a turn.
  Everything above it names a claim; nothing above it constructs a `Runner`.
- `from google.genai import types` **inside the function** — a local import, and an honest
  admission: it is used once, in one line, and hoisting it would put a third framework import at the
  top of a module that is otherwise about policy.
- `existing = await service.get_session(...)` then `if existing is None: create` — **get, then
  create.** Not create-and-ignore-the-error: this is the line that makes a second question about the
  same claim land on the same sheet rather than starting a new one.
- `state=check_state(state or {})` — **checked at the moment of creation**, which is the only moment
  it can be. A session's initial state is written once; anything added later goes through the
  runner's own machinery, which this project does not use yet.
- `Runner(app_name=APP, agent=agent, session_service=service)` — **no `auto_create_session`.** Day 7
  needed it because it never created a session; this file creates one deliberately, so the runner
  can be left strict. A runner that will not run against a session nobody created is a runner that
  cannot silently file a conversation under an address you did not choose.
- `events = []` and `events.append(event)` — **the events are collected, not just consumed.** The
  docstring says why: they are the run. A caller that wants the text ignores them; a caller working
  out what happened cannot.
- `if event.error_code or event.error_message:` — **either**, because a failure can carry one
  without the other, and a run where something went wrong must not depend on which.
- The comment above that log line — *"An error arrives as an event **and** as a raised exception"* —
  is the fact part 3.2 is built on, written where the code reacts to it.
- `if event.is_final_response() and event.content and event.content.parts:` — the same three
  conditions as day 7, and now there is a reason beyond caution: an error event **is** a final
  response with `content` of `None`, so the second condition is doing real work every time something
  fails.
- `log("session.turn", claim=..., session=..., yielded=len(events), chars=...)` — **`yielded`, not
  `events`.** The word matters: the runner yielded this many, and the session now holds more. Part
  2.1 is that difference.
- `async def stored(claim_id) -> Session | None` — the read side, returning `None` for a claim
  nobody has asked about. Same shape as the boundary's `read_decision` from day 5, and for the same
  reason: an absence is an answer.

```bash
uv run python -c "

from claims_desk.agents import classifier
from claims_desk.util.budget import Budget

async def main():
    b = Budget(limit=4)
    await classifier.classify('FNOL-4471', 'the flexible hose let go overnight', b)

    print('after one turn : events in session =', len(s.events), '| state =', dict(s.state))
    await classifier.classify('FNOL-4471', 'the ridge tiles came off', b)
    s = await sessions.stored('FNOL-4471')
    print('after two turns: events in session =', len(s.events), '| state =', dict(s.state))
    print('a different claim:', await sessions.stored('FNOL-4472'))
asyncio.run(main())
"
```

```
after one turn : events in session = 2 | state = {'claim': 'FNOL-4471'}
after two turns: events in session = 4 | state = {'claim': 'FNOL-4471'}
a different claim: None
```

**Line by line:**

- **`events in session = 2` after one question.** The question and the answer. A turn is two events
  in the record even when the runner yielded one, which is part 2.1.
- **`= 4` after two.** The sheet accumulated. This is what a session *is*: nothing was passed from
  the first call to the second by this project's code, and the conversation grew anyway.
- `state = {'claim': 'FNOL-4471'}` — **unchanged across both turns.** State is written when the
  session is created and survives every turn afterwards, which is exactly why the next part is about
  what may go in it.
- **`a different claim: None`.** Not an empty session — no session. Nothing about FNOL-4471 is
  reachable by asking about FNOL-4472, and the desk has never asked about 4472 at all.

## When it breaks

The service is a dictionary in this process, and the docstring says so. Here is what that means,
measured:

```bash
uv run python -c "
import asyncio
from claims_desk import sessions
from claims_desk.agents import classifier
from claims_desk.util.budget import Budget
asyncio.run(classifier.classify('FNOL-4471', 'the flexible hose let go overnight', Budget(limit=2)))
print('this process:', 'found' if asyncio.run(sessions.stored('FNOL-4471')) else 'none')
"
uv run python -c "
import asyncio
from claims_desk import sessions
print('a new process:', 'found' if asyncio.run(sessions.stored('FNOL-4471')) else 'none')
"
```

```
this process: found
a new process: none
```

The conversation exists for exactly as long as the program that had it. Nothing is corrupt and
nothing errored: the second process started with an empty dictionary, because that is what
`InMemorySessionService` is.

Somebody meets this the first time they try to answer a question about yesterday's batch — *what did
the classifier actually say about FNOL-4477?* — and finds that the only record is whatever was
logged. The smallest fix is not a different service; it is knowing which questions this desk can
answer. **What survives a run is the claim file and the log; the conversation does not.** A desk
that needs the conversation to survive needs a session service backed by something that outlives a
process, and choosing one is a decision about retention — which is precisely what the next part is
about.

## In production

**What a senior writes instead.** The same addressing, with a session service backed by a database,
and a retention rule attached to it: conversations about a claim kept for as long as the claim's own
record and no longer. The addressing is the part that survives unchanged — **filed by the thing it
is about** — because it is what makes both retrieval and deletion possible. A store organised by run
id can answer "what happened in this run" and cannot answer "delete everything about this
policyholder".

**What degrades at scale.** One session per notification, twelve notifications, four events each: an
in-memory dictionary is invisible. A morning's several hundred notifications with a five-agent cast
is thousands of events held in one process's heap until it exits, and the first symptom is a batch
that gets slower as it goes. The fix is not a bigger machine; it is that a batch process should be
writing its record out as it goes rather than accumulating one.

**The review comment.** *"The session id is the run's timestamp. Make it the claim reference —
otherwise when somebody asks what we said about a specific claim, the answer is 'search every run',
and when they ask us to delete it, the answer is worse."*

**The interview question.** *"Your agent framework stores conversations. What do you use as the
identifier, and how does that choice affect what you can answer six months later — both for a
support question and for a deletion request?"*
