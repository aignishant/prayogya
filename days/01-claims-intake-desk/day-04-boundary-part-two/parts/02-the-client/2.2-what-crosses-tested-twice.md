## One-line answer

Six more tests: three that the boundary offers what it says it offers, two that the transport is
one environment variable and no branch, and one that the desk still cannot learn a path — and one
assertion from yesterday had to change, which is the version pin doing its job.

## The idea

The department signs off a move of the file room by checking two things, not one. That the folders
still arrive — obviously. And that nobody had to be told anything: the adjusters' forms are
unchanged, the reference numbers are the same, and nothing that used to work now needs a note
pinned to it.

The second check is the one people skip, and it is the one that says whether the move was actually
clean. A migration where every caller changed one line is not a migration, it is a rewrite with a
sympathetic name.

So this file tests two things about the day's work. That the boundary genuinely offers a resource
and a prompt, with the content it claims. And that the transport is **configuration rather than
code**: `target()` returns a launch or a URL depending on one variable, and nothing else in the desk
has an opinion.

There is a third thing in here, and it arrived by accident, which makes it worth more than the other
two. Adding a resource and a prompt moved the boundary's version from `0.1.0` to `0.2.0` — and
yesterday's test pinned `0.1.0`, so it went red. That was not a nuisance. **It is the only mechanism
in this project that notices when the boundary's surface changes**, and it worked on the first
occasion it could have.

## The mechanism

The whole file, at `tests/test_transports.py`:

```python
"""Two transports, one server, and a desk that cannot tell which one it got.

These tests are about the line rather than about the data. The in-process ones check what the
server offers; the subprocess ones check that the desk's own client reaches it and comes back with
the same answer the tool returned.
"""

from __future__ import annotations

import asyncio
import json

from mcp import Client

from claims_desk import boundary
from claims_mcp.server import server


def test_the_server_offers_a_resource_and_a_prompt() -> None:
    async def ask() -> tuple[list[str], list[str]]:
        async with Client(server) as client:
            resources = await client.list_resources()
            prompts = await client.list_prompts()
            return (
                [str(resource.uri) for resource in resources.resources],
                [prompt.name for prompt in prompts.prompts],
            )

    uris, prompts = asyncio.run(ask())
    assert uris == ["claims://cover/perils"]
    assert prompts == ["deficiency_letter"]


def test_the_peril_resource_is_reference_data_not_policies() -> None:
    """A resource is read once; it must not be a way to enumerate the book."""

    async def ask() -> dict:
        async with Client(server) as client:
            body = await client.read_resource("claims://cover/perils")
            return json.loads(body.contents[0].text)

    perils = asyncio.run(ask())
    assert perils["escape-of-water"] == {"photo_required": True}
    assert perils["theft"] == {"photo_required": False}
    assert not any("SYN-POL" in key for key in perils)


def test_the_prompt_names_one_reason_and_forbids_a_promise() -> None:
    async def ask() -> str:
        async with Client(server) as client:
            got = await client.get_prompt(
                "deficiency_letter",
                {"claim_id": "FNOL-4477", "reason": "missing_photo_reference"},
            )
            return got.messages[0].content.text

    text = asyncio.run(ask())
    assert "FNOL-4477" in text
    assert "missing_photo_reference" in text
    assert "Name exactly one missing or failing item" in text
    assert "Do not promise a decision" in text


def test_the_desk_reaches_the_boundary_over_stdio_by_default(monkeypatch) -> None:
    monkeypatch.delenv(boundary.ENDPOINT, raising=False)
    assert boundary.target() is boundary.LAUNCH
    policy = asyncio.run(boundary.fetch_policy("SYN-POL-1004"))
    assert policy["found"] is True
    assert policy["product"] == "motor-private"


def test_an_endpoint_in_the_environment_selects_the_url(monkeypatch) -> None:
    """The choice of transport is one environment variable and no branch in any caller."""
    monkeypatch.setenv(boundary.ENDPOINT, "http://127.0.0.1:8931/mcp")
    assert boundary.target() == "http://127.0.0.1:8931/mcp"


def test_the_desk_never_learns_a_path_from_the_boundary() -> None:
    policy = asyncio.run(boundary.fetch_policy("SYN-POL-1001"))
    flattened = repr(policy)
    for smell in ("data/", "\\\\", ".json", "policies"):
        assert smell not in flattened, f"{smell!r} crossed the boundary"
```

**Line by line:**

- `from claims_desk import boundary` **and** `from claims_mcp.server import server` — this file
  imports both sides, which is legitimate for a test and would be a breach anywhere else. A test
  stands outside the system and checks that two halves agree; production code stands inside one
  half.
- `assert uris == ["claims://cover/perils"]` — **the whole list, exactly**, like day 3's tool
  assertion. A resource appearing without a test noticing is the same failure as a tool appearing.
- `[str(resource.uri) for resource in resources.resources]` — **`str()` is required.** The SDK hands
  back a URI object, and comparing it to a string without converting gives a false negative that
  looks exactly like a missing resource. This was found by the assertion failing on a resource that
  was plainly there.
- `json.loads(body.contents[0].text)` — a resource read comes back as a list of content blocks;
  `[0].text` is the body, and it is a string even though the `mime_type` says JSON. **The protocol
  carries bytes and a type, not a parsed object**, which is the right call and means the caller
  parses.
- `assert perils["escape-of-water"] == {"photo_required": True}` — the whole value, not just the
  boolean, so adding a field to the resource has to come past this test.
- `assert not any("SYN-POL" in key for key in perils)` — **the containment assertion.** The resource
  publishes a vocabulary; if a policy number ever appeared in it, the boundary's promise that there
  is no way to list the book would be false. It is written over the keys because that is where an
  accidental `for policy in store.policies()` would leak them.
- `assert "Do not promise a decision" in text` — **a test on prose**, and it is deliberate. That
  line is a constraint an insurer would be held to, and the reason to assert it is that prompts get
  edited casually in a way code does not. If somebody softens the wording, this goes red and the
  change becomes a conversation.
- `monkeypatch.delenv(boundary.ENDPOINT, raising=False)` — `raising=False` so the test works whether
  or not the variable happens to be set in the shell that ran pytest. A test that only passes on a
  clean environment is a test that fails on somebody's laptop for no reason.
- `assert boundary.target() is boundary.LAUNCH` — **`is`, not `==`.** The default is the one
  module-level object, and identity says so. `==` would also pass for an equal-but-different
  `StdioServerParameters`, which would mean a new one was built per call.
- `policy = asyncio.run(boundary.fetch_policy("SYN-POL-1004"))` — this line launches a real
  subprocess. It is the slowest test in the file and it is the one that proves the desk's client and
  the boundary agree end to end.
- `test_an_endpoint_in_the_environment_selects_the_url` — **asserts on `target()` and opens no
  connection.** Testing the URL branch by actually connecting would need a running server, which
  would make the suite depend on something started by hand. Extracting `target()` in part 2.1 is
  what makes this one line.
- `test_the_desk_never_learns_a_path_from_the_boundary` — the same four smells as day 3's boundary
  test, applied one level further out: through the client, through the desk's own function, on the
  dictionary a caller actually receives. **Day 3 asserted it at the server; this asserts it at the
  consumer**, and the two together mean nothing added in between can reintroduce a path.

And one line elsewhere had to change. This is a **marked diff against `tests/test_boundary.py` as
printed on day 3 part 3.1**:

```diff
     name, version, tools = asyncio.run(ask())
     assert name == "claims-boundary"
-    assert version == "0.1.0"
+    assert version == "0.2.0"
     assert tools == ["fetch_policy"]
```

**Line by line:**

- **This edit is the point of the assertion existing.** The boundary grew a resource and a prompt,
  its declared surface changed, its version moved, and a test went red — in the same commit, before
  anything shipped.
- `assert tools == ["fetch_policy"]` is **unchanged**, and that is worth noticing: the tool list did
  not change today. The version moved because the *docket* changed, of which tools are one third.
- The change is one character and it is not a nuisance edit. Somebody reviewing this commit sees a
  version assertion move and knows to ask what was added.

## When it breaks

Add the policy numbers to the resource **alongside** the perils — the shape a debugging session
actually produces, because nobody removes the working part — and the containment assertion catches
it:

```python
    out = {peril: {"photo_required": peril in PHOTO_REQUIRED_FOR} for peril in known}
    out.update({p.number: {"perils": sorted(p.perils)} for p in store.policies()})  # handy for debugging
    return out
```

```
>       assert not any("SYN-POL" in key for key in perils)
E       assert not True
E        +  where True = any(<generator object test_the_peril_resource_is_reference_data_not_policies.<locals>.<genexpr> at 0x0000022DAC73D080>)

tests\test_transports.py:45: AssertionError
```

Verbatim, from this project. The resource still worked, the client still read it, the JSON was still
valid, and **the two assertions above it still passed** — `escape-of-water` and `theft` were exactly
where they had always been. Only the containment line objected, and what it objected to is that the
boundary's `instructions` had quietly become a lie: a caller reading one resource could now
enumerate the book.

Worth noting what happens if the change is less careful. Replacing the peril keys entirely, rather
than adding to them, fails earlier and less usefully — `KeyError: 'escape-of-water'` from the first
assertion, which reads like a broken resource rather than a leak. **The containment assertion is the
one that names the actual problem, and it only gets the chance when the obvious things still work.**
That is the case worth writing a test for.

## In production

**What a senior writes instead.** The same tests, plus a snapshot of the whole docket — tools,
resources and prompts with their descriptions — checked into the repository and compared on every
run. That turns *any* change to the boundary's surface into a visible diff rather than only the
changes somebody thought to assert on. The version pin here is a cheap approximation of that, and
it is worth having precisely because it is cheap.

**What degrades at scale.** Nineteen seconds is the number to watch. Every test that launches a
subprocess costs about the same, and the temptation as the boundary grows is to write another one
each time — at which point the suite is minutes long and gets run on the branch rather than on the
change. The shape that holds is the one here: the *contract* tested in-process, the *line* tested
once or twice, and nothing tested over a subprocess that could have been tested without one.

**The review comment.** *"This adds a resource and does not touch `test_the_server_offers_a_resource_and_a_prompt`.
Either the assertion is wrong or the resource should not be there — but a boundary that grows a
surface with no test moving is how the thing we agreed not to expose gets exposed."*

**The interview question.** *"You moved a component behind a network boundary and every test still
passes. What would you check to convince yourself the move was real, and what would you expect to
have got slower?"*
