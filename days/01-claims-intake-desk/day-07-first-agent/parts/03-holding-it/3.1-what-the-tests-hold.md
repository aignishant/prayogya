## One-line answer

Twelve tests hold the agent to its remit, the double to its announcements, the budget to its
ceiling and the queue to the numbers `PROJECT.md` promised — and nine tests from days 2 and 6 had to
change, because the desk's shape changed.

## The idea

When the interpreter arrangement was introduced, the department did not only test that
interpretations were correct. It tested the *arrangement*: that the interpreter is on the line only
when needed, that they do not offer opinions, that the practice telephone is a different colour, and
that the handler's own procedure still works.

The last of those is the one people forget. Adding a capability changes what everything around it
does, and a suite that only tests the new thing goes green while the old things quietly mean
something different.

Nine tests from earlier days went red today, and every one of them was right to. `assess` takes a
`Cover` rather than a `Policy`, `decide` takes a budget, `rules_that_need_no_reading` no longer
exists, and the queue's counts moved from four-and-eight-pending to four-and-eight-decided. **None
of those are the new agent's tests failing.** They are the tests that existed doing their job on a
day when the thing underneath them was rebuilt.

## The mechanism

The whole file, at `tests/test_agent.py`:

```python
"""The first agent: what it is asked, what it answers, and what it costs.

Every test here runs the real `Agent`, the real `Runner` and the real event loop against this
project's stand-in model. Nothing contacts a provider, and every answer carries `scripted: true`
so that no transcript from these tests can be mistaken for evidence about a real one.
"""

from __future__ import annotations

import asyncio
from contextlib import asynccontextmanager

import pytest
from mcp import Client

from claims_desk import boundary, desk, models
from claims_desk.agents import classifier
from claims_desk.scripted import SCRIPTED_PREFIX, ScriptedClassifier
from claims_desk.store import Store
from claims_desk.util.budget import Budget, BudgetExceeded
from claims_mcp import tools
from claims_mcp.server import server


@pytest.fixture(autouse=True)
def _in_process_boundary(tmp_path, monkeypatch):
    """The same substitution day 6 made: swap the transport, keep everything else real."""
    monkeypatch.setattr(tools.store, "claims", tmp_path / "claims")

    @asynccontextmanager
    async def connected():
        async with Client(server) as client:
            yield client

    monkeypatch.setattr(boundary, "connected", connected)
    return tmp_path


def test_the_stand_in_announces_itself_in_its_name() -> None:
    assert ScriptedClassifier().model.startswith(SCRIPTED_PREFIX)


def test_the_stand_in_announces_itself_in_every_answer() -> None:
    answer = asyncio.run(
        classifier.classify("the flexible hose let go overnight", Budget(limit=2))
    )
    assert answer["scripted"] is True


def test_the_registry_admits_a_stand_in_because_it_is_announced() -> None:
    """Not an exemption: the prefix is the reason. A double that stops saying so stops passing."""
    double = ScriptedClassifier()
    assert models.pinned(double) is double
    with pytest.raises(models.UnpinnedModel):
        models.pinned("gemini-flash-latest")
    with pytest.raises(models.UnpinnedModel):
        models.pinned(models.LEGACY)


def test_the_agent_is_configured_with_a_pinned_model() -> None:
    agent = classifier.build()
    assert agent.name == "classifier"
    assert agent.model.model.startswith(SCRIPTED_PREFIX)
    assert "Do not decide whether the claim can be fast-tracked" in agent.instruction


def test_the_classifier_reads_a_denial_that_the_keyword_scan_could_not() -> None:
    """FNOL-4471 ends "No one hurt." Day 2's keyword scan called that an injury; this does not."""
    queue = {n.id: n for n in Store().notifications()}
    answer = asyncio.run(
        classifier.classify(queue["FNOL-4471"].description, Budget(limit=2))
    )
    assert answer["loss_type"] == "escape-of-water"
    assert answer["injury_reported"] is False


def test_the_classifier_reports_rather_than_guesses() -> None:
    """A description the stand-in has no answer for is an error, not an invented classification."""
    answer = asyncio.run(classifier.classify("something nobody scripted", Budget(limit=2)))
    assert "error" in answer
    assert "loss_type" not in answer


def test_one_classification_costs_one_call() -> None:
    budget = Budget(limit=2, label="one notification")
    asyncio.run(classifier.classify("the flexible hose let go overnight", budget))
    assert budget.spent == 1
    assert budget.by == {"classifier": 1}


def test_the_budget_refuses_the_third_call() -> None:
    budget = Budget(limit=2, label="one notification")
    for _ in range(2):
        asyncio.run(classifier.classify("the flexible hose let go overnight", budget))
    with pytest.raises(BudgetExceeded):
        asyncio.run(classifier.classify("the flexible hose let go overnight", budget))


def test_a_notification_settled_by_the_field_rules_costs_no_model_call() -> None:
    """FNOL-4473 has no date of loss. Nothing about it depends on reading the description."""
    queue = {n.id: n for n in Store().notifications()}
    budget = Budget(limit=2, label="FNOL-4473")
    verdict = asyncio.run(desk.decide(queue["FNOL-4473"], budget))
    assert verdict.reason == "missing_date_of_loss"
    assert budget.spent == 0


def test_a_notification_that_needs_reading_costs_exactly_one() -> None:
    queue = {n.id: n for n in Store().notifications()}
    budget = Budget(limit=2, label="FNOL-4479")
    verdict = asyncio.run(desk.decide(queue["FNOL-4479"], budget))
    assert verdict.reason == "peril_not_covered"
    assert budget.spent == 1


def test_a_classification_that_fails_leaves_the_claim_pending() -> None:
    """The desk does not decide on a failed reading. It says what it is waiting for."""
    queue = {n.id: n for n in Store().notifications()}
    notification = queue["FNOL-4471"]
    unreadable = notification.__class__(
        id=notification.id,
        policy_number=notification.policy_number,
        description="a description nothing in the script recognises",
        estimate=notification.estimate,
        date_of_loss=notification.date_of_loss,
        photo_ref=notification.photo_ref,
        contact_ref=notification.contact_ref,
    )
    verdict = asyncio.run(desk.decide(unreadable, Budget(limit=2)))
    assert verdict.outcome == desk.PENDING
    assert verdict.waiting_for == desk.NEEDS_CLASSIFICATION
    assert verdict.decided is False


def test_the_whole_queue_now_matches_what_the_brief_promised(_in_process_boundary) -> None:
    """`PROJECT.md`, written on day 0: twelve notifications, four fast-tracked, eight letters."""
    counts = asyncio.run(desk.run_queue())
    assert counts == {"fast-track": 4, "deficiency": 8, "pending": 0}

    import json

    written = sorted((_in_process_boundary / "claims").glob("*.json"))
    assert len(written) == 12
    reasons = [
        json.loads(path.read_text(encoding="utf-8"))["reason"]
        for path in written
        if json.loads(path.read_text(encoding="utf-8"))["reason"] is not None
    ]
    assert len(reasons) == 8
    assert len(set(reasons)) == 8, "eight letters, each naming a different missing field"
```

**Line by line:**

- **The module docstring says what these tests cannot prove**, in the same breath as what they run.
  Everything here is real except the model, and a reader is told before the first import.
- `@pytest.fixture(autouse=True)` — **the same substitution day 6 made**, copied rather than shared.
  Two test files with the same eight-line fixture is duplication; extracting it into a `conftest.py`
  is the obvious fix and it is a rep in the hub, because the argument for keeping a fixture visible
  in the file that depends on it is real and worth making yourself.
- `test_the_stand_in_announces_itself_in_its_name` — one line, and it is the cheapest of the three
  announcements to check. `startswith(SCRIPTED_PREFIX)` uses the constant, so the test and the
  double cannot drift.
- `test_the_stand_in_announces_itself_in_every_answer` — the second announcement, checked through
  the whole agent and runner rather than by calling the double directly. **The flag has to survive
  the round trip**, and a test that called `_answer_for` would not prove that.
- `test_the_registry_admits_a_stand_in_because_it_is_announced` — **three assertions in one test, on
  purpose.** The double passes, an alias is refused, the legacy model is refused. Splitting them
  would lose what the test is about: that the prefix is an addition to the rules rather than a hole
  in them.
- `assert models.pinned(double) is double` — **identity.** `pinned` returns what it was given, and
  `is` says so; `==` would pass for any equal object and would not prove the pass-through.
- `test_the_agent_is_configured_with_a_pinned_model` — the agent's name, its model's prefix, and one
  line of its instruction. Asserting on **the prohibition rather than the purpose** is deliberate:
  "Do not decide whether the claim can be fast-tracked" is the line most likely to be softened, and
  softening it is the change this project would most want to notice.
- `test_the_classifier_reads_a_denial_that_the_keyword_scan_could_not` — **the day-2 payoff, as an
  assertion.** Its docstring names the earlier failure so that anybody reading it knows why this
  particular notification. Note what it is honest about: it proves the *stand-in* reads it
  correctly, which is a fact about the script.
- `test_the_classifier_reports_rather_than_guesses` — `"error" in answer` **and** `"loss_type" not
  in answer`. The second assertion is the one that matters: an implementation that returned an error
  *and* a guess would satisfy the first.
- `test_one_classification_costs_one_call` — `budget.spent == 1` and `budget.by == {"classifier":
  1}`. The breakdown as well as the total, because day 9 has five agents and the breakdown is what
  will matter then.
- `test_the_budget_refuses_the_third_call` — the ceiling, exercised through the real agent. Two
  calls succeed, the third raises. This is day 1's `budget.py` being used for the first time by
  something other than its own unit test.
- `test_a_notification_settled_by_the_field_rules_costs_no_model_call` — **`budget.spent == 0`.**
  The ordering from part 2.1, asserted as a number. If somebody moves the classifier call above the
  field rules, this is the test that objects, and it objects for the right reason: the cost changed,
  not the verdict.
- `test_a_notification_that_needs_reading_costs_exactly_one` — the other side. `peril_not_covered`
  cannot be reached without knowing the peril, so this one must cost a call, and `== 1` says it must
  not cost two.
- `test_a_classification_that_fails_leaves_the_claim_pending` — builds a notification with an
  unreadable description by copying a real one field by field. `notification.__class__(...)` rather
  than importing `Notification` — a small economy, and arguably worse than the import; it is here
  because the test is about *this* notification with one field changed.
- `test_the_whole_queue_now_matches_what_the_brief_promised` — **the day-0 sentence, as a test.** Its
  docstring quotes `PROJECT.md`. The counts, the twelve files, and the eight distinct reasons: every
  clause of the promise except the cold clone and the eval, which are days 19 and 18.
- `assert len(set(reasons)) == 8, "eight letters, each naming a different missing field"` — the same
  distinctness assertion day 2 part 3.1 made about the *fixture*, now made about the desk's actual
  **output**. Day 2 asserted the questions were varied; this asserts the answers are.
- `import json` **inside the function** — local, because one test uses it. Ruff's import rules do not
  object and the reader gets it next to its use.

## When it breaks

Soften the instruction — let the classifier have an opinion about the outcome, which is the change
somebody will genuinely propose — and one test objects:

```
>       assert "Do not decide whether the claim can be fast-tracked" in agent.instruction
E       AssertionError: assert 'Do not decide whether the claim can be fast-tracked' in 'You classify a first-notice-of-loss description...'
```

Verbatim, from this project, after the line was removed from `INSTRUCTION`.

Read what that test is doing, because it is unusual: **it asserts on prose, inside a prompt, by
substring.** That is brittle by every normal standard — rewording the line breaks it — and it is
here for the same reason day 4 asserts on the deficiency letter's wording. The line is a constraint
somebody would be held to, prompts get edited far more casually than code, and a brittle test on a
line that must not change quietly is a feature.

What it cannot do is notice that the prohibition was *weakened while keeping the words*. `Do not
decide whether the claim can be fast-tracked, unless it is obvious` contains the string. That is a
real limit and it is why the hub's build brief asks for a second reader on the instruction rather
than a cleverer test.

## In production

**What a senior writes instead.** The same tests, plus a small evaluation set for the classifier
itself — a dozen descriptions with known answers, scored — because a unit test can say the agent was
*configured* correctly and cannot say it is *right*. That is day 18, and the fixture set from day 2
is already the evaluation set waiting to be used.

**What degrades at scale.** Thirteen tests around one agent is proportionate. Five agents tested this
way is sixty, most of them near-duplicates, and the suite becomes a place where a genuine
regression hides among the noise. The shape that survives is the one starting to appear here:
**properties asserted once across all agents** — every agent's model is pinned, every agent's
instruction contains its prohibitions — with per-agent tests only for what is genuinely per agent.

**The review comment.** *"This adds a third agent and copies eleven tests from the classifier's file
with the names changed. Write the two that are about *this* agent and add it to the parametrised
list for the rest — otherwise the next agent copies twelve."*

**The interview question.** *"You changed a function's signature and nine existing tests went red.
How do you decide which to update, which to delete, and which are telling you the change was
wrong?"*
