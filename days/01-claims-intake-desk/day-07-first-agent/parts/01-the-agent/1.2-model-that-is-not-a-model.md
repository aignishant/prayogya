## One-line answer

A stand-in replays a fixed script, costs nothing, needs no key — and it announces itself three
ways, so that nothing it produces can be mistaken for evidence about a real model.

## The idea

The training room has a telephone on the desk that is not connected to the exchange. Pick it up and
a colleague in the next room plays the caller, from a script, so a new handler can practise taking a
notification without a policyholder on the line.

Everybody involved knows it is not a real call. That is the arrangement working. The failure mode is
not that the practice is fake — it is somebody, weeks later, quoting *"we handled a water damage
call in under two minutes"* as though it had happened. The practice call was real practice and it
was never evidence about real calls, and the only thing keeping those apart is that everyone
remembers which it was.

Memory is a bad mechanism. So the training telephone is a different colour.

This project needs a stand-in for the same reason and takes the same precaution. A **test double**
is an object that stands in for a real dependency so a run can be reproduced exactly — same shape,
none of the work. It proves things about your own code and nothing whatever about the thing it
replaces.

The stand-in here means every day from now can be run by somebody with no API key, no bill and no
rate limit, and reproduced exactly. What it costs is that **no transcript in this project is
evidence about a provider**, and the whole design of this file is about making that impossible to
forget.

## The mechanism

The whole file, at `claims_desk/scripted.py`:

```python
"""A TEST DOUBLE that stands in for a provider, and says so in everything it produces.

This is not a model. It replays a fixed script, calls nothing, costs nothing and knows nothing —
and it exists so that every day from here can be run and reproduced by somebody with no API key.

**It announces itself three ways**, on purpose:

- its `model` name begins with `scripted/`, so any transcript it appears in says what it is;
- it returns `scripted: true` inside every answer it gives;
- `claims_desk.models.pinned` recognises the prefix and lets it through *because* of the prefix,
  rather than by an exemption somebody could forget to remove.

Nothing it emits is evidence about a real model. A run that goes green against this double proves
that **this project's own code** works: the agent is configured, the runner produces events, the
classification reaches the rules. What a provider would actually answer is a `TODO(me)` in the
hub, and it stays one until somebody runs it with a key.
"""

from __future__ import annotations

import json
from collections.abc import AsyncGenerator

from google.adk.models.base_llm import BaseLlm
from google.adk.models.llm_request import LlmRequest
from google.adk.models.llm_response import LlmResponse
from google.genai import types

#: The prefix every stand-in model name carries. `claims_desk.models.pinned` matches on it.
SCRIPTED_PREFIX = "scripted/"

#: What this double answers, keyed by a distinctive phrase in the notification's description.
#: Twelve entries for twelve notifications, written by hand from the same reading a person would
#: do — which is to say they are an answer key, not a model's output, and they are here for the
#: same reason `data/notifications.json` carries one.
CLASSIFICATIONS: dict[str, tuple[str, bool]] = {
    "flexible hose": ("escape-of-water", False),
    "ridge tiles": ("storm", False),
    "tumble dryer": ("fire", False),
    "washing machine outlet": ("escape-of-water", False),
    "shed broken into": ("theft", False),
    "chip pan": ("fire", False),
    "candle left burning": ("fire", False),
    "bookcase came off": ("accidental-damage", True),
    "radiator valve": ("escape-of-water", False),
    "stone off a lorry": ("windscreen", False),
    "mains pipe": ("escape-of-water", False),
    "fence panels": ("storm", False),
}


class ScriptedClassifier(BaseLlm):
    """Replays a classification for a notification description. A stand-in, not a classifier."""

    model: str = SCRIPTED_PREFIX + "claims-classifier"

    @staticmethod
    def _description_from(llm_request: LlmRequest) -> str:
        """The text of the last user turn — which is what the agent was asked about."""
        for content in reversed(llm_request.contents or []):
            if content.role == "user":
                return " ".join(part.text or "" for part in (content.parts or []))
        return ""

    def _answer_for(self, description: str) -> dict[str, object]:
        """Look the description up by phrase, or refuse. A double that guesses is a liar."""
        lowered = description.lower()
        for phrase, (loss_type, injury) in CLASSIFICATIONS.items():
            if phrase in lowered:
                return {
                    "scripted": True,
                    "loss_type": loss_type,
                    "injury_reported": injury,
                }
        return {
            "scripted": True,
            "error": "no scripted answer for this description",
        }

    async def generate_content_async(
        self, llm_request: LlmRequest, stream: bool = False
    ) -> AsyncGenerator[LlmResponse, None]:
        """Yield one response carrying the scripted answer as JSON.

        One response, never partial. A real provider streams and this does not; day 8's part on
        events is where that difference is looked at rather than papered over.
        """
        answer = self._answer_for(self._description_from(llm_request))
        yield LlmResponse(
            content=types.Content(
                role="model",
                parts=[types.Part(text=json.dumps(answer))],
            ),
            turn_complete=True,
        )
```

**Line by line:**

- **The docstring opens with `A TEST DOUBLE`, in capitals**, and the second sentence is *"This is
  not a model."* Anybody who opens this file has been told what it is before they read a line of
  code.
- **The three announcements are listed as a numbered contract**, because they are the mechanism
  rather than a courtesy. Each one covers a different way somebody could be misled: a log line, an
  answer, a configuration.
- **"What a provider would actually answer is a `TODO(me)` in the hub, and it stays one."** — the
  honest limit. This project can prove its own code works and cannot prove anything about a model,
  and the difference is written where the double is defined.
- `SCRIPTED_PREFIX = "scripted/"` — a constant here and imported by `models.py`, so the two agree by
  construction rather than by both spelling the same string.
- `CLASSIFICATIONS: dict[str, tuple[str, bool]]` — **twelve entries for twelve notifications**, and
  the comment is careful about what they are: *an answer key, not a model's output.* Same rule as
  `data/notifications.json`. If these were produced by running a model, every test in this project
  would be checking that the system still agrees with a recording of itself.
- **Keyed by a distinctive phrase, not by the whole description or by an id.** By phrase because a
  test can then send a shortened description and still get an answer; not by id because the double
  must not know which notification it is looking at — it sees a description, like a model would.
- `class ScriptedClassifier(BaseLlm)` — subclassing the framework's model base, which is a pydantic
  model with exactly one field: `model`. That is why the override below is a field declaration
  rather than an assignment in `__init__`.
- `model: str = SCRIPTED_PREFIX + "claims-classifier"` — **the name, built from the prefix.** It
  cannot be given a non-announcing name by accident; it can only be given one on purpose, which is
  part 3.2.
- `_description_from(llm_request)` — walks the request's contents **backwards** looking for the last
  user turn. Backwards because a conversation may have several, and the agent is being asked about
  the most recent one.
- `" ".join(part.text or "" for part in (content.parts or []))` — the same defensive join as the
  runner loop in part 1.1, for the same reason: parts may be empty and a part's text may be `None`.
- `def _answer_for(self, description)` — **"A double that guesses is a liar."** The single most
  important design decision in this file. A stand-in that returned a plausible peril for an unknown
  description would make this project's tests pass on descriptions nobody had thought about, which
  is exactly the confidence a double must not manufacture.
- `for phrase, (loss_type, injury) in CLASSIFICATIONS.items(): if phrase in lowered:` — first match
  wins, over a dictionary whose order is the insertion order. Twelve entries chosen to be mutually
  exclusive; a thirteenth that overlapped would be a bug this loop would hide, which is a fair
  criticism of the design at four times the size.
- `return {"scripted": True, "error": "no scripted answer for this description"}` — **the refusal
  still announces itself.** Even the failure carries the flag, so an error transcript cannot be
  mistaken for a provider's error.
- `async def generate_content_async(self, llm_request, stream=False) -> AsyncGenerator[...]` — the
  one method the framework requires. It is an async generator: a real model yields many responses as
  they stream in, and the signature is shaped for that whether or not an implementation uses it.
- **"One response, never partial."** — and the docstring says so rather than leaving it to be
  discovered. A real provider streams; this yields once with `turn_complete=True`. That difference
  is a real limitation of every transcript in this project, and day 8 is where it is looked at
  rather than papered over.
- `json.dumps(answer)` as the text — the double produces **text**, like a model, and the agent's
  caller parses it, like it would. If the double returned a dictionary directly it would be
  standing in for the parsing as well, and part 1.1's error handling would never run.

**Line by line:**

- **"lets it through *because of the announcement* rather than by an exemption"** — the distinction
  the whole change turns on. There is no `if is_test:` and no environment variable. The registry
  accepts a model whose name says what it is, which means a double that stops saying so stops being
  accepted.
- `def name_of(model: object) -> str:` — extracted, because an agent may now be configured with a
  string ID or with a model object and the registry's business is the name either way.
- `getattr(model, "model", None)` — duck-typed, deliberately. `models.py` does not import anything
  from the framework, so this file stays the project's own decision about which models it will use
  rather than becoming a wrapper around somebody else's class.
- `def pinned[T](model: T) -> T:` — **the type-parameter syntax from day 1 part 2.3**, saying it
  returns what it was given. Day 1's version took and returned a string; this one preserves whatever
  came in, which is what lets `Agent(model=models.pinned(chosen))` work for both kinds.
- `if name.startswith(SCRIPTED_PREFIX): return model` — **checked first**, before the alias and
  legacy rules, because a stand-in named `scripted/anything` is not subject to a registry of
  provider IDs.
- `return model` at the bottom instead of `return name` — the only other change, and it is what
  makes the function usable inline for objects.

## When it breaks

The double's answers are correct and its *behaviour* is not a model's, and the framework says so on
every call:

```
Skipping missing token usage metadata for agent classifier and model scripted/claims-classifier
```

Verbatim, from this project, on standard error. A real provider returns usage metadata — tokens in,
tokens out — and this returns none, so the framework's telemetry has nothing to record and logs the
gap by name.

That warning is worth keeping rather than silencing, because it is a list of everything this project
cannot learn from its own transcripts. **No token counts**, so nothing here can say what a run
costs. **No streaming**, so every event count in this project is one where a real run would have
many. **No latency**, so day 15's retry logic will be exercised against a model that always answers
instantly. **No refusals, no truncation, no rate limits** — none of the things that actually go
wrong with providers.

Somebody would be caught by this the first time they quoted an event count or a timing from this
project as though it described a real system. The smallest fix is not to silence the warning. It is
the hub §9's `TODO(me)`: run one notification with a real key, once, and write down what differs.

## In production

**What a senior writes instead.** The same double, and a second suite — small, marked, excluded from
the default run — that goes against the real provider on demand. The double is what makes the fast
suite possible; the marked suite is what stops the double becoming the only thing anybody ever
tests against. What they would insist on is the naming: a double called `FakeModel` gets used by
accident, and one called `scripted/claims-classifier` announces itself in every log line it touches.

**What degrades at scale.** Twelve scripted answers is a fixture a person can read. At a hundred it
is a second implementation of the classifier — with its own bugs, its own drift from the real
model's behaviour, and a growing temptation to make it "smarter" so that more tests pass. The
discipline is the refusal: the moment the double starts inferring rather than looking up, it has
opinions, and a test suite that passes against a double with opinions is measuring the double.

**The review comment.** *"The stand-in now falls back to `accidental-damage` when it has no scripted
answer, so the new tests pass. Put the refusal back — those tests are now green because our fake
guessed, and we have no idea what the real model would have said."*

**The interview question.** *"You have a test double for a language model. What can a green test
suite against it actually prove, and what would you have to run to learn the rest?"*
