## One-line answer

An `Agent` is a filled-in form — a name, a model, a description and an instruction — and it does no
work; a `Runner` is what runs one, and the whole of this desk's first agent is two questions it is
allowed to answer and five things it is forbidden to do.

## The idea

A caller who does not speak the handler's language is put through to an interpreter. The
arrangement is narrow on purpose. The interpreter renders what the caller said into English and
what the handler said back into the caller's language. They do not advise the caller. They do not
decide whether the claim is covered. If asked, they say that is not their part of the call.

The narrowness is not politeness. It is what makes the interpreter's mistakes *findable*. If an
interpretation is wrong, that is a wrong sentence and somebody can point at it. If an interpreter
who was also advising gets something wrong, nobody can say afterwards whether the problem was the
translation or the advice.

The desk has been waiting six days for an interpreter. Day 2 established that four of its eight
rules need somebody to have read a sentence, and that a keyword scan is not that somebody. Day 6
ran the desk and put two thirds of the queue in a pending tray for exactly that reason.

Today it gets one, and it is given the interpreter's job and nothing else: **which peril is this,
and was anyone hurt.** It does not decide whether the claim can be fast-tracked. That question is
still answered by day 2's rules, from fields, in one place — and the reason is the interpreter's
reason. An agent that also decided the claim would produce mistakes nobody could attribute.

Two words, because they are used interchangeably everywhere and are not the same thing:

- An **agent** is a configuration object: a name, a model, a description, an instruction, and later
  a list of tools. It is filled in, never subclassed, and it does no work on its own. In this
  framework `Agent` and `LlmAgent` are the same class.
- A **runner** is what executes one turn for an agent. It holds the agent and the session service
  and it produces the turn's events as they happen. The agent is the brief; the runner is the work.

## The mechanism

The package first. The whole file, at `claims_desk/agents/__init__.py`:

```python
"""The cast: one module per agent, and nothing else in here.

An agent is an instruction, a description and a pinned model. Everything about *when* an agent runs
belongs to whatever owns the order, so a module in this package holds a `build()` and the prose that
configures it, and no orchestration at all.
"""
```

**Line by line:**

- **A docstring and nothing else**, which is what makes it a package rather than a folder. There is
  no re-export here: a caller says `from claims_desk.agents import classifier`, so the module names
  stay visible at every call site.
- **"one module per agent"** — the rule this package is for. Today there is one; the sentence is
  written now so that the second one has somewhere obvious to go.
- **"no orchestration at all" is a promise this project breaks and then keeps.** Today `classify`
  lives here and does open a session and spend a budget. Day 10 takes all of it out, and this
  sentence is what that day is measured against.

The whole file, at `claims_desk/agents/classifier.py`:

```python
"""The classifier: the one thing in this desk that reads a sentence a person spoke.

It is asked exactly two questions about a notification's description — which peril this is, and
whether anyone was hurt — because those are the two facts day 2's rules need and cannot compute.
It is asked nothing else. An agent that is also allowed to decide the claim is an agent whose
mistakes are indistinguishable from the desk's rules.
"""

from __future__ import annotations

import json
from typing import Any

from google.adk.agents import Agent
from google.adk.runners import Runner
from google.adk.sessions import InMemorySessionService
from google.genai import types

from claims_desk import models
from claims_desk.scripted import ScriptedClassifier
from claims_desk.util.budget import Budget
from claims_desk.util.logging import log

#: The name this agent answers to. It appears in every event the runner emits and in the budget's
#: breakdown, so it is chosen to read well in both.
NAME = "classifier"

#: The app name the session service files conversations under. One desk, one app.
APP = "claims-intake-desk"

#: What the classifier is for, and — more of it — what it must not do. Every prohibition here is
#: a thing a fluent model does by default unless told otherwise.
INSTRUCTION = """You classify a first-notice-of-loss description for an insurance intake desk.

You are given one description, exactly as a caller gave it over the telephone. Answer with a JSON
object and nothing else:

  {"loss_type": "<one of the peril slugs>", "injury_reported": true or false}

The peril slugs are: escape-of-water, fire, theft, storm, accidental-damage, windscreen.

Rules:
- Choose exactly one loss type. If none of the slugs fits, use the closest and say nothing about
  your uncertainty; the desk's rules will refuse it against the policy's cover.
- `injury_reported` is true only if the description says a person was hurt. "No one hurt" is
  false. A damaged object is not an injury.
- Do not decide whether the claim can be fast-tracked. That is not your question.
- Do not mention the policy, the excess, the estimate or any amount.
- Do not add commentary, apology or explanation. The object, and nothing else.
"""


def build(model: Any | None = None) -> Agent:
    """Build the classifier agent, with its model pinned explicitly.

    `model` defaults to this project's stand-in. Passing a real model in is how day 15 runs the
    same agent against a provider without this file changing.
    """
    chosen = model if model is not None else ScriptedClassifier()
    return Agent(
        name=NAME,
        model=models.pinned(chosen),
        description="Reads a loss description and names the peril and whether anyone was hurt.",
        instruction=INSTRUCTION,
    )


async def classify(description: str, budget: Budget) -> dict[str, Any]:
    """Ask the classifier about one description. Spends one call from the budget.

    Returns the parsed answer, or `{"error": ...}` when the model said something that is not the
    object it was asked for. **It never guesses on the model's behalf**: an unparseable answer is
    reported, not repaired.
    """
    budget.spend(NAME)
    agent = build()
    runner = Runner(
        app_name=APP,
        agent=agent,
        session_service=InMemorySessionService(),
        auto_create_session=True,
    )
    message = types.Content(role="user", parts=[types.Part(text=description)])

    answer_text = ""
    events = 0
    async for event in runner.run_async(
        user_id="desk", session_id="one-notification", new_message=message
    ):
        events += 1
        if event.is_final_response() and event.content and event.content.parts:
            answer_text = "".join(part.text or "" for part in event.content.parts)

    log("classifier.answered", model=agent.model.model, events=events, chars=len(answer_text))
    try:
        parsed = json.loads(answer_text)
    except json.JSONDecodeError:
        return {"error": "the classifier did not answer with an object", "said": answer_text[:120]}
    if "loss_type" not in parsed or "injury_reported" not in parsed:
        return {"error": "the classifier's object is missing a field", "said": answer_text[:120]}
    return parsed
```

**Line by line:**

- **The module docstring gives the agent's remit and its prohibition in four lines.** *"An agent
  that is also allowed to decide the claim is an agent whose mistakes are indistinguishable from
  the desk's rules"* — that is the sentence a reviewer should be able to quote back at anybody
  widening this agent's job.
- `from google.adk.agents import Agent` — `Agent` and `LlmAgent` are the same class in this
  framework; `Agent is LlmAgent` is `True`. Using the shorter name consistently means a reader
  never wonders whether two things are meant.
- `NAME = "classifier"` — **a constant, because the name is used three ways**: the agent's identity
  to the runner, the key in the budget's breakdown, and the prefix on this module's log event.
  Three places, one string.
- `APP = "claims-intake-desk"` — the app name a session is filed under. Day 8 is where that matters;
  today it is one desk and one value.
- `INSTRUCTION` as a module-level string — **not inline in `build`**, so it can be read, diffed and
  reviewed as prose. It is the closest thing this project has to a document that a non-programmer
  should sign off.
- **The instruction states the output shape as a literal object**, with the field names and the
  allowed values. A model that has seen the shape is far more likely to produce it than one told to
  "respond in JSON".
- **"The peril slugs are: escape-of-water, fire, …"** — the vocabulary, spelled out. The boundary
  publishes this same list as a resource, and day 12's rep is to fetch it rather than restate it;
  today it is written twice and that is a known duplication.
- `- "No one hurt" is false.` — **the exact sentence from FNOL-4471**, in the instruction. Day 2
  proved that phrase breaks a keyword scan; naming it here is cheap and it is the one case this
  desk knows is hard.
- `- Do not decide whether the claim can be fast-tracked. That is not your question.` — the
  prohibition that matters most. A fluent model asked to classify a claim will happily add a
  recommendation, and a recommendation that arrives next to a classification gets used.
- `- Do not mention the policy, the excess, the estimate or any amount.` — **the classifier is not
  given those facts and must not invent them.** Every number a model produces about money is a
  number an insurer might be held to.
- `- Do not add commentary, apology or explanation.` — because the caller of this function parses
  the answer, and a model that prefixes `Here is the classification:` produces valid JSON inside
  invalid JSON.
- `def build(model: Any | None = None) -> Agent:` — **a function rather than a module-level agent
  object.** Two reasons: an agent built at import time would build one at import time in a test that
  wanted a different model, and the parameter is how day 15 swaps the stand-in for a provider
  without editing this file.
- `models.pinned(chosen)` — **day 1's registry, enforcing the pin at the point of configuration.**
  It returns the model it was given, which is what lets it be wrapped inline. Part 3.2 is what
  happens when it refuses.
- `description="Reads a loss description and names the peril and whether anyone was hurt."` — an
  agent's `description` is what *other agents* read when deciding whether to hand work over. There
  is one agent today, so nothing reads it; day 9 has five, and this field becomes the docket again.
- `budget.spend(NAME)` — **first, before anything else happens.** Spending before the call means a
  call that fails still counts, which is right: the provider was asked. Spending afterwards would
  let a loop of failures run free.
- `runner = Runner(app_name=..., agent=..., session_service=InMemorySessionService(), ...)` — the
  runner's arguments are keyword-only. `InMemorySessionService` is a dictionary in this process that
  nothing evicts and no restart survives, which is exactly right for a desk that does not remember
  anything between notifications — and is day 8's subject.
- `auto_create_session=True` — without it the runner refuses to run against a session that was never
  created, and this desk creates one per classification and throws it away.
- `types.Content(role="user", parts=[types.Part(text=description)])` — the question, as a turn. A
  `Content` is a role and a list of parts; a text part is the simplest kind.
- `async for event in runner.run_async(...)` — **the loop is the point.** A turn is not one answer;
  it is a stream of events, and the caller consumes them as they arrive. With one agent and no tools
  there is exactly one event today, and day 8 is where that number grows.
- `if event.is_final_response() and event.content and event.content.parts:` — **three conditions,
  all needed.** `is_final_response()` distinguishes the answer from everything leading up to it;
  `event.content` may be `None` on an error event; `parts` may be empty. Any one of them missing
  gives an `AttributeError` on a bad day rather than on a good one.
- `answer_text = "".join(part.text or "" for part in event.content.parts)` — joined, because a
  response may arrive in several parts, and `or ""` because a part may carry something other than
  text and leave `text` as `None`.
- `log("classifier.answered", model=agent.model.model, events=events, chars=len(answer_text))` —
  **the model's name in every line.** `agent.model.model` is the name on the model object, and for
  this project's stand-in it begins with `scripted/`, so no log line from a double can be mistaken
  for one from a provider.
- `except json.JSONDecodeError: return {"error": ...}` — **the model said something that is not an
  object, and that is reported.** No repair, no regex to fish the JSON out of a sentence, no retry
  with a sterner prompt. Those are all reasonable things to build and every one of them hides how
  often this happens.
- `if "loss_type" not in parsed or "injury_reported" not in parsed:` — valid JSON that is not the
  right object. A model that answers `{"peril": "fire"}` has followed the format and not the schema,
  and the difference is worth its own branch.
- `"said": answer_text[:120]` — **the first 120 characters of what it actually said**, carried in
  the error. Without it, a classification failure is a mystery; with it, the first thing a reader
  sees is the model's own words.

  while doing it. Part 1.2 is about what else the double cannot tell you.

  response. That number is the simplest possible version of the loop and it goes up on day 8.
- `"model": "scripted/claims-classifier"` — the double, named in this project's own log line as well
  as in the framework's.
- `"injury_reported": false` — **and this is the day's payoff.** The description ends *"No one
  hurt."* Day 2's keyword scan called that an injury and sent the most fast-trackable claim in the
  queue to an adjuster. Something that reads the sentence does not.
- `"scripted": true` inside the answer — the third announcement. Nothing that comes out of this
  arrangement can be quoted as evidence about a real model.
- `budget: 1 of 5 {'classifier': 1}` — **day 1's budget, counting for the first time.** It was
  written on a day with nothing to count, and it has been in the project for six days doing nothing.
  The breakdown names the agent, which is what makes it useful when there are five.

## When it breaks

Give it a description the stand-in has no answer for:

```bash
uv run python -c "
import asyncio, json
from claims_desk.agents import classifier
from claims_desk.util.budget import Budget
print(json.dumps(asyncio.run(classifier.classify('the roof blew off in a way nobody scripted', Budget(limit=2)))))
"
```

```
{"error": "the classifier's object is missing a field", "said": "{\"scripted\": true, \"error\": \"no scripted answer for this description\"}"}
```

Verbatim, from this project. Two refusals, nested, and both of them honest. The stand-in has no
scripted answer and says so rather than picking a plausible peril. The parser sees valid JSON
without the required fields and reports **which** kind of failure it was, carrying the model's own
words in `said`.

Somebody would meet this on the first real notification whose wording nobody anticipated, and the
temptation is immediate: fall back to the closest peril, or retry with a firmer prompt, or default
to `accidental-damage` because most things are. Every one of those turns a visible failure into an
invisible wrong answer. The smallest fix is to leave it — a claim the desk cannot classify is a
claim the desk should not decide, which is precisely the pending verdict day 6 built.

## In production

**What a senior writes instead.** The same agent, with the output shape enforced rather than asked
for — a schema on the way out, so that "valid JSON with the wrong fields" cannot happen. That is
day 13 and it is the right next step. What they would keep exactly as it is: **the narrow remit.**
The pressure to let this agent decide the claim will come from a real place — it has read the
description, it knows more than the rules do — and giving in to it means the desk can no longer say
which component was wrong about a claim.

**What degrades at scale.** One classification per notification, one model call, and a desk taking
several hundred notifications a day is several hundred calls before any retry. That is a bill and a
rate limit, and day 15 is where both get handled. The subtler cost is the instruction: it is sent
in full on every single call, and every prohibition added to it is paid for on every notification
forever. An instruction that grows by a line a week is a cost that grows by a line a week.

**The review comment.** *"The instruction now says 'if the claim looks straightforward you may
suggest fast-tracking it'. Take that out. The moment this agent has an opinion about the outcome,
we cannot tell a bad classification from a bad decision — and the rules that decide are the ones we
can test."*

**The interview question.** *"You have one agent that reads free text and a set of deterministic
rules that use what it read. Why not let the agent apply the rules too, and what would you lose?"*
