## One-line answer

One server object, one decorated function, and the function's own signature and docstring become
the entire interface a caller gets — no import, no shared type, and no file path crossing the line.

## The idea

The clerk at the hatch has a docket of what can be asked for. Not a list of the shelves — a list of
*requests*: fetch a claim by reference, check whether a file is out, log a return. If what you want
is not on the docket, the answer is no, and the answer is no in a way that does not depend on the
clerk's mood.

The docket is a better object than it looks. It is short, it is readable by somebody who has never
been in the file room, and it is the complete description of what the room can do for you. Nobody
needs to know how the shelves are arranged.

A **tool** is one entry on that docket: a name, a description in prose, and a schema for its
arguments. The description is not documentation of the tool — from day 7, when a model is choosing
between tools, **the description is the API**. It is the only thing the model has to go on.

What makes the Model Context Protocol worth using here rather than inventing something is that it
fixes the shape of the docket. **MCP** is a JSON-RPC protocol by which a program exposes tools,
resources and prompts to a model's client, so the tool lives in its own process instead of inside
the agent. Its versions are dated revisions, and which one you speak is a fact about your installed
SDK.

This project speaks `2026-07-28`, the current revision, which carries the version on every request
rather than agreeing it once in a handshake. That choice, what it cost and what it rules out is
`docs/adr/ADR-0009` in the authoring repository; inside this project the consequence is simple and
visible in the next part: there is no handshake to watch, and `client.protocol_version` reports the
revision that governed the call.

## The mechanism

The whole file, at `claims_mcp/server.py`:

```python
"""The claims boundary: the only process that opens the policy store.

One server object, one declared tool. The tool's description and its parameter names are the whole
interface a caller gets — there is no import, no shared type and no file path crossing this line.

Run it over stdio with `python -m claims_mcp`, or in-process from a test by handing the `server`
object straight to a `Client`.
"""

from __future__ import annotations

from typing import Any

from mcp.server import MCPServer

from claims_desk.store import Store
from claims_desk.util.logging import log

#: The server's identity. A client reads this back and it appears in every log the boundary keeps,
#: so the version moves when the tools this server declares change.
server = MCPServer(
    name="claims-boundary",
    title="Claims Intake Desk boundary",
    version="0.1.0",
    instructions=(
        "The policy store and the claim file for a first-notice-of-loss desk. "
        "Every policy in it is synthetic. Ask for a policy by its number; there is no way to "
        "list them all, and no way to read a file."
    ),
)

#: The one object in this process that touches the disk. It is created here, at import, so that
#: exactly one `Store` exists per server process.
store = Store()


@server.tool()
def fetch_policy(number: str) -> dict[str, Any]:
    """Look up one policy by its number.

    Returns the policy's cover and its dates, or `{"found": false}` when the store has never heard
    of that number. A number that does not exist is an answer, not an error: an intake desk is
    given wrong policy numbers every day, and the caller needs a letter rather than a traceback.

    Args:
        number: The policy number exactly as the caller gave it, for example `SYN-POL-1001`.
    """
    policy = store.policy(number)
    log("boundary.fetch_policy", number=number, found=policy is not None)
    if policy is None:
        return {"found": False, "number": number}
    return {
        "found": True,
        "number": policy.number,
        "product": policy.product,
        "status": policy.status,
        "inception": policy.inception.isoformat(),
        "expiry": policy.expiry.isoformat(),
        "excess": policy.excess,
        "fast_track_limit": policy.fast_track_limit,
        "perils": sorted(policy.perils),
    }
```

**Line by line:**

- `from mcp.server import MCPServer` — the high-level server class from the 2.x SDK. **The names in
  this package are read off the installed version, not remembered**: the Python models use
  snake_case where the wire format is camelCase, so it is `tool.input_schema` and
  `result.structured_content`, and the camelCase spellings raise `AttributeError` from pydantic.
- `from claims_desk.store import Store` — **the one import that crosses from the boundary back into
  the desk**, and it goes in this direction only. The boundary reuses the desk's store code; the
  desk never imports the boundary. Reversing that arrow is the failure part 1.1 exists to prevent.
- `from claims_desk.util.logging import log` — day 1's logger, and it matters here more than
  anywhere: it writes to **standard error**, and standard output on this process is the protocol.
  Part 3.2 is what happens when that is forgotten.
- `server = MCPServer(...)` — **a module-level object, created at import.** A client can be handed
  this object directly for an in-process test, or the module can be run as a process; both use the
  same server, which is what stops the tested thing and the shipped thing drifting apart.
- `name="claims-boundary"` — the identity a client reads back. Not the package name and not the
  file name: the name of the *service*, which is what appears in a log when three of them are
  running.
- `version="0.1.0"` — **the boundary's own version, separate from the project's.** It moves when
  the tools this server declares change, because that is what a client cares about. A client
  connected to `claims-boundary 0.1.0` knows exactly which docket it is holding.
- `instructions=(...)` — prose the client can show to a model, describing what this server is for.
  Read the last clause: **"there is no way to list them all, and no way to read a file."** Saying
  what a boundary *cannot* do is as useful as saying what it can, because it stops a model spending
  a turn asking.
- `store = Store()` — one store per server process, created at import. The desk no longer has one
  at all from here on: the object that opens files lives on the far side of the hatch.
- `@server.tool()` — the decorator that puts `fetch_policy` on the docket. Called with no
  arguments, so **everything the client sees is derived from the function itself**: the name from
  `__name__`, the description from the docstring, the argument schema from the annotations.
  Nothing is written twice, so nothing can drift.
- `def fetch_policy(number: str) -> dict[str, Any]:` — **`number: str` is not just a type hint any
  more.** It becomes `{"type": "object", "properties": {"number": {"type": "string"}}, "required":
  ["number"]}` in the schema a model reads. An un-annotated parameter would produce a schema that
  says nothing, and a model would guess.
- **The docstring's first line, "Look up one policy by its number."** — this is what a model sees
  when choosing between tools. From day 7 it is the API, and it is written for a reader who has
  none of the context you have.
- **"A number that does not exist is an answer, not an error"** — the contract, stated in the
  docstring where a caller will read it. It is day 6's whole subject and it starts here: the tool
  returns `{"found": false}` rather than raising, because an intake desk is given wrong policy
  numbers every day and the caller needs a letter.
- `Args:` with a description and an example — the argument's own documentation, including the shape
  of a real value. A model that has seen `SYN-POL-1001` is far less likely to invent a number that
  looks like a policy number from somewhere else.
- `log("boundary.fetch_policy", number=number, found=policy is not None)` — the boundary keeps its
  own record of every request. It logs **the number and whether it was found**, not the policy: a
  log that carries the answer as well as the question is a copy of the store in a place with none
  of the store's rules.
- `return {"found": False, "number": number}` — the number is echoed back so a caller correlating
  several requests does not have to remember which is which.
- **The returned dictionary is cover, not storage.** Product, status, dates, excess, limit, perils
  — every field is something the desk's rules read. There is no path, no filename, no record id and
  no `_synthetic` marker: if a path crossed this line, something above it could be written to open
  the path, and the whole arrangement would be decoration. Part 3.1 asserts that.
- `policy.inception.isoformat()` — the `date` objects from day 2 become ISO strings on the way out,
  because JSON has no dates. The desk parses them back on its side. **Parsing at both edges is the
  cost of a real process line**, and it is the honest version of what a boundary is.
- `sorted(policy.perils)` — a `frozenset` has no order, and JSON needs one. Sorting makes two
  identical answers identical byte for byte, which matters the moment anything caches or compares
  them.

## When it breaks

Ask for a tool the server does not declare, and the refusal comes back as a protocol-level error
rather than as a result:

```bash
uv run python -c "
import asyncio
from mcp import Client
from claims_mcp.server import server

async def main():
    async with Client(server) as client:
        await client.call_tool('read_file', {'path': '.env'})

asyncio.run(main())
" 2>&1 | tail -4
```

```
Tool 'read_file' failed: 'Unknown tool: read_file'
```

The docket is the whole surface. `read_file` is not on it, so there is nothing to route the call
to, and the client is told so by name — as a failed *result* rather than as a raised exception,
because the client is constructed with `raise_exceptions=False` by default and hands failures back
for the caller to read. Somebody arrived at this trying to give an agent "just a
little" filesystem access for debugging, and found that the only way to do it was to declare a tool
that does it — which is a change to a file, in a commit, that a reviewer can see. **The boundary
turns a capability into a diff.**

## In production

**What a senior writes instead.** The same server, with the tool descriptions treated as
user-facing copy — reviewed, versioned and tested — because from day 7 they are the interface a
model is reasoning about, and a vague description produces wrong tool choices that look like model
failures. They would also split `instructions` from the tool docstrings deliberately: the first
says what this server is, the second says what one request does.

**What degrades at scale.** One tool with one string argument is a docket anybody can read. A
boundary with thirty tools is a menu a model has to choose from on every turn, and the cost is not
only tokens — it is that similar descriptions produce ambiguous choices. The discipline that scales
is the one this file already shows: **every field in the return value is something a rule reads**,
so the docket grows because the desk needs it rather than because it was easy to add.

**The review comment.** *"`fetch_policy` returns the whole policy record including `holder_ref`.
Nothing in the desk's rules reads it. Take it out — every field that crosses this line is a field
somebody downstream will start depending on, and the ones a model can see are the ones it can put
in a letter."*

**The interview question.** *"Your tool's docstring is derived into the schema a model reads. What
does that mean for how you review a change to a comment, and what would you put in a test to stop
it drifting?"*

## Check yourself

- **Run:** `uv run python -c "import claims_mcp.server; print(claims_mcp.server.server.name)"` —
  expect `claims-boundary`. That proves the module imports and the server object exists; the next
  part is where anything actually crosses the line.
- **Say out loud:** `claims_mcp` imports from `claims_desk`, and `claims_desk` never imports
  `claims_mcp`. Say what that one-way arrow buys, and what would be lost the first time somebody
  reverses it "just for a test".
