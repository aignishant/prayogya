## One-line answer

A citation is only worth printing if somebody can follow it, so this desk's answers hand back
sections and their identifiers and never a summary — because the moment prose is written *from* the
sections, the citation stops being able to check the prose.

## The idea

Two ways of answering a handler who asks whether a windscreen claim needs a photograph.

The first: *"No — windscreen is inspected by the repairer, so a photograph is not required."* Fluent,
correct, and unverifiable. If it is wrong, nothing about it says so, and the handler has no way to
find out short of reading the whole handbook themselves.

The second: *"Handbook HB-02, When a photograph is required."* Less pleasant to read, and it has a
property the first does not: **the handler can go and look.** Thirty seconds later they know whether
the answer is right, and if it is right they now know the rule rather than the answer.

The difference is not politeness. It is where the responsibility sits. The first answer asks to be
trusted; the second asks to be checked.

There is a version of this that looks like the second and behaves like the first, and it is the one
that ships most often: *"No — windscreen is inspected by the repairer [HB-02]."* A summary with a
citation stapled to it. It is worse than either, because the citation now vouches for a sentence the
handbook does not contain. Somebody who follows it finds a real section and reads it as confirmation
of a paraphrase that may have inverted an exception.

So `cited()` returns sections and does not summarise. That is a deliberate refusal, and it puts the
prose-writing where this project has always put it — with whoever is willing to be quoted, which as
of day 9 is a model with a house style and a checker.

Two properties make a citation worth having, and both are testable:

**It resolves.** `handbook.md#HB-02` names a section that exists. A citation nobody can follow is a
lie with a footnote.

**It is absent when there is nothing to cite.** A retriever that always returns three results always
cites three sections, whatever it was asked. The zero case has to be a real answer.

## The mechanism

The citation itself, from `claims_desk/recall.py`, printed whole in part 1.2:

```python
@dataclass(frozen=True)
class Chunk:
    """One section of the handbook, and the citation that resolves to it."""

    id: str
    title: str
    text: str

    @property
    def citation(self) -> str:
        """What an answer prints so a reader can go and check it."""
        return f"handbook.md#{self.id}"


def resolves(citation: str, corpus: list[Chunk] | None = None) -> bool:
    """Does this citation point at a section that exists? A citation nobody can follow is a lie."""
    known = {chunk.citation for chunk in (corpus if corpus is not None else chunks())}
    return citation in known
```

**Line by line:**

- `def citation(self)` **as a property on the chunk** — one spelling, in one place, derived from the
  identifier. Nothing anywhere else in this project builds a citation string, so a change to the
  format is one line and cannot leave half the answers on the old format.
- `f"handbook.md#{self.id}"` — **file, then fragment.** It is a URL fragment because that is what it
  becomes the day the handbook is served rather than read, and a citation format that survives its
  own corpus moving is worth choosing on day one.
- `def resolves(citation, corpus=None) -> bool` — **the check is set membership and nothing else.**
  Not a regular expression on the shape of the string, not a lookup that tolerates near-misses: the
  set of valid citations is exactly the set the corpus produces.
- **`resolves` builds the set from the corpus every call.** Wasteful, and correct: a check that
  cached would be a check that could pass against a handbook the process no longer has.
- **The docstring says what a bad citation *is*** — a lie — rather than what the function returns.
  The reader can see what it returns.

And the answer that carries them:

```python
def cited(question: str, k: int = 3, index: Index | None = None) -> dict[str, object]:
    """What the handbook says about a question, with every claim carrying its citation."""
    found = (index or Index()).top(question, k)
    return {
        "question": question,
        "found": len(found),
        "sections": [
            {"id": chunk.id, "title": chunk.title, "citation": chunk.citation, "score": round(s, 3)}
            for chunk, s in found
        ],
    }
```

**Line by line:**

- **Four keys per section and none of them is the text.** `id`, `title`, `citation`, `score` — enough
  to decide which section to read and where to read it, and not enough to be mistaken for the rule.
- `"question": question` **echoed back** — so an answer that has travelled through a log or a queue
  says what it was an answer to. Day 11 made the same argument about the claim reference.
- `"found": len(found)` **as a number, next to the list.** Redundant, and it is the field a caller
  checks: `if answer["found"] == 0` reads better than `if not answer["sections"]` and is harder to
  get wrong.
- **No `text` field**, which is the refusal this part is about. Handing back the section's prose
  invites a caller to paste it somewhere, and a pasted section with no citation beside it is where
  every unattributed quotation in a company comes from.
- **The list is empty when nothing scores above zero**, because `top()` filters. That is what makes
  the next demonstration possible.

Ask it something the handbook has nothing to say about:

```bash
uv run python -c "
from claims_desk import recall
print(recall.cited('xylophone quantum bassoon', 3))
"
```

```
{'question': 'xylophone quantum bassoon', 'found': 0, 'sections': []}
```

**Line by line:**

- **`found: 0`, and no sections.** Not a low-scoring guess, not "the closest thing we have": nothing.
- **Three words the corpus has never seen**, so `self.idf.get(term, 0.0)` weighs each at zero, the
  question's vector has no non-zero terms, and every cosine is `0.0`.
- **`top()`'s filter is what turns that into an empty list** rather than three sections at zero. A
  retriever that returned `scored[:k]` unconditionally would hand back HB-01, HB-02 and HB-03 here,
  with citations, all of them resolving, none of them relevant.
- **This is the answer most retrieval demonstrations do not show**, and it is the one that decides
  whether the citations mean anything. If every question produces three citations, a citation is
  decoration.

## When it breaks

Take the filter off — return `scored[:k]` and let the zeros through, which is what the line looked
like before somebody thought about it:

```
{'question': 'xylophone quantum bassoon', 'found': 3, 'sections': [{'id': 'HB-01', 'title': 'What the fast-track is for', 'citation': 'handbook.md#HB-01', 'score': 0.0}, {'id': 'HB-02', 'title': 'When a photograph is required', 'citation': 'handbook.md#HB-02', 'score': 0.0}, {'id': 'HB-03', 'title': 'Injuries stop the fast-track', 'citation': 'handbook.md#HB-03', 'score': 0.0}]}
```

Verbatim, from this project. Three sections, three citations, and **every one of them resolves.**
`resolves("handbook.md#HB-01")` is `True`. The test that checks citations is green. The handler is
being told that the handbook's answer to a question about xylophones is the fast-track eligibility
rule.

The score is `0.0` and it is right there in the output, which is the only thing standing between
this and a straightforwardly wrong answer — and scores are the first field a display drops.

Notice which guard failed here and which did not. **Citation validity is not relevance.** A resolving
citation proves the section exists; it says nothing whatever about whether the section answers the
question. Two different properties, two different tests, and the one that is easy to write is the one
that does not matter on its own.

The smallest fix is `if pair[1] > 0.0`. The rule underneath: **a retriever must be able to return
nothing**, and if the interface makes that awkward — a caller that always expects `k` results — the
interface is where the bug will live.

## In production

**What a senior writes instead.** The same shape, with a **relevance floor** rather than a
greater-than-zero test: a score below some threshold is treated as no answer, because the difference
between `0.0` and `0.03` is not the difference between irrelevant and relevant. What they would want
beside it is the count of questions that returned nothing, tracked over time — a retriever whose
no-answer rate suddenly halves has usually got worse, not better.

**What degrades at scale.** With eight sections, a zero score means the words genuinely are not
there. With several hundred sections, almost every question shares *some* rare word with *some*
section, so the zero case stops happening and the filter stops protecting anything. The number that
matters then is not whether the score is above zero but how far the top result is above the second,
and this project's `0.406` against `0.194` on a wrong answer is the warning that the gap is not a
guarantee either.

**The review comment.** *"The answer includes the section text now so the agent does not have to
fetch it. That means the model sees the prose and the citation together, and the first time it
paraphrases one while quoting the other we will not be able to tell. Give it the identifier and make
it ask."*

**The interview question.** *"Your system cites its sources and every citation is valid. Give me two
ways it can still mislead somebody, and say which one a test could catch."*
