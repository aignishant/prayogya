## One-line answer

Retrieval is a similarity between two bags of words: count the terms, weight each one by how rare it
is across the corpus, take the cosine between the question's vector and each section's — and because
it is arithmetic over one file, every number this desk prints can be checked by somebody with a
calculator.

## The idea

A new handler learns to use the handbook in about a minute, and what they learn is a trick.

They do not read it. They look for the *unusual* word in their question. Somebody asks about a
windscreen and they go looking for "windscreen", because it appears in one rule and nowhere else. If
the question is about a claim, they do not look for "claim" — every rule is about claims, so the
word tells them nothing about which one.

That is the entire idea behind the retriever in this file. A word is worth attention in proportion
to how *rare* it is in the corpus, and a section matches a question in proportion to how many
attention-worthy words they share.

The mechanism has three named pieces and no magic in any of them.

**Term frequency** — how often a word appears in a section. Say "photograph" three times and the
section is more about photographs than one that says it once.

**Inverse document frequency** — how rare the word is across the corpus, written `log(N / n)`: the
number of sections, divided by how many contain the word, logged. A word in every section scores
zero, which is the arithmetic saying what the handler learned in a minute.

**Cosine similarity** — the angle between two vectors of weighted terms, which is a number from 0 to
1 that ignores length. Without it, the longest section wins every question simply by containing more
words.

None of this is an embedding, and it is worth being exact about the difference rather than vague.
An embedding is a vector produced by a model that has read a great deal of text, and its virtue is
that *related* words land near each other — "hurt" and "injured" and "casualty" are close together
without anybody saying so. This index has no such idea. It matches on the words themselves, and
part 2.2 is where that costs a question.

What it buys is that this project can **run**. No key, no provider, no network call, nothing to go
down and nothing to pay for — and every number is reproducible by anyone holding the same file,
which is exactly what a curriculum needs and is very often what a first version needs too.

## The mechanism

The whole file, at `claims_desk/recall.py`:

```python
"""Looking something up, as against remembering it.

Day 8 gave this desk a session and a rule: a conversation is kept against one claim reference and
nothing a policyholder said travels out of it. That rule is not negotiable, and it is exactly what
makes **memory** the wrong tool for most of what a desk needs to know.

What a handler actually needs during a claim is not last week's caller. It is the handbook: which
perils need a photograph, what the fast-track is for, what a deficiency letter may not contain.
That is a fixed corpus, written by the department, the same for every claim and every policyholder
— so the desk **looks it up** and remembers nothing.

The retrieval here is hand-rolled and small on purpose: the corpus is one file, the vectors are term
frequencies weighted by inverse document frequency, and the similarity is a cosine. No provider is
contacted and no embedding model is involved, which means every number this module produces is
reproducible by anyone with the file. What a real embedding model would change is written down in
day 12 part 2.2 rather than guessed at here.
"""

from __future__ import annotations

import math
import re
from collections import Counter
from dataclasses import dataclass
from pathlib import Path

from claims_desk.util.logging import log

#: Where the handbook lives. One file, in the repository, versioned with the code that reads it —
#: which is what makes a citation checkable at test time rather than at run time.
HANDBOOK = Path(__file__).resolve().parent.parent / "data" / "handbook.md"

#: A section heading, and the section id inside it. The id is the citation: `HB-02` resolves to one
#: place in one file, and a test can prove that it does.
HEADING = re.compile(r"^## (HB-\d\d) · (.+)$", re.MULTILINE)

#: Words too common in this corpus to tell two sections apart. Deliberately short: a long stop list
#: is a way of tuning a benchmark rather than improving a retriever, and part 2.2 measures it.
STOPWORDS = frozenset(
    # fmt: off
    [
        "a", "an", "and", "are", "as", "at", "be", "by", "for", "from", "has", "have", "in",
        "is", "it", "its", "not", "of", "on", "or", "that", "the", "to", "was", "which", "with",
        "claim", "claims", "handler", "policyholder", "policy",
    ]
    # fmt: on
)


@dataclass(frozen=True)
class Chunk:
    """One section of the handbook, and the citation that resolves to it."""

    id: str
    title: str
    text: str

    @property
    def citation(self) -> str:
        """What an answer prints so a reader can go and check it."""
        return f"handbook.md#{self.id}"


def words(text: str) -> list[str]:
    """The terms of a piece of text: lowercase, letters only, stopwords dropped.

    Crude, and every choice in it is visible: no stemming, so `photograph` and `photographs` are two
    terms; no phrases, so "fast-track limit" is two terms and not one. Part 2.2 is what that costs.
    """
    return [w for w in re.findall(r"[a-z]+", text.lower()) if w not in STOPWORDS]


def chunks(path: Path | None = None) -> list[Chunk]:
    """The handbook, split at its own headings.

    **Split on the document's structure, not on a character count.** A section is one rule written
    by one team; cutting it at six hundred characters would put half a rule in one chunk and half in
    another, and a top-k answer would then cite a fragment that says the opposite of the rule.
    """
    source = (path or HANDBOOK).read_text(encoding="utf-8")
    found = list(HEADING.finditer(source))
    out: list[Chunk] = []
    for index, match in enumerate(found):
        end = found[index + 1].start() if index + 1 < len(found) else len(source)
        body = source[match.end() : end].strip()
        out.append(Chunk(id=match.group(1), title=match.group(2), text=body))
    return out


class Index:
    """Term frequencies weighted by inverse document frequency, and a cosine between them.

    Built once from the corpus and held in memory. It has no state that outlives the process and
    nothing in it is per-policyholder, which is the property that makes it safe to share across
    every claim the desk handles.
    """

    def __init__(self, corpus: list[Chunk] | None = None) -> None:
        self.chunks = corpus if corpus is not None else chunks()
        counts = [Counter(words(f"{c.title} {c.text}")) for c in self.chunks]
        appearances = Counter(term for count in counts for term in count)
        total = len(self.chunks)
        #: The weight of a term: rare in the corpus means informative. `log(N / n)` and nothing
        #: cleverer, so a person can recompute any number in this index with a calculator.
        self.idf = {term: math.log(total / seen) for term, seen in appearances.items()}
        self.vectors = [self._weigh(count) for count in counts]

    def _weigh(self, count: Counter) -> dict[str, float]:
        return {term: n * self.idf.get(term, 0.0) for term, n in count.items()}

    @staticmethod
    def _cosine(left: dict[str, float], right: dict[str, float]) -> float:
        shared = set(left) & set(right)
        if not shared:
            return 0.0
        dot = sum(left[term] * right[term] for term in shared)
        size = math.sqrt(sum(v * v for v in left.values())) * math.sqrt(
            sum(v * v for v in right.values())
        )
        return dot / size if size else 0.0

    def top(self, question: str, k: int = 3) -> list[tuple[Chunk, float]]:
        """The `k` sections closest to the question, best first, with their scores.

        Returns the scores because a caller that cannot see them cannot tell a confident answer
        from a coincidence — and at this corpus size coincidences are common.
        """
        asked = self._weigh(Counter(words(question)))
        scored = [
            (chunk, self._cosine(asked, vector))
            for chunk, vector in zip(self.chunks, self.vectors, strict=True)
        ]
        scored.sort(key=lambda pair: (-pair[1], pair[0].id))
        best = [pair for pair in scored[:k] if pair[1] > 0.0]
        log(
            "recall.top",
            k=k,
            returned=len(best),
            cited=[chunk.id for chunk, _ in best],
            best=round(best[0][1], 3) if best else 0.0,
        )
        return best


def cited(question: str, k: int = 3, index: Index | None = None) -> dict[str, object]:
    """What the handbook says about a question, with every claim carrying its citation.

    The shape is deliberate: **no prose.** This function does not summarise, because summarising is
    what a model would do and a summary is the thing a citation stops being able to check. It hands
    back the sections and where they came from, and whoever writes prose from them says which
    section each sentence came out of.
    """
    found = (index or Index()).top(question, k)
    return {
        "question": question,
        "found": len(found),
        "sections": [
            {"id": chunk.id, "title": chunk.title, "citation": chunk.citation, "score": round(s, 3)}
            for chunk, s in found
        ],
    }


def resolves(citation: str, corpus: list[Chunk] | None = None) -> bool:
    """Does this citation point at a section that exists? A citation nobody can follow is a lie."""
    known = {chunk.citation for chunk in (corpus if corpus is not None else chunks())}
    return citation in known


#: The questions this desk's retrieval is measured against, and the section each one should reach.
#: Hand-written from the handbook by somebody who read it, which is the only honest way to build a
#: set that measures a retriever rather than the retriever's own opinion of itself.
QUESTIONS = Path(__file__).resolve().parent.parent / "data" / "handbook_questions.json"


def recall_at_k(k: int = 3, index: Index | None = None) -> dict[str, object]:
    """The share of questions whose expected section is somewhere in the top `k`.

    **A number that can go down.** It is reported with the misses named, because a score on its own
    tells you that something changed and never which question stopped working.
    """
    import json

    asked = json.loads(QUESTIONS.read_text(encoding="utf-8"))
    engine = index or Index()
    misses = []
    for case in asked:
        got = [chunk.id for chunk, _ in engine.top(case["asked"], k)]
        if case["expect"] not in got:
            misses.append({"asked": case["asked"], "expect": case["expect"], "got": got})
    hits = len(asked) - len(misses)
    return {
        "k": k,
        "asked": len(asked),
        "hit": hits,
        "recall": round(hits / len(asked), 3),
        "misses": misses,
    }
```

**Line by line:**

- **The module docstring opens on day 8's rule**, not on retrieval. This file exists because a
  session may not carry a policyholder's words out of a claim, and everything a desk is tempted to
  remember has to go somewhere else or nowhere.
- **"No provider is contacted and no embedding model is involved."** Said in the file rather than in
  the day, because the first person to read this in six months will want to know whether the numbers
  they are looking at came from a model.
- `HANDBOOK = Path(__file__).resolve().parent.parent / "data" / "handbook.md"` — **the corpus is
  versioned with the code that reads it.** A citation is checkable at test time only if the thing it
  cites is in the repository; a corpus behind a network call makes every citation a run-time promise.
- `HEADING = re.compile(r"^## (HB-\d\d) · (.+)$", re.MULTILINE)` — **two capture groups, the
  identifier and the title**, and the ` · ` between them is load-bearing. Part 1.1's failure is what
  happens when it is not there.
- `re.MULTILINE` so `^` means *start of a line* rather than start of the file. Without it this
  matches nothing at all and `chunks()` returns an empty list, silently.
- `STOPWORDS` with **`claim`, `claims`, `handler`, `policyholder`, `policy` in it** — the
  corpus-specific half. Every section is about claims, so the word cannot tell two apart. The generic
  half is the ordinary English filler.
- **The list is deliberately short**, and the comment says why: lengthening a stop list until a
  benchmark improves is tuning the benchmark. Part 2.2's numbers were taken with this list and not
  adjusted afterwards.
- `# fmt: off` / `# fmt: on` — **the words are laid out to be read, not to satisfy a formatter.**
  Somebody arguing about whether `not` belongs in a corpus about prohibitions needs to see the list.
- `@dataclass(frozen=True) class Chunk` — **frozen, because an index holds these and a mutable chunk
  would let a caller change the text under a vector that was computed from it.**
- `def citation(self) -> str: return f"handbook.md#{self.id}"` — **a property, so there is exactly
  one spelling of a citation** in this project. Part 2.1 is what that one spelling is worth.
- `def words(text)` — **three decisions on one line**: lowercase, letters only, stopwords dropped.
  `re.findall(r"[a-z]+", ...)` after `.lower()` throws away digits and punctuation, so `HB-02`
  becomes `hb`, and "two thousand five hundred pounds" survives as words while `2500` would not.
- **The docstring names what it does not do**: no stemming, no phrases. `photograph` and
  `photographs` are two unrelated terms to this index, which is a real limitation stated where the
  limitation lives.
- `body = source[match.end() : end].strip()` — **a section runs from its own heading to the next
  one.** That single expression is what part 1.1's failure exploits: a heading that stops matching
  does not lose its own section, it dissolves into the one above.
- `class Index` with `self.chunks`, `self.idf`, `self.vectors` — **three attributes and no
  persistence.** Nothing here is written to disk, nothing survives the process, and nothing is
  per-claim. That is what makes one index safe to share across every claim the desk handles, and
  part 4.1 asserts it.
- `counts = [Counter(words(f"{c.title} {c.text}")) for c in self.chunks]` — **the title is indexed
  with the body.** "Escalation" appears once in HB-08's body and once in its heading; a title is a
  human's summary of the section and it is the most informative sentence in it.
- `self.idf = {term: math.log(total / seen) ...}` — **`log(N / n)`, the textbook form, with no
  smoothing and no `+1`.** A term in all eight sections gets `log(8/8) = 0`, which is the arithmetic
  saying the same thing the stop list says, arrived at from the data rather than from a hand-written
  list.
- `def _weigh(self, count)` — **used for both the sections and the question**, so a question is
  weighted by the corpus's idea of what is rare rather than by its own. A question's own term
  frequencies would tell you nothing: it says each word once.
- `self.idf.get(term, 0.0)` — **a word the corpus has never seen weighs nothing.** Not an error, not
  a special case: a question about xylophones simply has a zero vector and matches nothing.
- `shared = set(left) & set(right)` / `if not shared: return 0.0` — **the early exit is the common
  case**, not an optimisation. Most questions share no terms with most sections.
- `size = sqrt(...) * sqrt(...)` over **all** terms, not just the shared ones — that is what makes it
  a cosine rather than a dot product, and it is what stops the longest section winning every time.
- `scored.sort(key=lambda pair: (-pair[1], pair[0].id))` — **score descending, then identifier
  ascending.** The tiebreak matters more than it looks: without it two sections with identical scores
  come back in whatever order the corpus happened to be in, and a test that pins the top result is
  flaky rather than wrong.
- `best = [pair for pair in scored[:k] if pair[1] > 0.0]` — **k is a maximum and not a quota.** A
  retriever that always returns k things always cites something, and part 2.1 is about why that is
  worse than returning nothing.
- `log("recall.top", ..., cited=[...], best=...)` — **the identifiers and the top score, in the
  run's record.** Day 11 established that a log says how much rather than what; here the *what* is a
  public handbook section, so the identifiers are exactly what belongs in the line.
- `def cited(...)` returning `{"question", "found", "sections"}` — **no prose, deliberately.** This
  function does not summarise, because a summary is the thing a citation stops being able to check.
- `round(s, 3)` on the score — **three decimals, so a reader can compare two answers** without
  reading fifteen digits of float.
- `def resolves(citation, corpus=None)` — **the whole of citation checking, in three lines.** A
  citation is valid when it is in the set of citations the corpus produces, and nothing else counts.
- `QUESTIONS = ... "handbook_questions.json"` — **the evalset is a data file, not a Python list.**
  Part 2.2 is why, and the short version is that a person who is not writing code has to be able to
  add a question.
- `import json` **inside** `recall_at_k` — the only local import in this project, and it is here
  because measuring is not what this module is for. Everything above the line runs without it.

**Line by line:**

- **The first question is the retriever working.** `HB-02` at `0.32`, and the gap to second place is
  nearly threefold. "Photograph" appears in two sections and "escape" in two, so the shared rare
  words pile up on one section.
- **The second question is the retriever working with a much smaller margin.** `HB-03` at `0.15`,
  `HB-02` at `0.132` — a difference of `0.018`. Both sections are about injuries and fast-tracks;
  the right one wins, and it very nearly does not.
- **`HB-02` is second on the injury question, and that is correct rather than noise.** The photograph
  rule genuinely contains a sentence about injuries. A retriever whose second result is relevant is
  doing its job; the risk is reading rank as certainty.
- **The third question is the retriever failing, at the top of the list.** *"May I tell the
  policyholder the fast track limit"* is HB-04's subject exactly — and `HB-01` wins at `0.406`
  against `0.194`, more than twice the score.
- **Why it fails is visible in the words.** The question says "fast track limit"; `words()` has no
  phrases, so that is three terms, and HB-01 is *about* the fast-track and says the phrase several
  times. HB-04 mentions the limit and spends most of its length on the schedule and on the
  prohibition. The question's rare words are HB-01's common words.
- **The score of the wrong answer is the highest number on the page.** That is the thing to take
  away: a confident retriever is not a correct one, and `0.406` is not evidence about anything.
- **The failure is a *phrase* failure**, which is the characteristic weakness of this whole family
  of retrievers and the first thing an embedding model would fix. Part 2.2 measures how often it
  happens rather than leaving it as an anecdote.

## When it breaks

Drop `re.MULTILINE` from `HEADING` — the flag, not the pattern:

```
[]
index over 0 chunks; top -> []
recall@3 -> 0.0
```

Verbatim, from this project. An empty list, no error, and every function above still works: `Index()`
builds happily over nothing, `top()` returns nothing, `cited()` reports `found: 0`, and
`recall_at_k()` scores `0.0` for every question — a perfect zero, which reads like a broken
retriever rather than a missing corpus.

Nothing anywhere says *the corpus did not load*. The desk simply knows nothing and reports it
politely, which is the worst available behaviour and the easiest one to ship — because "no result"
is a legitimate answer that this project deliberately made legitimate two sections ago.

The smallest fix is one flag. The general shape is that **an empty corpus and an unanswerable
question are indistinguishable downstream**, so the corpus needs its own assertion: part 4.1's
`test_the_handbook_splits_at_its_own_headings` names all eight identifiers, and it is the only thing
between this project and a silently empty index.

## In production

**What a senior writes instead.** For a corpus this size: exactly this, and they would be right to.
The version that changes is when the handbook is a few hundred sections — then the vectors go into a
store that can search them without a linear scan, the index is built once at deploy rather than per
process, and the embedding comes from a model. What survives every one of those changes is the part
this file gets right: **the chunk boundary, the identifier, and the citation.**

**What degrades at scale.** `top()` is a linear scan: eight cosines per question, which is free. At
several hundred sections it is still free, and at the point where the corpus is every letter the
department has sent — several hundred a morning, hundreds of thousands a year — it is not, and the
answer is an index rather than a loop. The number that moves first is not the scan, though: it is
`idf`, which is recomputed over the whole corpus every time an `Index` is constructed, and this desk
constructs one per process.

**The review comment.** *"`Index()` is built inside `cited()` when no index is passed. Every call
without one re-reads the handbook off disk and recomputes the idf for eight sections. It is cheap
today and it is a per-question file read, so pass the index or make it a module-level singleton
before somebody calls this in a loop."*

**The interview question.** *"Explain inverse document frequency to somebody who has never seen it,
using a document you both know. Then tell me what it cannot do."*
