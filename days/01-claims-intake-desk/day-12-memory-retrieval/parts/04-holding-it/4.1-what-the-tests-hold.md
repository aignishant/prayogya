## One-line answer

Eighteen tests hold the corpus to its eight sections, every citation to something that exists, the
recall to a floor it can fall below — and three of them assert failures on purpose, because a
retriever's known weaknesses are worth pinning where a change will disturb them.

## The idea

Most of this file is ordinary. A few tests in it are not, and they are the ones worth reading twice.

**A test with a number in its name that can fall.** `recall@3` is 0.9 and the floor is 0.9, so this
project is exactly one regression away from red. That is deliberate. A floor set comfortably below
the current score is a floor that never fires, and a score nobody has to defend drifts.

**Three tests that assert the retriever is wrong.** The prohibition question reaches the wrong
section; the escalation question reaches the wrong section; recall@1 is 0.7 and not 1.0. Writing
those down turns "we know about that" into something that goes red when it changes — including when
it changes for the better, which is the correct moment to delete the test.

**A test that reads the source of another module.** `test_the_desk_registers_no_memory_service`
greps `sessions.py` for `memory_service`. That is a crude thing to do and it is the only way to
assert an *absence* of a keyword argument. Part 3.1's whole argument is that nothing goes wrong when
that keyword is added, so nothing but a test looking for it will notice.

And one that is about privacy rather than retrieval: the index is asserted to hold nothing about a
policyholder, because that is the property that makes a single index safe to share across every
claim the desk handles.

## The mechanism

The whole file, at `tests/test_recall.py`:

```python
"""Retrieval: what the index finds, what every citation resolves to, and a score that can fall.

Nothing here contacts a provider or builds an embedding. The whole retriever is arithmetic over one
file in this repository, so every number in this file is reproducible by anyone who has the file.
"""

from __future__ import annotations

import asyncio
import json

import pytest
from google.adk.memory import InMemoryMemoryService
from google.adk.sessions import InMemorySessionService

from claims_desk import recall, sessions
from claims_desk.agents import classifier

#: The floor this project holds itself to. Below it, the desk is citing the wrong rule often enough
#: that a handler reading the citation would be misled — which is worse than no citation at all.
FLOOR = 0.9


@pytest.fixture()
def index() -> recall.Index:
    return recall.Index()


def test_the_handbook_splits_at_its_own_headings(index: recall.Index) -> None:
    assert [chunk.id for chunk in index.chunks] == [f"HB-0{n}" for n in range(1, 9)]
    assert all(chunk.title for chunk in index.chunks)
    assert all(chunk.text for chunk in index.chunks)


def test_no_chunk_is_a_fragment_of_a_rule(index: recall.Index) -> None:
    """Split on structure, not on length. Every chunk ends where its section ends."""
    for chunk in index.chunks:
        assert not chunk.text.startswith("##")
        assert chunk.text.rstrip().endswith(".")


def test_every_citation_resolves(index: recall.Index) -> None:
    """A citation nobody can follow is a lie, so this is asserted rather than assumed."""
    for chunk in index.chunks:
        assert recall.resolves(chunk.citation)
    assert not recall.resolves("handbook.md#HB-99")
    assert not recall.resolves("HB-01")


def test_the_answer_carries_a_citation_for_every_section(index: recall.Index) -> None:
    out = recall.cited("does an escape of water claim need a photograph", 3, index)
    assert out["found"] == 3
    assert [section["id"] for section in out["sections"]][0] == "HB-02"
    for section in out["sections"]:
        assert recall.resolves(section["citation"])
        assert 0.0 < section["score"] <= 1.0


def test_the_answer_is_sections_and_never_prose(index: recall.Index) -> None:
    """It hands back what the handbook says and where. Summarising is what breaks a citation."""
    out = recall.cited("what makes a claim eligible for fast-track", 2, index)
    assert set(out) == {"question", "found", "sections"}
    assert set(out["sections"][0]) == {"id", "title", "citation", "score"}


def test_a_question_with_nothing_to_match_returns_nothing(index: recall.Index) -> None:
    """No result is an answer. A retriever that always returns k things always cites something."""
    assert index.top("xylophone quantum bassoon", 3) == []
    assert recall.cited("xylophone quantum bassoon", 3, index)["found"] == 0


@pytest.mark.parametrize(
    ("asked", "expect"),
    [
        ("does an escape of water claim need a photograph", "HB-02"),
        ("somebody was hurt, can this still be fast tracked", "HB-03"),
        ("how many sentences may a deficiency letter be", "HB-05"),
        ("can I keep a note of what this caller told me", "HB-07"),
    ],
)
def test_the_obvious_questions_reach_the_obvious_section(
    asked: str, expect: str, index: recall.Index
) -> None:
    """Obvious means the question shares its rare words with the section. Nothing more."""
    assert index.top(asked, 1)[0][0].id == expect


def test_a_question_phrased_as_a_prohibition_misses(index: recall.Index) -> None:
    """The retriever's real weakness, named. "What may a letter never contain" is about HB-05 and
    reaches HB-01, because the words it shares with the corpus are the wrong ones: a bag of terms
    has no idea that "never contain" and "does not contain" are the same question."""
    assert index.top("what may a deficiency letter never contain", 1)[0][0].id == "HB-01"
    assert "HB-05" in [chunk.id for chunk, _ in index.top(
        "what may a deficiency letter never contain", 3
    )]


def test_recall_at_three_is_at_or_above_the_floor(index: recall.Index) -> None:
    """The test that can go red. It names the misses, because a score alone says nothing."""
    measured = recall.recall_at_k(3, index)
    assert measured["asked"] == 10
    assert measured["recall"] >= FLOOR, measured["misses"]


def test_recall_falls_as_k_falls_and_the_numbers_are_written_down(index: recall.Index) -> None:
    """Three measurements this project has actually taken, pinned so a change is visible."""
    assert recall.recall_at_k(1, index)["recall"] == 0.7
    assert recall.recall_at_k(2, index)["recall"] == 0.8
    assert recall.recall_at_k(3, index)["recall"] == 0.9


def test_the_one_question_this_retriever_still_misses(index: recall.Index) -> None:
    """Named rather than hidden. It reaches HB-07 — the rule about keeping notes — for a question
    about escalating, because both sections are about what a handler may do on their own."""
    misses = recall.recall_at_k(3, index)["misses"]
    assert len(misses) == 1
    assert misses[0]["expect"] == "HB-08"
    assert misses[0]["got"][0] == "HB-07"


def test_the_evalset_only_expects_sections_that_exist() -> None:
    """An eval that expects a section nobody wrote scores a retriever against a typo."""
    asked = json.loads(recall.QUESTIONS.read_text(encoding="utf-8"))
    known = {chunk.id for chunk in recall.chunks()}
    assert {case["expect"] for case in asked} <= known
    assert all(case["why"] for case in asked)


def test_the_index_holds_nothing_about_a_policyholder(index: recall.Index) -> None:
    """The property that makes one index safe to share across every claim the desk handles."""
    everything = " ".join(chunk.text for chunk in index.chunks).lower()
    for private in ("fnol-", "ph-", "0000", "@"):
        assert private not in everything


def test_a_memory_service_would_carry_one_claims_words_into_another() -> None:
    """Not what this desk does. The handbook forbids it at HB-07, and this is what it forbids."""
    service = InMemorySessionService()

    async def two_claims_then_remember() -> tuple[bool, list[str]]:
        sessions.service = service
        await sessions.turn(classifier.build(), "FNOL-4471", "the flexible hose let go overnight")
        await sessions.turn(classifier.build(), "FNOL-4472", "the ridge tiles came off")
        first = await sessions.stored("FNOL-4471")
        second = await sessions.stored("FNOL-4472")
        crossed = "flexible hose" in _text_of(second)

        memory = InMemoryMemoryService()
        await memory.add_session_to_memory(first)
        await memory.add_session_to_memory(second)
        found = await memory.search_memory(
            app_name=sessions.APP, user_id=sessions.BATCH_USER, query="flexible hose"
        )
        return crossed, [_content_of(entry) for entry in found.memories]

    original = sessions.service
    try:
        crossed, remembered = asyncio.run(two_claims_then_remember())
    finally:
        sessions.service = original

    assert crossed is False
    assert any("flexible hose" in text for text in remembered)


def test_the_desk_registers_no_memory_service() -> None:
    """The decision, asserted. `sessions.turn` builds a runner with a session service
    and nothing else that could keep a claim past its own conversation."""
    source = (recall.HANDBOOK.parent.parent / "claims_desk" / "sessions.py").read_text(
        encoding="utf-8"
    )
    assert "memory_service" not in source
    assert "MemoryService" not in source


def _text_of(session) -> str:
    out = []
    for event in session.events:
        if event.content and event.content.parts:
            out.extend(part.text or "" for part in event.content.parts)
    return "\n".join(out)


def _content_of(entry) -> str:
    return "".join(part.text or "" for part in (entry.content.parts or []))
```

**Line by line:**

- **The module docstring says what does not happen**: no provider, no embedding. Anybody reading a
  score in this file needs to know whether it came from a model, and the answer is in the first
  paragraph.
- `FLOOR = 0.9` **as a module constant with a comment giving the consequence** — below it, a handler
  following a citation is being misled often enough that citing is worse than not citing. A floor
  without a stated consequence is a number somebody will lower.
- `@pytest.fixture() def index()` — **one index, built per test.** Not session-scoped: `Index()` is
  cheap here, and a shared one would let a test that mutates it affect the next.
- `assert [chunk.id for chunk in index.chunks] == [f"HB-0{n}" for n in range(1, 9)]` — **all eight
  identifiers, in order, generated rather than typed.** This is the test part 1.1's failure needs: a
  heading that stops matching removes an identifier from this list.
- `assert chunk.text.rstrip().endswith(".")` — **every chunk ends on a full stop**, which is a cheap
  proxy for "ends where its rule ends". It would not catch a rule cut mid-paragraph after a sentence,
  and it does catch a chunk that ends mid-sentence.
- `assert not recall.resolves("handbook.md#HB-99")` **and** `assert not recall.resolves("HB-01")` —
  **two ways to be invalid**: a well-formed citation to a section that does not exist, and a bare
  identifier that is not a citation at all. Testing only the positive case is how a `resolves` that
  returns `True` for everything passes.
- `assert 0.0 < section["score"] <= 1.0` — **strictly above zero**, which is part 2.1's filter
  asserted from the outside. A section at exactly `0.0` in a result set means the filter is gone.
- `assert set(out) == {"question", "found", "sections"}` — **equality on the key set, not
  membership.** That is what makes it a test about the refusal to summarise: adding a `text` or
  `answer` key fails here, which is exactly the change part 2.1 argues against.
- `assert index.top("xylophone quantum bassoon", 3) == []` — **the zero case, asserted twice**, once
  on the index and once through `cited`. Two layers, because the filter lives in one and the caller
  reads the other.
- `@pytest.mark.parametrize(...)` **with four questions and their sections** — the working cases, at
  `k=1`, which is the strictest form. Its docstring defines what "obvious" means here: shares its
  rare words. Nothing more mystical is claimed.
- `test_a_question_phrased_as_a_prohibition_misses` — **a test that asserts a wrong answer**, with
  the reason in its docstring. It pins `HB-01` at k=1 and `HB-05` present at k=3, so a change that
  fixes the phrasing problem turns this red and somebody deletes it deliberately.
- `assert measured["asked"] == 10` **before the recall assertion** — a score over the wrong number of
  questions is not the score. If somebody deletes half the evalset, this fails first and says so.
- `assert measured["recall"] >= FLOOR, measured["misses"]` — **the misses as the assertion message.**
  When it goes red, pytest prints which question stopped working, which is the whole difference
  between a useful failure and a number.
- `test_recall_falls_as_k_falls_and_the_numbers_are_written_down` — **three exact equalities**, not
  inequalities. Any change to the corpus, the stop list or the tokeniser moves at least one of these,
  and the point is to be told rather than to be safe.
- `test_the_one_question_this_retriever_still_misses` — **the known miss, pinned by expectation and
  by what it reaches instead.** `misses[0]["got"][0] == "HB-07"` is the part 2.2 finding in one line.
- `test_the_evalset_only_expects_sections_that_exist` — **the exam checked against the corpus.** An
  expectation of `HB-9` scores the retriever against a typo forever, and nothing else in this file
  would notice.
- `assert all(case["why"] for case in asked)` — **the field nothing reads, asserted non-empty.** It
  exists for a human deciding whether a miss means the retriever is wrong or the question is, and a
  blank one is a question nobody can adjudicate.
- `for private in ("fnol-", "ph-", "0000", "@")` — **four shapes of thing that must not be in a
  shared corpus**: a claim reference, a policy number, a telephone number's filler, an email address.
  Crude, and it is the check that would catch somebody pasting a real example into the handbook.
- `sessions.service = service` **inside the async function, restored in a `finally`** — the same
  discipline day 11's fixture uses, written out by hand here because this test is about a global that
  the fixture does not cover.
- `assert crossed is False` **before the memory assertions** — the control. Without it, a test where
  the sessions had leaked into each other would still pass its second assertion and prove nothing.
- `assert any("flexible hose" in text for text in remembered)` — **the policyholder's own words,
  found by content.** That is the sentence part 3.1 is about, asserted so the demonstration cannot
  quietly stop demonstrating.
- `source = (...).read_text(...)` **then two substring assertions** — **a test that reads another
  module's source**, which is ugly and is the only way to assert that a keyword argument is absent.
  Both spellings are checked, because `memory_service=` and `MemoryService()` are two ways in.
- `_text_of` and `_content_of` **at the bottom, after the tests that use them** — the same shape day
  10 used, and legal for the same reason: names are resolved when a test runs.

- **Eighteen from fifteen functions**, the three extras from the parametrised questions.

## When it breaks

Lengthen the stop list. Add `"about"` — the word part 2.2 showed was carrying the escalation miss on
its own — which is the obvious fix and looks like a strict improvement:

```
FAILED tests/test_recall.py::test_the_one_question_this_retriever_still_misses
1 failed, 17 passed in 1.43s
```

And the scores, from the same change:

```
recall@1=0.7 misses=[('HB-04', ['HB-01']), ('HB-08', []), ('HB-05', ['HB-01'])]
recall@2=0.8 misses=[('HB-08', []), ('HB-05', ['HB-01', 'HB-03'])]
recall@3=0.9 misses=[('HB-08', [])]
```

Verbatim, from this project, and it is not what the change was expected to do.

**Every recall number is unchanged.** 0.7, 0.8, 0.9 — the same three figures as before, so
`test_recall_falls_as_k_falls_and_the_numbers_are_written_down` stays green and the floor is never
approached. By the measurement this project has, nothing happened.

**Something did happen.** Look at the miss: `('HB-08', [])`. The escalation question used to reach
HB-07 — the wrong rule, confidently, on the strength of the word "about". Now it reaches **nothing
at all**. The one shared term is gone, every cosine is zero, and part 2.1's filter turns that into an
empty result.

For that question this is plainly better. A handler asking whether to escalate now gets *no answer*
rather than a citation to the rule about what the desk must not keep. And **recall@k cannot see the
difference**, because recall only asks whether the right section was in the list, and it was not
either way.

The one test that goes red does so almost by accident: `misses[0]["got"][0]` raises on an empty list.
It was written to pin *which wrong section* the retriever reaches, and it caught a change in kind
rather than a change in degree.

Two things follow, and the second is the one to keep.

The narrow one: this project does not take the change, because a stop-list edit made to fix one
question needs all ten measured before and after, and the hub carries that as a `TODO(me)` with the
stemmer.

The general one: **a wrong answer and no answer score identically under recall@k, and they are not
the same thing.** One sends a handler to the wrong rule; the other sends them to the handbook. If the
difference matters — and here it plainly does — it needs a measurement of its own, and this project
does not have one.

## In production

**What a senior writes instead.** The same tests, with the recall measurement also emitted as a
number the build records over time — a floor catches a fall through it, and a trend catches the slow
drift from 0.95 to 0.91 that never trips anything. What they would add is a **second evalset that
nobody optimises against**, held back, run less often, and used to check that improvements against
the first one are real.

**What degrades at scale.** Ten questions is a score in steps of 0.1, so this floor can only be
crossed by a change big enough to move a whole question. That is fine at this size and hopeless at
the size where retrieval starts to matter: several hundred sections and a hundred questions, where
the interesting regressions are half a point and the floor never notices. The thing that scales is
not the floor, it is the miss list — a diff of *which* questions fail between two runs stays readable
however many there are.

**The review comment.** *"This adds four words to `STOPWORDS` and updates the three pinned recall
numbers in the same commit. Split it: the stop-list change with the numbers it produces, so the diff
shows what the change did rather than that the tests were made to pass."*

**The interview question.** *"You have a retrieval score with a floor in CI. Give me two ways that
floor can be green while the system gets worse."*
