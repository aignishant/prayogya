## One-line answer

A correlation id lives in a `ContextVar` and is read by `log` rather than passed as an argument — so
fifty existing call sites across nine modules started carrying it without one of them being edited,
and every line about one claim can be collected by a single `grep`.

## The idea

A claim file has a reference number on the front, and the reason is not filing.

The reference is what lets four different people work on the same claim without meeting. The handler
writes an assessment, the policy department answers a cover query, somebody in correspondence sends a
letter, and an adjuster visits the house — and none of them has to know the others exist, because
everything any of them produces goes into a folder with `FNOL-4477` on it. Six months later, when a
complaint arrives, one person pulls one folder and has the whole story.

Now look at what this desk produces instead. Fifty-odd log lines a claim, from `desk`, `workflow`,
`sessions`, `hooks`, `security`, `reliability`, `boundary` and the server process — and they are
interleaved with eleven other claims, because the queue does not stop between them. Some carry a
`claim` field. Some do not: `boundary.connected` says a connection opened, `hooks.model` says a model
answered, and neither knows which claim it was for. The story is all there and it is not in a folder.

So the first thing observability needs is the reference number. One value, generated once per unit of
work, on every line that unit of work produces — through every module and, in the next part, through
a second process.

The obvious way to do that is to pass it as an argument. Add a `trace` parameter to `decide`, to
`run_triage`, to `write_letter`, to every `log` call — and it works, and it is a bad trade. It is
fifty edits; it puts a plumbing parameter into the signature of every function that has nothing to do
with tracing; and it is unenforceable, because the one function that forgets to pass it on produces
lines nobody can find and no test will notice. The cost is not the typing. It is that the mechanism
depends on everybody remembering forever.

The alternative is **ambient context**: a value attached to the current execution, which anything can
read without being handed it. Python's `contextvars` does exactly this, and the reason it is right
here rather than a module-level global is day 10. That day's parallel queue runs several claims
concurrently in one process. A global would hold whichever id was set last, and every line would be
labelled with some other claim's reference — a tracing system that produces confidently wrong
answers, which is worse than none. A `ContextVar` gives each concurrent task its own value, and
`asyncio` propagates it into every task and callback automatically.

There is a second thing this module supplies, and it belongs beside the first: a **span**. The
reference number tells you which lines belong together. It does not tell you how long anything took,
and "why did this morning's queue take so long" is the other question people actually ask. A span is
a named region with an elapsed time and a parent, and part 2.1 is about what happened when this desk
grew some.

## The mechanism

The whole module, at `claims_desk/util/trace.py`:

```python
"""One id for one piece of work, and a span around each thing that takes time.

A claims desk answers two questions when somebody complains. *What happened to claim FNOL-4477?*
and *why did this morning's queue take so long?* Neither can be answered by a log line on its own:
the first needs every line about that claim collected from four modules and two processes, and the
second needs to know how long each step took rather than only that it happened.

So this module supplies two things and nothing else.

- **A correlation id.** One value, generated once per unit of work, carried in a `ContextVar` so
  nothing has to pass it as an argument, and put into the boundary subprocess's environment so it
  survives a process line. Every line `logging.log` writes picks it up automatically.
- **A span.** A named region with an elapsed time in milliseconds and a parent — logged whether
  the region succeeded or raised, because the ones that raise are the interesting ones.

What this module deliberately is **not** is a tracing system. There is no exporter, no sampling,
no propagation format anybody else understands, and the ids are not unique across a fleet. It is
the smallest thing that answers the two questions above from a file of JSON lines, and day 19 is
where it would be replaced by something that speaks a standard.
"""

from __future__ import annotations

import os
import secrets
import time
from collections.abc import Iterator
from contextlib import contextmanager
from contextvars import ContextVar
from typing import Any

#: How a trace id crosses a process line. The desk puts it in the boundary subprocess's environment
#: at launch, and the boundary reads it from there, because nothing hands it one in a call.
TRACE_ENV = "CLAIMS_TRACE"

#: The id of the work in flight, or "" outside any traced work. A `ContextVar` rather than a
#: global, because day 10's parallel queue runs several claims in the same process at the same
#: time and a global would hand all of them whichever id was set last.
trace_id: ContextVar[str] = ContextVar("trace_id", default="")

#: The span in flight, innermost first. Also a `ContextVar`, and also for day 10's sake: two
#: claims being triaged concurrently each need their own stack.
span_stack: ContextVar[tuple[str, ...]] = ContextVar("span_stack", default=())


def new_id() -> str:
    """A fresh trace id: `t-` and twelve hex characters.

    Twelve is enough for a day's work on one desk and short enough to read out over the
    telephone, which is the actual use — somebody rings up and reads you the id from a letter.
    """
    return f"t-{secrets.token_hex(6)}"


def start(existing: str | None = None) -> str:
    """Begin a trace, or adopt one that arrived from somewhere else. Returns the id in force."""
    chosen = (existing or "").strip() or new_id()
    trace_id.set(chosen)
    return chosen


def current() -> str:
    """The trace id in force: the one set in this context, or the one this process was given.

    The environment fallback is what makes the boundary work. It is never given a trace by a
    call — it is a separate process — so it reads the one the desk put in its environment.
    """
    return trace_id.get() or os.environ.get(TRACE_ENV, "")


def where() -> str:
    """The innermost span in flight, or "" outside any span. Read by `logging.log` on every line."""
    stack = span_stack.get()
    return stack[0] if stack else ""


@contextmanager
def span(name: str, **fields: Any) -> Iterator[dict[str, Any]]:
    """Time a named region, and log its end whether it returned or raised.

    Yields a mutable dictionary. Anything put in it before the region ends is logged on the span's
    line, which is how a span reports a count it could not know when it started — how many events
    an agent turn yielded, how many characters a letter came to.

    There is no start line. One line per span keeps a file of JSON greppable by `event` and halves
    what a busy queue writes; the start time is recoverable as `ts` minus `ms`.
    """
    from claims_desk.util.logging import log

    parent = where()
    token = span_stack.set((name, *span_stack.get()))
    extra: dict[str, Any] = {}
    began = time.perf_counter()
    failed: BaseException | None = None
    try:
        yield extra
    except BaseException as raised:  # noqa: BLE001 - re-raised; this only records the type
        failed = raised
        raise
    finally:
        span_stack.reset(token)
        log(
            "span",
            span=name,
            parent=parent or None,
            ms=round((time.perf_counter() - began) * 1000, 1),
            ok=failed is None,
            failed=type(failed).__name__ if failed else None,
            **fields,
            **extra,
        )
```

**Line by line:**

- **The docstring says what this is not**, in its own paragraph. There is a large industry of tracing
  systems with exporters, sampling and a wire format, and somebody arriving at this module needs to
  know within ten seconds that it is none of those. It is the smallest thing that answers two
  questions from a file of JSON lines.
- `TRACE_ENV = "CLAIMS_TRACE"` — **an environment variable name at the top of a tracing module** looks
  odd until part 1.2. It is the whole mechanism for crossing a process line, and putting it here
  rather than in `boundary.py` keeps the propagation contract in one file.
- `trace_id: ContextVar[str] = ContextVar("trace_id", default="")` — **the default is empty, not
  `None`.** Every reader does string work with it, and `""` is falsy in exactly the way the callers
  need without any of them writing `if x is not None`.
- **The comment names day 10 as the reason.** That is the load-bearing justification for the whole
  design, and a reader who does not know it will "simplify" this to a module-level global within a
  year. Concurrency is why, and the comment says so at the point of the decision.
- `span_stack` **is a tuple, innermost first**, not a list. `ContextVar` values should be immutable:
  a list would be shared by reference between concurrent tasks, and each task appending to it would
  corrupt the others' stacks. Setting a new tuple gives each context its own.
- `secrets.token_hex(6)` — **twelve hex characters.** `secrets` rather than `random` is a habit rather
  than a requirement here; the ids are not a security boundary, and the habit costs nothing.
- **The docstring justifies the length by the use**, which is the right way to choose it. Somebody
  reads this back over the telephone; a UUID would be unusable for that and no more useful here.
- `start(existing)` **adopts an id that arrived rather than replacing it.** That single behaviour is
  the difference between a trace that spans two processes and two unrelated traces. `(existing or
  "").strip() or new_id()` also handles the case that matters in practice — an environment variable
  set to the empty string — which is not the same as absent and would otherwise become an id.
- `current()` **falls back to the environment.** The boundary process is never given an id by a
  function call, because it is a different program; it reads the one it was launched with. This one
  line is why the server's own log lines carry the desk's trace.
- `where()` **returns the innermost span**, and `logging.log` calls it on every line. That is what
  puts `"span": "triage"` on a line written by `sessions.turn`, which knows nothing about spans.
- `span` **is a `@contextmanager`, not a decorator.** A decorator would time whole functions; the
  interesting regions here are smaller than a function — the `await` in the middle of `run_triage`,
  not `run_triage` itself.
- `from claims_desk.util.logging import log` **inside the function**, deliberately. `logging` imports
  `trace` to read the context, so a module-level import here is a cycle. The comment for a future
  reader is the shape of the dependency: logging depends on trace, and trace only needs logging at
  the moment it writes.
- `parent = where()` **before pushing**, so the span records what contained it.
- `extra: dict[str, Any]` **is yielded and read after the block.** This is the small trick that makes
  spans useful rather than decorative: `turn_span["events"] = len(events)` records a fact the span
  could not know when it opened, and it lands on the same line as the timing, so one record answers
  "how long did the triage take and how many events did it produce".
- `except BaseException` **with the `noqa`** — broad on purpose, and the comment says why: the span is
  re-raised untouched on the next line. This exists to catch `asyncio.CancelledError` too, which
  inherits from `BaseException` and is exactly what a timed-out claim raises.
- `finally:` **with the reset before the log.** Both matter. The `finally` is why a span that raises
  still produces a line — the ones that raise are the ones somebody is searching for. The reset
  before the log is why a failed span does not leave its name stuck on every subsequent line in the
  process.
- `round(..., 1)` — **tenths of a millisecond.** Enough to see that a tool call took 12.5 and a
  process launch took 2078.9, and not so much that the numbers stop being readable.
- `ok=failed is None` **and** `failed=type(failed).__name__` — a boolean to filter on and a name to
  read. `grep '"ok": false'` is the query somebody types at three in the morning.
- `**fields, **extra` — **the caller's fields, then whatever the block added.** Both after the fixed
  ones, so a span cannot accidentally overwrite its own `ms`.

Now the other half, and the part with the highest ratio of value to diff in the whole day.
`claims_desk/util/logging.py`, **a marked diff against the file day 1 printed**:

```diff
 A claims desk writes about policyholders. Every line this module emits is machine-readable, so a
 run can be filtered and counted months later, and nothing that looks like a secret survives the
 trip to the page.
+
+Day 17 added two fields and no call sites. Every line now carries the trace id of the work in flight
+and the span it happened inside, read from `util.trace` rather than passed in — which is why fifty
+existing `log(...)` calls across nine modules became correlated without one of them being edited.
 """
@@
 def log(event: str, **fields: Any) -> dict[str, Any]:
     """Write one redacted JSON record and return it.
 
     Returning the record is what makes redaction testable without capturing a stream.
+
+    `trace` and `span` are read from the context rather than accepted as arguments. A caller that
+    passes either one explicitly keeps its own value — which is how `trace.span` labels its own
+    line — and both are omitted when empty, because a null field on every line of an untraced run
+    is noise nobody can filter out.
     """
+    from claims_desk.util import trace
+
+    where = {
+        name: value
+        for name, value in (("trace", trace.current()), ("span", trace.where()))
+        if value and name not in fields
+    }
     record = {
         "ts": datetime.now(UTC).isoformat(timespec="milliseconds"),
+        **where,
         "event": event,
         **redact(fields),
     }
```

**Line by line:**

- **Nine lines of code, and every log line in the project changed.** That is the argument for ambient
  context made concrete: the alternative was fifty call sites and a permanent obligation to remember.
- `if value and name not in fields` — **two guards, two different reasons.** `value` drops the field
  when there is no trace, because a line reading `"trace": null` on every record of an untraced run is
  bytes nobody can filter on. `name not in fields` lets a caller override, which is how `trace.span`
  writes its own `span=name` rather than being labelled with its parent.
- `**where` **placed after `ts` and before `event`** — cosmetic, and worth the thought. These lines are
  read by people as well as machines, and the identifying fields belong at the front where the eye
  finds them.
- **`event` is not overridable and `ts` is not either**, because they come before `**redact(fields)`
  in name only — a caller passing `event=` would collide with the positional argument first. The
  redaction still applies to everything the caller sent, unchanged from day 1.
- **The local import is a cycle-breaker**, the mirror of the one in `span`.

## When it breaks

Swap the `ContextVar` for a module-level global — the simplification anybody would propose, because a
`ContextVar` looks like a heavyweight answer to "store one string":

```diff
-trace_id: ContextVar[str] = ContextVar("trace_id", default="")
+trace_id = ""
```

Every test in this file still passes. The whole suite still passes. The queue runs, and every line
carries an id.

The failure needs day 10's parallel queue to show itself, and here it is in one paragraph of
consequence: two claims triaged concurrently in one process both read whichever id was set last, so
`FNOL-4477`'s lines are labelled with `FNOL-4481`'s trace. The system is not broken and nothing errors.
It produces **confidently wrong answers to the only question tracing exists to answer** — and it
produces them six months later, to somebody investigating a complaint, who pulls a trace and reads
another claim's story.

That is why this is the one design decision in the module with a comment naming its reason. The
smallest fix is the `ContextVar`. The general rule: **anything ambient in a concurrent program is a
`ContextVar` or it is a bug you will not find by testing**, because the sequential case — which is
every test you will write first — passes either way.

## In production

**What a senior writes instead.** OpenTelemetry, and not a hand-rolled module. A `trace_id` and
`span_id` in the W3C `traceparent` format, propagated by the library, exported to a collector, and
read in a tool that draws the waterfall rather than in `grep`. The reason to write this one first is
that it is ninety lines and you can see all of it — and the day the exporter is wired in, you already
know which regions are worth a span, which is the part a library cannot decide for you.

**What degrades at scale.** Twelve claims produce about three hundred lines. An intake desk taking
eight thousand notifications a day produces something on the order of two hundred thousand, which is
a few hundred megabytes a day of JSON on stderr — fine to write, expensive to keep, and hopeless to
`grep` once it is a week old. That is the point at which sampling arrives, and the rule that survives
is: sample the traces, never the lines. Half the lines of every claim is useless; every line of half
the claims is a working system.

**The review comment.** *"`current()` falls back to the environment on every call, which means every
log line in the desk does a dictionary lookup in `os.environ` for a value that cannot change after
start-up. Read it once at import and cache it. Not for the speed — for the honesty, because right now
a test that sets the variable mid-run changes the past."*

**The interview question.** *"Your agent handles requests concurrently and you want one id per
request on every log line. Where do you put the id, and what breaks if you put it somewhere else?"*
