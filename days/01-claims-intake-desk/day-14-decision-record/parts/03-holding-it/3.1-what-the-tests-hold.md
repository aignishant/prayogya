## One-line answer

Twenty-four tests hold every stored record to replaying its own verdict, the facts to being exactly
what the rules read, every citation to resolving, and the policyholder's own words to being nowhere
in the record — and one of them decides twelve real claims to do it.

## The idea

One test in this file is the day. The other twenty-three exist to make its failure readable.

`test_every_decided_claim_replays_to_its_own_verdict` runs the whole queue over the real boundary,
loads all twelve records back out of their claim files, and re-derives every verdict from the record
alone. When it goes red, the assertion prints which claim, what it claims, and what its own facts
actually produce.

That is worth arranging deliberately, because the natural way to write it — assert each record is
defensible in a loop — fails on the first bad one and tells you nothing about the rest. Collecting
the failures and asserting the collection is empty turns one red test into a report.

The rest of the file is three groups, and the grouping is the argument of the day repeated in test
form: **does it replay**, **does it carry only what a rule reads**, and **what does it say about who
decided**. A test that does not belong to one of those three is a test about something other than a
decision record.

## The mechanism

The whole file, at `tests/test_record.py`:

```python
"""The decision record: does it replay, does it carry only what a rule reads, does it resolve.

The test that matters is `test_every_decided_claim_replays_to_its_own_verdict`. Everything else in
this file exists to make its failure readable.
"""

from __future__ import annotations

import asyncio
import json
from contextlib import asynccontextmanager
from datetime import date

import pytest
from google.adk.sessions import InMemorySessionService
from mcp import Client
from pydantic import ValidationError

from claims_desk import boundary, desk, recall, record, sessions
from claims_desk.domain import Cover, Notification, Outcome, Peril, Reason
from claims_mcp import tools
from claims_mcp.server import server

COVER = Cover(
    in_force=True,
    perils=frozenset({Peril.ESCAPE_OF_WATER.value, Peril.FIRE.value}),
    fast_track_limit=2500,
)


@pytest.fixture(autouse=True)
def _in_process(tmp_path, monkeypatch):
    monkeypatch.setattr(tools.store, "claims", tmp_path / "claims")
    monkeypatch.setattr(sessions, "service", InMemorySessionService())

    @asynccontextmanager
    async def connected():
        async with Client(server) as client:
            yield client

    monkeypatch.setattr(boundary, "connected", connected)
    return tmp_path


def a_notification(**over) -> Notification:
    fields = {
        "id": "FNOL-4471",
        "policy_number": "SYN-POL-1001",
        "description": "the flexible hose let go overnight",
        "estimate": 800,
        "date_of_loss": date(2026, 8, 14),
        "photo_ref": "IMG-4471",
        "contact_ref": "C-4471",
    }
    return Notification(**{**fields, **over})


def a_record(**over) -> record.DecisionRecord:
    note = over.pop("notification", a_notification())
    cover = over.pop("cover", COVER)
    loss_type = over.pop("loss_type", "escape-of-water")
    injury = over.pop("injury_reported", False)
    outcome = over.pop("outcome", "fast-track")
    reason = over.pop("reason", None)
    return record.DecisionRecord(
        claim_id=note.id,
        outcome=outcome,
        reason=reason,
        facts=record.facts_from(note, cover, loss_type, injury),
        provenance=record.Provenance(
            model="scripted/claims-classifier",
            calls={"classifier": 1},
            handbook=record.cites(reason),
        ),
        **over,
    )


# --- does it replay -----------------------------------------------------------------------------


def test_a_record_replays_to_its_own_verdict() -> None:
    assert record.replay(a_record()) == ("fast-track", None)
    assert record.defensible(a_record()) is True


def test_a_record_whose_outcome_was_edited_is_not_defensible() -> None:
    """The whole point. Change the stored verdict and the facts no longer produce it."""
    tampered = a_record(outcome="deficiency", reason="injury_reported")
    assert record.defensible(tampered) is False
    assert record.replay(tampered) == ("fast-track", None)


def test_every_decided_claim_replays_to_its_own_verdict(_in_process) -> None:
    """Twelve claims, decided over the real boundary, every record re-derived from itself alone."""
    counts = asyncio.run(desk.run_queue())
    assert counts == {"fast-track": 4, "deficiency": 8, "pending": 0}

    stored = [
        json.loads(path.read_text(encoding="utf-8"))
        for path in sorted((_in_process / "claims").glob("*.json"))
    ]
    assert len(stored) == 12
    undefendable = []
    for claim in stored:
        loaded = record.DecisionRecord.model_validate(claim["decision"])
        if not record.defensible(loaded):
            undefendable.append((loaded.claim_id, loaded.outcome, record.replay(loaded)))
    assert undefendable == []


def test_replay_needs_no_store_no_boundary_and_no_model(_in_process) -> None:
    """Asserted by doing it: serialise the record, forget everything else, replay it."""
    built = a_record(
        notification=a_notification(estimate=4000),
        outcome="deficiency",
        reason="above_fast_track_limit",
    )
    as_json = json.dumps(record.as_stored(built))
    reloaded = record.DecisionRecord.model_validate(json.loads(as_json))
    assert record.defensible(reloaded) is True
    assert record.replay(reloaded) == ("deficiency", "above_fast_track_limit")


@pytest.mark.parametrize(
    ("over", "expect"),
    [
        ({"notification": None, "date_of_loss": None}, Reason.MISSING_DATE_OF_LOSS),
        ({"notification": None, "contact_ref": None}, Reason.MISSING_CONTACT),
        ({"cover": None}, Reason.UNKNOWN_POLICY),
        ({"loss_type": "theft"}, Reason.PERIL_NOT_COVERED),
        ({"notification": None, "photo_ref": None}, Reason.MISSING_PHOTO_REFERENCE),
        ({"injury_reported": True}, Reason.INJURY_REPORTED),
        ({"notification": None, "estimate": 9000}, Reason.ABOVE_FAST_TRACK_LIMIT),
    ],
)
def test_each_rule_replays_from_a_record(over: dict, expect: Reason) -> None:
    """Every deficiency reason, re-derived from a record's facts and nothing else."""
    if over.pop("notification", "keep") is None:
        over = {"notification": a_notification(**over)}
    built = a_record(outcome="deficiency", reason=expect.value, **over)
    assert record.defensible(built) is True


# --- does it carry only what a rule reads -------------------------------------------------------


def test_the_facts_are_exactly_what_assess_reads() -> None:
    """A field in the record that no rule consults will be read as evidence by somebody."""
    assert set(record.Facts.model_fields) == {
        "policy_number",
        "date_of_loss",
        "contact_ref",
        "photo_ref",
        "estimate",
        "policy_found",
        "in_force",
        "perils",
        "fast_track_limit",
        "loss_type",
        "injury_reported",
    }


def test_no_part_of_the_record_holds_what_the_policyholder_said() -> None:
    """The description is not a fact any rule reads, so it is not in the record."""
    built = record.as_stored(a_record())
    assert "flexible hose" not in json.dumps(built)
    assert "description" not in built["facts"]


def test_an_undeclared_field_is_refused() -> None:
    with pytest.raises(ValidationError) as refused:
        record.Facts.model_validate({**record.as_stored(a_record())["facts"], "confidence": 0.9})
    assert refused.value.errors()[0]["type"] == "extra_forbidden"


def test_the_letter_is_stored_beside_the_record_and_not_inside_the_facts() -> None:
    built = a_record()
    built.letter = "We have opened claim FNOL-4471 and need to see the damage."
    stored = record.as_stored(built)
    assert stored["letter"].startswith("We have opened")
    assert "letter" not in stored["facts"]
    assert record.defensible(built) is True


# --- provenance and citations -------------------------------------------------------------------


def test_provenance_is_ignored_by_the_replay() -> None:
    """It answers "who said this", not "does it follow". Changing it cannot change the verdict."""
    built = a_record()
    built.provenance.model = "something-else-entirely"
    built.provenance.calls = {}
    assert record.defensible(built) is True


def test_the_rules_version_is_recorded_on_every_record() -> None:
    assert a_record().provenance.rules_version == record.RULES_VERSION
    assert record.RULES_VERSION


def test_every_citation_on_every_reason_resolves() -> None:
    """A record that cites a handbook section nobody can find is a record with a footnote."""
    for reason in Reason:
        citations = record.cites(reason.value)
        assert citations, reason
        for citation in citations:
            assert recall.resolves(citation), (reason, citation)
    for citation in record.cites(None):
        assert recall.resolves(citation)


def test_a_fast_track_cites_the_rule_that_permits_it() -> None:
    assert record.cites(None) == ["handbook.md#HB-01"]


def test_the_rule_that_fired_is_derived_rather_than_stored() -> None:
    assert record.which_rule(a_record()) == "no rule fired: every check passed"
    deficiency = a_record(outcome="deficiency", reason="injury_reported", injury_reported=True)
    assert record.which_rule(deficiency) == "injury_reported"
    assert "rule" not in record.as_stored(deficiency)


def test_every_reason_the_desk_can_give_has_citations() -> None:
    """A reason added to `Reason` without a handbook section is a verdict nobody can look up."""
    assert set(record.CITES) == {reason.value for reason in Reason}


# --- reading a record back later ----------------------------------------------------------------


def test_a_peril_the_enum_no_longer_holds_is_visible_on_read() -> None:
    """Day 13's schema refuses it at write time. This is the audit question, asked later."""
    built = a_record(loss_type="subsidence", outcome="deficiency", reason="peril_not_covered")
    assert record.peril_is_known(built) is False
    assert record.defensible(built) is True


def test_the_boundary_refuses_a_record_for_a_different_claim() -> None:
    """A record filed against the wrong claim is the one error that makes an audit worthless."""
    mismatched = record.as_stored(a_record())
    refused = asyncio.run(
        boundary.record_decision(
            "FNOL-4472", Outcome.FAST_TRACK.value, None, None, mismatched
        )
    )
    assert refused["recorded"] is False
    assert refused["refused"] == "the decision record is for a different claim"


def test_a_pending_claim_has_no_record_because_there_is_nothing_to_defend() -> None:
    queue = {note.id: note for note in desk.Store().notifications()}
    verdict = asyncio.run(
        desk.decide(queue["FNOL-4477"], desk.Budget(limit=0, label="nothing"))
    )
    assert verdict.outcome == desk.PENDING
    assert verdict.record is None
```

**Line by line:**

- **The docstring names the one test that matters** and says the rest exist to make its failure
  readable. A file with twenty-four tests needs a sentence saying which one you would keep.
- **The fixture is days 6, 8, 9, 10, 11 and 12's, unchanged** — scratch claims directory, fresh
  session service, boundary swapped in-process. Sixth file. The rep to extract it has been owed since
  day 11 and is owed harder now.
- `def a_notification(**over)` **and** `def a_record(**over)` — **two builders with keyword
  overrides.** Twenty-four tests each needing a valid record would otherwise be twenty-four copies of
  eleven fields, and the one that mattered would be invisible among them.
- `over.pop("notification", a_notification())` — **the builder takes either a whole notification or
  nothing.** A test that changes a field the notification owns passes a rebuilt notification; a test
  that changes cover or the reading passes those directly.
- `COVER` **as a module constant with `fast_track_limit=2500`** — the same figure the handbook's HB-04
  gives as typical. A fixture that used 999 would work and would stop the numbers in a failure
  reading like a claim.
- `test_a_record_replays_to_its_own_verdict` — **the simplest possible statement of the property**,
  first in the file, so a reader knows what `defensible` means before meeting anything subtle.
- `test_a_record_whose_outcome_was_edited_is_not_defensible` — **the inverse, immediately after.** It
  asserts `False` *and* asserts what the facts actually produce, because a detection that cannot say
  what the right answer was is half a detection.
- `undefendable = []` **collected in a loop, asserted empty** — the arrangement described above. The
  list holds the claim id, the stated outcome and the replayed one, so a failure is a table.
- `assert counts == {"fast-track": 4, "deficiency": 8, "pending": 0}` **before the records are
  read** — if the queue itself changed, the record failures that follow would be a consequence rather
  than the cause, and this line says which happened.
- `test_replay_needs_no_store_no_boundary_and_no_model` — **asserted by doing it**: the record is
  serialised to JSON, parsed back, and replayed. Nothing about the round trip is mocked; if a date
  survived as an object rather than a string, this is what would notice.
- `@pytest.mark.parametrize(("over", "expect"), [...])` **with seven rows, one per deficiency
  reason** — every rule in `assess` re-derived from a record. Day 2's eight tests asserted the rules;
  these assert the rules are still reachable from what was stored.
- `if over.pop("notification", "keep") is None:` — **a sentinel, because `None` is a meaningful
  value here.** Three of the seven rows turn on a notification field being absent, so the row says
  `"notification": None` to mean *rebuild the notification with these overrides*, and `"keep"`
  distinguishes "not mentioned" from "explicitly none".
- `test_the_facts_are_exactly_what_assess_reads` — **an equality on the field set**, which is part
  1.1's whole discipline in one assertion. Adding a field to `Facts` fails here, and the failure is
  the review conversation.
- `assert "flexible hose" not in json.dumps(built)` — **the policyholder's own words, searched for in
  the serialised record.** The description is in the fixture, so this would find it if any layer put
  it back.
- `assert "description" not in built["facts"]` — the same check by field name, because a record could
  hold an empty description and pass the first assertion.
- `test_an_undeclared_field_is_refused` — **day 13's `extra="forbid"`, asserted on the record's own
  schema.** The record is the artefact most likely to accumulate helpful additions, and this is what
  makes that a conversation instead of a commit.
- `test_the_letter_is_stored_beside_the_record_and_not_inside_the_facts` — **three assertions in one
  test**: the letter is stored, it is not in the facts, and the record still replays with it there.
  The third is the one that says the letter is not evidence.
- `test_provenance_is_ignored_by_the_replay` — **changes the model name and empties the call counts,
  then asserts the verdict is unmoved.** Part 1.2's structural claim, made executable.
- `test_every_citation_on_every_reason_resolves` — **iterates `Reason` and calls day 12's
  `resolves`.** This is the cross-day check: a handbook section deleted in `data/handbook.md` turns a
  record's citation into a footnote, and this is the only thing that would notice.
- `assert citations, reason` — **the reason as the assertion message**, so a missing mapping says
  which one rather than "assert []".
- `test_every_reason_the_desk_can_give_has_citations` — **set equality between `CITES` and `Reason`.**
  Not a subset in either direction: a citation for a reason that no longer exists is dead weight, and
  a reason with no citation is a verdict nobody can look up.
- `test_the_rule_that_fired_is_derived_rather_than_stored` — **asserts the derivation and the
  absence.** `"rule" not in record.as_stored(...)` is what stops somebody helpfully storing it.
- `test_a_peril_the_enum_no_longer_holds_is_visible_on_read` — **a record with `subsidence` in it,
  which day 13's schema would refuse at write time.** It loads, it replays, and `peril_is_known` says
  `False`. That is the audit question — *was this a peril we recognised* — asked of history.
- `test_the_boundary_refuses_a_record_for_a_different_claim` — **the one error that makes an audit
  worthless**, refused at the boundary in the shape day 5 established: `recorded: false` and a
  sentence saying which rule.
- `test_a_pending_claim_has_no_record_because_there_is_nothing_to_defend` — **`Budget(limit=0)` to
  force a pending verdict**, reusing day 11's mechanism, and asserting `verdict.record is None`. Day
  6's rule about claim files, applied to records.

## When it breaks

Change a business rule. Take `fire` out of `PHOTO_REQUIRED_FOR` — the correspondence team decides a
fire claim does not need a photograph — and run the suite:

```
FAILED tests/test_record.py::test_every_decided_claim_replays_to_its_own_verdict
1 failed, 23 passed in 2.62s
```

One test, and it is the one this day is about. What it is telling you is not that the change is
wrong. It is that **history stopped being defensible**:

```bash
uv run python -c "
import json, pathlib
from claims_desk import record

history = json.loads(pathlib.Path('history.json').read_text(encoding='utf-8'))
broken = []
for claim_id, stored in sorted(history.items()):
    loaded = record.DecisionRecord.model_validate(stored)
    if not record.defensible(loaded):
        broken.append((claim_id, loaded.reason, record.replay(loaded)))
print('records written before the change:', len(history))
print('no longer defensible            :', len(broken))
for row in broken:
    print('   %-11s filed as %-24s now replays as %s' % row)
"
```

```
records written before the change: 12
no longer defensible            : 1
   FNOL-4477   filed as missing_photo_reference  now replays as ('fast-track', None)
```

Verbatim, from this project, against twelve records written before the rule moved. One claim was
refused for want of a photograph on a fire loss; under the new rule the same facts produce a
fast-track. The record did not change. The rules moved underneath it.

That is exactly what `RULES_VERSION` exists to describe and **does not currently prevent**. It is a
hand-bumped string, nothing forces it to change when `assess` does, and `replay` does not check it.
So the honest state of this project is: the replay notices that history broke, which is the important
half, and reports it as one bad record rather than as *the rules changed* — the diagnosis is still a
person's job.

Now the failure inside the failure, and it is the more useful one.

**Swap two checks in `assess` instead** — put the injury rule above the photograph rule — and the
suite is entirely green. Twenty-four passed. Not one record is reported as undefensible.

The reason is in how the test builds its evidence: it runs the queue, which writes records **with the
current rules**, and then replays them **against the current rules**. Both halves moved together, so
they agree. The test cannot see a rule change at all; it saw this one only because the demonstration
above kept records from before it.

So `test_every_decided_claim_replays_to_its_own_verdict` proves something narrower than its name
suggests: *the records this code writes are consistent with the rules this code has.* Valuable —
it is what catches a record assembled from memory, a field dropped in serialisation, a rule applied
inconsistently within one run — and it is not a test that history survived.

The fix is the review comment in the next section, and it is a fixture: records checked in as JSON,
written by an older version of this code, replayed on every run. This project does not have one, the
hub carries it as a `TODO(me)`, and the reason it is worth naming loudly is that **a test that
creates its own evidence can only ever find bugs in the thing it did not create.**

## In production

**What a senior writes instead.** The same suite, with the replay run over a sample of *real* stored
records in a scheduled job rather than only over records the test just created — because the test
creates records with today's code and the store holds records from every version that ever ran. A
replay that only ever sees fresh records cannot discover that history broke.

**What degrades at scale.** Twenty-four tests over twelve claims runs in under three seconds. The
number that moves is the queue test: it decides every notification in the fixture, so it grows with
the fixture, and it is already the slowest test in this project. At a realistic fixture — a few
hundred notifications covering the cases a real desk sees — it stops belonging in the unit suite and
becomes a job, and the thing that has to stay in the fast suite is the parametrised one that replays
each rule from a hand-built record.

**The review comment.** *"`test_every_decided_claim_replays_to_its_own_verdict` builds its records by
running the queue, so it can only ever fail for a rule change, never for a storage change. Add a
fixture of records checked in as JSON — written by an older version of this code — and replay those
too."*

**The interview question.** *"Your test replays every decision your system made and they all pass.
Somebody changes a business rule. What should happen to that test, and what should happen to the
records?"*
