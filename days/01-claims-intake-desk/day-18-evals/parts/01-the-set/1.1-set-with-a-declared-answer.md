## One-line answer

An evalset is an answer key plus something that is not the desk to mark against it — so this one runs
`python -m claims_desk` in a fresh process, reads what came out, and marks every claim against the
`expected` block `data/notifications.json` has carried since day 2, with **no partial credit on a
file**.

## The idea

Every claims department has a file audit, and every handler dreads the week it lands.

A senior handler pulls a sample of closed files — twelve, say, from last month — and goes through
each one with a marking sheet. Not a vague read: a sheet. Was the policy checked? Was the right letter
sent? Does the reason on the file match the reason on the letter? Each file gets a row of ticks and
crosses, and a file with one cross is a failed file, however many ticks sit beside it. Then the total
goes on a chart, next to last quarter's, and if it has dropped somebody has a meeting.

Three things make that audit worth doing, and they are the three things this day builds.

The first is that **the auditor is not the handler.** A handler marking their own files gets full
marks, every time, honestly. The audit works because the person with the sheet had nothing to do with
the decision and reads only what is in the file: the notes, the letter, the timestamps. Nothing the
handler remembers counts. This is the whole difference between this day and the 247 tests this desk
already has. A test imports `desk.decide` and asks it a question. An audit runs the desk the way a
person does — one command, a fresh process — and reads what it leaves behind.

The second is that **the right answer was decided before the file was opened.** The marking sheet
does not say "does this look reasonable". It says *this* claim should have been fast-tracked, *that*
one should have had a letter about the date of loss. This desk has had that sheet since day 2: every
notification in `data/notifications.json` carries an `expected` block with the outcome, the reason,
the peril and whether anyone was hurt, written by hand, by somebody who read all twelve. The desk has
never been allowed to see it — `Notification.from_record` skips it on purpose, and the `Store` method
that returns it says in its own docstring that nothing the desk runs may call it. Today is the day
that method gets its reader.

The third is that **a file passes or it does not.** Eleven ticks and a cross is a failed file, because
the cross is the thing that reaches a policyholder. An eval that awards seven marks out of eight is
an eval that lets a wrong letter through with a good score, and a score that can hide a wrong letter
is not a score anybody at a claims desk can use.

So the shape of this part is the marking sheet. A **case** is one claim and its declared answer. A
**mark** is one thing checked on it — what was expected, what was found, whether they agree. A
**result** is all the marks on one claim, and it passes only if every one of them does. And the whole
thing runs from one command, `./run eval`, which exits non-zero if any file failed — because a score
that is printed and not enforced is the chart on the wall that nobody has looked at since spring.

Two marks are made in this part: the outcome and the reason. The route the desk took to them, the
letter it wrote, and what the number means are parts 1.2, 2.1 and 2.2, and each of them is a column
added to the same sheet.

## The mechanism

The whole file, at `claims_desk/evals.py`. It is the complete marking sheet — every column parts 1.2,
2.1 and 2.2 will explain is already in it, because a file printed in pieces is a file somebody types
in pieces, and the explanations of `expected_tools`, `judge` and `baseline` belong beside the
transcripts that motivate them. This part walks the spine: the set, the run, the two first marks, the
report, and the exit code.

```python
"""The file audit: the whole desk, run as a person runs it, marked against a declared answer key.

Every test this project has written so far asks a function a question and checks the answer. That
is the right tool for `assess` and the wrong tool for the desk, because the desk's correct output is
not a return value. It is twelve claim files, seven letters, a held claim and a trail of log lines —
produced by two processes, three agents and a workflow runtime, and any one of them can be wrong in
a way that leaves every unit test green.

So this module does what a senior handler does with a morning's closed files. It **runs the desk
exactly as a person runs it** — `python -m claims_desk`, a subprocess, no import and no hook — reads
what came out, and marks each claim against the answer `data/notifications.json` has declared since
day 2. Four things are marked on every claim, and a claim passes only if all four do:

- **the outcome and the reason** — what the desk decided;
- **the loss type** — what the classifier read, when it was asked to read at all;
- **the trajectory** — which boundary tools the desk called and how many model calls it spent,
  because a right answer reached by the wrong route is a right answer nobody can rely on;
- **the letter** — judged against the house style, one rubric row at a time.

And a **baseline**: the same twelve claims decided by a desk that reads nothing at all. A score on
its own is a number. A score beside the score of a desk with no model in it is a measurement of what
the model is worth, and it turns out to be less than a first glance at 12/12 suggests.

**Nothing in here may be reached by the desk.** `Store.expectations` is the answer key; the desk
importing this module would be a claims handler marking their own files.
"""

from __future__ import annotations

import json
import re
import shutil
import subprocess
import sys
from collections.abc import Callable
from dataclasses import dataclass, field
from pathlib import Path
from typing import Any

from claims_desk.domain import Cover, Outcome, Reason, assess
from claims_desk.store import Store

#: How the audit runs the desk: the same command day 6 gave a person, in a fresh process. The
#: interpreter is this one, so the run happens in the same environment — but nothing else is shared,
#: which is what makes the log lines a black-box account rather than a view of internals.
DESK = [sys.executable, "-m", "claims_desk"]

#: Reasons `assess` reaches before any description is read. A claim that stops at one of these costs
#: no model call, and an audit that did not check would let a desk quietly pay for readings it never
#: uses. Day 7 chose this ordering to save money; this is where the saving is measured.
SETTLED_BY_FIELDS = frozenset(
    {
        Reason.MISSING_DATE_OF_LOSS.value,
        Reason.MISSING_CONTACT.value,
        Reason.UNKNOWN_POLICY.value,
        Reason.POLICY_NOT_IN_FORCE.value,
    }
)

#: Reasons reached before the boundary is asked whether the policy was on risk. The desk only asks
#: `check_in_force` when it has a policy and a date, so these two are the claims where it never
#: does.
BEFORE_IN_FORCE = frozenset({Reason.MISSING_DATE_OF_LOSS.value, Reason.UNKNOWN_POLICY.value})

#: What the house style refuses in a letter: a figure. The claim reference is the one exception, and
#: `judge` removes it before looking, exactly as `workflow.HouseStyle` does.
A_FIGURE = re.compile(r"\d")

#: The three things a deficiency letter is allowed to ask for. A letter that asks for none of them
#: has told the policyholder something is wrong and not what to do about it, which is the failure
#: the whole letter exists to prevent.
AN_ASK = ("please send", "please confirm", "nothing further for you to send")

#: The marking scheme for a letter. Each row is one thing a reader of the letter can check, with the
#: check itself and the reason the department cares — the `why` is there for the same reason it is
#: in `alerts.RULES`: a rubric row nobody can justify in a sentence is a row that fails good
#: letters.
RUBRIC: tuple[dict[str, Any], ...] = (
    {
        "id": "L1",
        "asks": "names the claim reference",
        "why": "a letter with no reference is filed against nothing",
        "check": lambda letter, claim: claim in letter,
    },
    {
        "id": "L2",
        "asks": "carries no figure except the reference",
        "why": "a figure in a letter is a figure the insurer can be held to",
        "check": lambda letter, claim: A_FIGURE.search(letter.replace(claim, "")) is None,
    },
    {
        "id": "L3",
        "asks": "is four sentences at most",
        "why": "the house maximum; a longer letter is read less, not more",
        "check": lambda letter, claim: sentences(letter) <= 4,
    },
    {
        "id": "L4",
        "asks": "tells the policyholder what to send, or that there is nothing to send",
        "why": "a letter that names a problem and no action is a letter that generates a call",
        "check": lambda letter, claim: any(ask in letter.lower() for ask in AN_ASK),
    },
)


def sentences(text: str) -> int:
    """How many sentences a letter has, counted the way a reader counts them: by full stops."""
    return len([piece for piece in text.split(".") if piece.strip()])


@dataclass(frozen=True)
class Mark:
    """One thing checked on one claim: what was expected, what was found, and whether they agree."""

    name: str
    expected: Any
    got: Any

    @property
    def passed(self) -> bool:
        return self.expected == self.got


@dataclass
class CaseResult:
    """One claim, marked. It passes only if every mark passes: no partial credit on a file."""

    claim_id: str
    marks: list[Mark] = field(default_factory=list)

    @property
    def passed(self) -> bool:
        return all(mark.passed for mark in self.marks)

    @property
    def failed(self) -> list[Mark]:
        return [mark for mark in self.marks if not mark.passed]


def run_desk(root: Path | None = None) -> str:
    """Run the desk over the whole queue in a fresh process and return every line it logged.

    The claim files are cleared first. A file left by an earlier run is a decision the run under
    audit never made, and an audit that reads it is marking last week's work.
    """
    base = root or Path(__file__).resolve().parent.parent
    shutil.rmtree(base / "data" / "claims", ignore_errors=True)
    done = subprocess.run(DESK, cwd=base, capture_output=True, text=True, check=False)
    if done.returncode != 0:
        raise RuntimeError(f"the desk exited {done.returncode}: {done.stderr[-400:]}")
    return done.stderr


def records(logged: str) -> list[dict[str, Any]]:
    """Every JSON line in what the desk wrote, in order. What is not JSON is not a record."""
    found = []
    for line in logged.splitlines():
        try:
            found.append(json.loads(line))
        except json.JSONDecodeError:
            continue
    return found


def by_claim(lines: list[dict[str, Any]]) -> dict[str, list[dict[str, Any]]]:
    """Every record that belongs to each claim, attributed by the span that closed around it.

    Day 17 put a `claim` span round each notification and the queue works one claim at a time, so
    every line between one claim span's close and the next belongs to the next. That includes the
    `boundary.call` spans, which carry the tool's name and not the claim's — and it is the only way
    to know which claim a tool was called for. **This attribution is only right because the queue
    is sequential.** Day 10's parallel morning would interleave two claims' lines, and the
    trajectory would need the claim on every line; part 1.2 says what that costs.
    """
    buckets: dict[str, list[dict[str, Any]]] = {}
    pending: list[dict[str, Any]] = []
    for line in lines:
        pending.append(line)
        if line.get("event") == "span" and line.get("span") == "claim":
            buckets[str(line["claim"])] = pending
            pending = []
    return buckets


def expected_tools(expected: dict[str, Any], held: bool) -> list[str]:
    """The boundary calls a correct desk makes for a claim with this answer, in order.

    Derived from the answer rather than written out twelve times, because the route follows from the
    verdict by day 7's ordering: fetch the policy, ask about cover only when there is a policy and a
    date, draft a letter only for a deficiency, record only what a person has not put on hold.
    """
    route = ["fetch_policy"]
    if expected["reason"] not in BEFORE_IN_FORCE:
        route.append("check_in_force")
    if held:
        return route
    if expected["outcome"] == Outcome.DEFICIENCY:
        route.append("draft_letter")
    route.append("record_decision")
    return route


def expected_calls(expected: dict[str, Any], held: bool) -> int:
    """How many model calls a correct desk spends on a claim with this answer.

    One reading, unless the fields settle it. One draft, if a letter goes out — which every
    deficiency gets except a held one. So a fast-track costs one, a deficiency the classifier had to
    read costs two, and a deficiency the fields settled costs one: the letter, and nothing else.
    """
    reading = 0 if expected["reason"] in SETTLED_BY_FIELDS else 1
    draft = 1 if expected["outcome"] == Outcome.DEFICIENCY and not held else 0
    return reading + draft


def judge(letter: str | None, claim_id: str) -> list[Mark]:
    """Mark one letter against every row of the rubric. No letter fails every row at once."""
    return [
        Mark(
            f"letter.{row['id']}",
            expected=True,
            got=bool(letter) and bool(row["check"](letter, claim_id)),
        )
        for row in RUBRIC
    ]


def mark(
    claim_id: str,
    expected: dict[str, Any],
    lines: list[dict[str, Any]],
    claim_file: dict[str, Any] | None,
) -> CaseResult:
    """Mark one claim from what the desk logged about it and what it wrote to the claim file."""
    result = CaseResult(claim_id)
    events = {str(line.get("event")): line for line in lines if line.get("event") != "span"}
    closing = next(
        (line for line in lines if line.get("event") == "span" and line.get("span") == "claim"), {}
    )
    held = bool(closing.get("held"))
    decided = events.get("desk.decided")

    waiting = next(
        (
            f"pending: {line['event'].removeprefix('desk.')}"
            for line in lines
            if line.get("event")
            in ("desk.provider_unavailable", "desk.over_budget", "desk.classification_failed")
        ),
        None,
    )
    result.marks.append(
        Mark("outcome", expected["outcome"], decided["outcome"] if decided else waiting)
    )
    result.marks.append(Mark("reason", expected["reason"], decided["reason"] if decided else None))

    if expected["reason"] not in SETTLED_BY_FIELDS:
        read = events.get("workflow.rules", {})
        result.marks.append(Mark("loss_type", expected["loss_type"], read.get("loss_type")))

    called = [
        str(line["tool"])
        for line in lines
        if line.get("event") == "span" and line.get("span") == "boundary.call"
    ]
    result.marks.append(Mark("tools", expected_tools(expected, held), called))
    result.marks.append(Mark("calls", expected_calls(expected, held), closing.get("spent")))

    if expected["outcome"] == Outcome.DEFICIENCY and not held:
        letter = (claim_file or {}).get("letter")
        result.marks.extend(judge(letter, claim_id))
    return result


def evaluate(
    logged: str,
    claim_files: dict[str, dict[str, Any] | None],
    expectations: dict[str, dict[str, Any]],
) -> list[CaseResult]:
    """Mark every claim in the answer key. A claim the desk never reached is marked, and fails."""
    buckets = by_claim(records(logged))
    return [
        mark(claim_id, expected, buckets.get(claim_id, []), claim_files.get(claim_id))
        for claim_id, expected in expectations.items()
    ]


def baseline() -> dict[str, Any]:
    """The same twelve claims, decided by a desk with no reader in it.

    Day 2's rules, with the loss type guessed as the first peril on the policy's own schedule and no
    injury ever noticed. It is the cheapest desk that can be built from this project's parts, and it
    is what the classifier's score has to be measured against: a claim this desk gets right is a
    claim the model contributed nothing to.

    Two numbers come back, because they say different things. `verdict` counts claims where the
    outcome and the reason were right, whatever peril was guessed — a claim can be right for the
    wrong reason. `verdict_and_reading` also requires the guessed peril to be the real one wherever
    the rules read it at all, which is the standard the desk itself is marked to.
    """
    store = Store()
    policies = {policy.number: policy for policy in store.policies()}
    verdicts = 0
    readings = 0
    wrong: list[dict[str, Any]] = []
    for note in store.notifications():
        expected = store.expectations()[note.id]
        policy = policies.get(note.policy_number)
        cover = (
            Cover(
                in_force=policy.in_force_on(note.date_of_loss) if note.date_of_loss else False,
                perils=policy.perils,
                fast_track_limit=policy.fast_track_limit,
            )
            if policy
            else None
        )
        guess = sorted(policy.perils)[0] if policy else ""
        outcome, reason = assess(note, cover, guess, injury_reported=False)
        got = (outcome.value, reason.value if reason else None)
        want = (expected["outcome"], expected["reason"])
        read_right = expected["reason"] in SETTLED_BY_FIELDS or guess == expected["loss_type"]
        verdicts += got == want
        readings += got == want and read_right
        if got != want or not read_right:
            wrong.append({"claim": note.id, "guessed": guess, "got": got, "wanted": want})
    return {
        "of": len(store.expectations()),
        "verdict": verdicts,
        "verdict_and_reading": readings,
        "wrong": wrong,
    }


def report(results: list[CaseResult], floor: dict[str, Any], out: Callable[[str], None]) -> bool:
    """Print the audit, one line per claim, and say whether the gate is green. Returns green."""
    passed = [result for result in results if result.passed]
    for result in results:
        if result.passed:
            out(f"ok   {result.claim_id}  {len(result.marks)} marks")
        else:
            out(f"RED  {result.claim_id}")
            for failed in result.failed:
                out(f"       {failed.name}: expected {failed.expected!r}, got {failed.got!r}")
    out("")
    out(f"desk     {len(passed)}/{len(results)} claims right on every mark")
    out(
        f"baseline {floor['verdict_and_reading']}/{floor['of']} for a desk that reads nothing, "
        f"or {floor['verdict']}/{floor['of']} if being right for the wrong reason counts"
    )
    green = len(passed) == len(results)
    out("eval: green" if green else f"eval: RED, {len(results) - len(passed)} claim(s) failed")
    return green


def main() -> int:
    """Run the desk, pull every file, mark the lot. Exit 1 on any failed claim: that is the gate."""
    store = Store()
    logged = run_desk()
    files = {claim_id: store.claim(claim_id) for claim_id in store.expectations()}
    results = evaluate(logged, files, store.expectations())
    return 0 if report(results, baseline(), print) else 1


if __name__ == "__main__":
    sys.exit(main())
```

**Line by line** — the spine of the sheet. `expected_tools`, `expected_calls`, `judge`, `RUBRIC` and
`baseline` are walked in parts 1.2, 2.1 and 2.2, beside the runs that explain them:

- `from claims_desk.domain import Cover, Outcome, Reason, assess` and `from claims_desk.store import
  Store` — **the only two imports from this project, and neither is the desk.** The audit knows the
  domain's vocabulary and can read the store. It does not know `desk`, `workflow`, `boundary` or any
  agent exists, which is what makes it an audit: nothing it marks can be reached by anything but the
  desk's own output.
- `DESK = [sys.executable, "-m", "claims_desk"]` — **the command day 6 gave a person, run by a
  subprocess.** `sys.executable` rather than `"python"` so the child runs on the interpreter `uv run`
  chose for this process — day 0's pin, not whatever the shell's `python` resolves to. `-m
  claims_desk` rather than an import of `run_queue`: the desk decides its queue with nobody watching
  from inside. Everything the audit learns, it learns the way a person would, from the log and the
  claim files.
- `SETTLED_BY_FIELDS` — **the four reasons `assess` reaches without reading a sentence**, named as a
  set because three different marks turn on it: whether a loss type is marked at all, whether a
  reading was paid for, and whether the baseline's guessed peril matters. Day 7 put those four checks
  first to save a model call; this is the first time anything has verified that the saving happens.
- `class Mark` — **one thing checked, frozen.** `expected` and `got` are stored as they were, and
  `passed` is derived by comparing them, because a mark that stored only a boolean would print `RED
  FNOL-4474` and nothing else. The report needs both values, and so does whoever reads it.
- `class CaseResult` and `passed` — **`all(...)`, and no weighting.** This is the no-partial-credit
  rule in one line. A claim with the right outcome and a letter that names a figure is a claim whose
  policyholder received a figure; the outcome mark does not offset it.
- `run_desk` and `shutil.rmtree(base / "data" / "claims", ignore_errors=True)` — **the claim files
  are cleared before the run.** Day 15 made `record_decision` idempotent, so a stale file from an
  earlier run is silently accepted as "the same write" and the audit would mark last week's letter.
  An audit starts with an empty file. `ignore_errors=True` because on the first run there is nothing
  to clear, and that is not an error.
- `capture_output=True, text=True, check=False` — **the log is the return value.** Day 1 put every
  record on standard error as one JSON object per line, and day 17 gave every line a trace and a
  span; this reads all of it. `check=False` and then an explicit `RuntimeError` naming the exit code
  and the last 400 characters, because a desk that crashed mid-queue is a finding, and
  `CalledProcessError` would have hidden which claim it crashed on.
- `records` — **what is not JSON is not a record.** The boundary subprocesses share this stderr and
  the framework writes its own warnings there; skipping a line that will not parse is the only
  honest option, and it is the same helper day 17's tests used.
- `by_claim` — **attribution by the closing span.** Read part 1.2 for why this is the only way to
  know which claim a `boundary.call` was for, and why it is only correct because the queue is
  sequential.
- `mark` and `events = {...}` — **one record per event name, last one wins.** For the events this
  function reads — `desk.decided`, `workflow.rules` — there is exactly one per claim, so "last"
  never chooses. It is a dictionary rather than a list so a missing event is `None` and not an
  `IndexError`, which is what a claim the desk never decided produces.
- `waiting = next(...)` — **a pending claim is marked as pending, and says why.** Day 15's escalation
  and day 11's refusal both leave a log line and no `desk.decided`; the outcome mark for such a claim
  says `pending: provider_unavailable` rather than `None`, because the report is read by somebody who
  needs to know whether the desk was wrong or the provider was down.
- `Mark("outcome", ...)` and `Mark("reason", ...)` — **the two marks this part is about.** Both read
  from `desk.decided`, the one log line the desk writes at the moment it makes up its mind, which is
  before day 16's gate and before any letter. A held claim is therefore marked on its decision, not
  on the empty claim file — the audit asks what the desk decided, and the gate is a separate
  question about what it did next.
- `if expected["reason"] not in SETTLED_BY_FIELDS:` — **a reading is marked only where one should have
  happened.** The key says FNOL-4473 is a fire, and the desk never found that out, correctly, because
  the claim has no date of loss. Marking a loss type there would fail a right decision for not
  reading a sentence it was right not to read.
- `evaluate` — **every claim in the key, whether or not the desk reached it.** `buckets.get(claim_id,
  [])` hands `mark` an empty list for a claim the log never mentions, and an empty list fails every
  mark. An audit that iterated the log instead would silently pass a queue that stopped at claim
  six.
- `report(..., out)` — **the printer is a parameter.** `main` passes `print`; a test passes
  `list.append`, and asserts on the exact lines — because the report *is* the product, and a report
  that says `RED` without the mark, the expected value and the found value is a page somebody has to
  reproduce by hand.
- `return 0 if report(...) else 1` and `sys.exit(main())` — **the gate.** The exit status is the
  whole point of running this from `./run eval` rather than reading a chart: a non-zero exit is what
  a CI runner refuses on, and day 19 is where it gets one.

  claim: no letter, because none went out. Eighty-four marks in all, and part 4.1 holds that number.
- **`12/12` on a line by itself would be the number this day exists to distrust.** The line under it
  is part 2.2. Read them together or not at all.
- **`eval: green` is a sentence and an exit status.** The `OK eval` after it is the driver reporting
  the status; the word before it is for a person.

## When it breaks

Make the desk mark its own files. Import `run_queue` and call it in-process instead of launching the
command:

```diff
-    logged = run_desk()
+    from claims_desk.desk import run_queue
+    import asyncio, io, contextlib
+    captured = io.StringIO()
+    with contextlib.redirect_stderr(captured):
+        asyncio.run(run_queue())
+    logged = captured.getvalue()
```

It runs, it prints the same twelve `ok` lines and `eval: green` — and forty JSON lines appear on the
terminal that the audit never saw:

```
$ uv run python -m claims_desk.evals 2>leaked.jsonl >/dev/null; wc -l < leaked.jsonl
40
$ grep -c '"event": "boundary\.' leaked.jsonl
40
```

Every one of them is from the boundary. `redirect_stderr` swaps the Python object `sys.stderr`; the
forty boundary subprocesses inherit file descriptor 2, which is the terminal, so their lines never
reach `captured` at all. Today that costs nothing, because the marks only read desk-side lines. The
day somebody adds a mark on `boundary.record_decision`'s `letter_chars`, the mark reads `None`, fails,
and sends somebody to debug the boundary — which is fine and was never the point.

The point is the other thing the diff did: **the audit now shares a process with the thing it is
auditing.** Same `sessions.service`, same `hooks.current_budget`, same `ContextVar`s, same module
state — and the first time a test leaves a trace id set, or a budget half-spent, the audit inherits
it. A handler marking their own files does not lie. They just cannot see what they cannot see. The
smallest fix is the line that was there: a subprocess, and nothing shared but the interpreter.

## In production

**What a senior writes instead.** The same shape with the answer key in its own file, versioned
separately from the fixtures, and a *second* key written by a second person for a sample of the cases
— because an answer key written by the same hand that wrote the rules encodes the rule-writer's
assumptions, and the audit then measures agreement with those rather than correctness. Where two keys
disagree, the case is flagged rather than marked; that disagreement rate is itself reported, and it
is the first number a reviewer asks for.

**What degrades at scale.** Twelve claims, twelve declared answers, twelve minutes to write them by
hand. A real first-notice-of-loss desk sees three to four thousand notifications a month, and the
evalset that stands in for that traffic is a sample of a few hundred, re-drawn each quarter so the
desk is not tuned to one batch. Writing three hundred declared answers is a week of a senior
handler's time, every quarter, which is exactly why teams skip it — and a desk evaluated against a
year-old sample is a desk marked against claims that no longer arrive.

**The review comment.** *"`mark` reads the outcome from `desk.decided`, which is what the desk
*said*. For the ten claims that were recorded, the claim file says what it *did*. Mark both, and fail
the case if they disagree — a desk that decides one thing and records another is the failure this
whole project's boundary was built to make visible."*

**The interview question.** *"You have a hundred per cent on your evalset. Name three ways that
number can be true while the system is wrong."* (The key is wrong. The audit reads state the system
wrote to itself. The cases are the ones the system was built from.)
