## One-line answer

You cannot study a stream of events against a real model, because every run of one differs, costs
quota and needs a key — so this project carries a **test double**: a small class that subclasses
`BaseLlm`, replays a script you wrote, and is kept honest by two rules, that it never appears in an
answer and that its model string begins `scripted/` so any transcript it produced says so on its
face.

## The idea

The race is somewhere you are not. Somebody at the track has a phone pressed to their ear and is
telling you what is happening as it happens, and your job — the only job you have — is to write
down the result correctly when it comes.

That is harder than it sounds, and you would like to practise. But you cannot practise on a race.
There is no rerun; you cannot ask for the same commentary twice; and every time you want another go
somebody has to travel to a track and a race has to be run. So you do the thing every training
department eventually does. You write a commentary down on paper — a fixed set of sentences, in a
fixed order — and you have a colleague sit in another room and read it down the line to you. Now
you can practise the listening a hundred times, and the words are identical every time. When you
get the result wrong, you know exactly why, because nothing on the other end of the line changed.

And then somebody, at some point, takes a result they wrote down during a rehearsal and files it as
the result of a race. That is the failure this whole file is built to prevent, and it is worth
being blunt about how ordinary it is: the rehearsal is convenient, it is available, it is quiet,
and its output looks exactly like the real thing on paper. So the rehearsal room gets two rules
nailed to the wall. Nobody settles a bet on it. And every sheet that comes out of it is printed on
paper of a different colour, so a sheet that got into the wrong pile is visible from across the
room.

The terms, as they arrive. A **test double** is an object that stands in for a real dependency
during a test — it has the same shape and it does not do the same work. This one stands in for the
model, and it is the only way this day is runnable at all: there is no working provider key on this
machine, and even with one, a stream of events you cannot reproduce is a stream you cannot study.
What a double proves things about is **your code** — the order the runner emits events in, which
one is marked final, what a tool call looks like going past, whether a bound fires, whether an eval
scores a run correctly. What it proves about a model is **nothing whatsoever**, and no amount of
green from it is evidence that the desk answers well.

The two rules on the wall become two properties of the file. It never appears in an answer: the
commands a person actually asks a question with always reach for the pinned real model. And its
model string starts with `scripted/`, so a log line, an event or a pasted transcript that came from
it identifies itself without anyone having to remember which run it was from.

## The mechanism

`projects/01-ask-desk/ask_desk/scripted.py`, whole file. It is new today and nothing in this
project has stood in for the model before:

```python
# ask_desk/scripted.py
"""A local stand-in model that replays a fixed script. No network, no key, no cost.

This is a **test double**, and saying so plainly is the point of the file. It is not a model, it
does not think, and nothing it produces is evidence about what a real model would do. What it is
good for is everything downstream of the model: the events the runner emits, the order they arrive
in, which of them is final, what a tool call and its result look like going past, whether a bound
fires, and whether an eval scores the run correctly.

Those are the parts you have to be able to reproduce exactly, and a real model is the wrong
instrument for studying them — every run differs, every run costs quota, and a run needs a key.
Here the script is written by you, so a test that goes red went red because your code changed.

Two rules that keep it honest:

  * **It never appears in an answer.** `run.py ask` and `run.py adk` always use the pinned real
    model from `util/models.py`. Only `run.py events`, `run.py eval` and the tests reach for this.
  * **Its `model` string starts with `scripted/`**, so any transcript, log line or event that came
    from it says so on its face and cannot be mistaken for a provider response.

All scripts here are synthetic, as all data in this curriculum is.
"""

from __future__ import annotations

from dataclasses import dataclass, field
from typing import Any, AsyncGenerator, Literal

from google.adk.models.base_llm import BaseLlm
from google.adk.models.llm_request import LlmRequest
from google.adk.models.llm_response import LlmResponse
from google.genai import types


@dataclass
class Say:
    """One scripted turn: answer with this text."""

    text: str
    kind: Literal["say"] = "say"


@dataclass
class Fail:
    """One scripted turn: raise, the way a provider outage or a refusal reaches your code.

    Day 6 uses this to ask what a runner does with an exception raised inside a model call, and
    whether the failure reaches the caller or is quietly turned into an answer.
    """

    message: str
    kind: Literal["fail"] = "fail"


@dataclass
class CallTool:
    """One scripted turn: ask for this tool with these arguments."""

    name: str
    args: dict[str, Any] = field(default_factory=dict)
    kind: Literal["call"] = "call"


class ScriptedModel(BaseLlm):
    """Replays `script` one step per model call. The last step repeats if the run goes further."""

    # BaseLlm is a pydantic model, so state declared here has to be declared as a field. The
    # underscore name keeps it out of the schema ADK serialises for a model.
    _script: list[Say | CallTool | Fail] = []
    _calls: int = 0

    def __init__(self, script: list[Say | CallTool | Fail], *, name: str = "demo") -> None:
        super().__init__(model=f"scripted/{name}")
        # `object.__setattr__` because pydantic guards attribute assignment on the model; these two
        # are bookkeeping for the double and are deliberately not part of its schema.
        object.__setattr__(self, "_script", list(script))
        object.__setattr__(self, "_calls", 0)

    @property
    def calls(self) -> int:
        """How many times the runner has asked this model for a turn."""
        return self._calls

    async def generate_content_async(
        self, llm_request: LlmRequest, stream: bool = False
    ) -> AsyncGenerator[LlmResponse, None]:
        """Yield the next scripted turn.

        Non-streaming yields exactly one complete response. Streaming yields one partial response
        per word and then one complete one, which is the shape ADK documents and the shape day 5
        of this project needs in order to show what `partial` means.
        """
        step = self._script[min(self._calls, len(self._script) - 1)]
        object.__setattr__(self, "_calls", self._calls + 1)

        if isinstance(step, Fail):
            raise RuntimeError(step.message)

        if isinstance(step, CallTool):
            yield LlmResponse(content=types.Content(role="model", parts=[
                types.Part(function_call=types.FunctionCall(name=step.name, args=dict(step.args)))
            ]))
            return

        if not stream:
            yield LlmResponse(
                content=types.Content(role="model", parts=[types.Part(text=step.text)]))
            return

        words = step.text.split(" ")
        for index, word in enumerate(words):
            chunk = word if index == len(words) - 1 else word + " "
            yield LlmResponse(
                content=types.Content(role="model", parts=[types.Part(text=chunk)]),
                partial=True,
            )
        yield LlmResponse(
            content=types.Content(role="model", parts=[types.Part(text=step.text)]),
            turn_complete=True,
        )


#: The script the event walkthrough and the eval both run against: look the service up, then answer
#: from what came back. Two model calls, one tool call, one final answer.
LOOKS_IT_UP = [
    CallTool("check_service_status", {"service": "vpn"}),
    Say("The VPN is degraded: there is a known split tunnelling issue, and the gateway is up."),
]

#: A model that asks for the same tool for ever. Nothing here stops; the bound has to.
NEVER_STOPS = [CallTool("check_service_status", {"service": "vpn"})]

#: A model that answers without looking anything up — the ungrounded answer an eval must catch.
GUESSES = [Say("Yes, the VPN is completely down and engineering is aware.")]

#: A model that fails on the second call, after a tool has already run. The interesting case: some
#: work succeeded, and the question is what the caller is told about the part that did not.
FAILS_AFTER_A_TOOL = [
    CallTool("check_service_status", {"service": "vpn"}),
    Fail("the provider closed the connection"),
]
```

*Verified against google-adk 2.8.0 on this machine on 2026-09-10.*

**Line by line:**

- **The day numbers in the docstrings are this project's own, not the curriculum's**, the same
  convention `ask_desk/agent.py` uses and day 06 part 1.1 explained. "Day 5 of this project" is
  today. "Day 6" is the next sitting, `days/01-ask-desk/day-09-sessions-errors-surface/`. When you
  read the file, translate; when you read the repository, do not. The reason the file is written
  that way and not this way is that `projects/01-ask-desk/` has to be readable by somebody handed
  that folder alone, and *their* copy has no day 8 in it.
- The module docstring opens by naming the thing as a **test double** and then spends a paragraph
  saying what it is not evidence for. That is not throat-clearing. A file called `scripted.py` with
  a class called `ScriptedModel` will be imported by somebody in a hurry, and the only place a
  warning can reach them is the file itself.
- "*a test that goes red went red because your code changed*" is the whole engineering case for the
  double in one sentence. Against a real model, a red test has two possible causes and you cannot
  tell them apart from the output. Against a script you wrote, it has one.
- The **two rules**, in the docstring, are the honesty contract, and each is enforced somewhere
  real. The first is enforced by which commands import this module: `run.py ask` and `run.py adk`
  go through `models.require_pinned(models.ANSWERING)`, and nothing in either path can reach a
  `ScriptedModel`. The second is enforced two lines into `__init__` and is discussed below.
- `from __future__ import annotations` — annotations are stored as strings rather than evaluated at
  definition time, which is what lets `list[Say | CallTool | Fail]` be written on a line that runs
  before `Say` is a name anyone could resolve at runtime.
- `Say`, `Fail`, `CallTool` are three tiny `@dataclass`es rather than one class with a mode flag,
  because a script is easier to read as a list of verbs than as a list of dictionaries. Compare
  `Say("...")` with `{"kind": "say", "text": "..."}`: only one of them is refused by the editor when
  you misspell the key.
- `kind: Literal["say"] = "say"` on each — a **discriminator**. It is not read by anything in this
  file, which uses `isinstance`; it is there so that a script can be serialised to JSON and read
  back into the right class later, and so that a type checker can narrow a `Say | CallTool | Fail`
  by looking at one field. Writing it now costs a line; retrofitting it costs a migration.
- `args: dict[str, Any] = field(default_factory=dict)` — `field(default_factory=dict)` and never
  `= {}`. A bare `{}` as a default would be one dictionary shared by every `CallTool` ever built,
  so a script that mutated one call's arguments would change every other call's.
- `class ScriptedModel(BaseLlm)` — it subclasses the framework's own model base class rather than
  duck-typing something that looks like one. That matters because the runner does not call your
  object directly; it goes through whatever `BaseLlm` machinery sits between them, and a stand-in
  that skips the base class is a stand-in for a different thing from the one you are testing.
- `_script` and `_calls` are declared as class-level attributes with the **leading underscore**,
  and the comment above them says why: `BaseLlm` is a pydantic model, so anything the instance
  carries has to be declared, and the underscore keeps these two out of the schema ADK serialises
  for a model. They are bookkeeping for the double. A model's serialised form describing a Python
  list of dataclasses would be a lie about what a model is.
- `object.__setattr__(self, "_script", list(script))` rather than `self._script = list(script)`,
  and again the file's own comment carries the reason: pydantic guards attribute assignment on the
  model, and `object.__setattr__` goes round that guard to the underlying object. This is a
  deliberate reach past a framework's front door, which is exactly why it appears twice, in one
  constructor, with a comment on it, and nowhere else in this project.
- `list(script)` and not `script` — the double takes a **copy**. A caller who builds a script,
  hands it over and then appends to their list would otherwise be editing the double's script
  mid-run, and the run would change under a test that never touched the double.
- `super().__init__(model=f"scripted/{name}")` — **this is honesty rule two, and it is one line.**
  Every `LlmResponse`, every log line and every event that came out of this object can be traced to
  a model string that begins `scripted/`. There is no configuration to forget and no flag to leave
  off: you cannot construct one of these without the prefix, because the constructor writes it.
- `def calls(self)` as a `@property` rather than reading `_calls` from outside. The count is how the
  next parts say "three events, two model calls" — a public reading of a private counter, with
  nothing outside able to set it and skew the number it reports.
- `async def generate_content_async(self, llm_request, stream=False)` — the one method that has to
  match the base class, and its contract is documented rather than guessed. From the docstring of
  `BaseLlm.generate_content_async` in `google/adk/models/base_llm.py`, google-adk 2.8.0:

  > **Non-streaming mode (stream=False):** Yields exactly one LlmResponse containing the complete
  > model output (text, function calls, bytes, etc.). This response has `partial=False`.

  Everything below in this method is that sentence obeyed. Note that it is a **generator**, not a
  coroutine returning a value: the caller iterates it, which is what makes streaming expressible at
  all and is why the return annotation is `AsyncGenerator[LlmResponse, None]`.
- `llm_request` is accepted and **never read**. That is worth saying out loud rather than hiding:
  this double ignores the conversation entirely, so it cannot demonstrate anything about how a
  model responds to context. It is a stand-in for the *shape* of a model, not for its judgement.
- `self._script[min(self._calls, len(self._script) - 1)]` — the index is clamped, so once the
  script runs out the last step repeats for ever rather than raising `IndexError`. That is a design
  choice with a consequence you will meet in part 2.3: it is what makes `NEVER_STOPS` a genuine
  runaway rather than a script that ends after one step.
- The counter is incremented **immediately after the step is read and before anything can raise**,
  so a `Fail` step still counts as a call. A double that did not count its failures would make the
  arithmetic in the next parts wrong in the one case where the arithmetic matters most.
- `if isinstance(step, Fail): raise RuntimeError(...)` — it raises rather than yielding an error
  response, because that is how a provider outage reaches your code: as an exception out of the
  call, not as a polite object. What the runner then does with it belongs to the next sitting.
- The `CallTool` branch yields **one** response whose single part is a `function_call`, and then
  `return`s. No text accompanies it. That empty text is not an accident of this double — it is what
  the real thing looks like too, and part 1.2 is about what it costs a client that was not
  expecting it.
- `types.FunctionCall(name=step.name, args=dict(step.args))` — `dict(...)` copies again, for the
  same reason `list(script)` did. A script reused across two runs must not accumulate whatever the
  first run's arguments were mutated into.
- The non-streaming branch yields exactly one `LlmResponse` and returns, which is the documented
  contract quoted above, honoured literally.
- The streaming branch splits on `" "` and yields **one partial response per word**, appending the
  space back onto every word except the last, so the fragments concatenate to exactly the original
  string with no repair needed at the far end. Splitting on whitespace and joining with `" "` would
  quietly normalise a double space and make a comparison in part 2.2 come out wrong for a reason
  that had nothing to do with events.
- `partial=True` on every fragment and **not** on the last response. That flag is the subject of
  part 2.1, and it is set here because this is where it has to be set: nothing downstream can
  work out after the fact whether a chunk was a fragment or a whole answer.
- The final `yield` carries **`step.text` in full again** — the entire sentence, not the last word
  — with `turn_complete=True`. Read that line twice. It is the single most consequential line in
  this file, it is the shape the framework documents, and it is what part 2.2's failure is made of.
- The four module-level scripts are constants with `#:` comments, so each one's purpose is written
  beside it. `LOOKS_IT_UP` is today's and day 7 of this project's eval; `NEVER_STOPS` is part 2.3's
  runaway; `GUESSES` and `FAILS_AFTER_A_TOOL` are named here because they are part of this file and
  the completeness rule says a file is printed whole, and they are used by later sittings rather
  than by this one.
- **All four scripts are synthetic**, including the service names and the sentence about split
  tunnelling. Nothing in them describes a real system, and that is the curriculum's standing rule
  rather than a detail of this file.

**Line by line:**

- `from google.adk.models.base_llm import BaseLlm` is imported **for the type annotation on
  `build_desk`**, not for any behaviour. It is what makes `model: str | BaseLlm | None` say the true
  thing: an agent's model may be an exact ID string or an object that behaves as a model, and the
  double is the second kind.
- The sessions import gains `BaseSessionService`, and `build_runner`'s annotation moves from the
  concrete `InMemorySessionService` to it. The old annotation was a promise this project could not
  keep past the first sitting that stores sessions anywhere else, and an annotation that has to be
  edited when a caller passes a perfectly valid argument is an annotation that was describing the
  default rather than the parameter.
- `build_desk` is a **function that builds a new agent** and not a mutation of the module-level
  `desk`. Setting `desk.model = something` would leave one shared agent whose model depends on
  whatever ran last in the process — and the module-level `desk` is built at import time, so "what
  ran last" can mean a different file entirely.
- `model if model is not None else models.require_pinned(models.ANSWERING)` and **not**
  `model or models.require_pinned(...)`. The `or` form treats an empty string as "not supplied" and
  silently substitutes the real pinned model. `is not None` is the test that distinguishes *nothing
  was passed* from *something falsy was passed*, and only one of those two should reach a provider.
- The default path still goes through `models.require_pinned`, so the honesty rule survives the new
  seam: the way to get the real model is to ask for nothing, and the way to get a double is to
  build one and hand it over on purpose. There is no configuration flag that could be left in the
  wrong position.
- The four other arguments are **repeated verbatim** from the module-level `desk`, and that
  duplication is real and worth naming rather than hiding. The instruction and the tool list now
  exist twice in one file, and the day somebody edits one of them is the day the double and the
  real desk stop being the same desk — which would make every result in this day's remaining parts
  a statement about a different agent. The check that would catch it does not exist in this project
  yet; the hub §5 asks you to write it.
- `agent: Agent | None = None` with `agent=agent or desk` — here `or` is correct and `is not None`
  would be noise, because an `Agent` is never falsy. The default keeps every existing caller, and
  every line of day 6, working unchanged.

## When it breaks

It breaks the day a green suite is mistaken for a working system, and the sharpest way to see the
gap is to run the two paths side by side on this machine. `run.py events` — the next part's command
— is green here, right now, with no key and no network. The path a person would actually use is
this, and it was observed on this machine with a `.env` file that does contain a value:

```console
ValueError: No API key was provided. Please pass a valid API key. Learn how to create an API key at https://ai.google.dev/gemini-api/docs/api-key.
```

Everything in this day is green and the desk cannot make a single call. Both statements are true at
once, and the double is what lets them be true at once — which is its whole value and its whole
hazard. The smallest fix is not in this file: this project reads its key into its own code and the
framework builds its client from somewhere else, and closing that gap is the next sitting's
subject. What belongs here is the discipline of never quoting a `scripted/` run as evidence about
the desk's answers, which is why the prefix exists.

## In production

**What a senior writes instead.** They keep the double and move the honesty rules out of the
docstring and into the build. The `scripted/` prefix becomes a startup assertion — the serving
entry point refuses to boot if the resolved model string is not in the pinned registry — so a
double that reached production is a crash on the first line rather than a plausible answer at
three in the morning. And they keep the double's scripts in the same repository as the evals that
consume them, because a fixture stored somewhere else is a fixture nobody updates.

**What degrades at scale.** The double costs nothing to run and the real model costs a request per
turn. `LOOKS_IT_UP` is two model calls for one question, so a suite of **200** eval cases shaped
like it is **400** provider calls per run against the real thing, and zero against this file. Run
that suite on every push and the arithmetic decides for you. The cost of the choice is that all 400
of those calls would have told you something about the model and none of the zero do — so a team
that has only doubles has a fast suite that cannot fail for the reason that matters most.

**The review comment.** "This PR points the `/ask` handler at `ScriptedModel` to get CI green.
`agent.build_desk(None)` is the only way that endpoint should obtain a model. Please revert, and if
CI needs a model that costs nothing, put the double behind the eval harness rather than behind the
request path — and add the check that refuses to start when the resolved model string does not
appear in `util/models.py`, so the next person cannot do this by accident."

**The interview question.** "You have a test double for your model. Name three things a green suite
against it genuinely proves, and three it cannot prove at all — and say what you would add to your
pipeline to stop the second list from being mistaken for the first."
