## One-line answer

An agent with no `model` on it is not broken and not experimental — it runs, it answers, and it calls
`gemini-3.5-flash`, which the provider ships as Stable and describes as its *legacy* Flash model, so
the bug you have shipped is four generations of staleness with no error, no warning and no line in
any log.

## The idea

Go back to the brief. You filled in the name, the standing orders and the three drawers, and you left
the line at the top blank — the one asking who the work should go to — because you did not know the
answer and the form did not insist. Nobody rings you about it. The work comes back, on time, in the
right envelope, answering the question you asked.

Think about what would have to happen for you to notice. If the agency had sent somebody who could
not do the job, you would know inside a day: the answers would be wrong in obvious ways and you would
pick up the phone. If they had sent somebody experimental — a new hire on their first week, still
being assessed — you would find out too, because that arrangement announces itself; there are forms
for it, and somebody checks in with you. Neither of those is what happens. What happens is that the
blank line gets filled in by whoever has been on their books the longest. Competent. Steady. Perfectly
capable of routine work, which is what the agency put them on for years. And four generations behind
the person you would have picked, on precisely the kind of work — long jobs, chasing things down,
deciding what to look up next — that they were never the strongest at.

That is the failure worth a whole document: not the loud one, the *plausible* one. Nothing goes wrong
in a way that has a name. The desk answers. The answers are fine, mostly, and slightly worse on the
hard questions, and you have no baseline to compare them against because this is the only version you
have ever run.

Two terms, and both are already defined in this repository rather than here. A **pin** is a
written-down exact version, recorded in a file so that a machine and not a memory decides what gets
used — `docs/GLOSSARY.md`, introduced in day 1 part 1.1. A **floor** is a requirement written as
`>=`: it says what is *too old* and hands the actual choice to whoever resolves it, on whichever day
— `docs/GLOSSARY.md`, introduced in day 3 part 2.1. What this part adds is a third thing, which is
neither: a field left empty, where the choice is not deferred to a resolver you could inspect but to a
constant inside somebody else's library.

## The mechanism

Three probes in one command. The first two are this part; the third and fourth lines of output belong
to part 2.2, which is where they are read. Nothing here needs a key, and nothing here sends anything:

```console
$ uv run --frozen python -c "
import warnings
warnings.filterwarnings('ignore')
from google.adk.agents import Agent
from google.adk.runners import Runner
from ask_desk.agent import desk

a = Agent(name='unpinned')
print('model field      :', repr(a.model))
print('what it will call:', a.canonical_model.model)

try:
    Agent(name='ask desk', model='gemini-3.8-flash')
except Exception as e:
    print(type(e).__name__, '->', str(e).strip().splitlines()[2].strip())

try:
    Runner(app_name='ask_desk', agent=desk)
except TypeError as e:
    print('TypeError ->', e)
"
model field      : ''
what it will call: gemini-3.5-flash
ValidationError -> Value error, Node name 'ask desk' must be a valid Python identifier. [type=value_error, input_value='ask desk', input_type=str]
TypeError -> Runner.__init__() missing 1 required keyword-only argument: 'session_service'
```

**Line by line:**

- `Agent(name='unpinned')` is a **complete, valid agent**. One argument. It constructs, it validates,
  it has a model, and pydantic — which refused an agent whose name had a space in it, two lines
  further down in the same run — has nothing to say about an agent with no model at all. That
  asymmetry is the document: the framework enforces the field it can check and defaults the field
  that costs money.
- `model field      : ''` — the field is the **empty string**, not `None`. Worth noticing, because
  the obvious hand-written guard is `if not agent.model: raise`, and `''` is falsy, so that guard
  does work. What does not work is assuming the field is where the answer lives: reading `desk.model`
  on an unpinned agent tells you nothing about what will be called.
- `what it will call: gemini-3.5-flash` — this is the line that matters, and the only way to get it is
  to ask a *different* attribute. `canonical_model` is the resolved model, after inheritance and
  defaulting have happened; `model` is what you typed. On the pinned agent in part 1.1 those two
  printed the same string, which is exactly why the pinned case is uninteresting and this one is not.
- The third and fourth lines are failures of two different kinds — a name that is not an identifier,
  and a runner with nowhere to keep a conversation. They are printed here because they were produced
  by this one run and a transcript is not edited to suit a document. They are read in part 2.2.
- `warnings.filterwarnings('ignore')` is at the top so that the four lines of output are the four
  lines of output. It is a convenience for reading a transcript, and it is the sort of line that must
  never migrate into `agent.py`, where its job would become hiding things you have not read.

The framework documents this, and the documentation is not hiding it. From
`https://adk.dev/api-reference/python/google-adk.html`, checked 2026-09-09, verbatim:

> `DEFAULT_MODEL : ClassVar[str] = 'gemini-3.5-flash'`

and, on the same page, describing the `model` field:

> The built-in default is `gemini-3.5-flash`.

**Line by line:**

- `ClassVar` means the default is one value on the class, not a per-agent setting. Every agent in
  every project on this machine that omits `model` gets the same one, and changing it is a decision
  about the whole process rather than about one agent.
- It is a **string constant in a library**, which is the sharpest way to say what has gone wrong when
  you rely on it: the version of your model choice is `2.8.0`, and it changes when you upgrade a
  package. That is not a floor and it is not a pin. It is somebody else's default, and your only
  record of it is the version of their library.

### Both of them are Stable, and that is the trap

From `https://ai.google.dev/gemini-api/docs/models`, last updated 2026-09-04, checked 2026-09-09.
What ADK gives you when the field is blank, badged **Stable**:

> Our legacy Flash model, providing baseline speed and foundational performance for routine,
> high-throughput workloads.

What this project pins, also badged **Stable**:

> Our most intelligent Flash model, engineered for long-horizon software engineering, autonomous
> agents, and complex enterprise workflows.

**Line by line:**

- Neither badge is a warning. If the default had been marked preview, experimental or deprecated,
  every tool in the ecosystem would have a way of telling you — a startup banner, a lint rule, a
  deprecation warning at import. **Stable** produces silence, correctly, and the silence is the
  problem.
- Read the two descriptions as job adverts and the mismatch is stark: *routine, high-throughput
  workloads* against *autonomous agents*. This project is the second sentence. The default is
  optimised for the first.
- `ask_desk/util/models.py`, printed on day 4, carries this same comparison in its module docstring,
  with the date it was read. That is not decoration either: a pin without the date it was chosen is a
  number nobody can re-examine.
- The plan §9 requires an explicit model on every agent for this reason, and
  `docs/adr/ADR-0004-generatecontent-by-hand-and-unpublished-limits.md` §4 is where the rule was
  corrected on the evidence: the plan originally said the default was a *preview* model, the
  observation said otherwise, and the ADR sharpened the rule rather than quietly restating it. An
  unpinned agent is not experimental. It is old, and old is harder to see.

## When it breaks

There is no error text for this one, and that is the finding rather than a gap in the document. The
only two lines on this machine that say anything at all about it are lines you had to go and write:

```text
model field      : ''
what it will call: gemini-3.5-flash
```

Somebody adds a second agent in a hurry on a Friday, copies the constructor call, deletes the
arguments they do not need yet, and ships. Nothing raises at import, nothing appears in the log, and
`run.py check` cannot help: its `model` check calls `models.require_pinned(models.ANSWERING)` — it
asks the registry about a **constant**, not about the agent — so deleting the `model=` line from
`agent.py` cannot move any of its five rows. Weeks later the desk is described as "a bit vague on the
tricky ones", which is not a bug report anybody can act on. The smallest fix is the line that was
deleted. The fix that stops it happening again is a check that reads `desk.canonical_model.model` and
compares it to `models.ANSWERING`, and it is a rep in the hub's §5 rather than code printed here.

## In production

**What a senior writes instead.** The model ID is never a literal at the constructor and never
absent. It comes from one registry module, exactly as this project does it, and the startup check
asserts the *resolved* value rather than the configured one — `canonical_model`, not `model` —
because those two agree only when the thing you are trying to catch has not happened. Where a service
runs several agents, the assertion runs over all of them in a loop, and it runs at boot rather than in
a test, so a bad deploy fails to start instead of answering.

**What degrades at scale.** The number is **three**, and it is the plan's own: P03 has a cast of three
agents, and three constructor calls that omit `model=` are three silently stale agents, each of which
is a separate investigation once somebody finally notices. Worse, the count is not visible anywhere —
you cannot grep for a line that was never written. The only way to enumerate unpinned agents in a
codebase is to construct each one and read `canonical_model`, which is a script somebody has to think
of writing.

**The review comment.** "This agent has no `model=`. That is not a default we chose — ADK's
`DEFAULT_MODEL` is `gemini-3.5-flash`, which the provider calls its legacy Flash model, so this agent
is four generations behind the other two in the same process. Pin it from `util/models.py` like the
rest, and add the resolved-model assertion to the boot check so the next one fails loudly instead of
answering."

**The interview question.** "A framework you depend on defaults a setting that costs money and affects
output quality. The default is a stable, supported value, so nothing warns you. Describe how you would
find every place in a large codebase that is relying on that default, and what you would put in CI so
that the next one is caught before it merges."
