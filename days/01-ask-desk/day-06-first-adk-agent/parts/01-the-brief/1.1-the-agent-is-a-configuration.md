## One-line answer

ADK's `Agent` is not a base class you inherit from and fill in with methods — it is a pydantic model
you *configure*, five fields long, and the whole hand-rolled desk of the last two days collapses into
that configuration plus a runner, with exactly one piece not carried across: the bound on how many
provider calls a single question may cost.

## The idea

You have been answering the phone yourself. Somebody rings the desk, you listen, you go and look
something up, you come back and tell them. It works, and it works because you are holding all of it
at once — who asked, what you already told them, which drawer you opened.

Then you hire an agency. You do not teach anyone to do the job by standing beside them; you write a
**brief** and hand it over. The brief is short, and it is short because it is only the things the
agency cannot work out for itself. Who they are, in a word, so that anything they file can be
found under it. What they answer, and from what — the standing orders, the sentence that begins
*you are the internal IT desk, and you answer from the notes you are given*. What they are allowed to
touch: three drawers, named. That is the whole brief. It is a page, not a manual, and nothing on it
is a procedure.

What comes back matters as much as what you sent. The agency supplies somebody who works to that
brief, and they bring their own way of doing it: they keep the file, they carry the thread from one
call to the next, they chase the callback while you get on with something else. Those are real
things you have stopped doing, and stopping is the point of hiring anyone.

And there is a line on the brief you did not write, because it did not occur to you that it was
yours to write. Nobody at the agency is watching your money. They will make as many calls as the job
seems to need, and the job seems to need however many the job says it needs. The last two days' desk
had a number in it for exactly this — a hard stop at a count of provider calls for one question,
enforced by your code, in a place the model cannot reach. Handing the work over does not hand that
over. It is still yours, and now it is not written down anywhere the new arrangement can see.

So: today the desk is rebuilt as a brief. Terms as they arrive. An **agent**, in this framework, is
an object holding that configuration — a name, a model, a description, an instruction and a list of
tools. A **runner** is the thing that takes the agent and actually works a question through it, and
it is the next section's subject. Everything in this part is the brief itself: what goes on it, what
each line prevents, and which line of the old desk has no home on the new one.

## The mechanism

The framework is a dependency, so it is pinned like every other one. This is the only change today
makes to `projects/01-ask-desk/pyproject.toml`, as a marked diff against the version day 4 printed
whole — days 4 and 5 needed nothing outside the standard library, so the list it is being added to
was empty:

**Line by line:**

- `google-adk==2.8.0` — `==`, not `>=`, and that is not a style preference. `run.py check`'s `pins`
  check, printed on day 4, refuses any dependency without `==` in it, so a floor here turns the
  project's own gate red. Version 2.8.0 was read off `https://pypi.org/pypi/google-adk/json` on
  2026-09-09 and is recorded, with that date, in this project's `PACKAGES.md`.
- The diff is two lines because `uv add` writes both files: `pyproject.toml` records what you asked
  for, `uv.lock` records what the asking produced. Neither is optional and they answer different
  questions — `PRIMER.md` §2 has the self-contained version, and the deep one is
  `days/00-foundry/day-03-keys-pinning-refusing-check/parts/02-the-pin-and-the-refusal/2.1-a-floor-is-not-a-pin.md`.
- Nothing else is added. In particular **`google-genai` is not a dependency line here**, and it is
  installed: the traceback in part 2.2 runs through `site-packages/google/genai/errors.py`, and the
  only thing this project asked for is the line above. It arrives with the framework, and adding it
  by hand would be a second pin on the same package that nothing keeps in step with the first.

Now the file the day exists for. `projects/01-ask-desk/ask_desk/agent.py`, whole:

```python
# ask_desk/agent.py
"""The same desk, as an ADK agent — and the runner that drives it.

Days 1 and 2 built this by hand: a request builder, a conversation list, a tool registry, a
declaration for each tool, a dispatcher and a bound. This file replaces all of it with about twenty
lines, and the point of days 3 and 4 is knowing exactly which of those pieces went where.

What ADK takes over, and where the hand-rolled version of each lives:

    the conversation list  ->  the session, held by a SessionService   (loop.Conversation.contents)
    resending the thread   ->  the runner, on every call               (loop.Conversation.ask)
    the declarations       ->  derived from the functions themselves   (tools.DECLARATIONS)
    the dispatcher         ->  the runner, between events              (tools.dispatch)
    the bound              ->  NOT taken over. Still yours.            (loop.MAX_CALLS_PER_QUESTION)

The last row is the one worth remembering.

Verified against google-adk 2.8.0 and https://adk.dev/api-reference/python/google-adk.html
on 2026-09-09.
"""

from __future__ import annotations

from google.adk.agents import Agent
from google.adk.runners import Runner
from google.adk.sessions import InMemorySessionService
from google.genai import types

from ask_desk import loop, tools
from ask_desk.util import models

APP_NAME = "ask_desk"

#: The agent. `model` is passed explicitly and never left to be inherited: ADK 2.8.0's built-in
#: default is `gemini-3.5-flash`, which the provider lists as Stable and calls its legacy Flash
#: model. An agent that omits this line still runs, still answers, and is four generations old.
desk = Agent(
    name="ask_desk",  # must be a valid Python identifier — a space here is a ValidationError
    model=models.require_pinned(models.ANSWERING),
    description="An internal IT ask desk that answers from a synthetic knowledge base.",
    instruction=loop.SYSTEM_INSTRUCTION,
    # The plain functions from day 2. ADK wraps each one in a FunctionTool and derives its
    # declaration from the signature and the docstring — which is day 4's subject.
    tools=[tools.search_notes, tools.fetch_note, tools.check_service_status],
)


def build_runner(session_service: InMemorySessionService | None = None) -> Runner:
    """A runner for `desk`.

    `session_service` has no default in ADK 2.8.0 — it is the one required keyword argument — and
    that is deliberate on ADK's part: an agent with nowhere to keep a conversation is an agent that
    forgets between turns, which is exactly the failure day 1 caused on purpose.
    """
    return Runner(
        app_name=APP_NAME,
        agent=desk,
        session_service=session_service or InMemorySessionService(),
    )


async def ask(question: str, *, user_id: str = "local", session_id: str = "s-1") -> str:
    """Ask the desk one question and return its final answer.

    Async because the runner is: model calls and tool calls are I/O, and `run_async` yields events
    as they arrive rather than returning once at the end.
    """
    session_service = InMemorySessionService()
    await session_service.create_session(
        app_name=APP_NAME, user_id=user_id, session_id=session_id)
    runner = build_runner(session_service)

    message = types.Content(role="user", parts=[types.Part(text=question)])
    answer = ""
    async for event in runner.run_async(
        user_id=user_id, session_id=session_id, new_message=message
    ):
        # `is_final_response()` marks the concluding message of the turn. Every other event is the
        # middle of the work — a tool being asked for, a tool answering, a partial chunk — and day
        # 5 is about reading those rather than skipping them.
        if event.is_final_response() and event.content and event.content.parts:
            answer = "".join(part.text for part in event.content.parts if part.text)
    return answer
```

**Line by line:**

- **The day numbers in that docstring count this project's own days, not the curriculum's.** "Days 1
  and 2" are `days/01-ask-desk/day-04-loop-hand/` and `day-05-tools-hand/`; "days 3 and 4" are this
  day and the next one. That is deliberate and it is not sloppiness: `projects/01-ask-desk/` has to
  be readable by somebody who was handed that folder and nothing else, and P01 day 3 is a thing they
  can find in it. When you read the file, translate; when you read the repository, do not.
- The docstring's five-row table is the whole day in five lines, and it is in the source rather than
  only here on purpose — the person who needs it most is somebody reading `agent.py` cold at eleven
  at night, and they are not holding this document.
- `from google.adk.agents import Agent` — and `Agent` **is** `LlmAgent`. Not a subclass of it, not a
  thin wrapper around it: the same class object, so `Agent is LlmAgent` is `True` on this machine
  under google-adk 2.8.0, and `Agent.__qualname__` is `LlmAgent`. You will meet both names in the
  documentation and in other people's code; there is no difference to hunt for, and the API
  reference documents the fields under `LlmAgent`.
- `from google.adk.runners import Runner` and `from google.adk.sessions import InMemorySessionService`
  — named here so the file's imports are complete. What they do is part 2.1, and they are not walked
  through in this part.
- `from google.genai import types` — the one import in this file that is not `google.adk.*`. It is
  the message types of the underlying provider SDK, and it is how a question is put into the shape
  the runner accepts. It is installed because `google-adk` brought it, which is why the diff above
  has one line in it and not two.
- `from ask_desk import loop, tools` — **the framework did not delete your code.** The standing
  orders still come from `loop.SYSTEM_INSTRUCTION` and the three functions are still the ones day 5
  wrote. That import line is the difference between rebuilding the desk and re-typing it, and it is
  what makes the comparison at the end of this project honest: both desks answer with the same
  instruction because there is one copy of it.
- `APP_NAME = "ask_desk"` — a module constant rather than two string literals, because the same value
  has to reach two different calls that are written apart from each other. Part 2.1 is where that
  matters.
- `desk = Agent(...)` at module level — the agent is built **at import time**. Everything pydantic
  validates, it validates then: before any key is read, before any network exists, at the moment
  something says `import ask_desk.agent`. That is why `run.py` imports this module inside the `adk`
  function rather than at the top, and it is also why the failure in *When it breaks* below arrives
  where it does.
- `name="ask_desk"` — an identifier, not a label. The underscore is not a style choice: a space
  raises before the object exists, and the message calls it a *node* name, which is a hint about how
  the framework addresses agents once there is more than one of them.
- `model=models.require_pinned(models.ANSWERING)` — the constant is not passed straight through. It
  goes via the registry day 4 printed, so the exact ID this agent will call is checked against a
  written-down list **at the place the value is used**, not only in `run.py check`. Two lines of
  defence exist because they catch different mistakes: the check catches a registry that is out of
  date, and this call catches an agent that reached around the registry.
- `description=` and `instruction=` are two different audiences and it is worth not blurring them.
  The instruction is sent to the model as the desk's standing orders — it is the same string day 4
  printed, and it is sent because the desk has to be told what it is. The description is a one-line
  statement of what this agent is *for*, and today it has exactly one reader: you. P03 is where a
  second agent exists and where the difference starts to earn its keep.
- `tools=[tools.search_notes, tools.fetch_note, tools.check_service_status]` — **plain Python
  functions, passed as objects.** No decorator, no registration call, no schema. The framework's own
  documentation, at `https://adk.dev/tools-custom/function-tools/`, checked 2026-09-09, verbatim:

  > When you assign a function to an agent's `tools` list, the framework automatically wraps it as a
  > `FunctionTool`.

  What that wrapping derives, where it derives it from, and what it silently gets wrong when the
  function is written carelessly, is the **next day's whole subject** —
  `days/01-ask-desk/day-07-functiontool-what-adk-does/`. Today the fact to hold is smaller and
  stranger: day 5 wrote a JSON declaration for each of these functions by hand, and this line
  replaced all of them without mentioning it.
- `build_runner` and `ask` are printed here because the file is printed whole, and they are **not**
  explained here. The runner, the session and the `await` are part 2.1; the `session_service`
  argument that has no default is part 2.2.

### What went where, and what did not

The docstring's table, with the column that matters most on the end — what each hand-rolled piece
was preventing, and whether the framework still prevents it:

| Day 4 / day 5 built | ADK's version | The hand version | Still guarded? |
| --- | --- | --- | --- |
| the conversation list you resend every turn | the session, held by a `SessionService` | `loop.Conversation.contents` | **Yes** — the thread is carried, just not by you. Part 2.1. |
| resending the whole thread on each call | the runner, on every call | `loop.Conversation.ask` | **Yes** — and you no longer see it happen, which is the trade. |
| a JSON declaration per tool | derived from the function itself | `tools.DECLARATIONS` | **Yes, differently** — derived rather than written, and day 7 measures the difference. |
| the dispatcher that matched a name to a function | the runner, between events | `tools.dispatch` | **Yes** — including the refusal when the model names a tool that does not exist. |
| **the bound on provider calls per question** | **nothing** | `loop.MAX_CALLS_PER_QUESTION` | **No. Still yours, and currently absent.** |

Read the last row twice. `MAX_CALLS_PER_QUESTION = 6` is enforced inside `loop.Conversation.ask`,
and the ADK path never calls it — `run.py adk` touches `loop` only to borrow one string. So the
number that used to stop a question from costing an unbounded number of provider calls is still in
the repository, still correct, and no longer on the path that runs. Nothing warns you. The hub's §7
states the request count for this cast, and part 2.1's production section is where the missing
ceiling gets its rep.

Here is the agent, and the tools it derived, with no key and no network:

```console
$ uv run --frozen python -c "
import asyncio, warnings
warnings.filterwarnings('ignore')
from ask_desk.agent import desk, build_runner

async def main():
    print('name       ', desk.name)
    print('model (set)', repr(desk.model))
    print('canonical  ', desk.canonical_model.model)
    for tool in await desk.canonical_tools():
        print(f'{type(tool).__name__:14} {tool.name}')
    print('runner agent  ', build_runner().agent.name)

asyncio.run(main())
"
name        ask_desk
model (set) 'gemini-3.8-flash'
canonical   gemini-3.8-flash
FunctionTool   search_notes
FunctionTool   fetch_note
FunctionTool   check_service_status
runner agent   ask_desk
```

**Line by line:**

- `model (set)` and `canonical` agree, and that agreement is the entire subject of the next part.
  `desk.model` is the string **you** put on the field; `desk.canonical_model.model` is the ID this
  agent will actually name in a request. When the field is filled they are the same sentence twice.
  When it is empty they are not, and nothing raises.
- Three `FunctionTool` objects, none of which appear in `agent.py`. The functions went in; wrapped
  objects came out, with the names taken from the functions. That is the documented wrapping
  happening, observed rather than believed.
- `await desk.canonical_tools()` — even *listing* the tools is a coroutine. That is your first sight
  of how far the async reaches, and part 2.1 is about why.
- `build_runner().agent.name` prints `ask_desk`, so the runner really is holding this agent and not a
  copy of a default one. It is a cheap assertion and it costs nothing to run.
- Nothing here contacted the provider. No key was needed, no request was sent, and every line above
  is knowable offline — which is the property that makes it worth checking before you spend a
  request finding out.

*Observed on this machine on 2026-09-09: uv 0.12.3, CPython 3.12.12, google-adk 2.8.0.*

## When it breaks

Somebody reads a model ID in a release announcement and swaps it into `models.ANSWERING`, or passes
it straight to `model=` to try it out. The agent never gets built, and the refusal arrives from this
project's own registry rather than from the provider:

```console
$ uv run --frozen python -c "
from ask_desk.util import models
for candidate in ['gemini-flash-latest', 'gemini-3.7-flash', 'gemini-3.8-flash']:
    try:
        print(f'{candidate:22} -> ok, {models.require_pinned(candidate)}')
    except models.UnpinnedModel as e:
        print(f'{candidate:22} -> UnpinnedModel: {e}')
"
gemini-flash-latest    -> UnpinnedModel: 'gemini-flash-latest' is an alias, not a pin. The provider documents `-latest` as hot-swapped with every release, so two runs a week apart can reach different models with no change here. Name an exact ID from the models page and add it to PINNED.
gemini-3.7-flash       -> UnpinnedModel: 'gemini-3.7-flash' is not in this project's registry. Add it to PINNED with the date you read it off https://ai.google.dev/gemini-api/docs/models, or use one of: gemini-3.8-flash.
gemini-3.8-flash       -> ok, gemini-3.8-flash
```

This is the good version of the evening. The failure lands at import, in one sentence, naming the
file to edit and the page to read it off — and it lands because `model=` goes through
`require_pinned` rather than taking a string. The smallest fix is the one the message asks for: read
the ID off the models page, add it to `PINNED` with the date you read it, and the constructor stops
objecting. The bad version of the same evening is the next part, where the field is left off
entirely, nothing refuses, and the desk answers.

## In production

**What a senior writes instead.** They rarely leave `desk = Agent(...)` at module scope. It becomes
`def build_desk(model: str = ...) -> Agent:`, for one reason that shows up immediately: a
module-level agent is constructed by the *import*, so every test, every CLI subcommand and every
tool that merely pokes at this module pays for the construction and inherits whatever it validated
against. A factory also makes the model injectable, which is how one codebase runs a cheap model in
CI and the pinned one in production without a second file. This project keeps the module-level form
because there is exactly one agent and the import cost is a line in `run.py` that already defers it
— and the moment there are three agents, the factory arrives with them.

**What degrades at scale.** Three tools are declared on this agent, and every declaration derived
from them rides on **every** provider call in a turn, not once per question. Day 4's bound allows a
single question to reach six provider calls, so those three schemas can be sent six times to answer
one question — and the ADK path, as the table above says, has no bound at all. Adding a fourth and
fifth tool is not a fifth of a cost increase; it is a fifth of an increase *multiplied by the number
of calls the model chooses to make*, and the multiplier is the part nobody budgets for.

**The review comment.** "Two things on `agent.py`. The `Agent` is built at import, so importing this
module for any reason validates the config and reads the registry — please make it a factory before
the second agent lands. And `MAX_CALLS_PER_QUESTION` is now dead code on this path: the ADK runner
does not know about it. Either wire a limit in or delete the constant, because a bound that is in the
repository and not on the path is worse than no bound — the next person will read it and believe it."

**The interview question.** "You migrate a hand-written agent loop onto a framework and the
line count drops by eighty percent. Name three things your loop was doing that the framework is now
doing for you, and one thing it was doing that the framework is not. How would you find the fourth
one on a codebase you had never seen?"
