## One-line answer

Against day 5's hand-written declarations, `FunctionTool` derived the name, the types and the
`required` list correctly and added a `default` field day 5 only had as prose — it **lost** every
per-parameter description, replacing guidance with a capitalised parameter name — and it never went
near the three things that decide what this desk does when something goes wrong: the bound, the
refusal to guess at a tool name it does not have, and what a tool returns on error.

## The idea

The clerk hands the form back and it is, by every visible measure, better than the one you brought
in. Neater. Complete. Boxes you had left as marginal notes are now boxes, filled in properly, in the
place the form expects them. You would sign it without reading twice.

What is not on it is everything you *meant*. The note explaining that the reference number is only
valid for the northern depot — that was your knowledge, spoken at the counter to nobody, and the
clerk was working from paper. And no clerk in the building decides how many times you are allowed to
come back to the counter today. That is a policy, it belongs to whoever runs the office, and if
nobody has set one then there isn't one.

This part is the ledger, written honestly in both directions, because a framework that is only
praised is a framework you cannot reason about.

Three columns of verdict. **What it derived correctly** — the fields that are facts about the
function, which a program can read off with no judgement required. **What it lost** — the fields
that were never facts about the function at all, but things day 5's author knew and typed. And
**what it never touches** — the decisions that were never in the declaration to begin with, which
means no derivation could have taken them over, which means they are still yours whether or not you
remember that.

The middle column is the one that surprises people, so it is worth being exact. Day 5's declaration
gave every parameter a `description`: `"Words to search for, e.g. 'vpn file share'."` for `query`,
and, for `check_service_status`, `"One of: vpn, printing, mail, identity."` — which is the list of
services this desk actually knows. ADK's derived schema has no `description` on any property. What it
has is `"title": "Query"`, the parameter name with a capital letter. That is not guidance and it is
not a smaller amount of guidance; it is the parameter name a second time. The four known service
names have no home in the derived declaration at all, and if the model needs them it must now be
told somewhere else — in the docstring, which part 2.1 established is the one place a tool's prose
still reaches the model from.

And the last column closes this project's first arc. Days 4, 5 and 6 built a loop, a set of tools
and an agent, and the framework arrived on day 6 and took several of those pieces over. Naming which
ones — and refusing to round the answer up — is what makes the rest of this project readable. The
row that matters is the last one, and it is the sentence to leave the day with: **the bound is still
yours.**

## The mechanism

One property, as day 5 typed it, from the file **day 05 part 1.2** printed whole:

```python
# ask_desk/tools.py — one property of DECLARATIONS[0], from the file day 05 part 1.2 printed whole

#: What the model is told. Hand-written on day 2; every field here is a promise about the function
#: above it, and nothing checks that the two agree.
DECLARATIONS: list[dict[str, Any]] = [
    {
        "name": "search_notes",
        # ── description and the rest of this entry unchanged from day 05 part 1.2 ──
        "parameters": {
            "type": "object",
            "properties": {
                "query": {
                    "type": "string",
                    "description": "Words to search for, e.g. 'vpn file share'.",
                },
                # ── limit unchanged from day 05 part 1.2 ──
            },
            "required": ["query"],
        },
    },
    # ── fetch_note and check_service_status unchanged from day 05 part 1.2 ──
]
```

**Line by line — recap depth.** The whole structure is taught by day 05 part 1.2, in
`days/01-ask-desk/day-05-tools-hand/`. Only the comparison matters here:

| Field | Where it went, and the failure that decides whether losing it costs anything |
| --- | --- |
| `"name": "search_notes"` | Derived from `__name__` (part 1.1). Deleting this hand-written copy removes the drift between a renamed function and a stale declaration. |
| `"type": "string"` | Derived from the annotation (part 1.2). Removes the drift between a changed signature and a stale schema. |
| `"required": ["query"]` | Derived from the absence of a default. Removes a list that could contradict the function it describes. |
| `"description": "Words to search for..."` | **Nowhere.** No property of the derived schema carries guidance. This is the column-two loss, and it is the only field in this block that was never a fact the function contained. |
| the `#:` comment above `DECLARATIONS` | The comment says nothing checks the two halves agree. Deriving one from the other is what makes the comment obsolete — which is the strongest single argument for the wrapper. |

The derived counterpart is printed in full in part 1.2 and is not repeated here. What is new is the
comparison across all three tools at once, run against the real file:

```console

"
```

**Line by line:**

- The `adk` rows print the *keys* of each derived property, sorted. Across four parameters the key
  `description` appears **zero** times. This is not a case of shorter guidance; the field does not
  exist in the derived schema.
- `limit` is the one row with three keys, and the third is `default` — the field ADK has that day 5
  did not. Compare its `hand` row: the same fact, as the English sentence `'Maximum notes to return.
  Defaults to 3.'` A field and a sentence are not equivalent, and only one of them survives somebody
  changing the default from `3` to `5`.
- `check_service_status`'s `hand` row is the expensive loss. `'One of: vpn, printing, mail,
  identity.'` is the list of services this desk knows, and after derivation it is nowhere in the
  declaration. Something must tell the model those names or it will guess at them, and after part 2.1
  we know the remaining channel is the docstring.
- `tools.REGISTRY[hand['name']]` is used to walk from a hand-written declaration to the function it
  describes. That the lookup succeeds for all three is day 5's registry and declarations still
  agreeing — which nothing enforces, and which is the drift the whole derivation exists to end.
- `sorted(got)` rather than the properties themselves keeps the comparison about *which fields
  exist*. The values are in part 1.2.

### The bound, which nothing took over

```python
# ask_desk/loop.py — the bound, from the file day 04 part 2.1 printed whole,
# with this block added as a marked diff on day 05 part 2.1

# The bound. Not a timeout and not a token budget: a count of provider calls for a single question,
# enforced here, by code the model cannot reach. A loop that ends "when the model stops asking for
# tools" ends when the model chooses to, and one that never chooses runs until the quota does.
MAX_CALLS_PER_QUESTION = 6
```

**Line by line — recap depth.** Taught by day 05 part 2.1, in `days/01-ask-desk/day-05-tools-hand/`.
What matters today is which column of the ledger it lands in:

| Line | What it does, and the failure it prevents |
| --- | --- |
| `MAX_CALLS_PER_QUESTION = 6` | A hard ceiling on provider calls for one question, in this project's own code. It prevents a question that never terminates from consuming the quota, and it is not a field in any declaration, so nothing about deriving declarations could have taken it over. |
| `enforced here, by code the model cannot reach` | The reason it is a constant and not an instruction in the prompt. Anything expressed to the model is advice; this is arithmetic. |

## When it breaks

It breaks when somebody reads a table like the one above, decides the framework has taken over
"the loop", and goes looking for where to set the ceiling:

```console
$ uv run --frozen python -c "
import warnings
warnings.filterwarnings('ignore')
from ask_desk.agent import build_runner
from google.genai import types
r = build_runner()
r.run_async(user_id='u', session_id='s',
            new_message=types.Content(role='user', parts=[types.Part(text='hi')]),
            max_calls=6)
"
Traceback (most recent call last):
  File "<string>", line 7, in <module>
TypeError: Runner.run_async() got an unexpected keyword argument 'max_calls'
```

The keyword does not exist, which is the honest answer to a question that was hoping for a different
one. This is the good version of the failure, because it is loud and it happens on the first run.
The bad version is the one where nobody looks: `agent.py` and its runner are so much shorter than
day 4's loop that the ceiling feels like something that came with them. It did not. The smallest fix
is to keep the bound in this project's own code and to count calls where you can see them — which is
day 8's subject, because the events are where the counting can happen.

## In production

**What a senior writes instead.** They keep the derived declarations and put the lost guidance back
where the derivation *will* read it: the docstring. `check_service_status`'s docstring names the four
services it knows, rather than leaving that fact stranded in a JSON `description` that no longer
exists. Where a parameter genuinely needs constraining rather than describing, they reach for a type
that carries the constraint — an enum rather than a `str` — so the schema says it instead of a
sentence asking nicely. And the bound stays in their own code, next to a counter they can log.

**What degrades at scale.** The number is **6**, and what matters is that it is a number at all. With
`MAX_CALLS_PER_QUESTION = 6`, a question that loops costs at most six provider calls. Delete it
because the framework "handles the loop" and the ceiling becomes however many calls the model is
willing to make, which is not a quantity anybody has bounded — and this project's own package ledger
records that the provider's rate limits are no longer published, so there is no documented number to
be rescued by either. The failure is not one expensive question; it is one expensive question that
nothing stops.

**The review comment.** "This PR deletes `MAX_CALLS_PER_QUESTION` with the comment 'ADK handles the
loop'. ADK runs the loop; it does not bound it — `run_async` takes no such argument. Please restore
the constant and enforce it where we consume events, and add a test that a tool-calling question
cannot exceed it."

**The interview question.** "You have replaced a hand-rolled agent loop with a framework. List
everything the framework now owns and everything you still own, and for each item you still own, say
how you would notice if somebody removed it."
