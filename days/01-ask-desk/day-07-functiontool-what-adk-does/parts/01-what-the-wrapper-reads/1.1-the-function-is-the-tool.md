## One-line answer

`FunctionTool` is a wrapper around a plain Python function that builds the model-facing declaration
by reading the function object itself, and the framework wraps every function you put in an agent's
`tools` list automatically — so day 6's `tools=[tools.search_notes, ...]` had already replaced day
5's hand-written `"name"` fields before this day started, using the function's `__name__` and
nothing else.

## The idea

You come to a counter to have a new form made up, and you bring your old paperwork with you. The
clerk does not interview you. They put your papers flat on the desk, read across them, and copy each
box into the new form: the name at the top, the entries you filled in, the note you scribbled in the
margin last year. It takes a moment and it is exact. The name on the new form is the name on the old
one — not the name you would have chosen for this occasion, not the name your friends use. It is the
one already written, because that is the only name they were ever given.

That is the whole relationship between your Python function and the thing the model is told about.

Day 5 built a tool as two objects that must not drift apart. On the left, a function that does the
work — `search_notes`, in `ask_desk/tools.py`. On the right, a **declaration**: a small JSON
structure with a name, a description and a parameter schema, which is the *only* thing the model
ever sees of your tool. Day 5 wrote both halves by hand, in the same file, and its whole point was
that nothing on earth checked that the two agreed. The function could be renamed and the declaration
would keep advertising the old name, cheerfully, on every turn.

ADK's `FunctionTool` is the clerk. Its documented signature is
`class google.adk.tools.FunctionTool(func, *, require_confirmation=False)`, and its documented
purpose is one sentence: *"A tool that wraps a user-defined Python function."* It takes the function
object and derives the right-hand half from it. And you do not usually construct one, because the
framework's own documentation says *"When you assign a function to an agent's `tools` list, the
framework automatically wraps it as a `FunctionTool`."* Day 6 wrote
`tools=[tools.search_notes, tools.fetch_note, tools.check_service_status]` — three plain functions,
no declarations mentioned anywhere — and three declarations existed by the time the agent was
finished being constructed.

The first box the clerk copies is the name, and it comes from `__name__`, the attribute Python
writes on every function object at `def` time. Nowhere in `agent.py` does the string
`"search_notes"` appear. The name of the tool the model will ask for is the name of the function,
because the function is the only place a name was available to read.

That has a quiet consequence worth naming now, because it is the last easy thing in this day. The
provider documents a constraint on the name a model may call: *"Must be a-z, A-Z, 0-9, or contain
underscores and dashes, with a maximum length of 128."* Day 5 typed its three names into a string
literal by hand, where a stray space or a colon is one keystroke away and nothing local would object
until a request came back rejected. A Python function name written in the ordinary way — lowercase
ASCII letters, digits and underscores — satisfies that rule by construction, because Python's own
parser refused everything else at the moment you typed `def`. One whole class of bug is removed, not
by a check, but by the name having come from somewhere that already had rules.

Removed, not abolished. The clerk copies what is on the paper, including what should not have been.

## The mechanism

The left-hand half, unchanged. `ask_desk/tools.py` was printed whole by day 5 part 1.2; these are
the two lines of it that `FunctionTool` actually reads, and the body is exactly as that day printed
it:

```python
# ask_desk/tools.py — the two lines the wrapper reads, from the file day 05 part 1.2 printed whole

def search_notes(query: str, limit: int = 3) -> dict[str, Any]:
    """Find knowledge-base notes matching a query. An empty list is a valid answer."""
    # ── body unchanged from day 05 part 1.2 ──
```

**Line by line — recap depth.** This function is taught in full by **day 05 part 1.2**, in
`days/01-ask-desk/day-05-tools-hand/`, which printed the whole file and explained the scoring. What
matters *here* is only which parts of the lines above are read by something other than Python:

| Line | What it does, and the failure it prevents |
| --- | --- |
| `def search_notes` | The identifier is the tool name the model will call. Naming the function for the caller rather than for you is what stops the model asking for a tool nobody has. |
| `(query: str, limit: int = 3)` | The signature is the parameter schema — part 1.2's subject. Untyped, the schema constrains nothing. |
| `"""Find knowledge-base notes..."""` | The docstring is the description the model reads — part 2.1's subject, and the day's failure. |
| `-> dict[str, Any]` | The return annotation. Not read into the declaration; the model is shown the returned value at the tool-result turn, which day 5 built. |

Now the right-hand half, derived. This is the same command day 6 used to inspect its agent, and the
only lines that matter today are the three in the middle:

```console
$ uv run --frozen python -c "
import asyncio, warnings
warnings.filterwarnings('ignore')
from ask_desk.agent import desk, build_runner

async def main():
    print('name       ', desk.name)
    print('model (set)', repr(desk.model))
    print('canonical  ', desk.canonical_model.model)
    for tool in await desk.canonical_tools():
        print(f'{type(tool).__name__:14} {tool.name}')
    print('runner agent  ', build_runner().agent.name)

asyncio.run(main())
"
name        ask_desk
model (set) 'gemini-3.8-flash'
canonical   gemini-3.8-flash
FunctionTool   search_notes
FunctionTool   fetch_note
FunctionTool   check_service_status
runner agent   ask_desk
```

**Line by line:**

- `desk.canonical_tools()` returns **`FunctionTool` objects**, not the functions that were handed
  in. Day 6 passed three plain functions and got three wrappers back. Nothing in `agent.py` said
  `FunctionTool`; the framework did the wrapping on the way in, exactly as its documentation says.
- `tool.name` for each of them is the function's identifier, character for character. Search
  `agent.py` for the string `"search_notes"` and you will not find it: the name reaching the model
  travels from `def search_notes` in `tools.py`, through `__name__`, into the declaration.
- That is day 5's `DECLARATIONS[0]["name"]` field, gone. It was a hand-typed copy of a name that
  already existed, and every hand-typed copy of a name that already exists is a thing that can drift.
- The command is `await`ed and the whole probe runs under `asyncio.run` because `canonical_tools` is
  a coroutine. Nothing here contacts a provider — deriving a declaration reads the function object
  and stops.

The name is copied, not judged. Here is the same wrapper applied to this project's three real tools
and to a fourth function whose name is 138 characters long:

```console
$ uv run --frozen python -c "
import warnings
warnings.filterwarnings('ignore')
from google.adk.tools import FunctionTool
from ask_desk import tools

ns = {}
exec('def restart_' + 'x' * 130 + '''(service: str) -> dict:
    \"\"\"Restart one service.\"\"\"
    return {}''', ns)
over_limit = ns['restart_' + 'x' * 130]

for fn in (tools.search_notes, tools.fetch_note, tools.check_service_status, over_limit):
    t = FunctionTool(fn)
    print(f'{len(t.name):>3}  {t.name == fn.__name__}  {t.name[:30]}')
"
 12  True  search_notes
 10  True  fetch_note
 20  True  check_service_status
138  True  restart_xxxxxxxxxxxxxxxxxxxxxx
```

**Line by line:**

- The middle column is `t.name == fn.__name__`, and it is `True` on all four rows including the
  absurd one. The wrapper's rule is *copy the name*, with no clause about whether the name is any
  good.
- 138 is longer than the 128 the provider documents as the maximum. `FunctionTool` did not raise, did
  not warn, and did not truncate. Whatever happens to that name happens at the far end of a request,
  to whoever is holding the pager — and this machine has no key, so what the provider does with it
  is not something this day gets to claim.
- The three real rows are 12, 10 and 20 characters of lowercase ASCII and underscores. They satisfy
  the documented charset and length without anyone having checked, which is the point of the
  previous section: the constraint is met because Python's identifier rules are stricter than the
  provider's, not because anything verified it.
- `exec` is used only to build a function with a 130-character name, which cannot be typed at a
  `def` line without wrapping. It is a probe, not project code, and nothing in `ask_desk/` looks
  like this.

*Observed on this machine on 2026-09-09: google-adk 2.8.0, CPython 3.12.12, uv 0.12.3.*

## When it breaks

The failure arrives the first time somebody edits `agent.py` while still thinking in day 5's shape —
where a tool was a *name* plus a declaration, and the name was a string. They write the name:

```console
$ uv run --frozen python -c "
import warnings
warnings.filterwarnings('ignore')
from google.adk.agents import Agent
try:
    Agent(name='by_name', model='gemini-3.8-flash', tools=['search_notes'])
except Exception as e:
    print(type(e).__name__ + ':', e)
"
ValidationError: 3 validation errors for LlmAgent
tools.0.callable
  Input should be callable [type=callable_type, input_value='search_notes', input_type=str]
    For further information visit https://errors.pydantic.dev/2.13/v/callable_type
tools.0.is-instance[BaseTool]
  Input should be an instance of BaseTool [type=is_instance_of, input_value='search_notes', input_type=str]
    For further information visit https://errors.pydantic.dev/2.13/v/is_instance_of
tools.0.is-instance[BaseToolset]
  Input should be an instance of BaseToolset [type=is_instance_of, input_value='search_notes', input_type=str]
    For further information visit https://errors.pydantic.dev/2.13/v/is_instance_of
```

Three errors for one mistake, because `tools` accepts three different kinds of thing and the string
is none of them. It reads worse than it is. The first line is the one that matters — *Input should
be callable* — and it is the framework saying, in pydantic's voice, that a tool is an object it can
call and read, not a name it can look up. There is no registry to look a name up in any more: day
5's `REGISTRY` dict was the thing that turned a name back into a function, and once the function
*is* the tool, the lookup has nowhere left to happen. The smallest fix is to delete the quotation
marks.

## In production

**What a senior writes instead.** They keep the wrapper implicit — a bare list of functions, as
`agent.py` has it — and reach for `FunctionTool(...)` explicitly only when they need one of its
keyword arguments, such as `require_confirmation`. Wrapping by hand when you have nothing to
configure adds a name to every import list and buys nothing. What they *do* write instead is a test
that asserts the derived tool names against a literal list, because the names are now a public
interface that a refactoring tool will happily rename for you.

**What degrades at scale.** The number is **138**. A name that long is copied without complaint past
the 128 the provider documents, and the same indifference applies to every other name-shaped
mistake: `functools.partial(search_notes, limit=1)` derives the name `partial`, and two partials in
one `tools` list derive the name `partial` twice. Both were observed here with no exception raised.
At three tools you would notice. At thirty, across four agents, the collision is a row in a list
nobody reads.

**The review comment.** "This renames `search_notes` to `_search`. That is not an internal rename —
the function name is the tool name the model calls, so this changes the model-facing interface and
every saved session that mentions the old name. Either keep the name or say in the PR description
that the tool contract changed."

**The interview question.** "Your framework derives a tool's name from the Python function. Name
three ways that can produce a name you did not intend, say which of them raise and which are silent,
and describe the smallest check that would catch the silent ones before a request goes out."
