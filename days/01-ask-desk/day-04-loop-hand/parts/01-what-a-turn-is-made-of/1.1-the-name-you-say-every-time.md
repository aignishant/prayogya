## One-line answer

The model your code talks to is decided by a string, and there are only three places that string can
come from — a file you wrote, an alias somebody else redirects, or a default you never typed — so
this project writes it down once, as an exact ID, in one file, and refuses every call that names
anything else.

## The idea

You are about to write to somebody, and you have to address the envelope. There are two ways to do
it. You can write out the whole address — the number, the street, the town — or you can write the
name and *care of the sorting office*, because the sorting office knows where he sits this month and
will pass it along.

Both letters arrive. That is the trouble. The second one arrives for years, and it goes on arriving
after he leaves, because the sorting office does the sensible thing and hands it to whoever holds
that job now. You get a reply. It is polite, it is competent, and it is signed with the same job
title. Nothing in the envelope, the paper or the words tells you that you are corresponding with a
different person than you were last month. You would find out eventually — from a reply that
contradicts one you have in the file, probably, on a day when you are looking for something else.

The address on the envelope is the model ID, and this part is about writing it out in full, every
time, in one place.

Here is the ground the project stands on. Every request in this project names, in its URL, exactly
one model. Not a family, not a tier, not "the fast one" — one string, and the provider matches it
literally. So the only real question is where that string comes from, and there are three answers.

**You wrote it down.** It sits in a file in this repository, as an exact ID, and changing it is a
diff somebody reviews. This is the one this project uses, and the rest of this part is about the
file that does it.

**Somebody else redirects it.** The provider publishes *alias* names that end in `-latest`. From
`https://ai.google.dev/gemini-api/docs/models`, checked on 2026-09-09, verbatim:

> This alias will get hot-swapped with every new release of a specific model variation.

Read that as what it is: the name resolves to whichever model the provider has most recently
released in that line, and it re-resolves without you doing anything. Two runs a week apart, with a
byte-identical repository, can reach two different models. That is the sorting office. A **model
alias** is a name that stands in for whichever model currently holds a role, rather than for a
model — and day 3 already gave you the word for a thing that looks like a version and names none: it
is a **floor**, wearing a version's clothes.

> **Recap — a floor is not a pin.** `>=4.11.8` and `>=3.12` do not name a version. They say what is
> *too old* and hand the actual choice to whichever machine resolves them, on whichever day. That
> is correct for a library and never sufficient for an application, and the test is not whether a
> number appears in your config — it is whether handing this folder to somebody on another machine
> next March gets them what you have. Self-contained version: `PRIMER.md` §2.
> Deep version, if you have the full plan:
> `days/00-foundry/day-03-keys-pinning-refusing-check/parts/02-the-pin-and-the-refusal/2.1-a-floor-is-not-a-pin.md`

The word for the other half of that pair is one day 0 already defined: a **pin** is a written-down
exact version, recorded in a file so that a machine and not a memory decides what gets used. An
exact model ID in a file is a pin. `gemini-flash-latest` is not, whatever it looks like.

**Or nobody wrote it down at all**, and this is the quiet one. The framework this project adopts
later has a default, and a default is not nothing — it is a choice somebody else made, in a version
you did not read, that applies the moment you leave a field blank. From
`https://adk.dev/api-reference/python/google-adk.html`, checked 2026-09-09, verbatim:

> `DEFAULT_MODEL : ClassVar[str] = 'gemini-3.5-flash'`

Now put that beside the models page, same date. `gemini-3.5-flash` is badged **Stable** and
described, verbatim, as:

> Our legacy Flash model, providing baseline speed and foundational performance for routine,
> high-throughput workloads.

And the ID this project pins, `gemini-3.8-flash`, is badged **Stable** on the same page and
described, verbatim, as:

> Our most intelligent Flash model, engineered for long-horizon software engineering, autonomous
> agents, and complex enterprise workflows.

So an unset model does not get you something experimental that fails loudly on the first request.
It gets you the oldest thing still supported — four generations back, fully working, answering every
question you send it, slightly worse than what you thought you had, and completely silent about it.
That is the version of this failure that survives longest, because there is nothing to notice.

One more sentence and then the code. There is a fourth non-answer, which is typing the string inline
at each call site. It feels like writing it down, and it is not, because there is no *one place*: the
day you move the desk to a newer model you edit three files, find two of them, and ship a system
whose agents are on different brains. One file, one constant per role, and the call sites name the
constant.

## The mechanism

`projects/01-ask-desk/ask_desk/util/models.py` — this project's model registry, whole file. It is
the first file P01 has, and everything else in the project names a model from it:

```python
# ask_desk/util/models.py
"""This project's model registry. One exact ID per role, and nothing chooses for us.

Every agent and every raw call in this project names a model from here. Nothing anywhere calls a
provider with a model string typed inline, and nothing relies on a framework default.

Two things this file refuses to do, both deliberate:

  * It never uses an alias like `gemini-flash-latest`. The provider documents those as hot-swapped
    on every release, so an alias is a floor and not a pin — the same distinction P00 day 3 drew
    about `>=` in `pyproject.toml`.
  * It never leaves a model unset. ADK 2.8.0's built-in default is `gemini-3.5-flash`, which the
    provider's models page lists as Stable and calls "our legacy Flash model" — four generations
    behind the one below. An agent that inherits that default is not broken and not experimental;
    it is quietly old, which is harder to notice than either.

Verified against https://ai.google.dev/gemini-api/docs/models on 2026-09-09.
"""

from __future__ import annotations

from typing import Final

# The desk's one brain. Documented Stable on 2026-09-09 and described by the provider as
# "engineered for long-horizon software engineering, autonomous agents, and complex enterprise
# workflows" — which is what this project is.
ANSWERING: Final[str] = "gemini-3.8-flash"

# Every model this project is allowed to name, mapped to the date the ID was read off the
# provider's models page. `run.py check` asserts the ID a call is about to use is in here.
PINNED: Final[dict[str, str]] = {
    ANSWERING: "2026-09-09",
}

# The API version segment of every endpoint URL. Kept here rather than spelled into provider.py so
# that moving off v1beta is one edit in one file.
API_VERSION: Final[str] = "v1beta"

BASE_URL: Final[str] = "https://generativelanguage.googleapis.com"


class UnpinnedModel(RuntimeError):
    """Raised when code is about to call a model this project never wrote down."""


def require_pinned(model: str) -> str:
    """Return `model`, or refuse if it is not in `PINNED`.

    The alias check is separate and comes first, because `gemini-flash-latest` would otherwise be
    refused with a message about the registry when the real objection is that it is not a version.
    """
    if model.endswith("-latest"):
        raise UnpinnedModel(
            f"{model!r} is an alias, not a pin. The provider documents `-latest` as hot-swapped "
            f"with every release, so two runs a week apart can reach different models with no "
            f"change here. Name an exact ID from the models page and add it to PINNED."
        )
    if model not in PINNED:
        raise UnpinnedModel(
            f"{model!r} is not in this project's registry. Add it to PINNED with the date you "
            f"read it off https://ai.google.dev/gemini-api/docs/models, or use one of: "
            f"{', '.join(sorted(PINNED))}."
        )
    return model
```

**Line by line:**

- The module docstring carries the **date the IDs were read**, and that is not decoration. Every
  claim in this file is a claim about a page that changes: which models exist, which are Stable,
  what the default is. A file that states a fact about the outside world without saying when it
  looked is a file nobody can audit — the next reader cannot tell a checked fact from a remembered
  one. It is the same habit `docs/PINS.md` enforces for versions, applied to a string.
- `from __future__ import annotations` — annotations are stored as strings rather than evaluated at
  import. It costs nothing here and it means a type in a signature can never fail at import time
  because of the order the modules happen to load in. Every file in this project opens with it, so
  that none of them is the exception somebody has to remember.
- `ANSWERING: Final[str] = "gemini-3.8-flash"` — the name is the **role**, not the model. That is
  the choice worth arguing about. `ANSWERING` is what this string is *for*; `GEMINI_3_8` would be
  what it currently *is*, and a constant named after its own value has to be renamed every time the
  value changes, which means it does not get renamed. When P03 has three agents, the registry grows
  `SUMMARISING` and `CRITIQUING` beside this, and a role can move models without a single call site
  being touched.
- `Final` is a typing marker, not an enforcement — nothing at runtime stops a reassignment. It is
  there so a type checker refuses `models.ANSWERING = "..."` in review rather than at three in the
  morning, and so a human reading the file knows the intent without asking.
- `PINNED` maps **ID to the date it was read**, not ID to `True`. A set would have done the
  membership check just as well, and would have thrown away the only thing that makes the registry
  auditable later: when somebody added this, and therefore how stale the claim is. The dict costs
  one word per row and answers "how old is this pin?" without a git blame.
- `ANSWERING` is used as the dict key rather than the literal being typed twice. Two literals can
  disagree; one cannot. This is the smallest possible version of "one place".
- `API_VERSION` and `BASE_URL` live **here, in the registry**, and not in `provider.py` where the
  URL is assembled. The reason is that they are the same kind of fact as the model ID — a
  provider-side name that will change and that must change in exactly one edit. Putting them beside
  the ID they travel with means that moving off `v1beta` is one line in one file rather than a grep.
- `UnpinnedModel(RuntimeError)` — its own class, not `ValueError`. A caller that wants to handle
  "this project has never heard of that model" differently from "that argument was the wrong shape"
  needs two types to catch, and inventing the second one later means editing every `except` that
  already exists.
- `require_pinned` **returns the model** rather than returning `None` or a bool. That lets it be
  written inline — `url = f".../{require_pinned(model)}:generateContent"` — so the check and the use
  cannot drift apart. A validator you have to remember to call separately is a validator that gets
  skipped on the one path added in a hurry.
- The alias branch comes **first, and is a separate branch**. `gemini-flash-latest` is not in
  `PINNED`, so the second branch would already have caught it — with the message *add it to PINNED*,
  which is precisely the wrong advice. The objection to an alias is not that it is unregistered; it
  is that it is not a version, and registering it would make the problem permanent. Two failures
  that need two different sentences said back get two branches. That is the same argument day 3 made
  for testing `is None` and `not value.strip()` separately.
- `model.endswith("-latest")` is deliberately crude, and honest about it. It catches the alias form
  the provider documents and it would not catch a future alias spelled some other way. A check that
  reliably catches the case that actually happens is worth more than a general one that is subtly
  wrong; when the provider publishes a second alias shape, this line grows a second condition and
  the day that does it says so.
- Both messages end with **what to do next** — name an exact ID and add it, or use one of these.
  The list is built from `PINNED` itself with `', '.join(sorted(PINNED))`, so it cannot go stale.
  An error that says only *invalid model* makes the reader go and find the registry; this one brings
  the registry to them.

Now drive it through the three cases that matter. No key, no network, nothing sent:

```console
$ uv run --frozen python -c "
from ask_desk.util import models
for candidate in ['gemini-flash-latest', 'gemini-3.7-flash', 'gemini-3.8-flash']:
    try:
        print(f'{candidate:22} -> ok, {models.require_pinned(candidate)}')
    except models.UnpinnedModel as e:
        print(f'{candidate:22} -> UnpinnedModel: {e}')
"
gemini-flash-latest    -> UnpinnedModel: 'gemini-flash-latest' is an alias, not a pin. The provider documents `-latest` as hot-swapped with every release, so two runs a week apart can reach different models with no change here. Name an exact ID from the models page and add it to PINNED.
gemini-3.7-flash       -> UnpinnedModel: 'gemini-3.7-flash' is not in this project's registry. Add it to PINNED with the date you read it off https://ai.google.dev/gemini-api/docs/models, or use one of: gemini-3.8-flash.
gemini-3.8-flash       -> ok, gemini-3.8-flash
```

**Line by line:**

- Row one is the alias, and the sentence it gets back is about *what changes underneath you*, not
  about the registry. It
  does not say the name is unknown, because the name is perfectly well known and that is the
  problem. Somebody reading this at speed learns the actual objection in one line.
- Row two is an ID that could be real and is not written down here. The message says what to add and
  **where the value comes from** — the models page, by URL — because the failure mode of a registry
  is somebody adding a plausible-looking string from memory. Naming the source turns a guess into a
  lookup.
- Row three returns the string it was given. `require_pinned` is a pass-through, so it can sit in
  the middle of an expression, and this row is the evidence that it does not quietly normalise or
  rewrite what you handed it.
- Nothing here contacted anything. The whole registry is a dict and two `if`s, which is why
  `run.py check` can assert it on a machine with no key and no network — and why it fails before a
  request is built rather than after one is paid for.

*Observed on this machine on 2026-09-09, uv 0.12.3, CPython 3.12.12.*

## When it breaks

Somebody needs a fix out, hears that a newer Flash model is available, and edits the constant to a
version number that sounds right. The check refuses before anything is sent:

```console
gemini-3.7-flash       -> UnpinnedModel: 'gemini-3.7-flash' is not in this project's registry. Add it to PINNED with the date you read it off https://ai.google.dev/gemini-api/docs/models, or use one of: gemini-3.8-flash.
```

The refusal is the good outcome and it is worth sitting with, because the alternative is not an
error — it is a `404` from the provider on the first real question, at whatever hour that question
arrives, with a message about a model rather than about your registry. The smallest fix is the one
the message asks for: open the models page, read the ID off it, and add the row with today's date.
One lookup, one row, and that
small ceremony is the entire mechanism by which a string in this repository stays connected to a
string on somebody else's server.

## In production

**What a senior writes instead.** The same thing, one layer up: a settings module or a small
registry object that every agent reads its model from, validated once at process start, with the
resolved ID emitted into the first log line of every run and stamped onto every eval record. The
point of the last two is that a model change becomes visible in data you already collect — you can
answer "which model produced this answer?" about a result from three weeks ago, which is the
question you will actually be asked. What they do not do is spread model strings through call sites,
and what they never do is let a cast run with any agent's model unset.

**What degrades at scale.** The number is **three**, and it is the plan's own: three agents with no
explicit model is three agents silently on `gemini-3.5-flash`, four generations behind the one you
believe you deployed, with a zero-line diff to show for it. Nothing errors, nothing warns, every
answer arrives. The cost is a quality regression spread evenly across your whole system, invisible
to every test that only checks that a response came back, and undetectable by reading the
repository — because the repository does not contain the string that is being used.

**The review comment.** "This passes `model="gemini-flash-latest"`. That alias is documented as
hot-swapped on every release, so this line pins nothing and the model can change under us between
two deploys with no diff. Please take the exact ID from the models page, put it in
`util/models.py` with the date you read it, and call `require_pinned` at the call site so an
unregistered ID fails before we build a request rather than after we pay for one."

**The interview question.** "Your assistant's answers got noticeably worse last month. Nothing
was deployed in that window, the prompt has not changed, and the tests are green. Name every way
the model behind an unchanged codebase can change, and say which of them your repository would
have recorded."
