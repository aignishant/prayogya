## One-line answer

One server object, one decorated function, and the function's own signature and docstring become
the entire interface a caller gets — no import, no shared type, and no file path crossing the line.

## The idea

The scanner beside the cycle-count cage has one job: you point it at a bin label, it tells you what
the ledger thinks is there. Not the whole ledger — not the racking layout, not last week's
adjustments, not the file the terminal reads from. One bin, on request, and nothing else the
scanner was not built to hand back.

A **tool** is one entry on that docket: a name, a description in prose, and a schema for its
arguments. The description is not documentation of the tool — from day 8, when a model is choosing
between tools, **the description is the API**. It is the only thing the model has to go on.

What makes the Model Context Protocol worth using here rather than inventing something is that it
fixes the shape of the docket. **MCP** is a JSON-RPC protocol by which a program exposes tools,
resources and prompts to a model's client, so the tool lives in its own process instead of inside
the agent. Its versions are dated revisions, and which one you speak is a fact about your installed
SDK.

This project speaks `2026-07-28`, the current revision, which carries the version on every request
rather than agreeing it once in a handshake. Inside this project the consequence is simple and
visible in the next part: there is no handshake to watch, and `client.protocol_version` reports the
revision that governed the call.

## The mechanism

The whole file, at `stock_mcp/server.py`:

```python
"""The stock boundary: the only process that opens the ledger.

One server object, one declared tool. The tool's description and its parameter names are the whole
interface a caller gets — there is no import, no shared type and no file path crossing this line.

Run it over stdio with `python -m stock_mcp`, or in-process from a test by handing the `server`
object straight to a `Client`.
"""

from __future__ import annotations

from typing import Any

from mcp.server import MCPServer

from stock_desk.store import Store
from stock_desk.util.logging import log

#: The server's identity. A client reads this back and it appears in every log the boundary keeps,
#: so the version moves when the tools this server declares change.
server = MCPServer(
    name="stock-boundary",
    title="Warehouse Stock Control boundary",
    version="0.1.0",
    instructions=(
        "The stock ledger for a warehouse cycle-counting desk. Every bin in it is synthetic. Ask "
        "for a bin by its id; there is no way to list them all, and no way to read a file."
    ),
)

#: The one object in this process that touches the disk. It is created here, at import, so that
#: exactly one `Store` exists per server process.
store = Store()


@server.tool()
def fetch_bin(bin_id: str) -> dict[str, Any]:
    """Look up one bin by its id.

    Returns the bin's SKU, description and recorded quantity, or `{"found": false}` when the
    ledger has never heard of that bin. A bin id that does not exist is an answer, not an error: a
    counter walking the floor is handed a sheet with a typo on it more nights than not, and the
    caller needs a clean "no such bin" rather than a traceback.

    Args:
        bin_id: The bin id exactly as the caller gave it, for example `A-10-2`.
    """
    bin_ = store.bin(bin_id)
    log("boundary.fetch_bin", bin_id=bin_id, found=bin_ is not None)
    if bin_ is None:
        return {"found": False, "bin_id": bin_id}
    return {
        "found": True,
        "bin_id": bin_.bin_id,
        "sku": bin_.sku,
        "description": bin_.description,
        "aisle": bin_.aisle,
        "unit": bin_.unit,
        "recorded_qty": bin_.recorded_qty,
        "reorder_at": bin_.reorder_at,
    }
```

**Line by line:**

- `from mcp.server import MCPServer` — the high-level server class from the 2.x SDK. **The names in
  this package are read off the installed version, not remembered**: the Python models use
  snake_case where the wire format is camelCase, so it is `tool.input_schema` and
  `result.structured_content`, and the camelCase spellings raise `AttributeError` from pydantic.
- `from stock_desk.store import Store` — **the one import that crosses from the boundary back into
  the desk**, and it goes in this direction only. The boundary reuses the desk's store code; the
  desk never imports the boundary. Reversing that arrow is the failure part 1.1 exists to prevent.
- `from stock_desk.util.logging import log` — day 1's logger, and it matters here more than
  anywhere: it writes to **standard error**, and standard output on this process is the protocol.
  Part 3.2 is what happens when that is forgotten.
- `server = MCPServer(...)` — **a module-level object, created at import.** A client can be handed
  this object directly for an in-process test, or the module can be run as a process; both use the
  same server, which is what stops the tested thing and the shipped thing drifting apart.
- `name="stock-boundary"` — the identity a client reads back. Not the package name and not the file
  name: the name of the *service*, which is what appears in a log when several are running.
- `version="0.1.0"` — **the boundary's own version, separate from the project's.** It moves when
  the tools this server declares change, because that is what a client cares about.
- `instructions=(...)` — prose the client can show to a model, describing what this server is for.
  Read the last clause: **"there is no way to list them all, and no way to read a file."** Saying
  what a boundary *cannot* do is as useful as saying what it can, because it stops a model spending
  a turn asking.
- `store = Store()` — one store per server process, created at import. The desk no longer has one
  at all from here on: the object that opens files lives on the far side of the gate.
- `@server.tool()` — the decorator that puts `fetch_bin` on the docket. Called with no arguments,
  so **everything the client sees is derived from the function itself**: the name from `__name__`,
  the description from the docstring, the argument schema from the annotations. Nothing is written
  twice, so nothing can drift.
- `def fetch_bin(bin_id: str) -> dict[str, Any]:` — **`bin_id: str` is not just a type hint any
  more.** It becomes `{"type": "object", "properties": {"bin_id": {"type": "string"}}, "required":
  ["bin_id"]}` in the schema a model reads. An un-annotated parameter would produce a schema that
  says nothing, and a model would guess.
- **The docstring's first line, "Look up one bin by its id."** — this is what a model sees when
  choosing between tools. From day 8 it is the API, and it is written for a reader who has none of
  the context you have.
- **"A bin id that does not exist is an answer, not an error"** — the contract, stated in the
  docstring where a caller will read it. `fetch_bin` returns `{"found": false}` rather than
  raising, because a counter is handed a sheet with a typo on it more nights than not, and the
  caller needs a letter, not a traceback.
- `Args:` with a description and an example — the argument's own documentation, including the shape
  of a real value. A model that has seen `A-10-2` is far less likely to invent a bin id that looks
  like one from somewhere else.
- `log("boundary.fetch_bin", bin_id=bin_id, found=bin_ is not None)` — the boundary keeps its own
  record of every request. It logs **the bin id and whether it was found**, not the bin's contents:
  a log that carries the answer as well as the question is a copy of the store in a place with none
  of the store's rules.
- `return {"found": False, "bin_id": bin_id}` — the bin id is echoed back so a caller correlating
  several requests does not have to remember which is which.
- **The returned dictionary is cover, not storage.** SKU, description, aisle, unit, recorded
  quantity, reorder point — every field is something the desk's rules read. There is no path, no
  filename and no `_synthetic` marker: if a path crossed this line, something above it could be
  written to open the path, and the whole arrangement would be decoration. Part 3.1 asserts that.

## When it breaks

Ask for a tool the server does not declare, and the refusal comes back as a protocol-level error
rather than as a result:

```bash
uv run python -c "
import asyncio
from mcp import Client
from stock_mcp.server import server

async def main():
    async with Client(server) as client:
        await client.call_tool('read_file', {'path': '.env'})

asyncio.run(main())
" 2>&1 | tail -4
```

```
Tool 'read_file' failed: 'Unknown tool: read_file'
```

The docket is the whole surface. `read_file` is not on it, so there is nothing to route the call
to, and the client is told so by name — as a failed *result* rather than as a raised exception,
because the client is constructed with `raise_exceptions=False` by default and hands failures back
for the caller to read. Somebody arrived at this trying to give an agent "just a little" filesystem
access for debugging, and found that the only way to do it was to declare a tool that does it —
which is a change to a file, in a commit, that a reviewer can see. **The boundary turns a
capability into a diff.**

## In production

**What a senior writes instead.** The same server, with the tool descriptions treated as
user-facing copy — reviewed, versioned and tested — because from day 8 they are the interface a
model is reasoning about, and a vague description produces wrong tool choices that look like model
failures. They would also split `instructions` from the tool docstrings deliberately: the first
says what this server is, the second says what one request does.

**What degrades at scale.** One tool with one string argument is a docket anybody can read. A
boundary with thirty tools is a menu a model has to choose from on every turn, and the cost is not
only tokens — it is that similar descriptions produce ambiguous choices. The discipline that scales
is the one this file already shows: **every field in the return value is something a rule reads**,
so the docket grows because the desk needs it rather than because it was easy to add.

**The review comment.** *"`fetch_bin` returns the reorder point on every call. Nothing in the
desk's rules reads it yet — it is planted for day 12's replenishment slot. Say so in the docstring,
or take it out until the day that reads it exists."*

**The interview question.** *"Your tool's docstring is derived into the schema a model reads. What
does that mean for how you review a change to a comment, and what would you put in a test to stop
it drifting?"*

## Check yourself

- **Run:** `uv run python -c "import stock_mcp.server; print(stock_mcp.server.server.name)"` —
  expect `stock-boundary`. That proves the module imports and the server object exists; the next
  part is where anything actually crosses the line.
- **Say out loud:** `stock_mcp` imports from `stock_desk`, and `stock_desk` never imports
  `stock_mcp`. Say what that one-way arrow buys, and what would be lost the first time somebody
  reverses it "just for a test".
