## One-line answer

Every line this desk writes is one JSON object on standard error, with any field whose *name*
contains a secret-shaped **word** replaced by `<redacted>` — matched as whole words, so `api_key`
is hidden and `keys` is not, because a redactor that blanks the field listing a dictionary's keys
is a log that has quietly stopped saying anything.

## The idea

A counter's count sheet has a fixed layout: bin, part number, quantity, who, when — one line per
bin, the same columns on every sheet, so that a sheet from aisle A in March can be laid beside one
from aisle C in June and read the same way. What never goes on the sheet is the radio's channel
code, however often somebody says it near the counter. The sheet is filed, photocopied, sent to
finance; the channel code is not for any of those places.

A log is the count sheet, and this module is its layout. **One line, one record**: every event the
desk writes is a single JSON object on one line, with a timestamp, an event name, and whatever
fields the caller passed. Not prose — prose is for people at the moment it is written, and a log
is read by a program six months later, filtering three million lines for the one bin. JSON per
line is what makes `grep` and a JSON parser the same tool.

Where the line goes matters, and the choice is made now for a reason that arrives on day 3. The
line goes to **standard error**, never standard output. Standard output is a program's *answer* —
the thing whatever ran it is waiting for — and on day 3 this desk's boundary will speak a protocol
over standard output to whoever launched it, where a stray log line is a corrupt message. Standard
error is the channel for everything that is not the answer, and a log is exactly that.

And the channel code stays off the sheet. The redactor works on **field names**, because a value
tells you nothing reliable — a key looks like a string — and a name is what the call site chose on
purpose. A field called `api_key` is redacted. So is `provider.auth_token`, three levels down. The
choice worth a paragraph is *how* a name is matched, because the obvious way is wrong in a way
nobody notices. Matching by substring — does the name *contain* `key`? — catches `api_key`,
`API_KEY` and `provider_key` with one word in the list, and it also catches `keys`, `monkey` and
`keyword`. A field called `keys` is the natural name for the list of fields a tool answered with,
and under substring matching it says `<redacted>` on every line, forever, with no error, because
writing a log line succeeds whatever the line says. This module splits a name into **words** — on
underscores, dots, case changes, anything that is not a letter or digit — and asks whether one of
the words *is* a secret word. `api_key` has the word `key`; `keys` has the word `keys`, which is
not on the list. Same list, no exceptions, and the field that lists the keys says what it means.

The last design choice is small and is the reason this module is testable: `log` **returns** the
record it wrote. A test can call it and read the dictionary back without capturing a stream.

## The mechanism

The whole file, at `stock_desk/util/logging.py`:

```python
"""One JSON object per line, on standard error, with secrets redacted by field name.

A stock desk writes about suppliers, prices and the people who counted. Every line this module
emits is machine-readable, so a run can be filtered and counted months later, and nothing that
looks like a secret survives the trip to the page.

The redactor matches **whole words in a field's name**, not substrings. `api_key`, `API-KEY` and
`provider.key` are redacted because the word `key` is one of their words; `keys`, `monkey` and
`keyword` are not, because it is not. A redactor that matched substrings would silently blank the
field that lists a dictionary's keys, and a log line that says `<redacted>` where it meant to say
something is a line nobody notices has stopped speaking.
"""

from __future__ import annotations

import json
import re
import sys
from datetime import UTC, datetime
from typing import Any

REDACTED = "<redacted>"
SECRET_WORDS = frozenset({"key", "token", "secret", "password", "authorization", "credential"})

#: A field name is split into words on anything that is not a letter or a digit, so `api_key`,
#: `apiKey` and `api.key` all yield a word `key`. Case is folded first.
WORD = re.compile(r"[a-z0-9]+")


def words_of(name: str) -> set[str]:
    """The lower-case words in a field name: `provider_auth_token` -> {provider, auth, token}."""
    spaced = re.sub(r"([a-z0-9])([A-Z])", r"\1 \2", name)
    return set(WORD.findall(spaced.lower()))


def looks_secret(name: str) -> bool:
    """Does one of this field's words say its value must not be written down?"""
    return not SECRET_WORDS.isdisjoint(words_of(name))


def redact(fields: dict[str, Any]) -> dict[str, Any]:
    """A copy of `fields` with every secret-looking value replaced, at any depth."""
    clean: dict[str, Any] = {}
    for name, value in fields.items():
        if looks_secret(name):
            clean[name] = REDACTED
        elif isinstance(value, dict):
            clean[name] = redact(value)
        else:
            clean[name] = value
    return clean


def log(event: str, **fields: Any) -> dict[str, Any]:
    """Write one redacted JSON record and return it.

    Returning the record is what makes redaction testable without capturing a stream.
    """
    record = {
        "ts": datetime.now(UTC).isoformat(timespec="milliseconds"),
        "event": event,
        **redact(fields),
    }
    print(json.dumps(record, default=str), file=sys.stderr, flush=True)
    return record
```

**Line by line:**

- `SECRET_WORDS = frozenset({...})` — **six words, and they are words.** Not patterns, not
  prefixes. A name is redacted when one of *its* words is one of these. `frozenset` because the
  list is a rule, and a rule that can be appended to at run time is a rule somebody will append to
  from a test.
- `WORD = re.compile(r"[a-z0-9]+")` — **what counts as a word: a run of letters or digits.**
  Everything else — underscore, dot, hyphen, space — is a separator. `provider.key` and
  `provider_key` and `provider-key` are the same three words.
- `re.sub(r"([a-z0-9])([A-Z])", r"\1 \2", name)` — **a capital after a lower-case letter starts a
  new word**, so `apiKey` becomes `api Key` before it is lower-cased and split. Without this line,
  `apiKey` would be one word `apikey`, which is not `key`, and a caller who writes fields in
  camel case would get no redaction and no warning.
- `not SECRET_WORDS.isdisjoint(words_of(name))` — **do the two sets share a word.** Whole-word
  equality, by construction: `keys` is the word `keys`, and the set does not contain it. The
  transcript below shows every case the test holds.
- `redact` and `elif isinstance(value, dict): clean[name] = redact(value)` — **at any depth**, so a
  provider block with a token inside it is cleaned without the caller knowing the block's shape.
  A list is not descended into: a list of names is a list of values, not of fields, and a list of
  dictionaries is a shape this desk does not log.
- `"ts": datetime.now(UTC).isoformat(timespec="milliseconds")` — **UTC, to the millisecond,
  first.** A warehouse on two sites in two time zones sorts one log by this field; a local time
  would interleave two clocks. First in the record so the line reads as a line in a ledger:
  when, what, then the details.
- `print(json.dumps(record, default=str), file=sys.stderr, flush=True)` — **standard error,
  flushed.** `default=str` so a value the JSON encoder does not know — a `Path`, a `date` — becomes
  its string rather than an exception in the logger, which is the one place an exception must
  never come from. `flush=True` so the line is on the page before whatever happens next, which is
  the property a crash log needs.
- `return record` — **the record, after redaction**, so a test asserts on what was written and
  the desk can hand a line to whatever else wants it.

One line, with the shapes the redactor has to get right — a field called `keys`, a field called
`api_key`, and a token two levels down:

```bash
uv run python -c "
from stock_desk.util.logging import log
log('ledger.read', bin='C-07-2', keys=['sku', 'qty', 'counted_by'], api_key='AIzaSy-not-a-real-key', provider={'name': 'ledger', 'auth_token': 'nope'})
"
```

```
{"ts": "2026-09-12T11:09:38.131+00:00", "event": "ledger.read", "bin": "C-07-2", "keys": ["sku", "qty", "counted_by"], "api_key": "<redacted>", "provider": {"name": "ledger", "auth_token": "<redacted>"}}
```

**Line by line:**

- `"keys": ["sku", "qty", "counted_by"]` — **the list is there.** This is the line the whole
  matching rule exists for: a field named for the keys of an answer, and its contents intact.
- `"api_key": "<redacted>"` — **the secret is not.** The value was a placeholder shaped like a
  key; the redactor did not look at it, only at the name.
- `"provider": {"name": "ledger", "auth_token": "<redacted>"}` — **depth.** The block kept its
  shape and its harmless field, and lost the one whose name has the word `token` in it.

The words, one name at a time — the same cases the test in part 3.2 holds:

```bash
uv run python -c "
from stock_desk.util.logging import words_of, looks_secret
for name in ('api_key', 'apiKey', 'provider.key', 'AUTHORIZATION', 'keys', 'monkey', 'keyword', 'tokens_used'):
    print(f'{name:<14} {sorted(words_of(name))!s:<28} {looks_secret(name)}')
"
```

```
api_key        ['api', 'key']               True
apiKey         ['api', 'key']               True
provider.key   ['key', 'provider']          True
AUTHORIZATION  ['authorization']            True
keys           ['keys']                     False
monkey         ['monkey']                   False
keyword        ['keyword']                  False
tokens_used    ['tokens', 'used']           False
```

**Line by line:**

- **Four secrets, four non-secrets, and the middle column is the whole argument.** `apiKey` splits
  on the case change; `provider.key` splits on the dot; `AUTHORIZATION` folds to one word that is
  on the list.
- `tokens_used   ['tokens', 'used']   False` — **the plural is not the word.** A count of tokens
  spent is a number a log should carry; the word `tokens` is not `token`. This is the case that
  will matter most once a model is billing this desk per token, and it is why the list holds
  singulars and the matcher does not stem.

And the stream — the answer on one channel, the log on the other:

```bash
uv run python -c "
from stock_desk.util.logging import log
log('ledger.read', bin='C-07-2')
print('{\"answer\": 52}')
" 2>/dev/null
```

```
{"answer": 52}
```

**Line by line:**

- `2>/dev/null` — **standard error discarded, and the log line went with it.** What is left is
  what the program *answered*. Day 3's boundary is a program whose standard output is read by
  another program as protocol; this is the property that lets it log at all.

## When it breaks

The obvious matcher. Substring, one line shorter, and it catches every spelling of `key` without
the regular expression:

```diff
 def looks_secret(name: str) -> bool:
     """Does one of this field's words say its value must not be written down?"""
-    return not SECRET_WORDS.isdisjoint(words_of(name))
+    lowered = name.lower()
+    return any(word in lowered for word in SECRET_WORDS)
```

```
>       assert desk_logging.looks_secret(name) is secret
E       AssertionError: assert True is False
E        +  where True = <function looks_secret at 0x000001E841ACC540>('keys')
E        +    where <function looks_secret at 0x000001E841ACC540> = desk_logging.looks_secret
FAILED tests/test_kit.py::test_redaction_matches_whole_words_and_not_substrings[keys-False]
FAILED tests/test_kit.py::test_redaction_matches_whole_words_and_not_substrings[monkey-False]
FAILED tests/test_kit.py::test_redaction_matches_whole_words_and_not_substrings[keyword-False]
FAILED tests/test_kit.py::test_redaction_matches_whole_words_and_not_substrings[tokens_used-False]
4 failed, 13 passed in 0.12s
```

And the line from the mechanism section, written by that version:

```
{"ts": "2026-09-12T11:09:39.162+00:00", "event": "ledger.read", "bin": "C-07-2", "keys": "<redacted>"}
```

Four tests red, and they are the four non-secrets: `keys`, `monkey`, `keyword`, and `tokens_used`,
the last because `token` is a substring of `tokens`. Every secret is still caught — the substring
version is *stricter*, which is exactly why it looks safe in review. The cost is the line above: a
field that was meant to say which fields the ledger answered with says `<redacted>` instead, on
every line, and writing it succeeded. Somebody shipped this on a Friday, and on the night a bin
count came back with a field missing, the one log line that would have said which fields arrived
said nothing at all. The smallest fix is the two lines the file has, and the rule behind them: a
redactor is a **list of words**, matched as words, with no exception list — because the day the
list grows an exception for `keys` is the day it grows one for `api_keys`.

## In production

**What a senior writes instead.** Typed events — one small class per event name with declared
fields, and the sensitive ones marked at the declaration — so that nothing can be accidentally
called `keys` because nothing is called anything without being declared, and the redactor reads a
mark rather than guessing from a name. That is the right end state for a desk with forty event
types and the wrong starting point for one with none; today the name-based rule is the whole
scheme, and it is written so the typed version can replace `looks_secret` without touching a call
site.

**What degrades at scale.** A three-aisle warehouse logs a few hundred lines a night. A
distribution centre's stock system logs a few hundred thousand — every bin read, every count
recorded, every variance explained — and at that volume two things happen to a name-based
redactor. False positives stop being funny: a field called `turnkey_supplier` is blank in every
report about that supplier, and a field called `low_key_priority` is blank in every ticket. And
false negatives arrive from vocabularies the list never heard of: a field called `bearer` or
`pat`. The answer at that size is a scanner over the log *output* that looks for things shaped like
secrets by value, kept beside this name-based rule as the cheap first line.

**The review comment.** *"`SECRET_WORDS` gained `pin` in this diff, for the terminal PIN. `pin`
is also the word in `pin_file` and `pinned_version`, both of which this desk logs. Either use a
more specific word at the call site — `terminal_pin_code` still redacts under `code`? no, it does
not — or add `pin` and accept that two fields go quiet. Say which in the commit."*

**The interview question.** *"Your log redacts fields by name. Give me a field name it should not
redact and does, one it should and does not, and how you would find each in a log you did not
write."*
