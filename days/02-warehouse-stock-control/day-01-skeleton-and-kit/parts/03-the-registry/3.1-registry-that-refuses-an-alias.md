## One-line answer

Every model this desk may name is written down once, as an exact ID observed on the provider's own
page today, and a function refuses anything else — an alias that is hot-swapped on every release, the
legacy model an unpinned agent silently lands on, or any name not in the list — so that which model
explained a variance is a fact in a commit and not a guess about a Tuesday.

## The idea

Every counter on the night shift is handed the same scanner from the kit cage, and the scanner's
firmware version is on a label on its back. That label is not there for the counter. It is there for
the morning a bin shows forty-eight where the ledger says fifty-two and the stock controller asks
which scanner counted it — because two firmware releases apart, the inner-pack rounding differs, and
a four-unit gap that is a rounding rule is not a four-unit gap that is a theft.

Now suppose the label said "current". Every scanner in the cage says "current", the supplier pushes
a new firmware on a Tuesday, and from Wednesday every count is made by something with a different
rule and the same label. Nobody changed anything. Nobody can say when the counts stopped being
comparable, because the label never changed.

A model name with `-latest` on the end is that label. The provider's page, read today, says exactly
what it does: the alias "will get hot-swapped with every new release of a specific model
variation." An agent configured with one is an agent whose behaviour changes without a commit, and
a stock desk whose reconciler changed on a Tuesday cannot explain a replenishment it raised on
Monday.

So this desk keeps a **registry**: one file that names every model it may use, as an exact ID
copied from the provider's page with the date it was read, and one function — `pinned` — that every
agent's configuration must pass its model name through. The function returns the name if it is one
of the exact IDs and raises if it is anything else. Three things are refused, each for a reason
worth its own sentence:

- **An alias**, anything ending `-latest`, because it names a role rather than a model.
- **The legacy model**, by name. The framework this desk installs on day 8 defaults, when nothing
  is pinned, to the provider's legacy Flash model — so an agent that forgets to pin does not get a
  random model, it gets a specific old one, and this registry names that one so it can be refused
  on sight rather than by accident. (`TODO(me)`: confirm the framework's default model ID on the
  day it is installed, by reading the installed source.)
- **Anything not in the list**, because a registry with a gap is a comment.

Today there is no agent to configure. The registry is written on day 1 for the same reason the
scanner labels are printed before the shift: it is a promise about every agent this desk will ever
have, and a promise is cheapest to keep when nothing has been built that could break it.

## The mechanism

The whole file, at `stock_desk/models.py`:

```python
"""Every model this desk may name, pinned to an exact ID, with nothing resolved at run time.

Observed at https://ai.google.dev/gemini-api/docs/models on 2026-09-12:

    gemini-3.8-flash       New Stable  "Our most intelligent Flash model, engineered for
                                        long-horizon software engineering, autonomous agents,
                                        and complex enterprise workflows."
    gemini-3.7-flash       Stable      "Our previous-generation Flash model for complex coding,
                                        agentic workflows, and reliable multi-step execution."
    gemini-3.5-flash       Stable      "Our legacy Flash model, providing baseline speed and
                                        foundational performance for routine, high-throughput
                                        workloads."

The same page says of a `-latest` alias: "This alias will get hot-swapped with every new release
of a specific model variation." A stock desk that changes which model explains a variance, without
a commit, cannot explain a replenishment it raised last month.
"""

from __future__ import annotations

PRIMARY = "gemini-3.8-flash"
FALLBACK = "gemini-3.7-flash"

#: The legacy Flash ID. Named here so the registry can refuse it by name rather than by silence:
#: it is what an unpinned agent can end up on, and this desk never chooses it deliberately.
LEGACY = "gemini-3.5-flash"

ALLOWED = frozenset({PRIMARY, FALLBACK})


class UnpinnedModel(ValueError):
    """A model name this project will not use: an alias, or an ID not in the registry."""


def pinned(name: str) -> str:
    """Return `name` if it is an exact allowed ID, or raise `UnpinnedModel` saying why.

    Called wherever an agent is configured, so the pin is enforced by code rather than promised
    by a comment.
    """
    if name.endswith("-latest"):
        raise UnpinnedModel(
            f"{name!r} is an alias, not a pin: it is hot-swapped on every release, "
            f"so it names whichever model currently holds the role rather than a model"
        )
    if name == LEGACY:
        raise UnpinnedModel(
            f"{name!r} is the provider's legacy Flash model and this desk does not choose it; "
            f"pin {PRIMARY!r} or {FALLBACK!r}"
        )
    if name not in ALLOWED:
        raise UnpinnedModel(f"{name!r} is not in this project's registry: {sorted(ALLOWED)}")
    return name
```

**Line by line:**

- **The docstring is an observation, dated.** Three IDs and the provider's own one-line
  description of each, copied from the page on the day, with the URL. The quotation about the
  `-latest` alias is there because it is the whole argument for this file, in the provider's words
  rather than this project's. Somebody reading this in six months can open the URL and see what
  moved.
- `PRIMARY = "gemini-3.8-flash"` — **the newest stable Flash on the day**, and the one every agent
  in this desk will be configured with. `FALLBACK = "gemini-3.7-flash"` — the previous generation,
  named now so that day 15's reliability work has a second exact ID to fall back to rather than an
  idea of one.
- `LEGACY = "gemini-3.5-flash"` — **named in order to be refused.** A registry that only listed
  what it allows would refuse this by silence — "not in the list" — and a reader of that message
  would not learn that this is the model an unpinned agent lands on. Naming it lets the message say
  why it is here.
- `ALLOWED = frozenset({PRIMARY, FALLBACK})` — **the whole registry, as a set.** Frozen because
  nothing at run time may add to it; two members because that is how many this desk has decided
  on. Adding a third is an edit to this file and a commit, which is the point.
- `class UnpinnedModel(ValueError)` — **its own exception**, so a caller can catch exactly this
  and nothing else, and so the traceback names what happened in one word.
- `if name.endswith("-latest")` — **the alias check comes first**, with a message that says what an
  alias is, because the person who wrote `gemini-flash-latest` did so believing it was safest. The
  message argues with that belief in one sentence.
- `if name == LEGACY` — **the second refusal, with the fix in it.** `pin 'gemini-3.8-flash' or
  'gemini-3.7-flash'` — both allowed IDs, quoted, so the reader does not have to open this file to
  find out what to type.
- `if name not in ALLOWED` — **the catch-all.** Any ID not in the set — a typo, a real model this
  desk has not adopted, an alias that does not end in `-latest` — is refused with the list. This
  line alone would make the file correct; the two above it make the messages worth reading.
- `return name` — **the name comes back unchanged.** `pinned` is a gate, not a lookup: it is
  written to be called inline, `model=models.pinned(PRIMARY)`, so that a configuration line that
  skipped it looks visibly different from one that did not.

Ask the registry the four questions, from the project root:

```bash
uv run python -c "
from stock_desk import models
print(models.pinned('gemini-3.8-flash'))
for bad in ('gemini-flash-latest', 'gemini-3.5-flash', 'gemini-2.0-flash'):
    try:
        models.pinned(bad)
    except models.UnpinnedModel as why:
        print('refused:', why)
"
```

```
gemini-3.8-flash
refused: 'gemini-flash-latest' is an alias, not a pin: it is hot-swapped on every release, so it names whichever model currently holds the role rather than a model
refused: 'gemini-3.5-flash' is the provider's legacy Flash model and this desk does not choose it; pin 'gemini-3.8-flash' or 'gemini-3.7-flash'
refused: 'gemini-2.0-flash' is not in this project's registry: ['gemini-3.7-flash', 'gemini-3.8-flash']
```

**Line by line:**

- `gemini-3.8-flash` — **the one allowed name, echoed back.** Nothing else printed, because nothing
  else happened.
- **Three refusals, three different sentences.** The first says what an alias is. The second says
  which model this is and which two to pin instead. The third is the plain case — a model that
  exists at the provider and not in this desk — and it prints the registry so the reader can see
  the gap is deliberate.
- `['gemini-3.7-flash', 'gemini-3.8-flash']` — **sorted**, so the message reads the same on every
  run. A set prints in whatever order it likes; a message that changes between runs is a message
  people stop reading.

## When it breaks

Two experiments, and the first one is the reassuring kind. Disable only the alias line, the way
somebody does when they decide the special case is fussy:

```diff
-    if name.endswith("-latest"):
+    if False and name.endswith("-latest"):
```

```
refused: 'gemini-flash-latest' is not in this project's registry: ['gemini-3.7-flash', 'gemini-3.8-flash']
```

Still refused, and the tests stay green (`17 passed`). The alias never reached the provider,
because the catch-all did its job — the registry has two lines of defence against an alias, and
losing the first costs a good message rather than the protection. That is worth knowing, and it is
not the failure this part is about.

The failure is the other edit: make `pinned` a name for "return what I was given":

`DID NOT RAISE` is the whole finding. Every configuration line in the desk still reads
`model=models.pinned(...)`, every one of them still looks pinned, and none of them is — the gate
has become a mirror. Somebody who shipped this on a Friday to "stop the registry getting in the
way" would have a reconciler on whatever the alias resolved to by Monday, and the first sign would
be a variance explanation that read differently from last week's for no reason anyone could name.
The smallest fix is the eleven lines back. The general rule is that a gate is only a gate while a
test proves it refuses something, which is part 3.2.

## In production

**What a senior writes instead.** The same registry, with the provider's page fetched by a check
in the pipeline and diffed against the docstring — so that the day `gemini-3.8-flash` stops being
"New Stable" is a red line rather than a surprise — and a second pin beside the model ID: the
*prompt* version, so that a change to what the reconciler is told is also a commit. A model pinned
under a prompt that drifts is half a pin.

**What degrades at scale.** A three-aisle warehouse reconciles sixty bins a night and one model
explains every variance. A regional distribution centre runs cycle counts on six thousand bins a
night across four sites, each site's desk deployed on its own schedule — and the morning the
provider retires an alias's target, four sites are on three different models and the variance
explanations stop being comparable across sites. Every one of the roughly two hundred variances
a night that goes to a human is then a question about which model wrote it, and the registry is
the only file that can answer.

**The review comment.** *"This adds `gemini-3.8-flash-latest` to `ALLOWED` so the alias check is
satisfied. That defeats the alias check by construction. If the team wants the newest 3.8, pin the
ID it resolves to today, in this file, with the date, and let the next bump be a diff."*

**The interview question.** *"Your agent's model is configured as `something-latest` and the
provider rolls a new release overnight. Tell me what changes about your system's behaviour, how
you would find out, and what you would have written down to stop it."*
