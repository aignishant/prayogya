## One-line answer

Two of the four files on this project's toolwall are tools you have used before, so they are printed
whole and walked at recap depth — a table naming the failure each decision prevents, then a pointer
pair — and the one genuinely new thing about them is that this project **re-decided** its pins on its
own date rather than inheriting them, which is why the model ID matching P01's is a coincidence and
not a setting.

## The idea

Every tool on a well-kept board has a label under its outline, and the label is not the tool's name —
the shape on the wall already tells you that. The label says which one it is: the make, the size, and
the date it came into the shop. The reason is dull and it is the whole reason. Two 17mm spanners can
sit on the same wall, one of them a good one and one of them the soft one you were given, and on the
day a nut rounds off, the only useful question is *which one was I holding*. A board with shapes and
no labels tells you what is missing. A board with labels tells you what you have.

So the first thing a new shop does with a borrowed design for a board is re-measure it. Not because
the other shop's board is wrong — it is probably fine — but because *fine last month* and *fine here*
are two different claims, and only one of them was ever checked. You lay out your own tools, you
write your own labels, and if half of them end up matching the labels across the road, that is a fact
about the tools, not about the boards.

Two files on this project's wall are like that. One says which model may be called — a name written
down once, in one place, so that nothing in this project ever names a model at a call site and
nothing ever inherits a default from the framework. The other reads a secret out of a file and
refuses, by name, when one is not wired. You have used both ideas before. Neither is being taught
again here, and both are printed in full anyway, because the rule from part 1.1 says a project's own
documents carry every line the project needs.

What *is* new is the labelling. The plan requires every project to pin **independently**: its own
package versions, its own model ID, its own interpreter, each recorded in that project's own
`PACKAGES.md` with the date it was observed. Two projects may legitimately sit on different versions
of the same package, and that is not drift — it is what independence means, and the freshness check
run at the start of each project is where the newer one wins. This project ran that check on its own
date. It happens to have landed on the same model ID P01 uses. That match is a coincidence of two
projects being started a sitting apart; it is not a shared setting, there is no shared file that
holds it, and if the provider had retired that ID overnight, this project would have picked a
different one and P01 would have gone on unchanged until somebody opened it.

Two terms are being used above and both were defined on earlier days rather than here: a
[**pin**](../../../../../docs/GLOSSARY.md) is a written-down exact version, recorded in a file so
that a machine and not a memory decides what gets used; a [**model
alias**](../../../../../docs/GLOSSARY.md) is a name like `-latest` that stands in for whichever model
currently holds a role, which makes it a floor wearing a version's clothes. The pointer pairs at the
end of each walkthrough below are where the arguments behind both live.

## The mechanism

`projects/02-parts-counter/parts_counter/util/models.py`, whole file. Nothing in it imports anything
outside this project, and nothing outside this project is on its import path:

```python
# parts_counter/util/models.py
"""This project's model registry. One exact ID per role, and nothing chooses for us.

Every agent and every raw call in this project names a model from here. Nothing anywhere calls a
provider with a model string typed inline, and nothing relies on a framework default.

Two things this file refuses to do, both deliberate:

  * It never uses an alias like `gemini-flash-latest`. The provider documents those as hot-swapped
    on every release, so an alias is a floor and not a pin — the same distinction P00 day 3 drew
    about `>=` in `pyproject.toml`.
  * It never leaves a model unset. ADK 2.8.0's built-in default is `gemini-3.5-flash`, which the
    provider's models page lists as Stable and calls "our legacy Flash model" — four generations
    behind the one below. An agent that inherits that default is not broken and not experimental;
    it is quietly old, which is harder to notice than either.

This project pins independently of every other one (the plan section 9). The ID below happens to
match P01's; that is a coincidence of two projects being started two days apart, not a shared
setting, and the freshness check in `PACKAGES.md` is what re-decided it.

Verified against https://ai.google.dev/gemini-api/docs/models on 2026-09-10.
"""

from __future__ import annotations

from typing import Final

# The desk's one brain. Documented Stable on 2026-09-09 and described by the provider as
# "engineered for long-horizon software engineering, autonomous agents, and complex enterprise
# workflows" — which is what this project is.
ANSWERING: Final[str] = "gemini-3.8-flash"

# Every model this project is allowed to name, mapped to the date the ID was read off the
# provider's models page. `run.py check` asserts the ID a call is about to use is in here.
PINNED: Final[dict[str, str]] = {
    ANSWERING: "2026-09-10",
}

# The API version segment of every endpoint URL. Kept here rather than spelled into provider.py so
# that moving off v1beta is one edit in one file.
API_VERSION: Final[str] = "v1beta"

BASE_URL: Final[str] = "https://generativelanguage.googleapis.com"


class UnpinnedModel(RuntimeError):
    """Raised when code is about to call a model this project never wrote down."""


def require_pinned(model: str) -> str:
    """Return `model`, or refuse if it is not in `PINNED`.

    The alias check is separate and comes first, because `gemini-flash-latest` would otherwise be
    refused with a message about the registry when the real objection is that it is not a version.
    """
    if model.endswith("-latest"):
        raise UnpinnedModel(
            f"{model!r} is an alias, not a pin. The provider documents `-latest` as hot-swapped "
            f"with every release, so two runs a week apart can reach different models with no "
            f"change here. Name an exact ID from the models page and add it to PINNED."
        )
    if model not in PINNED:
        raise UnpinnedModel(
            f"{model!r} is not in this project's registry. Add it to PINNED with the date you "
            f"read it off https://ai.google.dev/gemini-api/docs/models, or use one of: "
            f"{', '.join(sorted(PINNED))}."
        )
    return model
```

**Line by line — recap depth.** This code is taught in full on day 4, in P01's first sitting. One row
per line that carries a decision, each naming the failure that line exists to prevent:

| Line | What it does, and the failure it prevents |
| --- | --- |
| `ANSWERING: Final[str] = "gemini-3.8-flash"` | One name, in one file, for the model this project calls. Without it the ID is typed at three call sites, changing it is three edits, and two of the three get found. |
| The exact ID rather than `gemini-flash-latest` | An alias is documented as hot-swapped with every release, so a byte-identical repository can reach two different models a week apart with nothing in the history to say so. |
| A model set at all, rather than left to the framework | ADK 2.8.0's built-in default is the provider's own "legacy Flash model". An unset model is not an error and not an experiment: it is quietly old, which is harder to notice than either. |
| `PINNED` mapping the ID to **a date** | The registry records when the ID was read off the provider's page, so a stale pin is visible as an old date rather than invisible as a plausible string. |
| `Final[...]` on all four constants | Declares these as write-once. A type checker objects to a reassignment elsewhere; without it, a helpful `models.ANSWERING = ...` in a test leaks into every later call in the process. |
| `API_VERSION` kept here, not spelled into the caller | Moving off `v1beta` becomes one edit in one file. Spread across call sites, the migration is done when somebody notices the last one, which is never. |
| `class UnpinnedModel(RuntimeError)` | A type a caller can catch on its own, so `run.py` can report a wiring problem as a wiring problem instead of letting a traceback look like a code bug. |
| The `-latest` branch coming **first**, and separately | An alias would otherwise be refused with a message about the registry when the real objection is that it is not a version at all. Two wrong values need two different sentences said back. |
| Both messages naming the models page and the fix | The error carries the remedy, so nobody has to open the source of the check that refused them to find out what to do. |
| `require_pinned` **returning** the model | Check and use are one expression, so no call site can validate and then call something else. A validator you must remember to call separately is the one skipped on the path added in a hurry. |

> **Recap — a floor is not a pin, and `-latest` is a floor.** A version written as `>=` says what is
> too old and hands the choice to whichever machine resolves it, on whichever day; that is right for
> a library and never enough for an application. The same idea reaches models: an alias names
> whichever model currently holds a role rather than a model, so it is a floor wearing a version's
> clothes. Self-contained version: `PRIMER.md` §1.

Now the key reader. `projects/02-parts-counter/parts_counter/util/keys.py`, whole file, exactly as it
sits on disk — including the stale `PRIMER.md` §1 in its docstring that part 1.1 caught, which is
left in place because a document that quietly corrects the code it is printing is a document you
cannot check anything against:

```python
# parts_counter/util/keys.py
"""Read this project's secrets, and refuse — by name — when one of them is not wired.

Nothing loads a `.env` file for you. This project carries its own reader, as every project in this
curriculum does, because a project that borrowed one from a sibling would not run alone.

Recap depth. The deep version of this idea — the process environment against the file, the three
states of a key, and the one no local check can settle — is P00 Foundry day 3, and recapped again in P01 day 1. `PRIMER.md` §1 has
the self-contained version, and you do not need to have read either to use this file.
"""

from __future__ import annotations

import os
from pathlib import Path

# Anchored to this file, not to the working directory, so the answer does not depend on where the
# shell was standing. parts_counter/util/keys.py -> parts_counter/util -> parts_counter -> the project root.
PROJECT_ROOT = Path(__file__).resolve().parent.parent.parent
ENV_FILE = PROJECT_ROOT / ".env"
EXAMPLE_FILE = PROJECT_ROOT / ".env.example"


class MissingKey(RuntimeError):
    """Raised with the name of the key, where it was looked for, and what to do about it."""


def read_env_file(path: Path | None = None) -> dict[str, str]:
    """Parse `KEY=value` lines into a dict. Nothing is exported; the caller decides."""
    path = ENV_FILE if path is None else path
    values: dict[str, str] = {}
    if not path.exists():
        return values
    for line in path.read_text(encoding="utf-8").splitlines():
        line = line.strip()
        if not line or line.startswith("#") or "=" not in line:
            continue
        name, _, value = line.partition("=")
        values[name.strip()] = value.strip().strip('"').strip("'")
    return values


def names_this_project_reads(path: Path | None = None) -> list[str]:
    """Every key name `.env.example` declares. The committed file is the list of names."""
    return sorted(read_env_file(EXAMPLE_FILE if path is None else path))


def get(name: str) -> str | None:
    """The process environment wins; the file is the fallback. Absent is `None`, never `''`."""
    from_process = os.environ.get(name)
    if from_process is not None:
        return from_process
    return read_env_file().get(name)


def require(name: str) -> str:
    """Return the value, or raise `MissingKey` naming the key and the file it belongs in."""
    value = get(name)
    if value is None:
        raise MissingKey(
            f"{name} is not set. Add a line `{name}=...` to {ENV_FILE}, or export it in this "
            f"shell. `.env.example` lists every name this project reads."
        )
    if not value.strip():
        raise MissingKey(
            f"{name} is present in {ENV_FILE.name} with an empty value. An empty string is a "
            f"value, so a check written as `if not os.environ.get(...)` cannot tell this apart "
            f"from the key being absent, and will tell you it is not set."
        )
    return value
```

**Line by line — recap depth.** Taught in full on day 3, in P00 Foundry. One row per decision, each
naming what it prevents:

| Line | What it does, and the failure it prevents |
| --- | --- |
| `PROJECT_ROOT = Path(__file__).resolve().parent.parent.parent` | Anchors every path to **this file**, not to the working directory. Otherwise the same program finds `.env` from inside the project and silently finds nothing from a directory above it — and "silently finds nothing" reads exactly like "the key is not set". |
| `.resolve()` before walking up | Turns a relative or symlinked path into a real absolute one before counting parents, so a project invoked through a symlink cannot land on a `.env` belonging to something else. |
| Three `.parent` calls and not four | Stops at `projects/02-parts-counter`. A fourth would reach the repository root and let this project read a sibling's secrets, which is the exact dependency part 1.1 exists to forbid. |
| `class MissingKey(RuntimeError)` | A type `run.py` catches on its own, so a wiring problem is printed as a wiring problem rather than arriving as a traceback that looks like a code bug. |
| `path: Path \| None = None`, resolved in the body | A default argument is evaluated once, at `def` time. Written as `path: Path = ENV_FILE`, the module-level value is frozen into the function object and reassigning `keys.ENV_FILE` afterwards changes nothing — which makes the file untestable. |
| `if not path.exists(): return values` | An absent `.env` is an empty dict, not an exception. Every deployment target injects secrets as environment variables and none writes this file; raising here fails every container on a file it correctly does not have. |
| `line.startswith("#") or "=" not in line` | Comments and blanks are skipped rather than parsed into garbage. Otherwise a commented-out line becomes a key named `# GOOGLE_API_KEY` that nothing will look up and nothing will report. |
| `name, _, value = line.partition("=")` | Splits on the **first** `=` only, and always returns three parts. `split("=")` breaks on any value containing `=` — which base64 padding produces constantly — by raising or by truncating the secret. |
| `.strip('"').strip("'")` | Removes wrapping quotes a shell tolerates and this parser would otherwise keep, so the credential does not travel with quotation marks attached and get refused while looking correct in the file. |
| `names_this_project_reads` reading `.env.example` | The committed example file **is** the list of names, so there is no second list to keep in step. Two lists drift; one cannot. |
| `get`: process environment first, file second | Every deployment target injects secrets as variables. If the file won, your machine would behave unlike every place the code actually runs, and the difference would surface first in production. |
| `if from_process is not None` rather than `if from_process` | Distinguishes an exported-but-empty variable from an unset one. The truthiness test collapses them, and a deliberately emptied variable then falls through to the file — using a value somebody thought they had removed. |
| `require`: `value is None` and `not value.strip()` as **two** branches | Absent and present-but-empty are two situations needing two different sentences. One condition covering both forces a message vague enough to tell somebody a key is not set while they are looking at the line that sets it. |
| Both messages naming `ENV_FILE` by absolute path | The error carries the fix, and it names *this* project's file — which is how a reader with four project folders open finds out which one refused them. |

> **Recap — reading a key, and the three states of one.** Nothing loads a `.env` for you; the process
> environment wins and the file is the fallback, because that is the way round every deployment
> target works. A key can be **absent** (`None`), **present and empty** (`''`, usually a CI secret
> that was never populated), or **present, non-empty and not accepted** — and nothing running on your
> machine can decide the third, because a credential is valid only because a server holding the other
> half says so. Self-contained version: `PRIMER.md` §3.

## When it breaks

Ask for a key this project does not declare, and read where the message sends you:

```console

$ uv run --frozen python -c "from parts_counter.util import keys; keys.require('NOT_A_REAL_NAME')"
Traceback (most recent call last):
  File "<string>", line 1, in <module>
  File "C:\Users\nisha_gnzw\OneDrive\Desktop\Projects\agentic-projects\projects\02-parts-counter\parts_counter\util\keys.py", line 60, in require
    raise MissingKey(
parts_counter.util.keys.MissingKey: NOT_A_REAL_NAME is not set. Add a line `NOT_A_REAL_NAME=...` to C:\Users\nisha_gnzw\OneDrive\Desktop\Projects\agentic-projects\projects\02-parts-counter\.env, or export it in this shell. `.env.example` lists every name this project reads.
```

Somebody added a second provider to a project like this one, wired the key into the `.env` they had
open, and could not work out why the check still refused — because the `.env` they had open belonged
to the sibling project in the next folder, and both files are called the same thing. The message
above is why this one is survivable: it names the key, it names **this** project's `.env` by absolute
path, and it names the committed file that lists what may go in it. The smallest fix is to read the
path in the error rather than the path in your editor's tab.

## In production

**What a senior writes instead.** One settings object, built at process start and validated once —
`pydantic-settings`, or a single `load_config()` called from `main` — so a misconfigured process
refuses to serve rather than failing at whichever request happens to reach the missing value first.
For the model, the same shape: an enum or a small registry module with the IDs and the date each was
approved, and a CI check that no other module contains a provider model string. What nobody senior
does is scatter `os.environ[...]` through the call sites, and what nobody senior does twice is leave
a model unpinned.

**What degrades at scale.** The number is **three**. A cast of three agents that each inherit the
framework's default model is three silent bugs, not one — three agents quietly running the provider's
own legacy Flash model, all answering, none failing, and nothing anywhere reporting a version. The
plan says exactly this in §9, and it is the reason `require_pinned` exists as a refusal rather than a
warning: a warning about a model that still answers questions is a warning nobody reads twice.

**The review comment.** "The `PINNED` dict has an ID but the date next to it is from the last
project. Either you re-checked it, in which case put today's date on it and add the row to
`PACKAGES.md`, or you copied it, in which case we are pinned to a page nobody has read since. This is
the whole reason the value is a date and not a `True`."

**The interview question.** "Two services in your organisation call the same model. One pins the exact
version, one uses the provider's `-latest` alias. The provider ships a new revision behind that alias
overnight and quality drops. Describe how each service finds out, how long the second one can plausibly
go without noticing, and what you would put in place so that the answer is not 'a customer told us'."
